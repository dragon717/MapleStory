# 现代冒险岛 TMS V273：调研结论与复刻计划 v0.1

研究日期：2026-09-07。目标读者：产品负责人、客户端、游戏后端、数值策划、关卡、UI/UX、测试。

## 0. 阅读约定与执行边界

本轮是公开资料分线研究，不是已经完成客户端逐帧测试或完整游戏内容还原。没有实际启动独立子代理；`workstreams/` 是可直接分派的八份研究工单，不冒充子代理执行日志。来源见 `01_SOURCE_REGISTER.json`，已证实事实与缺口见 `03_FACTS_AND_GAPS.md`。

标记约定：**T**＝台服同期直接证据；**R**＝其他地区官方资料，仅供结构参照；**P**＝本项目建议；**U**＝待取证。官方 Wiki 也可能落后于官方补丁，不以抓取日期充当规则生效日期。没有证据的概率、掉率、帧数和任务 ID 均不填“看起来合理”的原作值。

默认研究对象为台服 TMS V273：2025-09-10 改版及其周期内已公布的 9 月 17 日开放内容；不把 GMS、MSEA 的版本号与台服直接等同，也不混入手游、MapleStory N、怀旧版本或 2026 年后续改版。具体客户端小版本与热更哈希仍待确认。默认复刻常规世界的永久玩法，挑战者世界及燃烧、签到、联动均作为独立规则层。

## 1. 决策摘要

**先做一段能完整体验“打怪—成长—换打法—挑战 Boss—进入新区域”的现代冒险岛，而不是先做全职业、全地图、全商城。**

复刻分四层验收：

| 层 | 真正要还原什么 | 不足以证明还原的东西 |
|---|---|---|
| 操作 | 起跳、位移、转向、攻击起效、收招、受击、平台移动 | 人物能走、能播技能动画 |
| 战斗 | 练级覆盖、单体输出、爆发准备、资源循环、生存窗口 | 同一伤害逻辑换几十张特效 |
| 成长 | 装备多轴强化、核心、区域力量、账号成长 | 只有升级加属性或穿更高等级装备 |
| 长线 | 剧情解锁、区域日常、Boss 周期、明确下一目标 | 堆大量没有因果关系的任务和地图 |

首个版本可以缩小数量，但不能删掉后三层后仍称为“现代玩法复刻”。所有美术、音乐、文本和代码按原创或获授权实现；拥有某个客户端不作为素材可公开分发的依据。

|---|---|---|
| 账号/角色 | 角色创建、职业身份、角色与账号持久化 | 一主职业；为第二职业留验证入口 |

| 五转/六转 | V Matrix 与 HEXA、旧技能升级、新技能、材料 | 代表性功能可玩，不追求全职业全核心 |

| 收集/生活 | 成就、图鉴、制造采集、装扮、椅子、坐骑 | 非主线首版，可占位 |

## 5. 主线怎么跑：不是一条从 1 级刷到底的任务链

### 5.1 三条并行轨道

**成长轨道**：职业开局 → 狩猎/主题副本/经验内容 → 转职与技能扩展 → 200 级五转 → 260 级六转 → 高等级区域成长。200 与 260 两个转职门槛可在官方系统指南中确认；职业例外、任务精简与区域规则仍以目标台服为准。[S09][S10]

**剧情轨道**：各职业的起源章节 → 共同世界事件与区域章节 → 奥术之河相关篇章 → 后续格兰蒂斯区域。研究地图可按“消亡旅途—啾啾—拉契尔恩—阿尔卡娜—莫拉斯—艾斯佩拉—后续黑魔法师相关区域—赛尔尼温及后续区域”组织，台服译名、精确等级和跳过条件列入实测表，不把该概览当逐条任务攻略。[S12][S22]

**战力轨道**：装备底材与套装 → 强化 → 核心/符文 → 挑战适合的 Boss → 获得下一阶段资源。剧情的演出战、解锁前置与常规高难度 Boss 击杀必须分别建模；不能默认打通某个困难 Boss 才能进入所有后续剧情。

### 5.2 按玩家阶段理解

| 阶段 | 玩家主要行为 | 产品要回答的问题 |
|---|---|---|
| 开局 | 理解职业、攻击、移动、互动、穿装备 | 我是谁？我能做什么？ |
| 前五转阶段 | 找合适练级内容、做必要前置、开技能 | 下一步去哪里？为什么值得去？ |
| 200 级起 | 五转任务、核心装配、奥术区域故事/日常 | 我如何从等级成长切换为多系统成长？ |
| 260 级起 | 六转、HEXA、格兰蒂斯区域与新材料 | 哪个核心最改变当前打法？ |
| 中后期 | 练级、区域资源、Boss 周期、账号角色 | 本次上线怎样向下一个目标推进？ |

不要求玩家做完全部低等级旧支线。官方 Maple Guide 按等级推荐内容、提示转职，并允许前往满足条件的地点；部分内容仍要求先完成相关任务。[S08]

### 5.3 五转与六转的流程骨架

五转：收到引导/灯泡任务 → 前往任务地点并完成试炼 → 完成转职 → 获得/装配核心 → 把技能绑定到键位 → 在战斗中使用。三女神、秘法石等存在于官方指南，但本轮不把这份持续维护页面的全部旧步骤认作 TMS273 原样步骤。[S09][S11]

六转：达到门槛并完成必要前置 → 接取六转任务 → 完成与艾尔达及既有力量有关的任务 → 解锁 HEXA → 消耗材料激活/强化核心。其重要性是“新能力+旧能力进化+新资源循环”，而不只是增加一条技能栏。[S10]

**P：复刻流程要录三种账号**：全新账号普通成长、已有账号小号成长、活动加速角色。三条录像分开，才不会把战地/传授或活动赠装误认为新手默认属性。

## 6. 任务与引导：从弹窗变成可执行下一步

**R**：官方 UI 区分永久内容灯泡、限时活动星标、奖励通知；官方 Maple Guide 将推荐内容、转职提示与移动入口结合。[S08][S13]

**P：任务状态**：`Locked → Available → Accepted → ObjectivesComplete → RewardClaimed`。完成目标与奖励到账是两个事实。放弃、章节跳过、组队计数、地图实例和重复任务需独立规则；不强行用单条任务状态表达所有章节。

**P：一条引导至少展示**：当前目标、目的地、推荐理由、奖励用途、阻塞原因、一个下一步操作。展示锁定状态时必须说明是等级不够、前置未做、次数不足还是队伍条件不符。

**P：升级后的通知优先级**：阻塞继续游玩的转职/解锁最高；可提升效率的技能/装备其次；收集、活动与商城最后。一次展示一个主行动，其余进入通知中心。不要复刻满屏红点与重复确认造成的摩擦。

**P：背包满场景**：任务达到完成态仍可保留；奖励事务尚未成功就不能标记已领奖。没有邮箱实现时，保留可领取状态并明确所需空位；有邮箱时也须以同一幂等键保证只到账一次。

## 7. 战斗、技能与效果：按行为还原，不按动画数量还原

**R**：同期官方技能补丁会同时改动作延迟、是否受攻速影响、无目标能否施放、空中可否使用、召唤持续时间、冷却与被动状态，说明“技能效果”远超伤害百分比。[S07]

**P：一个技能至少有八组规格**：输入方式；资源消耗；前摇/起效/后摇与取消规则；有效范围与目标上限；每段/每次伤害的时间；位移与地形关系；Buff/Debuff/召唤/触发；表现与遮挡。

**P：统一执行链**：输入 → 权威校验 → 创建施法实例 → 动作时间轴 → 命中/召唤事件 → 伤害与效果结算 → 客户端表现 → 持久化必要结果。动画不能直接决定随机掉落；UI 按键不能直接修改属性。

**P：首职业的行为样本**：群攻、单体持续输出、短爆发、位移、纵向移动、引导攻击或蓄力、召唤/持续区域、保命、触发被动。一个职业未必天然包含所有类型，缺的类型用测试技能或第二职业验证，不能为了架构测试歪曲原职业。

**P：表现要点**：人物姿态/武器 → 施法特效 → 弹道/场域 → 命中特效 → 飘字/音效。允许独立调低自己与队友效果；Boss 危险预警的可见性不能被战斗特效遮蔽。大招的长演出与无敌、控制、有效伤害窗口须分别记录。

**U**：技能原始帧时、攻速档位、取消窗口、坐标范围、受击无敌、服务端 Tick 与延迟容忍未测量。不得把项目使用的 60 FPS 显示目标说成原作逻辑帧率。

## 8. Buff 与属性：五类来源，多种生命周期

**T/R**：V273 原创资料与同代官方补丁均提示部分英雄技能改为被动；不能把旧版主动 Buff 表直接导入。[S04][S07]

| 类别 | 是否适合倒计时图标 | 需要单独核对的规则 |
|---|---|---|
| 常驻被动 | 通常不必 | 生效条件、技能版本、死亡/重登重算 |
| 开关/姿态 | 状态图标 | 消耗、互斥、跨图、死亡、预设切换 |
| 临时爆发/药水 | 适合 | 延长效果、CD、驱散、死亡、离线计时 |
| 触发/层数/资源 | 按需 | 触发条件、内部 CD、层数、衰减 |
| 队伍光环/敌方异常 | 适合且需分组 | 来源、范围、免疫、控制抗性、退队/离场 |

**P：定义中包含** `stackGroup`、叠加策略、持续时间策略、延长效果适用性、死亡/离线/换图策略、驱散标签、来源实体、属性修饰项。冷却、持续时间与周期触发是三个不同计时器。

**P：属性计算按来源图重算或受控增量更新**：装备/套装、技能被动、账号效果、临时效果分别输入。保存基础事实与效果实例，不在退出时“减回之前加过的百分比”。普通伤害、Boss 条件伤害、最终伤害、暴击、无视防御等不要一律加在一个百分比字段里；目标版本公式另有证据后才填入。

**P：并发例子**：两个角色施加同组增益，强者效果离场后应按规则回落到仍在场的弱者效果，而不是整个组消失。是否取最高、叠加或覆盖，必须由规则定义，不默认为原作统一做法。

## 9. 掉落、背包与经济

**R**：Boss 指南包含难度/前置、练习模式与收益区别；核心、潜能道具、符文等来自不同内容循环。准确掉率和每周次数不能从多年旧指南直接取得。[S11][S12][S16][S20]

**P：四种奖励分开**：地面掉落、直接到账、完成后领取、开启箱子/兑换。共享归属、个人独立归属和队伍分配是另一维度，不能混成“所有东西都在玩家脚下生成”。

**P：交易边界**：可交易、账号内可转移、角色绑定、装备后绑定、带使用期限、带保管期限分开建模；同样的道具模板可能有不同实例限制。

**P：可靠拾取流程**：权威怪物死亡 → 计算奖励资格 → 创建唯一掉落实例 → 校验玩家/宠物拾取权限 → 预检容量 → 幂等入包并记录领取 → 发布消失与反馈。多人同时拾取、连续按键、断线重试都不能重复生成装备。

**P：经济必须能画出来源与消耗**：练级货币、Boss 收益、强化材料、核心材料、活动替代奖励分别进入哪些消耗点；掉率加成是否适用于某类掉落需允许清单。掉落数量多不等于奖励体验好，重要物品需可见、能理解用途并能形成下一目标。

**U**：普通/稀有掉率、共享/个人奖励边界、宠物吸附范围、台服怪怪卡和特殊掉宝效果、每次活动的奖励上限，需要目标版本实测或公告支持。

## 10. 装备与账号成长：不要做成一个 upgradeLevel

**R**：官方资料分别定义潜能/附加潜能、套装与陶德传承，另有卷轴、星力和附加选项等强化维度。传承、装备破坏后的痕迹恢复与高级武器成长不是同一操作。[S16][S17][S18][S19]

**P：装备状态至少分开保存**：底材模板/等级/部位、基础属性、卷轴结果、星力、主潜能、附加潜能、附加选项、灵魂类扩展、套装、绑定/期限、锁定、装备实例 ID。

**P：首版做三轴**：底材/套装选择、星力式定向强化、潜能式随机强化。其余先有数据接口和可视说明，第二阶段实现；这样能验证“升级当前装备还是保留材料换下一件”的决策，而非无限加数字。

**重要版本风险**：MSEA 2025-08-20 补丁已记载符合条件装备上限扩到 30 星，并改动失败降星等规则。因此拿网上旧 25 星表直接写死不可靠。但这不是 TMS273 具体概率与费用已经核定的证明。[S06]

**R**：五转核心区分技能核心、强化既有技能的核心和特殊核心；六转包含新能力、旧技能精通与五转强化；区域符文又提供另一条增长线。[S10][S11][S12]

**R/P**：传授与战地让账号其他角色影响当前角色。首版可用“空账号/成长账号”两套数据快照验证差异；完整账号成长应等第二个职业和角色切换可靠后实现，避免第一版同时写完整账号玩法与全职业。[S21][S23]

## 11. 地图与 Boss

**R**：官方主题副本与大陆移动指南体现了不同地图规则和便捷移动；区域更新还会调整猎场与区域门槛。因此地图不是一张背景图加几只怪。[S14][S15][S22]

**P：地图有三层数据**：

- 世界拓扑：区域、地图、连接、解锁、传送限制。
- 可行走空间：平台/斜面、单向落地面、梯绳、下降、边界、可站点、危险区。
- 运行规则：刷新、怪物活动、公共/个人/队伍实例、事件、Boss 阶段、复活点。

**P：练级地图用路线衡量**：完成一圈需要哪些跳跃/位移；能否覆盖上下层；召唤物能否补盲区；刷怪间隔与返回时间是否匹配；拾取是否迫使玩家频繁折返。先测三种地图：低落差闭环、多层垂直图、横向长图。

**P：Boss 地图用可读性和决策衡量**：预警 → 可应对动作 → 命中判定 → 失败反馈；位移、爆发、绑定、无敌和输出站位都有使用理由。首个 Boss 验证学会躲招后能过关；第二个 Boss 验证成长选择与爆发安排。

**T**：巴德利斯及其魔力侵蚀/巨型形态可作为 V273 高阶内容研究样本；不建议把高阶大 Boss 设为首个开发任务。[S01]

## 12. UI / UX 交互清单

**R**：官方 UI 指南给出小地图、永久/活动任务入口、聊天、角色状态、快捷栏等结构。同期开发说明明确把“清晰、减少操作割裂、统一强化入口”作为界面改版目标。[S13][S05]

| 界面 | 用户问题 | 必须写清的交互 |
|---|---|---|
| HUD | 我是否安全，哪些技能现在能用？ | 血量/资源、CD、重要增益、异常与 Boss 预警 |
| 背包/装备 | 这是什么，比当前装备好吗？ | 分类、悬浮对比、堆叠、锁定、绑定/期限、容量反馈 |
| 强化 | 要花多少，会发生什么？ | 选装备→选方法→条件/费用/概率→确认→差异与下一操作 |
| 技能/核心 | 学了什么，怎样用？ | 前置、升级预览、拖拽、装配、键位绑定、无效原因 |
| 任务/向导 | 接下来去哪？ | 当前目标、推荐、阻塞原因、追踪、移动、奖励用途 |
| Boss 入口 | 我能打谁，为什么进不去？ | 难度、前置、练习、队伍条件、次数、冷却与收益状态 |
| 地图 | 我在哪里，怎样过去？ | 当前点、连接、目的地、可达/未解锁、传送条件 |
| 设置 | 操作与画面是否适合我？ | 键位冲突、音量、自己/队友特效、窗口布局、显示适配 |

**T/P：具体教训**：V273 商城把现金仓时装预览改到右键。它减少取出/放回的步骤，但不易被初次使用者发现。复刻体验时保留便捷路径，并在悬浮提示或右键菜单清晰写出“预览”；不要只照搬一个隐藏快捷操作。[S03]

**P：输入焦点**：聊天输入不能同时施放技能；强化确认窗不能穿透到游戏场景；Escape 的关闭优先级明确；按住按键、双击、拖拽、窗口遮挡各有一致规则。窗口内失败不是默默无响应，而是可解释的错误状态。

## 13. 建议架构：先单进程跑通，模块边界按事实划分

本节为设计建议，不是原作内部实现披露。引擎与部署方式尚未确认，先冻结引擎无关的数据契约。采用联网目标时，客户端负责输入、预测与表现，权威模拟负责命中/状态/奖励；本地原型也使用同样命令接口，不必先拆微服务。

`Client UI/Input → Commands → World/Combat/Quest/Inventory/Progression → Committed Events → Views/Replication`

统一基础件：Entity/Instance ID；规则版本；单调模拟时间与墙上时间的区别；可控随机数；条件求值；事件总线；错误码；存档版本与迁移。

建议持久化事实：完成的章节、已领取奖励键、装备实例、已解锁的核心、已结算周期、当前预设、来源明确的永久成长。日周刷新以 `periodKey` 和业务时区定义，不用客户端跨零点判断；效果是否离线继续计时需逐类配置。

首批内容表：`JobDef / SkillDef / EffectDef / QuestDef / MapDef / MonsterDef / DropTable / ItemDef /EnhancementRule / ProgressionGate / BossDef / GuideEntry / ResetPolicy`。

先做内容工具：碰撞/平台编辑、技能范围与时间轴查看器、任务依赖检查、掉落/强化模拟器、快捷测试账号与战斗日志。省掉内容工具会让后续新增地图和职业都退化成程序改代码。

## 14. 首个可玩的现代切片

以下数量和节奏全是本项目提案，不是原作配置或已经验证的人力估时。

| 项目 | 提议范围 |
|---|---|
| 体验长度 | 约 60–90 分钟压缩成长，外加可反复挑战的 Boss |
| 职业 | 一个主职业、约 12–16 个代表性行为；第二职业先做输入/移动原型 |
| 世界 | 一个城镇，8–12 张小地图，含训练区、剧情实例和 Boss 房 |
| 任务 | 15–25 条原创任务，覆盖解锁、引导、失败恢复、奖励 |
| 敌人 | 约 10–15 类普通敌人，2 个验证目标不同的 Boss |
| 物品 | 约 30–50 个模板；少量套装、材料、药水和核心 |
| 成长 | 装备三轴、简版核心装配、一个旧技能进化节点、一个区域力量进度 |
| 运营节奏 | 一种区域日常、一种 Boss 周期，使用可测试的时间策略 |
| 暂不做 | 全职业、全大陆、商业商城、跨服拍卖、完整联动小游戏 |

不是用 1–30 级玩法冒充六转体验。通过独立“成长试炼/测试存档”进入后期代表内容，让测试者看见技能进化与 Boss 应用；正常试玩流程是否提前解锁由复刻目标决定，压缩规则不得混回原作事实表。

### 推荐先后顺序

1. 冻结版本、测量模板、数据边界。
2. 一张地图的移动/战斗/反馈。
3. 任务—掉落—背包—装备—存档闭环。
4. 核心强化、旧技能进化与区域成长。
5. 两个 Boss、练习/结算、引导与异常恢复。
6. 第二职业、小队、账号成长，验证可扩展性。
7. 最后增加内容数量和运营系统。

### 阶段门槛，不按“写了多少功能”验收

| 阶段 | 通过条件 |
|---|---|
| M0 规格冻结 | 原作事实、跨区参照、项目提案、未知参数可区分；数据 ID/单位统一 |
| M1 手感 | 三种地形可用；输入/判定日志支持复现；核心技能可重复执行 |
| M2 闭环 | 陌生测试者不借攻略走完任务、拾取、穿装、强化、重登 |
| M3 现代成长 | 强化/核心选择能改变杀怪路线或 Boss 策略；非只提高面板 |
| M4 战斗验证 | Boss 可练习、可解释失败、奖励不重复；版本迁移不坏档 |
| M5 扩展验证 | 新增第二职业/新地图主要是数据与表现工作，不复制业务核心 |

不在平台、人数和素材产能未知时承诺全量开发周期。排期以 M1 实测、每张地图/每个技能的实际制作成本和第二职业接入成本为基础，再估算后续内容量。

## 15. 优先补齐的证据与风险

| 缺口 | 为何影响计划 | 优先工单 |
|---|---|---|
| TMS273 精确构建/热更/世界类型 | 决定哪些规则属于同一版本 | A |
| 一主职业完整技能与台服改动 | 决定动作、资源、Buff、表现成本 | C/D |
| 新账号 0→五转→六转的实际引导 | 决定主线和系统解锁，避免用老账号代替 | A/B/H |
| 原作帧时与地图移动 | 决定手感，不可猜 | C/G |
| 星力/潜能的台服准确规则 | 决定经济与成长，不可照搬外服 | E/F |
| 个人/共享 Boss 掉落与结算资格 | 决定联机正确性 | E/G |
| 台服特色系统 | 决定本地版差异与 scope | F/A |
| UI 实际截图/动态交互 | 决定像素/布局复刻的验收基准 | H |
| 素材来源与权利范围 | 决定能否发布和内容生产方式 | 协调人 |

本轮已能支持范围、模块与里程碑决策；仍不足以声称已经获得可一比一还原的全职业数值、全任务数据库、原作掉率或网络协议。这些待测参数不阻碍先做核心闭环，但不能以猜测冒充原作参数。

## 16. 立即可启动的第一张开发卡

**标题：从进图到首次成长验证的闭环。**

进入村庄 → 看见一个当前目标 → 接任务 → 进入三层练级图 → 使用群攻与位移 → 完成击杀 → 拾取材料 → 回到引导入口领奖 → 选择强化方向 → 解锁一项技能行为变化 → 在练习 Boss 中验证 → 退出重进保持进度。

完成这个闭环后，再问“下一个职业和地图为什么值得加入”。不要反过来用内容数量掩盖闭环尚未成立。
