# 花蘑菇（菇菇寶貝 1210102）无法移动：已修复，待统一加载实玩（2026-09-12）

> 归档自 `PLAN.md`（超大文件治理：md 与代码同一口径）。原文逐字保留，未做改写。
> 归档位置：`docs/history/plan/03-2026-09-12-花蘑菇-无法移动-已修复-待统一加载实玩.md`　　归档顺序：03/66（PLAN.md 原倒序）


- 现象（用户）：花蘑菇原地不动；同时要求核对**所有**已部署怪的移动能力。
- 根因（源字段缺失被读成"不会走"，不是 AI/地图几何问题）：TMS273 的 `Mob/1210102.img/info` **没有
  `speed` 字段**（客户端 WZ 与 `WZ_JSON_TW` 两个独立来源一致；其 `info/link` 孪生 **100004** 同样没有），
  而 `shared/gameplay.json` 的模板只在源里真有 `speed` 时才写该字段（`scripts/generate_tms273_gameplay.py`
  原来无条件只写"作者写过的值"）。服务端 `MonsterTemplate::movement_force()` 取力写成
  `self.source_speed.map(...)` ⇒ **没有字段 = 没有力** ⇒ `can_move()` 为假 ⇒ `step_monsters` 在 `stand`
  分支直接 `continue`，怪物被永久钉在原地（两个模板都是花蘑菇，分别部署在 5 张图和 1 张图）。
- 源语义（本轮联网 + 本地全量核对，非猜）：`Mob.wz/info/speed` 是**可选的偏移量**，不是"能不能走"的开关——
  11614 只 TMS273 怪里 **3111 只没有 speed 节点**，其中 **731 只照样有 `move` 动画**（菇菇/木妖家族；
  2400100 等），另有 541 只把默认值显式写成 `0`；社区里改 `speed/chaseSpeed/flySpeed = -100` 就是"让怪不动"
  的做法，本地数据也印证：**`-100` 那一批全是道具/机关**（城門 3300112、寶箱 9601923-9601937、
  訓練用木頭人 9602083/9602084、巡邏用的枯木 9402047 = -200），`Gameplay::validate` 也只允许到 `-100`。
  ⇒ **缺字段 = 默认 0 偏移（普通速度），绝不等于不能动**。
- 修复（`server/src/world.rs::MonsterTemplate::movement_force`，**一处**）：力 =
  `(speed 或默认 0 + 100) * 0.001`，"是否缺 speed"由 `move_duration_ms` 判定（导出器只在源有 `move` 动画时
  才写这个字段，所以它就是"这只怪有走路动画"的证据）；力 `<= 0` 视为不可移动，于是 `-100` 哨兵不再进入
  `move` 动作（顺带修掉 speed 低于 -100 时"倒着走"的隐患）。**数据、协议、客户端零改动**：
  `client/src/features/mob/view.ts` 本来就按快照 `action` 播 `actions[action]`，manifest 里
  1210102/100004 的 `move` 帧（3 帧 / 480ms）与模板 `moveDurationMs` 一致。
- 全量移动能力审计（17 个已部署模板 / 390 个部署点，逐只在 `mob_move_acceptance.rs` 里断言）：
  **修复前不能动的只有 1210102 与 100004（两只都是菇菇寶貝/花蘑菇）**，其余 15 只本来就正常
  （嫩寶 -65、藍寶 -50、菇菇仔 -30、嫩寶 100100 -65、藍寶 100101 -50、菇菇仔 120100 -30、木妖 -70、
  紅寶 -50、綠水靈 -20、黑木妖 -70、斧木妖 -50、發芽木妖 -45、奸笑的發芽木妖 -45、黑斧木妖 -20、
  幼魔精靈 -15）；树妖王 3220000 有速度但**未部署**（练习 Boss）。修复后 **17/17 全部可移动**。
  花蘑菇部署图：1210102 → 100010000 弓箭手村北邊山丘、100010100 做夢的森林小徑、
  101010000 閃爍森林的通路、101010100 森林的起始點、102010100 岩地荒野；100004 → 001010000 冒險者修練場入口。
- 验证：
  - 新增 `server/src/mob_move_acceptance.rs` 5 项：①已部署怪全可动（并把"已部署模板数 = 17"钉成
    tripwire，新增地图/怪必须重读本审计）；②1210102/100004 缺 speed 时力 = 0.1 且 `can_move`；
    ③真模板在 `stand` 决策边界（1700ms）之后确实进入 `move` 并位移 > 1px；④`-100` 哨兵 400 tick 原地不动
    （`-120` 在模板层断言无力，因为载入期就会被 `validate` 拒）；⑤无 `move` 动画的模板仍不可动、
    作者速度仍然优先。**已反证**：把 `movement_force` 临时改回 `self.source_speed.map(...)`，
    新增的 4 项立刻失败（另外 1 项按设计仍然通过）。
  - `cargo test --offline` **292 过 / 6 失败**，失败集与基线逐条一致（auth third_store、mage bundled_catalog、
    world config_drop / portal_command / reactor_area、third_sphere），**零回归**。
  - `scripts/check_tms273_runtime.cjs` 新增源级移动契约（带正反控制）：已部署怪源里必须有 `move`、
    源 `speed` 不得 `<= -100`、导出值与"怪自己的 `info.speed`"逐只对齐；同时把 `info/link` 解析写进检查
    （嫩寶 0100000→0100100、菇菇寶貝 0100004→1210102）——检查脚本自己抓到了这个坑：dump 只落怪自己的
    节点，不解析 link 会把有动画的怪误判成"无动画"。检查通过（44 maps / 50663 source references）。
- 待验（用户）：`启动3010.command` 统一加载后实玩——上述 6 张图上的花蘑菇开始左右走动、在 foothold 链端点
  掉头、并保留追打攻击它的玩家/回巢行为；其余 15 只怪的移动表现不变。
