## 3. 四扇脚本门的 P 级路由（本轮唯一的服务端新逻辑）

`server/src/edelstein.rs`（新建，约 110 行）：

```
EDELSTEIN_CITY_GATES = [
  ("310000000", "in00", "310000001", "out00"),   // 议會
  ("310000000", "in01", "310000004", "out00"),   // 住宅
  ("310000000", "in02", "310000010", "out00"),   // 臨時機場（双授权取已装配者）
  ("310000000", "in03", "310000003", "out00"),   // 美髮店
]
```

- 挂点：`portals.rs::handle_portal` 在通用查表**之前**调用 `edelstein_portal_gate`，
  与 `helios_portal_gate` / `ufo_portal_gate` 同形。命中则 `warp_player_at` +
  `send_portal_result`，未装配目标回 `map_unavailable`（不静默吞掉）。
- **`in02` 是双授权目标**：`Graph.json` 同时给 `931000600`（本仓库没有）与
  `310000010`（二期已随船线装配）。口径与 `ship.rs::station_in_exit` 一致：
  命中已装配的那个，其余如实拒绝，**不旁路**到任何未授权中间图。
- 四张内景图的源静态回门正对本门（`.../out00 → 310000000.inXX`，源内配对），
  落点直接取对图 `out00`。

### 3.1 客户端目录暴露（关键连带项）

`client/src/scenes/world.ts::tryPortal` 只受理带 `targetMapId` 的门，而源 `tm` 是
`999999999` ⇒ **不暴露＝服务端路由永远收不到消息＝死代码**。按既有机制在
`scripts/tms273_remaster.cjs::exposeScriptedGateRoutes` 里补四扇（并入既有
「已装配目标」表）：

```js
['310000000', 'in00', '310000001', 'out00'],
['310000000', 'in01', '310000004', 'out00'],
['310000000', 'in02', '310000010', 'out00'],
['310000000', 'in03', '310000003', 'out00'],
```

该函数本轮重构成 `expose(list, onlyAssembled)` 两张表，并加了**双向断言**：
`assert.equal(assembled.has(targetMapId), onlyAssembled)` —— 一条路线被放进错的
表里会直接失败，不会静默失效。装配后四扇门自动获得 8 帧 `pv/default` 光束。

| 门 | `Graph.json` 授权 | 处置 |
| --- | --- | --- |
| `west00` | `310020000` | 源静态门，目标随本片装配 ⇒ 本来就通 |
| `east00` | `310030000` | 同上 |

## 4. 城东步行链与它的**终点边界**

链：`城 east00 → 散步路道1 → 2 → 3 → 4 → 去礦山的路1 → 去礦山的路2`，全程源静态
门、双向配对。

**本片的净贡献**：`310040100 去礦山的路2` 在 2026-09-15 就已装配，但它唯一的入边
来自「礦山入口 `310040200`」自己，而礦山入口也没有任何可达入边 ⇒ 那一簇整体是
**孤岛**。本片接上 `310040000.east00`，让它第一次可达。

**步行链到此为止（不许写成「打通矿山」）**：

- `310040100.east00` 是 pt:7 脚本门 `enterBlackMine`，源 `tm = 999999999`，
  **脚本体不在本包** ⇒ 目录里没有目标，原版靠脚本进场。
- `310040100.in00`（pt:1）指向 `310040110 隱藏著的入口`，该图**未装配**。
- 结果：`310040200 礦山入口` 与整个雷本礦山簇（HEAD 就已装配）**仍然没有任何
  可达入边**。

> 这条边界是**本轮自己纠出来的一处过度断言**：初稿在 `import_tms273.py`、
> `check_tms273_runtime.cjs` 与 `edelstein_acceptance.rs` 三处写了「城…→ 礦山入口
> → … 成为一条连续可走路径」。核实 `310040100` 的两扇门后确认是错的，三处已改准，
> 并在 Rust 与 JS 两侧都加了**反向断言**：任何人给 `east00` 编一个目标、或把
> `310040110`/`310040200` 的入边接上，都会立刻失败。

## 5. 城内 NPC 职能与边界

### 5.1 能用的（装配后本来就能用，本片不改）

都在城 `310000000`（34 名 NPC）：

- `2150000 特隆奇`「倉庫老闆」→ 仓库（服务端按 `func` 含「倉庫」识别）。
- `2150001 邦傑斯基`「武器防具商人」→ 源商店 `2150001`（226 项）。
- `2150002 加列爾`「雜貨商人」→ 源商店 `2150002`（55 项）。
- `9072100 奈倍爾`「輔助武器商人」→ 源商店 `9072100`（134 项）。

`edelstein_acceptance.rs` 把这三个 `shopId` 与这一个 `func` 钉住：商店集被后来的
装配挤掉会失败。

### 5.2 明确登记的边界

1. **源自己隐藏的 NPC**：10 张新图的源 life 行里，`2121018`（美髮店）、
   `2151009`/`9075003`/`2159396`/`3005501`（秘密廣場，即第 7~10 名教官/怪醫）、
   `2159421`（去礦山的路1）**在源 `Npc/*.json` 里 `info.hide = 1`** ⇒ 只在特定
   任务条件下现身。它们按既有机制落在 `gameplay.hiddenSourceLife`（理由
   `Npc.info.hide is explicitly nonzero`）与 `sources.hiddenNpcConditions`
   （带条件键，如 `23211`/`1800`/`1804`/`23639`/`23610`/`23711`/`38300`/`23612`）。
   **不是漏配**，是本包的场景执行范围不含这些条件。
2. **脚本体缺失**：城 34 名 NPC 里 16 条 `info/script` 引用，**只有 4 条在包内**
   （`kasandra`/`unityPortal`/`NPC_unionShop`/`mParkShuttle`，且都属全局系统）；
   10 张新图的 7 条（`hair_edel1`/`hair_royal`/`henrite`/`bell`/`jaguar_in`/`cheki`/
   `illex`）**一条都不在**。所以秘密廣場的六名末日反抗軍教官、美髮店的两名 NPC
   目前只是**站着可看**，转职/髮型功能不可用——如实登记，不编替代。
3. **`secretElevator` / `check_xn` / `enterBlackMine` / `enterSecJobResi` 等门脚本
   全不在包**（`参考/.../script/portal/` 只有 `market19.js`），所以这些门按
   「源自己没给目标」保持关闭。

## 6. 耶雷弗簇：核定结论是「无需新增路由」

- `130000000 耶雷弗` **本身没有脚本门**：`Graph.json` 的 `13/130000000/portal` 只有
  两条（`portalNum` 3 → `130000101 騎士之殿`、4 → `130030006 小橋樑`），都是源静态门，
  两张目标图都已装配。城内 10 名 NPC（女皇/六团长/神獸/慧拉/奧莉維亞）无店无仓。
- 簇内三扇脚本门目标都不在：
  - `130030006.east00`（pt:7 `pt_01_130030006`，`portalNum` 4）→ `130030005 離開遺忘的森林的路`；
  - `130000200.in01`（pt:11 `cygnus_q20754`，`portalNum` 6）→ `913060000`（隐藏图，无名字）；
  - `130000200.pt_regionMove`（pt:8，`portalNum` 5）→ `999999999`。
  前两扇是「有授权、目标未装配」⇒ 写进目录让客户端说明；第三扇保持 `null`。
- 耶雷弗前庭 `130000200` 本身有 1 名仓库管理员（`1100000 奇里翁`「倉庫老闆」）与
  两家源商店（`1100001`/`1100002`），**二期装配时就已可用**，本片不动。
