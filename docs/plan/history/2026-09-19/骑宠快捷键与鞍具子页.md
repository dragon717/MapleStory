# 骑宠快捷键 + 装备窗骑宠格适配 + 鞍具子页（TMS273）

日期：2026-09-19。用户需求单：「我那个骑宠是能装备的，但骑宠的那个在装备的那个 UI 适配不太好。
然后，是不是因为没有马鞍？马鞍的那个道具是多少？嗯，他也加入到那个冒险笔记里面。然后也在骑宠
这个页签里嘛，然后它是一个骑乘系统的子页签。然后就是，是不是有快捷键？应该有个骑宠键，骑宠才
能真正骑宠。帮我调研一下，然后把它实现，然后更新修复。」

四项任务：① 新增「骑宠键」；② 修装备窗骑宠格的适配；③ 马鞍进冒险笔记，作为骑宠页的子页；
④ 实现后的更新与修复。

协议 **26 → 27**（`NotebookSection` 增加 `saddle`），内容版本沿用 **`tms273-32`**（未变），
目录版本 **`notebook-catalog-3` → `notebook-catalog-4`**。前后端必须一起换。

## 1. 调研结论（先回答用户的两个疑问）

- **骑宠不需要马鞍**。骑乘判定在服务端只看装备栏 `Tm` 槽的 `tamingMob`（
  `inventory::is_mount_item`）加 `ride_stats`，与 `Sd` 槽无关。所以「是不是因为没有马鞍」
  的答案是否：装不装马鞍都能骑。
- **马鞍确实存在，是 26 件**。`shared/mounts.json` 共 935 件，按源 `info.islot` 分成两半：
  `Tm` = 909 件骑宠（其中 888 件带 `tamingMob`）、`Sd` = **26 件鞍具**（如 `1912000 馬鞍`）。
  26 件**全部没有** `tamingMob`——同一条口径让它们从不被当作坐骑，这也正是「骑乘不需要马鞍」
  的根据。26 件在 `shared/mount-index.json` 里全都有名字，图标也全在 `mount-images` 里
  （`Character_TamingMob__Canvas_01912000.img_info_icon-*.png`）。
- **原先没有骑宠键**。骑乘只能双击装备栏 `Tm` 槽（→ `useItem(tab 0, -18, id)` → 服务端
  `mount_toggle`）。

## 2. 骑宠键（`KeyR`）

- `keybindings/model.ts`：`ACTIONS` 加 `'mount'`；`defaultBindings` 加 `['KeyR','mount']`；
  `view.ts` 的 `ACTION_NAMES` 加 `mount: '骑宠'`。
- **关键决定：骑宠键不占快捷栏格子。** 第一版把 `SLOT_COUNT` 32 → 33，结果 HUD 与
  `check_keybindings_ui.mjs` 双双失败——源快捷栏美术底板就是 2×16**固定 32 格**，第 33 格没有
  底板可贴。改为 **`STORAGE_VERSION = 2` + `ADDED_DEFAULT_BINDINGS`**：骑宠键只存在于**绑定层**，
  不占格子。
  - `ADDED_DEFAULT_BINDINGS = { 'KeyR:0': { type: 'action', action: 'mount' } }`；
    `parseStored` 只认 version 1 或 2，旧档（v1）补上缺席的新默认键（`migrated = true`），
    `setCharacter` 见到 `migrated` 立刻落盘一次。
  - **现行档里被玩家清掉的 `KeyR` 不会被复活**：迁移只补「存档里从来没有过这个键」的情况。
    这条有定向断言。
- `mounts/view.ts`：新增公开方法 `toggleCurrent(): boolean`——取 `store.toggleTarget()`，
  没有可骑的骑宠就如实提示「先在装备栏右侧的『骑宠』格装上骑宠」，有则复用既有 `toggle()`。
- `app/main.ts`：`activateBinding` 在 `escapeBlocked()` 之后加分支
  `if (binding.action === 'mount') { mountStatus?.toggleCurrent(); return; }`——骑宠是**世界动作**，
  不走窗口开关那一路。

## 3. 装备窗骑宠格适配

用户说的「装备 UI 适配不太好」在这个窗口里有两个具体毛病：

1. **行高硬编码**。底部 `Tm`/`Sd` 格的行高散在样式表里（`60px`）与源码里（`52`），窗口总高
   `layout.height + 52` 与 CSS 的 `bottom/height` 各写一份 ⇒ 换布局就错位。现在
   `equipment-view.ts` 导出唯一来源 `export const MOUNT_FOOTER_HEIGHT = 52;`，构造时
   `style.setProperty('--equipment-mount-footer-height', '52px')`，CSS 改
   `bottom: 0; height: var(--equipment-mount-footer-height); box-sizing: border-box;`。
2. **「装着」与「骑乘中」分不出来**。原格只能看出有没有装骑宠，看不出**正在骑**。现在
   `EquipmentHost` 新增 `mountedItemId()`（读服务器快照 `PlayerState.mount.itemId`，
   「装备着 ≠ 在骑」），`render()` 按它给骑宠格加 `equipment-slot-riding` 高亮、标签改
   「骑宠·骑乘中」、`aria-label` 区分「双击骑乘 / 双击下马」。
   配套：`inventory/view-model.ts` 的 `slotsSignature` 末尾追加 `mounted:${mounted}`——
   上/下马不改背包装备但要重绘骑宠格，签名不含它就会「骑了但格子不变」。
   **鞍具不进骑乘态**（`Sd` 格不参与这条判定）。

## 4. 鞍具进冒险笔记：骑宠页的**子页**，不是第七个页签

- 顶栏仍是**六个**分区（源快捷栏与页签条都是固定版式）。鞍具是骑宠页里的第二级导航
  `MOUNT_SUBSECTIONS = [{mount, notebookSubMount}, {saddle, notebookSubSaddle}]`。
- 但它**在服务端是独立分区** `NotebookSection::Saddle`：这样「一件东西只属于一个页」
  （分区是无重叠全覆盖）这条不变式在目录、协议、服务端三处都还成立。切子页 = **换一种查询**，
  不是本地过滤。
- `view-model.ts` 新增 `isMountFamily(section)`（`mount | saddle`）与 `tabKeyFor(section)`
  （`saddle → notebookTabMount`）。浏览方式、默认档、页眉、顶栏选中态全部走这两个函数——
  「加了子页却漏了某一页」这类漏网不会静默。
- `view.ts`：`renderSubSections()` 只在 `isMountFamily(this.section)` 时画子页按钮；
  `switchSubSection()` 与换页签同一套收尾（丢快照／丢选中格／丢待答请求 → 重新查）。
  子页各自持有自己的页码与浏览方式（`tab(section)` 本来就按分区存）。
- 详情面板：鞍具报**佩戴等级**，且**没有**「坐骑档」那一行——源不给鞍具 `tamingMob`，
  补一栏会被读成「它指向某个坐骑档」。页内 `SADDLE_BLOCKED` 把话说全：本版本没有开放的鞍具
  获取途径；鞍具在本构建里不带属性、也不参与骑乘判定，骑乘与否由骑宠本身决定。
- 分区判据的**双向**断言（`assemble_tms273.cjs` 与门禁各一份）：`mounts + saddles` 键集
  == `shared/mounts.json` 键集；鞍具 `equipmentSlot === 'Sd'`、骑宠非 `Sd`。只看「加起来对不对」
  会让「全塞进骑宠页」也过，所以两侧都要各自核对。
