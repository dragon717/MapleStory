# 战斗跳字与数值表现 + 怪物受击击退（TMS273）

日期：2026-09-19。用户需求单：「复刻实现以下战斗跳字与数值表现功能，参考原版 tms273 与 gms83
的逻辑进行落地：1）玩家受到伤害时的伤害跳字；2）回血跳字；3）回魔跳字；4）开启魔心防御后的
扣魔/扣血跳字；5）对怪物造成伤害时的伤害跳字，并包含命中怪物时的击退表现。要求各跳字样式、
触发时机与数值计算与原版一致，确保功能可正常运行并接入现有战斗系统。」

协议 **27 → 28**（`ServerMessage` 新增 `recoveryEvent`、`damageEvent` 补上早已在发但 TS 侧
未声明的 `mpDamage`），内容版本 **`tms273-32` → `tms273-33`**（新增了数字集资源文件，
不升版本客户端会一直吃旧缓存、新跳字永远不出现），目录版本不变（`notebook-catalog-4`）。
三处版本声明必须一起换：`shared/protocol.ts`、`server/src/protocol.rs`、`scripts/assemble_tms273.cjs`。

## 2. 数字集：颜色是**帧自身的像素**，不是运行期染色

导出器 `scripts/export_tms273.cjs::exportEffects` 原本只导两套：`normal=NoRed`、`critical=NoCri`。
本轮把候选集合逐个从 `.wz` 取帧、看主色，实测结果是：

| 集合 | 实测颜色 | 用途 |
|---|---|---|
| `NoRed0/1` | 橙红→黄渐变 | 普通伤害（对怪与自身受伤**共用**，与原版一致） |
| `NoCri0/1` | 深红、字号更大 | 暴击 |
| `NoProduction0/1` | **绿色**（白心） | HP 恢复 |
| `NoBlue0/1` | **蓝色**（青→蓝） | MP 恢复 / 魔心扣魔 |
| `NoViolet0/1`、`NoKite0/1` | 紫 | 非本需求，不导 |

⇒ 导出清单扩成四套：`normal` / `critical` / `recoverHp` / `recoverMp`。

**一个容易看错的地方**：`NoProduction` 与 `NoKite` 的 `0` 与 `1` 两档在源里解析到**同一批字节**
（UOL 指向同一个 canvas），也就是它们**只有一个字号**，没有「首位/后续」之分。导出时照实写两档
（保持 `DamageNumberSet` 的形状），**不伪造第二套尺寸**——拼多位数时首位与后续会自然取到同一帧，
这是源的事实而不是丢了一半。

字距沿用既有的 `damage-number.ts::damageNumberAdvances`（v83 `DamageNumber.cpp` 的
`BASE_ADVANCE` 表），恢复数字走**非暴击**分支：原版渲染代码是同一份，只是换了 sprite 集合。

## 3. 协议

```ts
| { type: 'damageEvent'; …; mpDamage?: number }            // 新增字段（服务端引入魔心时就在发）
| { type: 'recoveryEvent'; eventId; serverTick; playerId; x; y;
    hp?: number; mp?: number; source: 'potion' | 'recovery' | 'chair' | 'infinity' }
```

- `mpDamage` 不是新行为，是**把 TS 侧对齐到已经存在的事实**：`monsters.rs::commit_incoming_damage`
  一直在往 `damageEvent` 的 JSON 里写它。不声明它，客户端就只能靠 `any` 去捞。
- `recoveryEvent` 刻意**只发给当事人**（见 §4），`hp`/`mp` 是**实际增加量**，`source` 只用于追溯与
  门禁，不参与表现选型（颜色只由 `hp`/`mp` 各自决定）。
- 联合里**没有**自然恢复这一档：原版那条路径不产生跳字，且每秒触发只会持续刷屏（见 §4）。

## 4. 服务端：恢复跳字挂在哪四条路径上，以及刻意不挂的那一条

新增 `World::emit_recovery_event(id, hp, mp, source)`（`world.rs`，紧挨 `broadcast_to_map`）：

- **定向**发送（`player.output.try_send`），不做广播。恢复是私事：同图其他人不该看到你喝药水、
  坐椅子或魔力激发的数字。失败语义与 `broadcast_to_map` 一致——队列满就丢这一条（跳字是表现，
  不是状态），快照里的 HP/MP 仍是权威。
- 入口就挡掉 `hp <= 0 && mp <= 0`，所以调用点不必各自判断。

四个调用点，数值一律取**实际增加量**（已经被上限夹过的那一份），不是技能/道具声明的量：

| 路径 | 位置 | 关键点 |
|---|---|---|
| 药水 | `inventory_ops.rs` 消耗品分支（`use_effect` → `hpR`/`mpR` 百分比） | 只在 `remove_items` 成功后才跳字：那一步失败时物品还在包里，不该给出「已经喝了」的表现 |
| 恢复术 | `skills.rs::apply_beginner_heal_tick` | `healed_gain` 必须在 `state` 被 move 进 `healed_state` **之前**算出来 |
| 坐椅子 | `chairs.rs` | 借用的作用域收进块里，先取出增量再借用 `self` 去发 |
| 魔力激发 | `elemental.rs::step_infinity_tick` | `hp_gain`/`mp_gain` 是源里按百分比声明的量，顶到上限后真正加进去的更小 |

**刻意不接的那一条**：`skills.rs::step_natural_recovery`（`regeneration_passives_for_job` 的每秒
被动回复）。原版这条路径不产生跳字；而且它每秒都在跑（法师 MP +1/秒），接上去就是每秒一个蓝字
「1」刷屏。这条决定写在 `emit_recovery_event` 的文档注释里，避免以后被人"顺手补上"。

## 6. 怪物受击击退

### 6.1 先把 `info.pushed` 的语义定死

原版资料（unknowncheats 的 Mob.wz `info` 词条 + mapleclassic.wiki/Knockback）：

> `info.pushed` = **How much damage is required to Knockback a mob**；
> 「Editing this to a value of 0 will enable you to knockback a mob with any damage」。

也就是 **`pushed` 是「击退所需的单次伤害阈值」，不是击退距离**。阈值随等级增长（Lv1–9 → 1，
Lv40–49 → 225，Lv70–79 → 1500），Boss 远高于同级（Mushmom Lv40 阈值 2750 = 同級 Cold Eye 的 15 倍）。
这正好对上本仓库源里的分布：小怪 5 / 10 / 20 / 50 / 100 / 150 / 200 / 400 / 450 / 600，
高等级 1100 / 1200 / 1800，Boss 5000 / 5500 / 6000 / 6500，以及 6466800 / 6868800 / 999999
（高到任何一次命中都推不动）。**所以不需要为 Boss 另开分支**——阈值本身就是机制。

### 6.2 数据：源里有，表里没有

`shared/gameplay.json` 的 70 个怪物模板**全部没有 `pushed`**：生成器
`scripts/generate_tms273_gameplay.py` 的字段导入循环只取了 `PADamage`/`PDRate`/`speed`。

生成器加了一行 `("pushed", "pushed", True)`，以及 `sources.monsters[].pushed` 的溯源留痕。
但**整跑一次生成器在本机走不通**：它要 198 张地图的 `WZ_JSON_TW` 副本，而参考树当前缺其中若干张
（例如 `Map/Map/Map0/001000003.json`，`Map0` 只导了 15 张）。所以另加了定向模式：

```
python3 scripts/generate_tms273_gameplay.py --backfill-pushed
```

`pushed` 只从 Mob 源读、与地图无关，这个模式用**同一套 `unwrap` / `number` 口径**逐条重算并回填，
不触碰别的字段；生成器将来能整跑时，产出的 `pushed` 与本模式逐条相同。落盘格式刻意对齐
`shared/gameplay.json` 现有形态（紧凑、单行、末尾换行），否则一次回填会把整个文件重排、
真实改动被格式噪音淹没。

回填结果（70/70，与源逐条一致）：`5×8, 10×6, 20×3, 50×5, 100×6, 150×1, 200×2, 400×2, 450×1,
600×1, 1100×11, 1200×11, 1800×1, 5000×2, 5500×2, 6000×3, 6500×2, 999999×1, 6466800×1, 6868800×1`。
除 `pushed` 外与原文件字节等同，键序紧跟 `speed`。

### 6.3 判定与位移

- `MonsterTemplate.pushed: Option<i64>`（`#[serde(default)]`）。
- `register_monster_knockback(monster, damage, from_x: Option<f64>)`（`monsters.rs`）：
  伤害 `>=` 阈值才登记；`damage <= 0`、已打死（`hp == 0`）、**阈值缺失**、拿不到攻击者位置，
  都不登记。阈值缺失按「推不动」处理是刻意的——凭空给 `0` 会造出一条比源更强的规则
  （源里 `0` 的语义恰恰是「任何伤害都能击退」）。
- 登记只写 `Monster.knockback_pixels`（像素，正=向右）。**真正的位移由 `step_monsters` 在
  怪物步进的"最开头"结算**（早于冻结/眩晕/绑定的 `continue`）。放在最前面有两个理由：
  ① 位移要沿 foothold 走并可能撞墙，那需要地图与段链，只有那里拿得到；
  ② 挂在 `hit` 分支会被冻结/眩晕的 `continue` 吞掉，留下一个**过期的方向**，下一次命中若未达
  阈值就会把旧值结算出去。
- `step_monster_knockback`：沿当前 foothold 直线退开 `MOB_KNOCKBACK_PIXELS`；目标点越出段边界
  就停在边界——**不跨段、不换段**。跨段会牵出「掉下平台 / 撞墙掉头」一整套决策，那属于常规移动。
- **`MOB_KNOCKBACK_PIXELS = 50.0` 是 P**：原版客户端只记录阈值，mapleclassic.wiki 明说
  「推开多远」属服务端行为、文件里没有。取一个身位量级的值。
- 挂载点覆盖五条命中路径：普通攻击（`attacks.rs`）+ 技能三处（`skills.rs`）+
  冰系技能（`elemental.rs`）。攻击者位置都在进入 `monsters.get_mut` **之前**取出
  （否则借不到 `players`）。

### 6.4 客户端表现：无需改动

怪物位置在客户端是 `mob/view.ts` 里直接 `setPosition(monster.x, …)`，**没有插值**；击退位移由服务端
写进权威 `state.x`，随快照到达即生效。所以需求 5 的客户端侧是零改动，`hit` 动作也早已存在。

## 10. 交付后回访：`pushed` 曾经静默归零（已修）

写完本轮交付记录后回查磁盘，发现 **`shared/gameplay.json` 里一个 `pushed` 都没有**
（`monsters` 70 个模板、含 `pushed` 0 个），而唯一的差异是 `contentVersion` `tms273-32 → tms273-33`。
也就是说：`pushed` 这条链**在交付那一刻已经是坏的**，而当时所有门禁都是绿的。

### 10.1 为什么绿灯骗过了所有人

`pushed` 只参与表现，**不参与任何伤害数值**，所以少它不会让任何既有断言变红；而击退验收
测试断言的是 `shared/gameplay.json` 的实际内容，它在回填之后、装配器重跑**之前**跑过一次
——那时文件是对的，于是 579 全绿。**判据通过了，但它通过的是一份随后被覆盖的状态。**

### 10.2 真正的链路（写错了层）

```
参考/…/WZ_JSON_TW/Mob/*.json            （权威源，只读）
        │  generate_tms273_gameplay.py   ← DEFAULT_OUTPUT
        ▼
resources/tms273-export/gameplay.json   （导出树；**在 .gitignore 里**，可再生）
        │  assemble_tms273.cjs（并叠加 chapter/remaster/emoticons/cashShop 等补丁）
        ▼
shared/gameplay.json                    （装配派生副本；服务端 main.rs、几乎全部验收测试读它）
client/public-tms273/assets/gameplay.json（同一棵树的第二份派生物）
```

`--backfill-pushed` 第一版写的是 **`shared/gameplay.json`** —— 即派生副本。回填那一刻它是对的，
但紧接着为了升版本重跑装配器时，装配器按设计**从导出树重新派生**这个文件（导出树当时还没有
`pushed`），于是回填结果被整段覆盖，且**不留任何痕迹、不报任何错**。

### 10.3 修法（三件，缺一不可）

1. **写入目标改到权威层**：`backfill_monster_pushed(tms_root, output_dir)` 现在只写
   `<output-dir>/gameplay.json`（默认即导出树），函数 docstring 里写明「派生副本不是写入目标」。
   注意导出树在 `.gitignore` 里 ⇒ **能长期生效的修复是生成器源码里的字段映射**
   （`("pushed", "pushed", True)` + `sources.monsters.pushed`），回填模式只是本机修复手段。
2. **重跑装配器**：不重跑，派生副本仍是旧的。
3. **在装配器加断言**（`assemble_tms273.cjs` 的怪物收尾循环，它本来就在读同一个 Mob 源文件）：
   源里有 `info/pushed` 而导出树缺这一格 ⇒ 直接 `assert` 失败并提示「导出树过期，重跑生成器」；
   另断言取值是整数。**这类字段没有第二道防线，断言是唯一会发现它的东西。**
   转换口径仍只在生成器一处定义，装配器**只断言、不自算**。

## 11. 实玩回访 2：魔心扣魔没有蓝字（已修，用户实玩两次反馈）

**现象**：开着魔心防禦挨怪打，MP 确实在掉，但**没有跳字**（红字也没有）。

**两个缺陷叠在一起，第二个才是决定性的：**

### 11.1 决定性根因：客户端把「HP 那一份为 0」的整条事件丢掉了

`world::MAGIC_GUARD_COVERED_PERCENT = 99` ⇒ HP 承担的是未接下的 1%，而服务端按**整数向下取整**：
`hp = reduced_damage * 1 / 100`。**伤害 < 100 时它正好是 0**（普通小怪一击必落在这一档），
此时这一击唯一有意义的数字就是蓝字。服务端照常广播：

```json
{"type":"damageEvent","targetId":"<player>","damage":0,"mpDamage":9,"killed":false,...}
```

而客户端 `receiveDamageEvent` 的第一道闸是 `event.damage <= 0 → return`
⇒ **整条事件（连同 `mpDamage`）被丢弃** ⇒ 「MP 在掉、一根数字都没有」。
判据应当是**「两根都为 0 才丢」**，不是「HP 为 0 就丢」。

修法：把取舍抽成纯函数 `damage-number.ts::damageNumberLayers(damage, mpDamage)`，返回该画哪几根
（红=`damage > 0`、蓝=`mpDamage > 0`；HP 为 0 时蓝字上移到红字那一行，免得头顶空一截）；
事件入口与 `spawnDamageNumber` 共用它，入口只在**两根都为 0** 时丢弃。

### 11.2 并存的第二个缺陷：预加载只登记了两套数字集

`client/src/assets/preload-plan.ts` 只登记 `damageNumbers.normal` 与 `critical`——
`recoverHp`/`recoverMp` 的 40 张帧在 manifest 里、在服务目录里，却**从没进过纹理缓存**，
于是绿字（回血、坐椅子、魔力激发）在线上同样画不出来。已改为整本装载（40 张小图，成本可忽略）。

### 11.3 为什么两轮离线检查全是绿的

- 服务端那份验收测试（`mage_skill_runtime_covers_learning_targets_replay_guard_teleport_and_wave`）
  **本来就覆盖了「HP 掉 0、MP 扣 9」这一档**，但它用 `while rx.try_recv().is_ok() {}` 把广播
  出来的事件**直接倒掉**——只断了状态（HP/MP 数值），没断事件。于是「事件里带没带 `mpDamage`」
  这条契约从来没人钉。
- 客户端那份 `damage-number.check.ts` **文件存在，却从来没接进 `client/scripts/run-checks.mjs`
  的清单**——判据写了，没人跑。
- 第一条缺陷（预加载）离线无从发现：类型有、文件有、代码路径对，缺的是「运行期真把纹理装进缓存」。

### 11.4 判据补强（三处，都是「判据要真的被跑、要作用在产物上」）

1. **服务端**：把上面那段 `while rx.try_recv().is_ok() {}` 换成断言——护罩承伤必须广播
   `damageEvent`，且 `damage == 0`、`mpDamage == 9`（80% 抵偿档另断言 `mpDamage == 7`）。
   这直接钉住客户端依赖的那条契约。
2. **客户端**：`damage-number.check.ts` 新增四组取舍断言
   （`(0,12)` 只出蓝、`(30,12)` 红+蓝且蓝下移 20、`(30,0)` 只出红、`(0,0)` 什么都不出）。
3. **门禁接线**：`damage-number.check.ts` 加入 `client/scripts/run-checks.mjs`——**判据必须被真的跑**，
   放在文件里没人跑等于没有。
