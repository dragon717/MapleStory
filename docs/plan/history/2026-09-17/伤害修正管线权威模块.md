> **模块名**：伤害修正管线权威模块——玩家侧伤害修正的**唯一求值点**与**唯一口径**。
> 代码入口：`server/src/damage.rs`（新增，`world.rs:32 #[path="damage.rs"] mod damage;` + `use self::damage::*;`），
> 两条伤害路径的接入面是 `attacks.rs::resolve_pending_attacks`（普通攻击）与

① 同源 `damR` 由「各自乘」改为「求和后乘一次」；

## 2. 改前的三个无答案问题（为什么值得收口）

「把百分比变成伤害数字」这件事在服务端手写了 **16 处**，散在四条路径：`attacks.rs` 普通攻击 **4 处**、
`skills.rs::magic_damage_with_passives` **9 处**、两个技能施放点的前置修正 **3 处**。三件事没有一处说得清：

1. **哪些加算、哪些独立乘算**。源 `damR`（总伤害率）与源 `indieDamR`（独立伤害率）被写进**同一个百分比、
   乘在同一步**里（`passive_bonus.saturating_add(adventurer_bonus)`），而**同一个 `indieDamR` 来源**
   （傳說冒險 `2221053`）在普通攻击路径上又是自己单独乘一次
   ⇒ **同一个增益，两条路径两种口径**——这是源语义被抹平，不是数值微差。
2. **取整在哪一层**。每一步都 `.floor().max(1.0)`，只有区域系数用 `i128` 截断除法。于是**结果与修正项的
   施加顺序有关**：`attacks.rs` 把魔力無限（`SKILL_INFINITY`）放在最前，`skills.rs` 把它放在最后，
   两边对同一份输入给出不同数字。
3. **上限在哪一层**。`ignoreMobpdpR` 在调用点 `clamp(0,100)`，`mdR` / `z` / `damR` **完全不 clamp**；
   从代码里看不出「这个百分比到底有没有上限、上限是多少」。

## 4. 两处有意数值偏离（量化登记）

### 4.1 ① 同源 `damR`：各自乘 → 求和后乘一次

源里 `damR` 的语义是**总伤害率**（同类相加），`indieDamR` 是**独立伤害率**（各自乘）。改前把两类
塞进同一个百分比、乘在同一步。以 `base = 1000`、两个 `damR`（20% 与 50%，实测即
`2220046` 与 `魔力激發` 一类）为例：

| 口径 | 计算 | 结果 |
| --- | --- | --- |
| 改前（视为独立乘） | `floor(1000 × 1.2) = 1200` → `floor(1200 × 1.5)` | **1800** |
| 改后（加算组求和） | `floor(1000 × (100+20+50) / 100) = floor(1700)` | **1700** |

这是**唯一一处本次有意改变数值**的地方，由
`dmg_damage_rate_sources_add_up_and_reach_the_pinned_total` 把 1700 钉死（改回各自乘立即失败）。

### 4.2 ② 取整位置：逐步 floor → 末端一次 floor

改前每一步 `.floor().max(1.0)`，逐步向下取整只会把中间值压低 ⇒ **旧值 ≤ 新值**。用 Python 对
`base ∈ [1, 4000]` × 7 组修正系数 × 3 档区域系数（100/85/70）逐点比对：

| 项 | 实测 |
| --- | --- |
| 最大绝对偏离 | **+3**（`base=18`、修正 `[10,20,30]`、区域 85：旧 23 → 新 26） |
| 偏离分布（`base ∈ [1,2000]`，修正 `[33,50]`/`[20,50]`/`[10,20,30]`，区域 85） | 0 档 **1459** 次、+1 档 **3418** 次、+2 档 **1050** 次、+3 档 **73** 次 |

即绝大多数命中不变或 +1，**不会减小**。这条偏离是「结果与顺序无关」的代价，也是
`dmg_magic_damage_recomputes_exactly_from_the_recorded_factors` 用**独立重算**（拿留痕里的
`base` / `mitigation.after` / 各 `percent` 自己再算一遍）钉住的性质。

### 4.3 一处被刻意保留的不对称

**区域系数（Boss 练习场地护盾）改前用 `i128` 截断除法**，改后进独立乘算组。两者对正值等价
（`trunc` == `floor`），并且 `dmg_an_identity_region_coefficient_leaves_no_trace` 钉住
「系数为 100（恒等）时**不留任何因子记录**」——因为 `percent == 0` 且组基准 100 的修正
在 `add()` 里直接跳过，所以恒等系数不会在留痕里凭空多出一行。

## 5. 核心设计（五条纪律）

### 5.1 分组只按**源字段名**判定，且只有一处

```rust
DamageSource::DamageRate { .. } => ModifierGroup::AdditivePercent,      // 源 damR
DamageSource::CriticalDamage { .. } => ModifierGroup::Critical,          // 源 criticaldamage
DamageSource::IndependentDamageRate { .. }                               // 源 indieDamR
| DamageSource::UnmarkedField { .. }                                     // 源 x / z / damage / mdR
| DamageSource::FreezeLayerBonus { .. }
| DamageSource::RegionGuard => ModifierGroup::IndependentPercent,
```

调用点只给**来源**（`DamageSource` 的变体），分组由 `group()` 派生 ⇒ 结构上不可能
「同一个来源在 A 处当加算、在 B 处当独立」。

`UnmarkedField` 这个变体的存在本身就是一条纪律：**源里没有分组标记的字段（`x` / `z` / `damage` / `mdR`）
就不猜**，沿用改前语义归独立乘算，并把**字段名原样带在变体里**写进诊断串，便于回源核对。

### 5.2 取整与下限只在两处

(i) 目标侧减免那一条既有公式（`apply_target_mitigation`，**逐字保留含它自己那次 `floor`**），
它作用在**基准**上，是既有的第 0 层；(ii) 管线末端一次 `floor` + 一次 `max(1)`。
玩家侧修正的每一项**都不取整**。门禁第 5 组数出 `damage.rs` 里 `.floor()` **恰好 1 次**、
有理数终点取整**恰好 2 次**（一次是诊断投影，一次是权威 `total`）。

### 5.3 上限只在声明处，管线只有防负数守卫

`const MODIFIER_FLOOR_PERCENT: i64 = -99`：每条修正的百分比夹到 ≥ −99（因子 ≥ 1/100）。
**这不是游戏数值上限**（上限在各字段自己的 `clamp` 里，如 `ignoreMobpdpR` 的 `clamp(0,100)`，
`apply_target_mitigation` 里对 `ignored_percent` 又 clamp 一次）。源里没有任何把伤害乘成负数或零的
技能，一旦触发说明**数据出错**，而不是某条游戏规则。

### 5.4 有理数累乘 ⇒ 顺序无关

`resolve()` 用 `i128` 分子 / 分母累乘，只在最后 `num / den` 一次。加算组与暴击组**先求和再乘一次**
（各自合成一条 `FactorStep`），独立组一项一条。`a_zero_critical_still_doubles` 与
`result_does_not_depend_on_the_order_modifiers_were_added` 分别钉住。

### 5.5 暴击组的基准是 200，不是 100

源 `criticaldamage` 的语义是「在 200（= 双倍）之上再加」，所以：

```rust
ModifierGroup::Critical => 200,   // 没学 魔法爆擊 时 criticaldamage = 0，仍是 ×2
```

这条由 `base_percent()` 表达，并且 `add()` 里有一条**只对基准 100 的组成立**的短路
（`percent == 0 && group.base_percent() == 100 → return`）——暴击组的 0% **是**有效修正，
必须记下来。`critical_replaces_the_hundred_percent_baseline` / `a_zero_critical_still_doubles` 各钉一条。

### 5.6 同一来源在两条路径上用**同一个取值访问器**

`hyper_adventurer_damage_percent(mage_skills, player)` 是源 `indieDamR`（傳說冒險 `2221053`）在
两条路径上的唯一取值处。改前普通攻击取「已学等级」（再 clamp 0..100），魔法路径**固定取 1 级且不 clamp**：
该技能 `maxLevel = 1`，所以**今天的数值相同但形状不同** ⇒ 源码把 `maxLevel` 调大时两条路径会静默分叉。
门禁断言这个访问器**只在 `damage.rs` 定义一处**，且 `attacks.rs` 与 `skills.rs` **都通过它取值**。

### 5.7 可解释输出只往 stderr 走

`DamageBreakdown::explain()` 一行说清：基准 → 目标侧减免（原始率 / 无视 / 有效 / 减免后值）→
每个来源自己的百分比 → 走到这一步的值 → 合计。设 `MAPLE_DAMAGE_TRACE=1` 时 `resolve()` 打一行到
**stderr**。`percent_of()` 带 `#[cfg(test)]`——**生产构建里不存在**，免得留一个没人读的旁路取值口。
