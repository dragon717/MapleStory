# 属性聚合权威模块（`attribute.rs`，2026-09-17）

> **模块名**：玩家属性聚合权威模块——「玩家最终属性是多少」的**唯一入口**与**唯一口径**。
> 代码入口：`server/src/attribute.rs`（新增，`world.rs:35` 区 `#[path="attribute.rs"] mod attribute;`
> + `use self::attribute::*;`）；快照组装层 `server/src/derived.rs`（重写为纯组装）；
> 唯一装备折叠实现抽到 `server/src/combat_rules.rs::equipment_field_sum`。
>
> 本轮无任务单编号，属「按当前用户指令实现下一个核心模块」。审计依据：T07 卡（属性与技能组合边界）
> 里**「属性聚合口径」**那一条，原文是*「明确基础能力、装备实例、被动、临时 Buff/异常等来源如何聚合，
> 哪些加算、哪些独立乘算、上限和取整在哪一层发生。只对当前技能/装备真正使用的属性做类型化」*。
> 这是 T07「可解释输出」切片（上一轮 `damage.rs`）的姊妹篇：伤害管线回答「修正怎么乘」，
> 本模块回答「基准属性是多少」。
>
> 门禁：`scripts/check_tms273_attributes.cjs`（已进 `client/scripts/run-checks.mjs`）。

## 1. 范围与结论

| 项 | 结果 |
| --- | --- |
| 唯一聚合入口 | ✅ 新增 `attribute.rs::aggregate_attributes`；UI 与战斗四条路径共用同一份结果 |
| 来源如何聚合 | ✅ 层序 `PersistedAbility → PassiveSkill → ActiveBuff → Equipment`（枚举顺序即层序）；`AttributeInput` 收敛全部输入（tick / join 两条路线各一个构造器） |
| 哪些加算 / 取高 | ✅ 由 `AttributeOp` 表达：`Flat`（加算）/ `AdditivePercent`（同类百分比先求和、整组只乘一次，本版仅楓葉祝福）/ `Highest`（取高替换，本版仅 `mastery`） |

## 2. 实测分叉与**证伪**（本节是本模块最重要的经验）

改前「玩家最终属性」有两个入口：UI 侧（`derived.rs::compute_derived_stats`）与战斗侧
（`attacks.rs` / `monsters.rs` / `boss.rs` / world tick 直接 `with_ability_stats(原始 ability_stats)`）。
对着 `shared/mage-skills.json` 逐字段核实后：

| # | 项 | UI | 战斗（改前） | 结论 |
| --- | --- | --- | --- | --- |
| D1 | 智慧昇華 `2200007` + 極速詠唱 `2200012` 的 `intX`（满级合计 **+60 INT**） | 含 | 不含 | **真分叉**，已统一 |
| D2 | 楓葉祝福 `2221000` 的 `basicStatUp`（满级 +15% 四维） | 含 | 不含 | **真分叉**，已统一 |
| D3 | 魔力之盾 `2000010` 的 `pddX`（满级 **+90**） | 进 `defense()` | 进（`commit_incoming_damage` 内层 `shield_bonus`） | **误诊**：两侧拆在两处、总量一致 |
| D4 | 咒語精通 `2200006` / 冰龍吐息 `2221005` 的 `mastery` | 算出即丢（改前 `derived.rs` 里**写了没人读**） | 物理区间下限恒 0.1 | **真分叉**，已统一 |

**D3 的教训要写进流程**：诊断时看到「UI 的 defense 比 with_ability_stats 的 weapon_defense 多 90」
就下了「战斗漏了」的结论，漏看了 `monsters.rs::commit_incoming_damage` 里**第二次**减 `pddX`。
第一版实现据此把含 `pddX` 的 `defense()` 接进受伤路径 ⇒ **同一击扣两次**，
全量测试 `mage_skill_runtime_covers_learning_targets_replay_guard_teleport_and_wave`
当场抓出（预期 MP −9、实际 −0）。最终口径：

> **受伤路径的边界**：`apply_contact_damage` / `apply_boss_player_damage` 外层减伤读**装备侧**
> `weapon_defense`（经 `with_ability_stats`），`pddX` 留在 `commit_incoming_damage` 内层；
> 两处相加 = 面板的 `defense()`。**受伤路径禁止改成读 `defense()`**——门禁
> `check_tms273_attributes.cjs` 第 3 组有反向断言（扰动验证：改了立即红）。

## 3. 口径细则（实现即文档，这里只列「别再犯」）

1. **层序分界不是「源里有没有 `mpCon`」**——楓葉祝福**有** `mpCon`（源表实查 `mpCon=10`）。
   分界只有一条：**取值是否随「增益是否在手」变化**。`intX`/`basicStatUp`/`pddX`/`madX`/`x`/
   `mmpR`/`lv2mmp`/`psdSpeed`/`asrR`/`terR` 按已学等级查表 ⇒ 被动层；冥想 `indieMad`、
   初學者「迅捷腳步」`speed` 从生效中的状态读 ⇒ 增益层。
2. **源侧时长事实**（门禁第 5 组独立重算）：「学得即生效」的四个来源
   `2200007`/`2200012`/`2000010`/`2221000` 源 `common` 均**无 `time`**（构不成增益窗口）；
   `common` **带** `time` 却仍按被动读的必须登记进 `INTRINSIC_DURATION_SKILLS`——
   本版只有 `2221005`（冰龍吐息）的**技能固有** `mastery`（随等级固定、不随窗口变化）。
3. **楓葉祝福在装备折叠之前作用**（按 AP 四维的百分比，装备不吃这个乘法）；
   验收用例用 `(100×115/100)+50 = 165` vs `(100+50)×115/100 = 172` 互斥断言钉死顺序，
   并用 `STR 10 → 11`（截断）而非 12（四舍五入）钉死取整方式。
4. **留痕字段名写源字段名**（回源核对用）：冥想是 `indieMad` 不是内部名 `meditation_mad`；
   抗性是 `asrR` / `terR` 分开各一条，不是合并的 `asrR/terR`。
5. **最大 MP 从持久化基线算**：输入是 `Player::base_max_mp`（不是产物 `state.max_mp`），
   重连 / 换装备 / 每拍重算**都不复利**；验收用「把 `state.max_mp` 踩成 9,999,999 再重算」证明。

## 4. 消费路径接线

| 路径 | 改动 | 效果 |
| --- | --- | --- |
| world tick（`world.rs`） | `compute_derived_stats` 16 位置参数 → `aggregate_attributes` + `DerivedRuntime::of`；删除紧随其后的第二次 `with_ability_stats` | 每拍只算一次；`max_hp`/`max_mp`/`move_speed`/快照同源 |
| 加入路径（`commands.rs:299`） | 位置参数字面量串（`false, false, 0, None…`）→ `AttributeInput::joining` + `DerivedRuntime::joining` | 写错顺序从签名上消失；加入时施放类增益恒不生效是**真值**不是默认值 |
| 状态变更后（`derived.rs::refresh_player_derived`，40 处调用点） | 签名不变，内部改走聚合 | growth / skills / elemental / dialogue / revive / portals 等零改动 |
| 普通攻击（`attacks.rs`） | 基准改用 `attributes.attack_damage_against` | D1/D2 ⇒ 攻击区间**上升**；D4 ⇒ 区间下限**上升**（不再恒 0.1） |
| 受伤（`monsters.rs` / `boss.rs`） | **一行未动**（D3 证伪，见 §2） | 无玩家可见行为变化 |

`derived.rs` 从 390 行的「口径 + 组装」缩成纯组装；`compute_derived_stats` 5 个参数
（技能表、聚合结果、已学表、职业、运行期开关），UI 取值逐字不变。

## 5. 验收与门禁

- **验收**：`server/src/attribute_acceptance.rs`（经 `world_tests.rs` `include!`，助手 `attr_` 前缀），14 条：
  层序=枚举序、intX 两被动各记各的并传到物理区间、楓葉祝福先于装备折叠（含截断）、
  加算%整组只乘一次、魔力之盾面板口径、mastery 取高不相加且只抬下限、冥想是增益层且零贡献不留痕、
  魔法攻击公式独立重算（期望值从内容表现读）、max_mp 基线不复利（世界级用例）、
  移速 speedMax 上限 + 合并 clamp、抗性未学不报、**协议快照逐字段 = 聚合访问器**、
  留痕性质（非零/登记键/op 声明/逐键可解释）、refresh 幂等。
  期望值一律**现读内容表**（`MageSkills::bundled()` + `shared/gameplay.json`），不写死过期常量。
- **门禁**：`scripts/check_tms273_attributes.cjs`，六组：
  ① 解析自检（层/作用方式/键三张表）；② 聚合唯一入口 + 四条消费路径接线；
  ③ 战斗侧口径（含**受伤边界反向断言** + 原始 `ability_stats` 只许出现在两个登记点）；
  ④ 内容→表独立重算（10 个源字段 × 层/键/op 逐条对齐）；⑤ 源侧时长事实（无 `time` 的四个 + 登记表恰一个）；
  ⑥ 取整/上限/装备折叠唯一实现/接线/协议不进留痕。
- **扰动验证**（全部被拒后还原）：
  - 楓葉祝福取整改四舍五入 ⇒ 验收红（12≠11）+ 门禁红（形状丢失）；
  - mastery 取高改相加 ⇒ 验收红（1.0≠0.7）；
  - 受伤路径改读聚合 `defense()` ⇒ 门禁红（双扣断言）——与 §2 的真实事故同一形状。
