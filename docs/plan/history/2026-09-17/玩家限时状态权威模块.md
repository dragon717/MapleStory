## 2. 改前的三个缺陷（为什么值得收口）

1. **同一件事有两套时间表示**。`Player.skill_buffs: BTreeMap<u32, u64>` 存「剩余毫秒」并**逐 tick 相减**
   （`world.rs` tick 块里一行 `for remaining in player.skill_buffs.values_mut() { *remaining -= TICK_MS; }`），
   而五个疾病与免疫窗存「世界 tick 截止点」（`seal_until` / `stun_until` / `curse_until` / `poison_until` /
   `slow_until` / `status_immune_until`）。两套表示必然长出两套读法。
2. **三套「是否生效」判据**。`skill_buffs.contains_key(&id)`、`remaining_ms > 0`、`until > tick` 同时存在。
   减到 0 的记录不会立刻消失（要等那一段 `if remaining == 0` 清理），于是 `contains_key` 与 `remaining > 0`
   会**在同一时刻给出相反结论**——`derivedStats` 与技能判定读的正是不同那两套。
3. **清理按写死的技能名单**。同一段里六段 `if remaining == 0 { ... }` 逐条点名：初心者恢复術 / 迅捷腳步 /
   無限 / 楓葉淨化免疫窗 / 冰龙吐息 / 雷霆。名单漏一个，那个增益就**永远停在 0**（永不从 `skill_buffs` 移除），
   而用 `contains_key` 读它的那一侧仍判它生效；同时它的附属字段（`infinity_damage_bonus` 之类）
   再也没人收回去。这条缺陷无法被静态检查发现——它就是「注释即契约」的代价。

## 4. 核心设计（五条纪律）

### 4.1 一律「世界 tick 截止点」，且本状态自带唯一时钟

`PlayerStatus` 内部只有三种记录：`Timed { until, next }` / `TimedBuff { until, release }` / `immune_until`，
**没有一处存剩余毫秒**。剩余毫秒是 `until.saturating_sub(now).saturating_mul(TICK_MS)` 投影出来的，
所以它不可能与「是否生效」不一致。

`now` 是 `PlayerStatus` 自己的时钟，**只由 `advance()` 与各 `apply_*` 两个入口盖章**（共 6 处，全部在模块内）。
读取侧的每个访问器都**不收 tick 参数**——这就从签名上排除了「拿一个过期的 tick 去读」和
「两处读出不同剩余」这两类 bug。

### 4.2 与改前逐拍等价（这是「无行为变化」的证明，不是声明）

| 语义 | 改前 | 改后 | 等价性 |
| --- | --- | --- | --- |
| 增益截止 | 在 `t` 施加 `d` ms，逐 tick 相减，在首个 `remaining == 0` 的那拍移除 | `until = t + ceil(d / TICK_MS)`，`until <= now` 即失效并被 `advance()` 收掉 | 同一拍 |
| 疾病截止 | `*_until = tick + duration_ms / TICK_MS`（**向下取整**，无下界） | `until = now + max(duration_ms / TICK_MS, 1)` | 同拍；**多出的下界 1 拍修掉「0 时长被当成已施加」**，由 `zero_duration_is_never_applied` 钉住 |
| 疾病首脉冲 | `*_next_tick = tick + 1` | `next = now + 1`（仅对有脉冲的疾病） | 同拍 |
| 脉冲节拍 | `*_next_tick <= tick` 时扣血并 `+= cadence` | `due_dots()` 同条件、同推进 | 同拍，且 `due_dots()` 就地推进 `next` ⇒ 同一脉冲只返回一次 |
| 到期拍是否还脉冲 | 到期分支是 `else if` ⇒ 到期拍不脉冲 | `advance()` 先收掉，`due_dots()` 的 `taken.until > self.now` 再拦一次 | 同序、同结果（`advance` 在 `due_dots` 之前调用） |
| 刷新语义 | `insert` 覆盖 | `apply_buff` 覆盖（**不取较长者**） | 逐字相同，由 `a_buff_refreshes_on_reapply_and_never_stacks` 钉住 |

### 4.3 「是否生效」只有一支入口

所有改前的 `contains_key` 读法（`world.rs` / `skills.rs` / `elemental.rs` / `attacks.rs` / `derived.rs`
/ `party_acceptance.rs`）全部换成 `buff_active`。派生语义入口另有五个：
`suppresses_skill_cast()`（封印 ∥ 眩晕）、`locks_controls()`（眩晕）、`slows_walk()`（缓速）、
`is_immune()`（楓葉淨化窗口）、`abnormal()`（快照投影）。

### 4.4 到期是穷尽的，附属状态是效果自带的

```rust
for expiry in player.status.advance(self.tick) {
    match expiry {
        Expiry::Buff { release, .. } => match release {
            Release::None => {}
            Release::BeginnerRecovery => { /* 三个 beginner_heal_* */ }
            Release::BeginnerSpeed => { player.beginner_speed_percent = 0; }
            Release::Infinity => { /* infinity_next_tick + infinity_damage_bonus */ }
            Release::StatusImmunity => {}
        },
        Expiry::Disease(_) => {}
    }
}
```

改前这四件事是四段写死技能 id 的 `if remaining == 0`。现在的关键差别是**编译期强制**：
`Release` 增一个变体，上面这个 `match` 不补就编译不过。`apply_buff` 还带一条 `debug_assert`——
同一个技能 id 在不同调用点被声明成两种 `Release` 会直接炸（这是调用点写错，不是数据问题）。

`Release::StatusImmunity` 是空臂并且**刻意保留**：免疫窗的截止点由 `PlayerStatus` 自己持有，
增益到期时 `advance()` 已让它失效（`is_immune()` 随之为假），没有第二份状态需要收回；
留这一臂是为了「这个增益确实拥有免疫窗」这件事在类型上可见，而不是静默地不存在。

显式取消与到期是**两条不同的路**：`remove_buff`（冰龙吐息 / 雷霆 / 冒险家 / 無限 的引导收尾、
`clear_hyper_runtime`）理由与到期完全不同，所以返回 `bool` 让调用方知道是否真有记录被收掉。

### 4.5 死亡 / 换图 / 重连只有一个清理点

`clear_beginner_buffs`（名字是历史遗留，注释已更新说明它早就不只清初心者增益）现在以
`player.status.clear()` 起手；`clear()` 一次清掉增益 + 疾病 + 免疫窗，**保留时钟**（调用方随后会用当前 tick 继续推进）。
`death_map_change_and_reconnect_share_one_cleanup_point` 钉住三条路径终点一致。

## 5. 怪物技能 id 的处置是数据，不是注释

改前 `world.rs` 顶部用一段注释列出 `MapleDisease` 的 id 表然后说「只接子集」，
**从代码里查不出「哪些 id 真的会被放出来」「没接的那几个为什么没接」**（第四缺陷，与 §2.3 同源）。

现在它是 `mob_skill_effect(id) -> SkillEffect`：

| 源 id | 处置 | 说明 |
| --- | --- | --- |
| 120 / 123 / 124 / 125 / 126 | `Disease(Seal / Stun / Curse / Poison / Slow)` | **不再在这里各写一行**——由 `Disease::from_mob_skill_id` 单向派生，所以「正向表说 120 是 Seal、反向表说 120 是 Curse」在结构上不可能 |
| 121 / 122 / 133 / 134 / 137 | `Unmodelled(原因)` | 每一条都写明**为什么**与下一步，不写「未知」 |
| 128 | `Unmodelled(原因)` | 本版内容里唯一带它的怪（`5250007`）**没有可用的时长字段**，如实登记为「先登记不实现」 |
| 112 / 113 / 114 / 170 / 200 | `NotADisease` | 怪物自身的增益 / 召唤 / 治疗类，不是玩家疾病（源 `Skill/MobSkill/<id>.json` 的 `affected` 字段可独立证伪） |

**唯一性由构造保证**：正反向共用 `Disease::mob_skill_id` 一处定义，`from_mob_skill_id` 是它的
`find()` 派生；`a_reason_string_is_not_a_second_switch` 断言「未建模 id 集合」与「已建模 id 集合」不重叠，
即理由串不能变成第二张隐式开关表。

**内容侧实测**（门禁对着真实 `shared/gameplay.json` 与源 `Skill/MobSkill/*.json` 重算）：

- 已建模五个：**120 / 124 / 125 实际投放**，**123 / 126 已建模但本版内容未投放**（两种状态都必须在表里有结论）。
- 未建模六个：**128 实际投放**，每一条都带理由。
- 另有 5 个内容出现的 id 被源 `affected` 字段证伪为「怪物自身技能」，落 `NotADisease`。
