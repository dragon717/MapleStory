# 1402 法師之路「无法接取」修复

状态：代码与判定链已落地，待统一加载 3010 后实玩。日期：2026-09-13。

## 1. 现象

任务日志显示 `1402 [楓之谷世界的冒險家] 法師之路` 为「可接取」，提示为「前往101000003，与汉斯交谈接取任务」（裸地图 ID）。角色在**選擇岔道 `001020000`** 点面前的汉斯，菜单里没有这条任务，无法接取。

## 2. 根因

同名同职的转职官有两处（`shared/gameplay.json` 的 `npcs`）：

| NPC | 名字 | `func` | 所在图 | 角色 |
| --- | --- | --- | --- | --- |
| `10201` | 漢斯 | 法師轉職官 | `001020000` 選擇岔道 | 快捷转职入口，不发放任务 |
| `1032001` | 漢斯 | 法師轉職官 | `101000003` 魔法森林圖書館 | 1402 的 `start`/`complete` NPC |

`1402` 的源数据 `QuestData/1402.img` 明确 `Check.0.npc = 1032001`、`fieldEnter = 101000003`，因此「只能在图书馆找汉斯接取」是**正确的适配**，不是缺陷。缺陷有两条：

1. `quest_menu_choices` 对「可接取但作者 NPC 在别处」的任务**不给出任何去向**，玩家在選擇岔道点汉斯只看到法师训练菜单；
2. `quest.rs::quest_map_label` 只有 8 个硬编码地名，`101000003` 不在其中，提示回退成裸 ID，玩家无法从「101000003」得知目的地。

`continuation_story_1402_through_36314_uses_real_menus` 一直是绿的：它用 `chapter_place` 把角色直接放到 `101000003`，**绕过了走路和点错 NPC**，因此测不出这条断链。

## 3. 修复

| 改动 | 位置 |
| --- | --- |
| 新增 `npc_office()`：取 NPC `func` 去空格后的「轉職官」职能键，兼容 `法師轉職官` / `弓箭手 轉職官` 两种写法 | `server/src/quest.rs` |
| `quest_menu_choices` 未接取分支新增 `route_guide`：当前 NPC 与任务 `start` NPC 同职能、任务条件已满足、且作者 NPC 在别的图时，给一条「前往{地圖}接取：{任務}」 | `server/src/quest.rs` |
| 选择 `route_guide` 时由 `quest_route_target` 重新校验（仍未接取 / 条件仍满足 / 同职能 / 作者图存在）后 `warp_player_at` 送到作者 NPC 所在图 | `server/src/quest.rs` |
| 菜单文案新增 `route_guide` 中英文分支（英文 `Accept at {map}: {name}`） | `server/src/quest.rs` |
| `quest_map_label` 补齐任务链会引用到的 5 个地名：`101000003` 魔法森林圖書館、`101010100` 森林的起始點、`001010000` 冒險者修練場入口、`000020000` 嫩寶村、`310040200` 礦山入口 | `server/src/quest.rs` |

**边界**：`route_guide` 只负责带路，**不发放任务**。1402 依然由 `1032001` 接取，服务端既有特判（`npc_template != 1032001 || map_id != 101000003` 一律拒绝）保持不变，没有伪造第二个接取入口。

**为什么不给選擇岔道的汉斯直接加接取**：源数据里 1402 的 `Check.0.npc` 是 `1032001`，選擇岔道的五位转职官（`10200`–`10204`）在当前装配中不承担任何任务。让 `10201` 直接发任务属于硬编 NPC，与「后续章节源里没写 `Check.0.npc` 就不硬编入口」的既有纪律冲突。

## 7. 追加：一转等级门槛（同日第二轮反馈）

**反馈**：4 级就能在快捷入口转职法师，与原版不符。

**原版判定**：原版一转是 **10 级**，证据链：

- `Quest.wz/QuestData/1402.img` → `Check.0.lvmin = 10`；
- 1402 装配后 `start.conditions.levelAtLeast = 10`；
- `auth::commit_quest` 对 1402 完成态有 `level < 10 → Err("q1402 level requirement missing")`；
- `quest.rs` 完成 1402 时同样卡 10 级。

**根因**：`auth.rs::advance_job` 的 `required_level` 里，二转 30 / 三转 60 / 四转 100 均有门槛，**唯独 `(0, 200)` 一转落在 else 分支 = 0**（SQL 绑定 `level >= ?9`）。于是"走剧情"要 10 级、"走快捷入口"0 级即可，同一服务端两条路自相矛盾。快捷入口来自 `scripts/assemble_tms273.cjs` 中 2026-09-08 用户指定的 `10201` 汉斯 `choose → jobAdvance 0→200`，注释与 `compatibility.mageTransfer` 都写明 *not the original q1402 quest script*，当时未设等级。

**修复**：

| 改动 | 位置 |
| --- | --- |
| `required_level` 中 `(from_job 0, job 200)` 显式 = 10 | `server/src/auth.rs` |
| `10201` script 起点改 `gate`，加 `branch: {cond: {levelAtLeast: 10}}` → 满足走 `choose`，否则 `junior` 说「转职需要达到10级。先去提升等级吧。」 | `scripts/assemble_tms273.cjs` |
| 一转拒绝文案按 job 分支：初心者 → 「轉職需要達到10級。」；其它 → 原「只有新手可以在汉斯处转职为法师。」 | `server/src/dialogue.rs` |
| `compatibility.mageTransfer` 文案同步 | `shared/gameplay.json`（由 `assemble_tms273.cjs` 重生成，tms273-12 / maps 44 / npcs 210） |

**关键结论**：NPC 脚本节点**原生支持** `branch` + `cond.levelAtLeast`（`npc.rs:201` / `262`），这类对话门槛不需要改 Rust —— 只有 `advance_job` 这条带外入口才必须补 Rust 判断。

**测试同步（3 处，把错误行为钉住）**：

- `auth.rs` transfer 用例等级 9 → 10，并新增「9 级被拒且 job 仍为 0」断言；
- `auth.rs` beginner 用例**不可**直接把 `base.level` 改成 10（3 级决定 beginner SP 曲线），改为转职前 `load_profile` 取出、只改 level、再 `save_profile`；直接 `load_profile(eligible)` 会清掉已学技能；
- `world_tests.rs` `mage_job_advance_is_menu_bound_authorized_and_persisted` 的 `beginner.level` 9 → 10，`assert_eq!(persisted.level, 10)`。

**与本条第 1 项叠加后的实际表现**：已完成 36307 且 ≥10 级的玩家在選擇岔道点汉斯，看到的是任务菜单里的「前往魔法森林圖書館接取：法師之路」（任务菜单优先于 script）；快捷入口只在 36307 未完成时可见；<10 级看到等级提示。三条路都自洽可达，但"快捷入口被原版路径取代"这一体验变化尚未与用户确认。

**验证**：`cargo test --offline` **318 过 / 6 失败**（失败集 = 基线六项）；`npm run check` 29/31（`layer-animation`、`build-release` 两项 HEAD 既有失败）。**未重启在线 3010**。
