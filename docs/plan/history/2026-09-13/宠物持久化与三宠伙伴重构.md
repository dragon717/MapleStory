# 宠物持久化与三宠伙伴重构

状态：开发、定向检查与候选构建完成；加载与实玩仍见 `../../PLAN.md`。

## 范围与来源

用户要求现金宠物存档、TMS273 宠物界面及菜单按钮、传送常驻、角色关联 1～3 个独立宠物实例、各自变速/犬类前跑、离主人千码闪回、千码寻物时双速移动。

- T：本地 TMS273.7 `Item/Pet` / `String/Pet` 的 990 种宠物及原始动画。界面来自 `UI/UIWindow2.img/UserInfo/pet`、`UserInfo/character/BtPet`；已核看 backgrnd/2/3、三页签原始 PNG，保持源尺寸与坐标。导出入口 `scripts/export_tms273_pet_ui.cjs`，结果 `resources/tms273-export/pet-ui.json` → `manifest.petUi`。
- 研究包计划、PDF/HTML 索引没有宠物专用图卡，本轮以本地同版 WZ 详情窗为视觉依据。源窗外的召唤列表/移动信息是当前功能的 P 扩展，不宣称完整官方宠物系统 1:1。
- R：[Nexon 官方宠物说明](https://support-maplestory.nexon.com/hc/en-us/articles/211598646-What-is-a-Pet) 核实最多三宠，属于跨区结构依据。
- P：每个实例以稳定 ID 得到 120～180 基础移速，独立相位平滑变化 ±12%；100 移速对应项目角色基础 125 世界单位/秒。寻物实际速度为当刻普通速度的 2 倍。千码按地图世界坐标计算，目标同时处于宠物与主人的千码范围。犬类名称识别用于前跑；复杂地形使用跳跃/落地/墙碰撞与受阻回归，不引入通用寻路引擎。

## 根因与实现

1. `/add` 原先仅写内存背包，拾取等操作重载 SQLite 时会覆盖发放。现在库存新增和 requestId 在同一事务提交，再回填内存；相同请求不重复发放，改参数重用请求拒绝。
2. 旧单只 `Player.pet: Option` 是会话状态，门/卷轴/任务主动清空。现为 `Player.pets` 实例索引，`pets.rs` 管理挂接/脱离、地图归属和寻物，`pet_motion.rs` 管理各自速度、方向与纵向物理。召唤状态属于库存存档；换图快照立即使用主人的新落点，下一 tick 重建地图运行时。
3. 实例身份和 active 复用已有库存元数据 `_petInstanceId` / `_petActive`，不把类型 ID 或可变格位当实例 ID。ID 在 JavaScript 安全整数范围内，快照另发字符串 ID。同种可同时三只，第四只拒绝，收回不消耗道具。
4. 宠物 slotMax=1，整理、移动、仓库存取不合并实例。历史堆叠/缺失标记规范化时保留数量并写回稳定身份，不清库、不删装备、不重建账号。规范化只对实际变化的宠物元数据写回。
5. 旧拾取传入宠物位置，但 `PickupFacts` 仍用主人坐标。现修正为宠物真实位置；搜索排除异图/受保护/容量不足的目标，到达 32 单位领取距离才走既有 `apply_pickup` 和 SQLite 事务。三宠分配不同目标，提交仍复验所有权和容量。
6. 前端按 owner+实例 ID 渲染多宠，独立 move/jump 动画，离图销毁旧精灵。面板入口在 HUD 角色/背包旁；三页签、持有列表召唤/收回、实时速度与状态均已接入。快照更新保留按钮节点和焦点；等级/饱足感/亲密度不编造数值。
