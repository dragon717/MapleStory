# 创建装备目录缺失导致无法入图修复

状态：实现已完成，定向检查与加载结果见下；浏览器入图待用户验收。

## 根因与证据

用户报 `equipment slot mismatch for 1051353 (persistence)`，认证成功后无法入图。故障发生在 `Store::load_profile` 调用 `normalize_equipped_tx`：该函数遍历装备表，用 `inventory::equipment_slot` 比对存档槽位；物品定义缺失时返回空，同样触发 slot mismatch。

修复前 `shared/items.json` 与 public 目录均为 516 项、export 为 509 项，三者均缺 6 件创建连身衣（1050286..1050288、1051353..1051355）与 2 双创建鞋（1072833、1072834）。创建配置仍提供这些选择，manifest 图标也仍存在。只读实际数据库发现 `1051353` 有两条记录，均为 slot=-5、quantity=1，符合 TMS273 `Character/Longcoat/01051353.json` 的 `info.islot=MaPn`。数据本身无需迁移；全表规范化使缺失定义可能影响其它角色入图。

`generate_tms273_gameplay.py` 原只从固定装备、地图商店及掉落收集物品，覆盖写入 export 时丢掉创建导出器曾补充的装备；随后 assemble 又覆盖 shared/public。创建导出器已有单独补丁，但局部重生成不会执行它。启动原门禁只检查了其它资源契约，因此仍能成功构建并切换到无法加载角色的版本。

## 修复

- 玩法生成器从现有 `shared/character-creation.json` 纳入所有非零衣服、裤子、鞋和武器，从同版 WZ JSON 生成；必需来源/islot 缺失直接失败。
- 新增 `scripts/tms273_creation_catalog.cjs`，复用于装配、3010 启动前门禁与 Windows 资源检查，验证物品存在、装备分类、部位槽位；入口同时检查前后端创建配置一致。
- 实际运行修改后的生成器到临时目录，仅将 8 个缺失项补回三份物品目录，保留已有物品属性及其它未提交业务。现有图标齐全，无须重新导出贴图。
- 保留槽位校验、实例属性和数据库；未改变服务端持久化业务规则。`include_str!` 意味着必须重编并加载服务端才能生效。
