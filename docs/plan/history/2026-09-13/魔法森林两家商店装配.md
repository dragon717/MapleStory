# 魔法森林两家商店装配：101000001/101000002 传送阵补全

## 用户反馈

在魔法森林（`101000000`）走到两个门时提示：

- `此路线尚未开放：目标地图 101000001 尚未收录`
- `此路线尚未开放：目标地图 101000002 尚未收录`

（这是 `client/src/scenes/world.ts::tryPortal` 对「目标图不在装配目录」的关闭门提示，非错误态。）

## 关键事实（源）

- `101000000 魔法森林` 的两个 `pt: 2`（可见门、**无脚本体**）：`in00`(-664,-1046) → `101000001/out00`、`in01`(235,-669) → `101000002/out01`。反向 `out00`(-48,181) → `101000000/in00`、`out01`(300,182) → `101000000/in01`，双向闭环。
- `String/Map.json/victoria`：`101000001 魔法森林武器/防具商店`、`101000002 魔法森林雜貨店`；streetName 均为 `魔法森林`；两图 `info/bgm = Bgm02/WhenTheMorningComes`、`returnMap` 自指自身、`town = 1`、VR 均为 -400/400 × -300/300。
- 图内 life：`101000001` 有 `1031000 妖精 佛羅拉`（武器商人）与 `1031001 妖精 舍拉比`（防具商人）；`101000002` 有 `1031100 妖精 蓮`（雜貨商人）与 `9062704 요정 웡키`（`info.hide=1` + `limitedname=7000days`，按既有 `Npc.info.hide` 规则只进审计、不生成 spawn）。
- 三家店的商品表 `data/Shop/1031000|1031001|1031100.json` 都在（22/109/53 行），照原样装配进 `gameplay.shops`（商店总数 9 → 12）。
- 世界地图 `Map.wz WorldMap010` 的 `MapList/1/mapNo/0..3` 本就同时列出 `101000000/101000001/101000002/101000003`，所以新图装配后自动落回「魔法森林」那一个 spot，`WORLD_MAP_ABSENT` 无需改动。
- 两张图的 WZ JSON（`Map/Map/Map1/1010000{01,02}.json`）本来就在 `WZ_JSON_TW` 里，此前只是**没有登记进装配目录**，不需要从真 WZ 补解包。

## 根因

`scripts/import_tms273.py::ADDITIONAL_STORY_MAP_IDS` 只登记了 `101000000`/`101000003`。目标图不在录内 ⇒ 客户端 `catalogHasMap` 判为关闭门（走近提示一次），服务端即使收到请求也只能回 `map_unavailable`（服务端行为正确）。

## 改动

1. `scripts/import_tms273.py`：`ADDITIONAL_STORY_MAP_IDS` 追加 `"101000001"`、`"101000002"`（并补注释说明它们是 `101000000` 的 `in00`/`in01` 唯一目标）。重跑后 `references/tms273-data/maps.json` 由 48 → **50 图**，quests.json 逐字节未变。
2. 受影响导出链（不是全量 build）：`import_tms273.py` → `export_tms273.cjs maps|entities|portals|effects` → `export_tms273_reactor.cjs` → `export_tms273_minimap.cjs` → `export_tms273_worldmap.cjs` → `generate_tms273_gameplay.py` → `export_tms273.cjs items` → `backfill_tms273_slot_expand.py` → `assemble_tms273.cjs`。
3. 内容版本 `tms273-12` → **`tms273-13`**，四处同步：`scripts/assemble_tms273.cjs`、`shared/protocol.ts`、`server/src/protocol.rs`、`scripts/check_tms273_runtime.cjs` 的默认期望值。
4. `scripts/check_tms273_runtime.cjs`：
   - `catalog.maps.length` 48 → 50；
   - 新增「魔法森林两家店」双向门断言（`in00`→`101000001/out00`、`in01`→`101000002/out01`，双向贴地与光束都要有），与既有的「維多利亞港三家商店」同款；
   - 传送类消耗品断言由两件改为三件：新增 `2030002 魔法森林卷軸`（`spec.moveTo = 101000000`，雜貨店 1031100 售卖）。
5. `scripts/assemble_tms273.cjs`：`compatibility.returnScroll` 文案补记 `2030002`。
6. `scripts/build_tms273.cjs`：在 `generate_tms273_gameplay.py` 与 `export_tms273.cjs items` 之间插入 `backfill_tms273_slot_expand.py`（见「附带发现 1」）。
7. 服务端测试：`boss_acceptance.rs` 的 `world.maps.len()` 44 → 50 并补两家店断言；`world_tests.rs` 的装备派生断言改为「inline 卷轴加成 20 + 该武器源 `incMAD`」。

## 附带发现与处理

1. **`item-images.json` 的陈旧陷阱（已修流程）**。四张背包扩展券 `2430768..2430771` 在 TMS273 里走 NPC 脚本，`generate_tms273_gameplay.py` 只写它们的商店行、不写道具定义；定义由手工补丁 `backfill_tms273_slot_expand.py` 写进 `items.json`。历史上 `item-images.json` 含这 4 张券的图标，只是因为它在 backfill **之后**生成过。这次重跑 `items` 导出按最新 `items.json` 重建，把券的图标弄丢，`check_tms273_runtime` 立刻以 `2430768` 报错。补跑 `backfill → items → assemble` 后恢复。已把该顺序写进 `build_tms273.cjs`，防止下次全量重建再丢。
2. **`boss_acceptance.rs` 的地图数硬编码早已漂移**。断言写死 44，而目录在 2026-09-13 站台图交付时已到 48 ⇒ 该测试在 48 图状态下就已失败（当时的实玩清单只跑了 `check_tms273_runtime` 与 `npm run check`，没跑 `cargo test`）。本次随 50 图一并更正。
3. **新增道具改变了装备派生断言**。`1372000`（魔法森林武器店售卖）此前不在 items 表，装备派生只算装备实例上的 inline 卷轴加成（`incINT 5 → INT*4 = +20`）；现在它有源定义（`incMAD 53`），公式（`derived.rs` 的 `bonus("incMAD")`）自然多算 53 ⇒ 94。断言改为引用 `inventory::equipment_attributes` 的源值，数据再变也不会失配。
4. **未修的既有失败**：`world::tests::shop_sell_uses_the_source_auto_price_for_etc_drops` 仍失败。`4000019 嫩寶殼` 的源记录没有 `price`（只有 `autoPrice=1` + `lv=1`），而 `inventory::item_price` 只读 `info.price`，尚未实现测试注释里说的 `ItemSellPriceStandard` 按 `lv` 定价。该数据在本改动前后逐字段相同（HEAD 的 `shared/items.json` 亦然），故属既有缺口，按惯例不顺手修。

## 部署（待用户执行）

**客户端与服务端必须一起换**：服务端只在启动时读 `shared/maps.json`，只换客户端会让新客户端去请求 `101000001` 而旧服务端回 `map_unavailable`，正是本次要修的现象。请在终端执行：

```
zsh 启动3010.command
```

（本机受限 shell 里 `ps` 被系统拒绝，脚本依赖 `ps` 判定 3010 上的进程身份，因此不能由会话代跑。）

重启后会话表（`auth.rs` 的进程内 `HashMap`）会作废全部 token，页面需刷新并重新登录 —— 这不是回归。
