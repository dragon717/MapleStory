# 骑宠 / 椅子图标状态台账对账（2026-09-18）

起因：用户一句「若在 273 找不到，可以去 83 里找」，顺着查缺图时发现 `shared/mounts.json`(935)
与 `shared/chairs.json`(2797) 的 `spriteSourceStatus` **全表**写着 `wz-present-unextracted`
——而磁盘上 935 张骑宠图标、2681 张椅子图标早就导出并在服务目录里躺着。**写者没把状态写下去，
读的人就只能当「没查过」**：典型的自述 ≠ 事实。

## 1. 先查清「缺」到底是什么缺

| 项 | 结论 |
| --- | --- |
| 骑宠图标 | 935/935 齐全，0 缺 0 空 → 不用兜底 |
| 椅子图标 | 2797 件里缺 116 件，**全部是 `03019` 分组** |
| 116 件在 273 里 | 节点**在**（`Item/Install/03019.img/<id>/info/icon` 能解析），但报「像素分卷缺失」——icon 是外链 Canvas，像素在 `Item/Install/_Canvas/03019.img/…`，该目录只有 `_Canvas_000/001/002/004.wz`，**`_Canvas_003.wz` 不在包里** |
| 83 客户端 `Data` | `.img` 是私有加密格式（`0301.img` 头 `73f86c77`，非 `PKG1`），现有 `tms273_wz.cjs` 读不了；二进制里连 `03010000` 都搜不到 |
| 83 服务端 `wz` | HaRepacker 导出的 `.img.xml`，**只有结构无像素**；`Item.wz/Install` 只有 `0301.img.xml` + `0399.img.xml`，`grep 03019003` = 0 ⇒ v83 没有 `3019xxx` |

⇒ 这 116 件 273 缺、**83 也取不到**（版本太老）。跨版本兜底策略对它们不适用。

## 2. 改动

**生成器 `scripts/export_tms273_mounts_chairs.cjs`**（它是这两张表的唯一写者）：

- 新增 `settleIcons(items, frameFile, label)`，骑宠与椅子**共用**一套落定逻辑。判据两层，
  缺一层就写假结论：① 帧表里有这条 id；② 帧表 `url` 指向的 PNG 在 `client/public-tms273`
  下**真实存在且非空**。只认 ① 就是「自述 ≠ 事实」的老毛病（帧表写了 url、文件没落盘，
  状态照样 verified，浏览器拿到 404）。
- 帧表整体缺席 ⇒ 保持 `wz-present-unextracted` 并留住「未完成项」提示：**没查过就说没查过**。
- 落定的**只有状态**，不把帧挂回目录表（目录表答「是什么」、帧表答「怎么画」，这两张表是
  `include_str!` 进服务端二进制的，塞帧会让它们白胖一圈）。
- 椅子此前**根本没有**这一步，所以 2797 件永远停在未查状态——补 `applyChairIcons`。

**顺手修掉一个真缺陷（新门禁抓出来的）**：椅子收录判据原本是「`info` 里有
`slotMax / price / recoveryHP` 之一」。`03015159` / `03015161`（11 週年 楓之谷冰淇淋 椅子，
源名与描述都在 `String/Ins.json`）的 `info` 只有 `accountSharable` 与 `collabo` ⇒ 被整把漏收，
于是**图标导得出、目录里没人认领**：看得见图，服务端 `is_chair_item` 却答 false。
改为与服务端 `inventory::is_chair_source` **同一口径**（分组 `0301*` / `0302` 即椅子）；
分组外（0304 / 0370 / 0399 等装饰、分解机、椅子袋）仍按原字段过滤，保持
`chairs.json` 作为 Install 全类目表的现状。**净增 2 件**，无移除。
