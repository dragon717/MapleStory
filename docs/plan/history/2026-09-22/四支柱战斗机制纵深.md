## 1. 四支柱的设计：一条派生计划 + 两类跨拍状态

### 1.1 计划从源字段派生，不写技能名单

`mechanics.rs::AttackPlan::of(level: &MageLevel)` 是**唯一入口**，施法链与投射物到达共用同一份派生。
三个子结构各自只看「字段在不在 + 值是多少」：

| 子结构 | 派生自 | 关键语义（刻意写反过的地方） |
| --- | --- | --- |
| `segment_delay_ms: Vec<u64>` | `attackCount` + `ballDelay`/`ballDelay1..3` | `ballDelay: 0` 是「**写明的 0**」（首段本拍就到），不是「没写」——用 `present[]` 数组区分，**不靠 `unwrap_or(0)`** |
| `DotPlan` | `dot` / `dotInterval` / `dotTime` / `prop` | 时长**只认 `dotTime`，刻意不回落源 `time`** |
| `SecondHitPlan` | `lt2` ∧ `rb2` 齐备 + `damPlus` | 只有 `damPlus` 没有第二盒 ⇒ **不接**（见 §1.3） |

`subTime` **只在 `ballDelay*` 存在时才读**：它在召唤 / 持续场那边已经被消费过一次（当脉冲周期），
同一字段被两条路径各读一次会让判据与行为一起分叉。这条是第十二轮「配对消费」纪律的第一次实战。

**向后兼容是逐字节的**：不带 `ballDelay*` / `dot` / `lt2` 的技能，`segment_delay_ms` 全 0 ⇒ 走即时路径、
`finalize = true`，与本轮之前的 30 条技能行为**完全一致**。

### 1.2 四支柱的触发条件

| 支柱 | 触发条件 | 存活周期 |
| --- | --- | --- |
| **召唤物** | 源召唤技能施放成功；受 `World::summon_slots_available`（预算 `SUMMON_BUDGET = 2`）约束；同技能重放**先替换再判容量** | 到 `expires_at`；主人换图 / 倒地即清 |
| **DoT** | 第 1 段**真的打出伤害** ∧ `prop` 掷骰命中 | `dotTime` 秒；同 `(施法者, 技能, 目标)` 唯一实例，叠层 +1（上限 `DOT_MAX_STACKS = 5`） |
| **投射物** | 段延迟 > 0 的段（`flying_segments()`） | `arrive_at <= tick` 落地；主人换图 / 倒地 ⇒ **静默丢弃**，上限 `PROJECTILE_MAX_FLIGHT_MS = 10_000` |
| **二段命中** | `lt2` ∧ `rb2` 齐备 ∧ **首段链收尾时仍有真实命中** | 本施法最后一次结算的尾，一次性 |

### 1.3 交互关系（哪些互相影响、哪些刻意不互相影响）

| 交互 | 规则 | 理由 |
| --- | --- | --- |
| 投射物 × 碰撞 | 延迟段落地时**重做碰撞判定**（以施法时冻结的原点为基准重算 `area_targets_at`） | 「发射后走进盒子」应被打到、「走出去」不应被追加打到。命中的是**落地那一刻**的站位，不是发射那一刻 |
| 投射物 × 击杀 | 同段落地的怪若已被前一段打死 ⇒ 跳过（`settle_area_segments` 的存活判据） | 不重复计伤害 |
| DoT × 击退 | DoT 跳伤**不调用** `register_monster_knockback` | 源 `pushed` 是「**单次伤害阈值**」；用每跳的小额伤害推怪会得到与直接命中完全不同的位移 |
| DoT × 叠层 | 叠层 +1 且**时长取长者**，但**不重置 `next_tick`**；跳伤不刷新自己 | 连续点射是「越打越稳」而非「越打越拖」，也不会自激 |
| DoT × 暴击 / 冰冻层 | **都不参与** | DoT 是已挂上的残余伤害，没有「命中瞬间」可掷骰 |
| 二段 × 首段 | 二段以 `lt2/rb2` **独立重选**目标；**要求首段链真的打到人** | 它是「伤害分配」：主盒吃 `damage%` × N 段，第二盒再吃 `damPlus%`。空挥不会凭空多一段 |
| 召唤物 × 主人 | 脉冲复用主人**当拍**的属性快照（同一条 `cast_elemental_area_at`） | 主人的增益 / 武器 / 等级差修正对召唤物同样生效 |
| DoT × 击杀归属 | **世界拍顺序保证**（见 §1.4） | 不允许 DoT 抢投射物的击杀 |

### 1.4 结算优先级（写在代码里的单一判据）

同一拍内，数值越小越先：

| 序 | 阶段 | 触发条件 | 结算位置 |
| --- | --- | --- | --- |
| 1 | 触发骰 `roll` | 源 `prop`（缺省 100%），按 `(施法者, 请求, 目标, 机制名)` **确定性**掷骰 | 命中瞬间 |
| 2 | 首段直接伤害 `first-hit` | 段延迟为 0 的段 | 施法拍内即时 |
| 3 | DoT 挂载 / 刷新 `dot-apply` | 第 1 段真的打出伤害 **且** 掷骰命中 | 首段命中之后 |
| 4 | 二段命中 `second-hit` | `lt2`∧`rb2` 齐备 **且** 收尾时仍有真实命中 | 本施法最后一次结算的尾 |
| 5 | 召唤物脉冲 `summon-pulse` | 独立时间轴（`step_summons`） | 世界拍 |
| 6 | 投射物到达 `projectile-arrival` | `arrive_at <= tick` | 世界拍 |
| 7 | DoT 滴答 `dot-tick` | `next_tick <= tick` | 世界拍 |

世界拍里的顺序是 **召唤物 → 投射物 → DoT**，理由是同一条：**越「已确定、越被动」的结算越靠后**。
召唤物是主人主动放出去的「小号」，先打；投射物是已经发射、正在飞的实体，随后落地；
DoT 是挂在怪身上的残余，最后结算 ⇒ 它看到的血量已经被前两类削过，**永远不会抢走投射物的击杀归属**。

节奏上这就是「层次」的来源：一击之内有 1→2→3→4 四层（骰 → 首段 → 挂 DoT → 二段分配），
一拍之内又有 5→6→7 三层（召唤 → 投射物 → 残余）。玩家看到的是「先出手、再落弹、最后跳伤」，
而不是一坨同时结算。

## 2. 真缺陷修复：物理线的二段命中**永远凑不出「首段真的打到人」**

这是本轮最有价值的一条，而且**不是设计问题，是既有代码的静默缺口**。

`skills.rs` 里原本是：

```rust
if counts_as_direct_hit(skill_id) && resolution.damage > 0 {
    self.successful_direct_targets.insert(target_id.clone());
    self.advance_mystic_strike(id, request_id, target_id);
}
```

而 `counts_as_direct_hit` **刻意排除** `PHYSICAL_AREA_ATTACKS`（物理线区域攻击不算「直接命中类」，
否则会凭空开始叠法师的神秘狙擊）。于是 `3111015 閃光幻象`（物理线，本轮新接）走：
首段打出伤害 → `counts_as_direct_hit` 为假 → **`successful_direct_targets` 永远是空的** →
`settle_second_hit` 的「要求首段链真的打到人」**永远是假** ⇒ **二段命中结构上不可能触发**。

修法是把两件事**分开**（两件事共用一个门，是这里唯一的问题）：

```rust
// ① `successful_direct_targets` 是「本次结算里真的打出过伤害的目标」——
//    二段命中与暴风雪的隐藏追击都读它，与技能是不是「直接命中类」无关；
// ② 神秘狙擊叠层只认 `counts_as_direct_hit`（命中**次数**的语义），
//    并进 ① 会让物理线凭空开始叠法师的层。
if resolution.damage > 0 {
    successful_direct_targets.insert(target_id.clone());
    if counts_as_direct_hit(skill_id) {
        self.advance_mystic_strike(id, request_id, target_id);
    }
}
```

**扰动⑤实测**（把旧门重新套回去）：`mech_second_hit_uses_the_narrow_box_and_needs_a_real_first_hit`
立刻红，`left: 0, right: 1`——即「二段命中事件数 0（期望 1）」。改回即绿。

## 8. 复用提示（踩坑记录）

- **两个语义共用一个门 = 迟早有一个语义被另一个拖死**。`counts_as_direct_hit` 同时管「命中次数语义」
  和「本次结算有没有打出伤害」，于是物理线的二段命中结构上不可能触发，而代码看起来完全合理。
  判据：**任何 `if` 里的函数名一旦是「分类谓词」，就问一句「这个分支真的需要整个分类吗」**。
- **判据文件被静默回退比判据写错更危险**。`git status` 只告诉你「有改动」，不告诉你「改动是不是你要的」。
  问「扰动为什么没被抓」比问「测试为什么红了」更能发现这类问题。
- **扰动要选「形状相同、语义相反」的**：本轮扰动⑥⑦第一次尝试加 `dot` 回去，撞在分组注册断言上
  （正确但不够精确）；换成非见证字段 `ballDelay1` / `lt2`，才精确落在配对断言与常量断言上。
- **世界拍的顺序就是一条判据**，光断言「两个函数都调用了」不够，必须断言**先后**
  （`indexOf` 比较），否则顺序被换掉时门禁全绿而击杀归属已经错了。
- **告警基线要在独立 worktree 上取**（`git worktree add`），不是 `git stash`：工作区本来就脏时，
  stash 退到的是「我的 HEAD」而不是「干净基线」，两次对照会一起把历史漂移算成我的。
- **合成目录是钉时间语义的必要手段**：真实内容的 `ballDelay` 是百毫秒级，观测窗口太窄，
  「同拍优先级」这类判据用真实技能根本观测不到。合成技能用 `2_001_9xx` 段避开真实 id 空间。
