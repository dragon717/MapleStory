## 1. ① 物理线二转以上主动技能接执行链

### 1.1 本轮范围是从源表**重算**出来的，不是手挑的

第八轮的「物理线」只覆盖**四条一转书**（`100/200/300/400`）。本轮的输入面是**七本分支书族**
（`book / 10 ∈ {11,12,13,31,32,41,42}`，即三职业 × 二/三/四转共 21 本书）的**全部 326 条技能**。
按源字段做一次穷尽分类：

| 分类 | 判据（源字段） | 条数 |
| --- | --- | --- |
| **带贴身框的直接攻击** | 具备 `damage ∧ mobCount ∧ attackCount ∧ lt ∧ rb` | **56** |
| 有 `damage` 却无贴身框 | 有 `damage`、缺 `lt`/`rb`/`mobCount`/`attackCount` 之一 | 53 |
| 纯增益／召唤／治疗 | 无 `damage`、有 `mpCon` | 55 |
| 纯被动／其它 | 两者都无 | 162 |
| **合计** | | **326** |

只有第一类（56 条）是「和一转 6 条同形、可以复用同一条范围管线」的候选。再从 56 条里剔除：

- **14 条 `hidden` 节点**：源里由职业规则自动启用、玩家点不到；本包施法入口 `handle_cast_skill`
  在 `skill_hidden` 就早退了（`SKILL_MAGIC_WAVE_HIDDEN` 是唯一例外），接进表没有意义。
- **17 条带「机制标记」**（见 §1.3 的字段表）：本包还没有它们的机制。

⇒ **56 − 14 − 17 = 25 条**进表。加上一转 6 条，`PHYSICAL_AREA_ATTACKS` 由 **6 → 31 条**。

**执行路径与一转 6 条完全同形**（`cast_elemental_area_at_filtered` 的 `if physical` 分支）：

- 命中盒取源 `common/lt|rb` **绕玩家**，不走源 `range`；
- 段数／目标数取 `level` 的 `attackCount` / `mobCount`；
- 伤害基准 = **普攻攻击区间**（`attack_damage_against`，含四维聚合 / 等级差 / 目标侧 PDD）× `damage%`；
- **不掷暴击、不吃冰冻层**（普攻同口径）；
- 区域系数取**物理护盾**（`boss_damage_multiplier(&map_id, false)`）。

**上界不需要动**（这是本轮特意验的一条）：这 25 条里 `mobCount` 最大 **15**（`1221011 鬼神之擊`）、
`attackCount` 最大 **12**（`1321013 岡格尼爾之擊`），正好落在范围管线**既有**的两处 clamp 里
（`area_targets_at` 目标 1..15、`cast_elemental_area_at_filtered` 段数 1..12）。门禁对这一条做
**逐级自证**：任何一条未来的成员超出上界就红 —— 判据写的是「**超出就得改上界，不是改技能**」。

### 2.4 门禁新增两条断言：把「静默失败」变成会响的断言

`scripts/check_tms273_job_advance.cjs` 在既有的「奖励技能必须在目录里」等判据之外，新增：

- **§2b「外部前置必须真的接得到」**：对每条**表外前置**（如 `1401`/`1402`/`1403` 这类
  通用任务），断言它的**接取 NPC** 真的被摆在某张**已装配**的图上：

  ```js
  const generalQuestStartNpc = new Map(
    gameplay.quests.map(entry => [String(entry.questId), String((entry.start || {}).npcId || '')]),
  );
  const npcHasAnyPlacement = npcId =>
    [...npcPlacements].some(placement => placement.startsWith(`${npcId}@`));
  ```

  **这条断言的由来是一个真坑**：飞侠二转原本打算挂一转剧情 `1404` 作前置，但 `1404` 挂的
  NPC `1052001` **既不在** `shared/gameplay.json` 的 `npcs` 里、**也没有**任何摆位 ——
  挂上去就是「永远接不到」的静默失败。发现后改成**无外部前置**，理由如实登记在
  `provenance.P`（唯有一转剧情 `1404` 挂的 NPC 在墮落城市，该图与 NPC 都不在装配内容里），
  并加这条断言把同类错误挡住。

- **§2c「没有外部前置必须逐条登记理由」**：对 `fromJob ∈ {100,200,300,400}`（四条一转）的任务
  双向断言 —— 要么有外部前置，要么在 `PREREQ_LESS_ALLOWED` 里有登记：

  ```js
  const PREREQ_LESS_ALLOWED = new Map([['job-410', …], ['job-420', …]]);
  ```

  初版把飞侠二转前置「默默抹掉」是**不可检测**的；加这条后，任何一条二转任务少了前置都会红。

## 4. 顺手修掉的两处**注释里的事实错误**（本轮由「写文档时复核数字」逼出来）

写交付记录时按门禁规则**重算了一遍分类统计**，发现注释里的数字与实测不符：
