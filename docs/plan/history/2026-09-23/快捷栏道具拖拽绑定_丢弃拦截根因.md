# 快捷栏道具拖拽绑定：拖出丢弃拦截根因修复

- 日期：2026-09-23
- 用户指令：「根因修复：消耗道具、椅子 拖到快捷栏可以绑定快捷栏功能， 目前被丢弃拦截。」
- 遵循 AGENTS.md / BUSINESS_DEVELOPMENT.md：只做定向验证、不启动独立 QA、不重启在线服务。

## 结论

一条链路断了三处，「拖到快捷栏」被 document 级的「拖出窗口＝丢弃」先吃掉：

1. **丢弃判据只认窗口内**：`DragController` 的 document 级 `dragover`/`drop` 以
   「落点不在背包/装备窗口内」为丢弃判据，HUD 快捷栏在窗口外 ⇒ 被当作丢弃，
   物品真的掉了（根因）。
2. **快捷栏压根没有背包拖拽通路**：HUD `createShortcutCell` 只监听 `drop` 收
   `application/x-maplestory-skill`（技能拖拽），背包拖拽的 MIME 没人读。
3. **椅子端到端不可用**：`main.ts` 的 `useShortcutItem` 把 `inventoryType` **写死 2**、
   绑定校验只放行类 2，而椅子在设置栏（类 3）⇒ 即便绑上了也会被服务端判非法。

## 修法（单一权威）

落点**自报**，document 级不再替它做主；「是不是椅子」交给服务端具名退回。

### ① `drag-controller.ts`：窗口外落点认领契约

- 新增导出：
  - `INVENTORY_DRAG_MIME = 'application/x-maple-inventory'`（原字面量收口为常量）；
  - `INVENTORY_DROP_ZONE_ATTRIBUTE = 'data-inventory-drop-zone'`（落点自报属性）；
  - `InventoryDragPayload { inventoryType, sourceSlot, itemId }`；
  - `hasInventoryDrag(dataTransfer)`（dragover 阶段即认得出）；
  - `readInventoryDrag(dataTransfer)`（原样读回，坏载荷/缺字段按「不是背包拖拽」返回 `undefined`）。
- `DragHost` 新增必填 `claimsExternalDrop(node: Node): boolean;`。
- dragstart 两处 `setData('application/x-maple-inventory', …)` 改用常量。
- document 级处理器改为经 `handledByTarget(target) = containsTarget || claimsExternalDrop`
  判定：**认领的落点不 preventDefault、不丢弃、也不提前清空拖拽来源**；窗口外没人认领的空地
  仍是丢弃/卸下。类注释同步更新。

### ② `inventory/view.ts`：把属性落点接回 host

```ts
claimsExternalDrop: node => node instanceof Element && Boolean(node.closest(`[${INVENTORY_DROP_ZONE_ATTRIBUTE}]`)),
```

### ③ `hud/view.ts`：快捷栏接收背包拖拽 → 绑道具

- `HudViewOptions` 新增 `bindItem?: (slot: number, itemId: number) => void;`。
- `createShortcutCell` 的 `editSlot` 分支给按钮 `setAttribute(INVENTORY_DROP_ZONE_ATTRIBUTE, '')`
  （自报为落点 ⇒ document 级不接管），`dragover` 对技能/背包两种 MIME 放行；
  `drop` 先试 `readInventoryDrag` → `bindItem(sourceSlot, itemId)`，否则回落技能绑定的老路径。

### ④ `keybindings/view.ts`：绑定校验放行类 2 与类 3

- 新增 `bindItemToSlot(index, itemId)`：`canBindItem` 不过就提示「只能配置背包里的消耗品或椅子。」。
- `canBindItem`：类别（`Math.floor(itemId / 1e6)`）为 **2（消耗品）或 3（设置栏，椅子在此）**，
  且背包里确有该物品（`quantity > 0`）。
- `validBinding` 的 item 分支同样走 `canBindItem`。
- **刻意不在客户端判「是不是椅子」**：客户端没打包 `shared/chairs.json`（体积），手上两份
  椅子表（`chair-names.json`、`manifest.rideScenes.chairs`）都是**超集**（含 0304/3049/3996
  等非椅子装饰件），不能当判据；非椅子设置栏件由服务端 `not_a_chair` 具名退回，界面照译
  「这个装饰品不能坐」。

### ⑤ `app/main.ts`：栏位号按 itemId 类别推导 + 接线

- `useShortcutItem` 的 `inventoryType` 由 `inventoryTypeForTab(itemCategoryTab(item.itemId))`
  算出，不再写死 2；注释写明服务端 `chair_toggle` 只认 3，写死会让椅子落进 `InvalidInventoryType`。
- HudView 选项新增 `bindItem: (slot, itemId) => keybindingsView?.bindItemToSlot(slot, itemId)`。
