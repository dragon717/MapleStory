## 2. 口径（源字段逐条决策，不靠「没写」蒙过去）

源 `shared/mage-skills.json::skills['2321005']`，20 级：

| 源字段 | Lv1 → Lv20 | 决策 |
|---|---|---|
| `time` | `240`（各级相同，秒） | **消费** → 窗口时长 `240_000 ms`，过一遍 `buff_duration_ms`（大師魔法增益时长加成对它同样成立） |
| `x` | 11 → 30 | **消费** → 攻击力，`ActiveBuff` / `Flat` / `AttributeKey::WeaponAttack` |
| `y` | 11 → 30 | **消费** → 魔力，`ActiveBuff` / `Flat` / `AttributeKey::MagicAttack` |
| `z` | 398 → 550 | **消费** → 防御力，`ActiveBuff` / `Flat` / `AttributeKey::WeaponDefense` |
| `indieMhp` | 275 → 750 | **不消费**（登记理由见 §5） |
| `indieMmp` | 275 → 750 | **不消费**（登记理由见 §5） |
| `mpConReduce` | 10 → 20 | **不消费**（登记理由见 §5） |

源 `info`：`type=10` + `massSpell=1` + `magicSteal=1` + `action=alert2`
⇒ **队伍增益窗**：不是攻击技能，也不是開關技能（開關那批的源 `common` 里**没有** `time`）。

`ADVANCED_BLESSING_SHAPE = ['time','x','y','z','indieMhp','indieMmp','mpConReduce']`
由门禁**从源独立重算**并与 `world.rs::ADVANCED_BLESSING_SKILLS` 双向 `deepEqual`
（源里再出现这个形状就必须有人做决定）。

### 一条关键设计决定：数值**随身带**，不回表查

加成的量级来自**施法者那一本**的等级，而收到增益的队友**未必学得这一本**
⇒ 属性聚合时按 `learned_level` 回表查是查不到的，按自己的等级查又会用错等级。

所以沿用 `meditation_mad` 的既有写法：施放时把 `x`/`y`/`z` 算定成 `BlessingBonus` **挂在玩家身上**，
到期由 `Release::AdvancedBlessing` 收回成 `None` ⇒「有值即生效中」本身就是那条门，
**不需要**再查一次 `buff_active`。这条由验收用例 `ab_window_reaches_the_party_on_the_map_and_nobody_else`
实锤（队友 `b` 的技能表里**没有**这本，仍然拿到加成）。

## 5. 扰动验证（改一条就红，才算真门禁）

**第一次跑有两条没咬住** —— 值得单独记：

- P4（删 `skills.rs` 的准入表项）与 P5（删 `world.rs` 的清理语句）**一开始是绿的**。
  原因：`skills.rs` 里有**两处** `ADVANCED_BLESSING_SKILLS.contains(&skill_id)`（准入白名单 + 施法时长），
  `world.rs` 里也有**两处** `player.advanced_blessing = None;`（到期收回 + 会话重置），
  而我的断言写成「这个串在文件里出现过」，删掉任意一处，另一处仍能满足 ⇒ 门禁形同虚设。
- 修法：把每条正则**收窄到真正的代码体**——
  `let castable = ([^;]*);`、`fn clear_beginner_buffs\(player: &mut Player\) \{([\s\S]*?)\n\}`、
  `Release::AdvancedBlessing\s*=>\s*\{([\s\S]*?)\n {24}\}`，外加一条分发臂正则。
- 复跑：**8/8 全红**，扰动脚本已删除。

> 教训（与既有纪律同源）：**「串出现过」不是断言，「这个串出现在这个作用域里」才是。**
> 同一个常量在文件里出现 N 次时，全文匹配会让 N-1 个删除操作静默通过。
>
> **同一条教训第二次现形**：把 `AdvancedBlessing` 补进 `check_tms273_player_status.cjs` 第 6 组时，
> 那里原有的 `/Release::X\b/` 正则会被 **doc 注释里的 intra-doc 链接**（`[`Release::X`]`）满足——
> 实测删掉 `world.rs` 里真实的 `Release::AdvancedBlessing => { … }` 收回臂，它**照样绿**。
> 已收窄成 `Release::${variant}\s*=>\s*\{`（真实臂形状），复跑：原样通过、删臂变红 ✔。
> 那一组的**真正保证是 Rust 的穷尽 match**（删臂 ⇒ `error[E0004]`，已实测）。
> ⚠️ 另外：该门禁自身在 HEAD 就红（第 3/4 组的 MobSkill 内容漂移），⇒ 第 6 组在 CI 里本来就跑不到；
> 本轮**没有顺手修**那条内容漂移，改用「抽出该组单独跑」的方式做了隔离验证。

### 未消费字段的登记（不许靠「没写」蒙过去）
