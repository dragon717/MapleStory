## 缺口（收口前的两套账）

1. **实体与槽位是冰雷专属**：`elemental.rs` 的 `ThunderSummon` 只服务三转球形闪电；四转的冰魔 / 冰鋒刃
   另走 `Player::summons` 队列，于是「到期 / 换图收回 + 周期打击」的同一份判据在 `step_summons` 里**写了两遍**。
2. **容量判据有两处**：`SUMMON_BUDGET = 2` 只管队列，球形闪电走独立单槽 `Player::summon`（「同技能重放即替换」），
   `mechanics.rs` 里已如实登记为待办。
3. **脉冲周期按 `skill_id` 硬编码在两处**：单槽分支读 `subTime`，队列分支 `match skill_id`
   （`SKILL_ICE_DEMON => 1_080`、`SKILL_FROZEN_ORB => attack_delay`）。
4. **清理点只清单槽**：8 处 `player.summon = None`，队列部分靠 `step_summons` 惰性清 ⇒ 死亡 / 换图 / 复活后
   存在两种语义。

## 源字段核对（决定周期判据；逐条从 `shared/mage-skills.json` 读出，非推断）

| 技能 | 源字段（全等级一致） | 收口前的硬编码值 | 派生后 |
|---|---|---|---|
| `2221005 召喚冰魔` | `subTime=8`、`time=115` | 字面量 `1080ms` | `subTime` 8 **小于一拍、不是毫秒** ⇒ 回落契约值 1080 |
| `2221012 冰鋒刃` | `attackDelay=210`、`subTime=8`、`time=4000` | `attackDelay`（210） | 210 |
| `2211011 閃電球` | `subTime=1080`、`time=63` | `subTime`（1080） | 1080 |
| `2211015 閃電球`（hidden） | `subTime=1080`、`time=22` | `subTime`（1080） | 1080 |

⇒ 判据：**`attackDelay` > `subTime`（仅当其 ≥ 一拍 `TICK_MS`）> 契约值 1080**。
四件召唤逐一复现收口前的现行为（1080 / 210 / 1080 / 1080），**零行为漂移**。

## 做了什么

### ① 槽位合并（`world.rs` / `mechanics.rs`）

- `ThunderSummon` → **`Summon`**；`Player` 删掉 `summon: Option<Summon>` 单槽，`summons: Vec<Summon>`
  成为**唯一权威**；快照投影删掉 `.summon.iter().chain(player.summons.iter())`，只走队列
  （单槽原先也是并进同一个 `summons` 数组投影的 ⇒ **客户端报文形状不变**）。
- `SUMMON_BUDGET` **2 → 3**，文档改为「唯一的容量判据、完整答案」，删掉「单槽仍另算」的待办措辞。

### ② 位移形态在施放时定下（`world.rs`）

- 新增 `enum SummonMotion { Anchored, Follow, Drift }` 与 `const SUMMON_DRIFT_PX_PER_SEC: f64 = 180.0;`；
  `Summon.anchored: bool` → `Summon.motion: SummonMotion`。
- 冰魔 → `Anchored`（钉在施放点）；冰鋒刃 → `Drift`（沿朝向自行前进，180px/s 是既有的 P 运动学、不是周期）；
  球形闪电 → 移动形态 `Follow`、锚定形态 `Anchored`。
- 效果：`step_summons` **不再含任何技能名单**，两套分支合并成一个循环。

### ③ 脉冲周期唯一派生点（`mechanics.rs`）

- 新增 `pub(super) fn summon_pulse_ms(skills: &MageSkills, skill_id, level) -> u64` 与
  `pub(super) const SUMMON_PULSE_FALLBACK_MS: u64 = 1_080;`；判据即上表。
- 落在 `mechanics.rs` 而非 `elemental.rs`：该模块宪章表的「召唤物脉冲 `summon-pulse` / 独立时间轴」一行就是它的归属。
- 签名取 `&MageSkills` 而非 `&self`：调用点正同时持有 `player` 的可变借用，`self.方法()` 会被借用检查器挡下。

### ④ 施放与步进（`elemental.rs` / `skills.rs`）

- `cast_ice_demon` / `cast_frozen_orb`：改 `Summon` + `SummonMotion`，首跳时刻改用派生值
  （保留原有的 `/ TICK_MS` 向下取整写法，与 `div_ceil` 的差别为零，避免引入漂移）。
- `step_summons`：单槽分支与队列分支合并成一个循环；死亡即清空整队列；`next_hit_at` 推进改用派生值。
- `cast_thunder_sphere`：对队列做 `retain(去掉同技能)` → `summon_slots_available` → `push`；
  「同技能重放即替换」语义逐字保留 —— 锚定重放**就地改** `motion` / `skill_id = hidden` /
  `expires_at = min(旧, now + 时长)`，`summon_id` / `next_hit_at` / `pulse_index` **不动**（锚定不重置打击节拍）。
- `skills.rs` 的「锚定重放不吃 `mpCon`」判据（原读单槽）改为在队列里找球形闪电。

### ⑤ 清理点收敛（8 处）

`boss.rs` / `revive.rs` / `portals.rs`（2 处，含 `candidate`）/ `quest.rs` / `monsters.rs` /
`inventory_ops.rs` / `elemental.rs`（死亡分支）/ `commands.rs`（Player 字面量）：
`player.summon = None;` → `player.summons.clear();`。净效果与原行为一致（队列部分原先由 `step_summons`
在死亡 / 换图时惰性清掉，现在提前到同一处），**不再有两套语义**。

### ⑥ 验收（`server/src/**` 测试）

- `third_acceptance.rs`：新增 `sphere(world)` 助手（按技能从队列里筛），6 处读取改为该助手，
  `assert!(anchored.anchored)` → `assert!(matches!(anchored.motion, SummonMotion::Anchored))`；
  **断言真值一字未改**（重放不叠加、不重复扣 MP、锚定 `next_hit_at` 不变、到期精确收回、快照 `stationary` 一致）。
- `mechanics_acceptance.rs`：新增 `mech_summon_slots_are_one_queue_and_pulse_period_comes_from_source`，
  断言 ① 冰魔 + 冰鋒刃 + 球形闪电**三件共存于同一条队列**；② 三件在场时 `summon_slots_available` 报「装不下」
  （上限没被悄悄抬高）；③ 位移形态三分（冰魔不动 / 球形闪电跟主人 / 冰鋒刃自行前进）；
  ④ 派生周期逐件等于收口前的硬编码值（210 / 1080 / 1080）；⑤ 派生值**真被消费**
  （`next_hit_at - pulse_tick == 派生值.div_ceil(TICK_MS)`）。
  注：真实内容只有 3 件召唤技能，「第 4 件被拒」用直接断言容量判据（②）代替。
- `scroll_acceptance.rs`：`player.summon.is_none()` → `player.summons.is_empty()`。
