# 開關技能收口与 `2121054 火靈結界` 接执行链

2026-09-24（第七轮）。用户指令：「**2121054 开始。**」（承接同日的「继续」，明确点选了 `PLAN.md` §1② 缺口 C 里那条被判为「要新增机制」的火毒四转 Hyper 技能）。

## 开工前先证伪一句旧结论（本项目第三例）

上一轮（[法师四条待办技能源语义核定与判据纠偏](法师四条待办技能源语义核定与判据纠偏.md)）把 `2121054` 的缺口写成：

> `2121054 火靈結界` ⇒ **開關态**……DoT 与范围攻击本身**已有**，缺的只是「再次使用即关闭的持久开关位」与「每秒扣 MP 的结算点」。

逐字核源后，这句话**只有后半句成立**：

- 「再次使用即关闭」的持久开关位**早就有**，而且最贴切的先例就是**同一格**的 `2221054 冰雪結界`（源 `classification.role = "hyper-toggle-field"`）——`world.rs` 里已有 `hyper_barrier_enabled/_next_mp/_next_pulse` 三字段、`step_hyper_effects` 的每秒扣蓝与周期结算，只是**按一个 id 写死**：白名单 `skill_id == SKILL_HYPER_VORTEX`（`2221054`）、每秒固定扣 `60`、周期固定 `2400 ms`、像素侧 `2221055` 的隐藏节点只服务冰雷。
- 所以 `2121054` 连**白名单都进不去**（`castable` 里被 `skill_id == 2221054` 挡掉），报的是「该技能尚未开放施放」。

⇒ **真实缺口只是「按一个 id 写死」，不是「没有開關态」**。这与 `2321054` 那次的教训同型：**理由漂成与源不符，会把人锁死在错方向**（去造一套已存在的机制）。

## 实现方式（新增面最小：一张接纳表 ＋ 三个派生点）

1. **`server/src/world.rs`：把写死收成派生表。**
   - `const SKILL_FIRE_WARD: u32 = 2121054;`；`const TOGGLE_FIELD_SKILLS: [u32; 2] = [SKILL_HYPER_VORTEX, SKILL_FIRE_WARD];`
     ——**起这个常量本身就是 `MAGE_BRANCH_PENDING` 判据的设计意图**（判据是「`212`／`232` 里带 `mpCon`、非 `hidden`、`world.rs` 里没有常量」⇒ 起常量就逼着同时补机制、删登记）。
   - 形态表 `pub(super) enum ToggleFieldPulse { Freeze, Damage }` ＋ `fn toggle_field_pulse(skill_id) -> ToggleFieldPulse`（`2121054 ⇒ Damage`，否则 `Freeze`）——**只决定周期作用形态，不决定开不开**。
   - 每秒耗蓝 `pub(super) fn toggle_field_upkeep_mp(level: &MageLevel) -> i64 { level.mp_con.unwrap_or(0).max(0) }`（火毒那本＝源 `mpCon` 100；冰雷源同值 60 ⇒ **零行为回归**）。

   - `struct ToggleFieldRuntime { next_mp, next_pulse }` ＋ `set_toggle_field` / `toggle_field_enabled`。
   - **`Player` 的 `hyper_barrier_enabled/_next_mp/_next_pulse` 三字段合并成 `toggle_fields: BTreeMap<u32, ToggleFieldRuntime>`**（開關态**逐本**）；`clear_beginner_buffs` / `clear_hyper_runtime` 改为 `player.toggle_fields.clear();`；`hyper_barrier_active(player)` 首行改成 `toggle_field_enabled(player, SKILL_HYPER_VORTEX)`（保持旧语义、旧名字仍在）。

## 本轮踩到并修掉的两个坑（都不是产品缺陷，但都会让门禁「静默变松」）

1. **`check_protocol_errors.cjs` 把 message 里的表达式判成「message 是变量」**：`send_reject` 的文案我一度写成 `&format!("MP不足，{}已结束。", skill.name)`，门禁要求「客户端 i18n 表补码」，而客户端表一旦有条目就会**盖掉**服务端这句、把 `skill.name` 一起丢掉。
   **修法**：改回**调用点上的字面量** `"MP不足，開關技能已结束。"`——用**源文案的族名**（不写死某一本，也就不重引入按 id 分支）。
2. **`combat/skill.check.mjs` ＋ `combat/sound.check.mjs` 双双变红（基线外新增 2 红）**：两个检查脚本把要注入的 `player/input.ts` 导出名**手抄**成固定的 4 个，漏了我新加的 `TOGGLE_FIELD_SKILLS` ⇒ `view.ts` 顶层 `new Map(...)` 直接 `ReferenceError`。
   **修法**（符合仓库「白名单收口成派生表」纪律）：注入名单改为**从 `view.ts` 的 import 正则派生**，并把「导出的值不能是 `undefined`」变成**当场指名**的断言（`player/input.ts 没有导出 X，但 view.ts 在用它`）。扰动 I 证明改名会立刻报这句。

> 另记一条**测试写法**的坑（不是产品缺陷）：新验收用例第 ⑤ 段（MP 见底应关掉開關位）第一次是绿的。根因＝upkeep 的 `request_id` 形如 `toggle-field:{id}:{skill}:{tick}`，而我在 ③④⑤ 之间**没有推进 tick**，于是 ⑤ 复用了 ④ 的同一个 `request_id`，被 `store.cast_skill` 当成**重放**、直接回放上次结果（顺带证明了那条幂等守卫有效）。修法是测试里 `world.tick += 20;`。

## 新增验收用例（`server/src/hyper_acceptance.rs`）

`hyper_fire_ward_toggle_pulse_upkeep_close_and_no_down_variant`，钉七件事：

1. 表与源一致（`mp_con = 100`、`sub_time = 3000`、`dot` / `dotInterval` / `dotTime` 齐备、**`time` 与 `cooltime` 必须为 `None`**）；
2. 打开后 `fire_ward_active` 亮、`hyper_barrier_active` **不**亮（两本開關态互不串台）；
3. 周期拍打出范围伤害并挂上 DoT、且**不收 upkeep**；
4. `next_mp` 那一拍扣**源 `mpCon` = 100**（不是改前写死的 60）；
5. MP 见底 ⇒ 開關位自动关掉 ＋ 收到 `toggle_field_stopped`；
6. 再次施放即关闭、MP 恢复能重开；
7. ↓ 变体（`vertical = 1`）对火毒那本**显式拒绝**（`invalid_toggle_field_variant`），且不许静默打开開關位、不许生出 `hyper_vortex`。
