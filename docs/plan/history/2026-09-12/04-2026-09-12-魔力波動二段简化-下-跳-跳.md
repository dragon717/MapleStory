# 魔力波動二段简化：下+跳 → 跳（2026-09-12）
> 状态：已完成

> 归档自迁移前 `PLAN.md`（超大文件治理：md 与代码同一口径）。原文逐字保留，未做改写。
> 归档位置：`docs/plan/history/2026-09-12/04-2026-09-12-魔力波動二段简化-下-跳-跳.md`　　归档顺序：04/66（PLAN.md 原倒序）


- 需求（用户）：魔力波動 发动后第二段"气泡"（缓降）目前要 `上+跳` 再 `下+跳`，简化为 `跳`。
- 根因（服务端**一处**闸门）：`world.rs::handle_cast_skill` 对隐藏节点 2001012 的条件写作
  `player.state.grounded || vertical <= 0` ⇒ 只有**按住 ↓**（vertical=+1）才受理；按住 ↑ 或空手按跳
  都被拒成 `skill_cooldown`。客户端 `castJumpSkill()` 的空中分支本来就不看方向（`上+跳` 之后 ↑ 仍在
  按下集合里），所以真实操作序列被服务端逼成"松上→按下→跳"。
- 修改：该子句删掉 `vertical <= 0`，只留 `player.state.grounded`（仍必须离地）与一次性
  `magic_wave_float_used`。可见节点 2001011 继续要求 `vertical < 0`，第一步 `上+跳` 未变。
- 与源的关系：源 2001012 的 `maxUseCountInOneJump=1` 只表达"一次跳跃内限用一次"，**没有**任何"必须按下"
  字段 ⇒ 本轮不是新增 P 偏离，而是把实现收回源语义（第二段就是跳跃指令本身）。
- 验证：
  - 服务端 `wave_acceptance.rs` 新增 `air_float_needs_only_a_plain_jump_press`（`上+跳` 之后按
    vertical=0/-1/+1 三路都必须成功浮空并 arm `slow_fall_until`）与 `air_float_still_requires_leaving_the_ground`
    （地面按跳仍 `skill_cooldown`；2001011 不带 ↑ 仍 `skill_cooldown`），复用同文件既有 `wave_pool()` 夹具。
    **已反证**：临时把 `vertical <= 0` 放回去，前者立刻失败。
  - 客户端 `input.check.mjs` 补断言：松掉 ↑ 后空中 `Space` 仍发 2001012 且 `vertical=0`。
  - `cargo test --offline` **287 过 / 6 失败**，失败集与基线逐条一致（auth third_store、mage bundled_catalog、
    world config_drop / portal_command / reactor_area、third_sphere），**零回归**；客户端 `tsc --noEmit`、
    `input.check.mjs` 通过。
- 待验（用户）：`启动3010.command` 统一加载后实玩——`上+跳` 起跳，空中再按一次 `跳` 出现缓降气泡；
  按住 ↑ / 按住 ↓ / 空手三种按法表现一致。
