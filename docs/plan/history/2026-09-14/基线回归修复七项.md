# 基线回归修复：7 项长期失败清零（2026-09-14）

## 背景

长期基线是「389 通过 / 7 失败」，7 个失败被当作既有基线挂着不动，日久成了噪音，也掩盖了其中的真实缺陷。本次逐项判定：**真缺陷修代码，过期断言改断言**，目标是把基线压到 0 失败。

修复前：`389 passed; 7 failed`
修复后：`396 passed; 0 failed`（证据 `evidence/2026-09-14/基线回归修复/cargo-test.log`）

## 逐项判定与处置

### 真缺陷（改产品代码）

| 测试 | 症状 | 根因 | 修法 |
|---|---|---|---|
| `reactor_area_herb_auto_triggers_once_per_entry_and_can_trigger_again_after_exit` | 站在区域 reactor 的盒子里，状态继续推进（期望锁一次） | `world.rs::step_area_reactor_interactions` 把「冷却中 / 不可交互」的 `continue` 放在记录重叠集合**之前**，触发后 600ms 内该 reactor 被移出 `area_reactor_overlaps`，冷却一过玩家就被当成新进入者 → 站着不动也会反复触发 | 把冷却与可交互性判断移到 `next_overlaps.insert` 之后：只要在盒内就一直记为重叠，冷却只压制触发、不清除「已在内」状态 |
| `shop_sell_uses_the_source_auto_price_for_etc_drops` | `item_price("4000019")`（嫩寶殼）为 `None`，Etc 掉落卖不出钱 | 该道具只有 `info.autoPrice:1` + `info.lv:1`，没有 `price`；`item_price` 只读 `price`。`backfill_tms273_item_price.py` 本该补，**但它不在 items 导出链里**，`export_tms273.cjs items` 重写 `items.json` 时把补好的价又冲掉 | `inventory::item_price` 增加 `auto_price` 回退：按原版 `Item/ItemSellPriceStandard.json`（400 分类＝ `lv × 2`）现算。放在服务端而非数据里，任何重导出都冲不掉 |
| `third_sphere_and_adaptation_are_idempotent_and_bounded` | 锚定雷球对 boss 只打出 1 段（204），期望 3 段（612） | 锚定形态用隐藏技能 `2211015` 的目录行，而该行源里只有 `damage/subTime/u2`，**没有 `attackCount`**（移动球 `2211011` 有 `attackCount:3`）→ `attack_count` 退化为 1，固定球伤害只有移动球的 1/3 | `elemental.rs::step_summons` 里，隐藏形态（display variant）的脉冲改用父技能 `2211011` 的目录行结算；`summon.skill_id` 仍用于雷电特效与 boss 加成判定 |

### 过期断言（改测试，不动行为）

| 测试 | 为什么过期 | 改法 |
|---|---|---|
| `config_drop_and_exp_are_authoritative_without_client_values` | 固件里写死 `"contentVersion":"tms273-3"`，而 `CONTENT_VERSION` 早已是 `tms273-23`，`validate()` 直接拒载 | 解析为 `serde_json::Value` 后把 `contentVersion` 覆盖为 `crate::protocol::CONTENT_VERSION`，固件不再随版本升级而红 |
| `bundled_catalog_is_strict_and_has_energy_bolt_geometry` | 硬编码目录规模 43，实际已增长到 56 | 断言改为下界 `>= 43`（守「不丢行」，不挡「新增行」），失败信息带上实际行数 |
| `third_store_book_split_and_222_compatibility` | 期望 job 222 在 61 级升级时把 SP 加到 **220 书**。但 222 现在是四转（`FOURTH_JOB`），四转 SP 表从 101 级才开（`fourth_sp_for_level`），低等级给 0 且不该建 222 书 | 保留「兼容」意图但对齐现行规则：61 级不给点、不建 222 书；再把等级推到 101，断言点数落到 222 书且 220/221 不动 |
| `portal_command_changes_map_and_snapshot_scope` | 断言「传送后 step 推的第二条消息就是快照」，后来推进了 `friendState` 推送，第二条变成好友状态 | 改为 drain 整批消息、挑出 `type == "snapshot"` 再断言 `mapId == "target"`（换图本身一直是好的，`map_id` 断言在同一测试内已覆盖） |

## 影响面（实玩可感知）

- **固定雷球（锚定）伤害 ×3**：此前只有移动球 1/3，属真实战斗回归。
- **Etc 怪物掉落可以卖钱了**：嫩寶殼一类按 `lv×2` 定价，商店收半价（lv1 → 卖 1 金币）。
- **区域 reactor 不再「站着就反复触发」**：进入触发一次，离开再进才再触发。
- 其余四项只动测试与固件，无运行时行为变化。
