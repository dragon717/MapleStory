# 续章路径阻塞可解释与节点指引（审计 T05）

- 日期：2026-09-14
- 范围：审计 §11 **T05｜打通一段无需 GM 的续章与成长路径**（P1）中"停下要说清楚"的那一半
- 协议：**22 → 23**；内容版本：**`tms273-23` 未变**（装配数据一行未改）

## 1. 这次修的是什么

T03 之后 36315→36316 在装配世界里是真实可走的：36314 发放的两件收集物已挂在 `startItems`，36316 的接取/交付 NPC 赫麗娜（1012100）在 `100000201`。但**交完 36316 之后任务日志什么都不增加** —— 36317「再次前往現在的門」被源边界挡住（`Check/1` 只含 `order` 与 `exVariable=dummy` 的计数器，适配器记为 `script-counter`），而服务端只把 `executable()` 为真的任务写进日志。

结果是：**"这一段还没复刻"和"这里没有任务了"在界面上长得一模一样**。玩家走完一段续章，得到的反馈是沉默。这正是审计 §8.4「局部可执行与正常可达混淆」在任务链上的具体样子。

同一类沉默还有一处：36315 的进行中行只显示 `藍色蘑菇王 0/1`，不说它在哪张图。目标名有了，地点没有。

## 2. 实现范围（玩家能做的事）

1. **停下有解释**：前置已满足、但当前版本跑不起来的任务，日志里以 `blocked` 状态出现，带人话 `blockReason`，并指向**真实存在的**地图与 NPC，明说尚未开放。
2. **狩猎说地点**：进行中的击杀目标给出目标怪实际所在的地图（`gameplay.spawns` 查得出来才给，查不出来宁可不说），并同时填 `targetMapId`。
3. **不给按不动的按钮**：`blocked` 行不输出 `selfStart`/`selfComplete`，不进追踪条，排在列表最后。
4. **标签不露脸**：装配标签（`script-counter` 等）只作为内部名目，界面上永远是人话；未知名目落成「尚未復刻的環節（xxx）」，代码仅作诊断后缀。

## 3. 来源与边界

- **T**：任务前置、起止 NPC、目标怪与地图均来自 TMS273.7 `Quest.wz/QuestData` 与已装配的 `shared/gameplay.json`；36317 的阻塞来自源 `Check/1` 实际内容（见 §1）。
- **P**：**没有**把 36317 判成可执行。`Check/1` 与已可执行的 36316 只差一个 `exVariable=dummy` 的计数器，但 `infoex` 字段语义在本仓库仍未核定（见 T03 交付记录 §12），把占位计数器当空条件放行就等于替原作伪造完成条件 —— 不做。
- **未做**：36318 及之后的 `script-scene`、36331 的 `missing-start-npc`、36319/36322 的 `kill-target-missing` 都保持阻塞，现在只是**说清楚了**，没有打开任何一个。
- **保护**：不动任何任务规格、掉落、奖励、GM 政策；`gameplay.json` 未改，故内容版本不升版；`contentVersion` 仍要求二进制常量与装配文件严格相等。
