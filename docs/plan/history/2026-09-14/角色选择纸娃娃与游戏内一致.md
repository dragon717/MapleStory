# 角色选择纸娃娃与游戏内一致（快速开始／角色选择预览根因修复）

状态：实现与定向验收完成，**待统一加载 3010 后由用户实玩确认**。

## 问题与结论

用户问：快速开始／角色选择的纸娃娃预览，与游戏地图／商城预览是否同一套；并反馈快速开始／角色选择的纸娃娃不对。

结论：**是同一套渲染，不是同一份数据**。三处共用同一外观目录（`client/public-tms273/assets/entry/appearance.json`，`assets/manifest.ts:671` 把它装载为 `manifest.appearanceCatalog`）与同一组合函数 `features/entry/appearance.ts::composeAppearance`（同一 z 排序、同一 vslot 遮蔽规则）。差异只在装备入参：

- 游戏地图（`features/player/view.ts`）与商城（`features/cashshop/view.ts`）用角色**当前 equipped 行**组合。
- 快速开始／角色选择（`features/entry/view.ts`）用创角时冻结的 `appearance` 现造 `initialEquipment(look)`（创角四件），因为 lobby `CharacterSummary` 一直只带 `appearance_json`，不带装备。

角色一旦在游戏里换过装备（穿戴、商城时装、GM 发装），大厅预览仍显示创角外观——即用户看到的"不对"。

## 根因修复

- `server/src/lobby.rs`：`CharacterSummary` 新增 `equipped: Vec<InventoryItem>`；`list_characters`／`find_character`（覆盖 list／create／select 三条响应）经 `with_equipped` 在**同一事务内**读 `auth::db::read_equipped_db`（该函数 `pub(super)`→`pub(crate)`；不走 `Store::load_equipped` 以免对已持有的账号库锁重入死锁）。数据源与世界进图时 `store.load_equipped` 完全同源。
- `client/src/features/entry/api.ts`：`CharacterSummary` 增加可选 `equipped`。
- `client/src/features/entry/view.ts::renderPreviews`：角色预览改用 `character.equipped ?? initialEquipment(look)`（旧服务端／离线 stub 无该字段时保持旧行为）；创角草稿预览仍用 `initialEquipment`。两处都补齐与世界一致的 `weaponType` 语义（`appearanceWeaponType`）。
- 穿商城时装的角色：新增 `loadPendingAppearanceLayers`，对 equipped 中"已索引但未装载"的懒加载层先 `loadAppearanceLayers` 再重组合，成功/失败都有缓存防每帧重拉；失败层与世界一致地缺席，不猜测路径。

未动：世界／商城渲染、`composeAppearance` 组合规则、外观目录数据、协议 23 与内容 `tms273-24`（lobby 是 HTTP 加法字段，前后端由启动脚本一起换）。

## 已知边界

- legacy 物化角色在**首次进图前**没有 equipped 行（种子发生在 `load_profile::ensure_starter_equipment_tx`，进图时），此窗口内大厅预览与进图后世界一致地显示裸装基底；进图一次后即自行对齐。新建角色无此窗口（创建即种子）。
