## 2. 技能侧：与已实现分支同一套写法

### 2.1 导出与投影

- `scripts/export_tms273_skills.cjs`：新增 `FOURTH_JOB_BOOKS`（212 / 232）。它们是**目录型**条目
  （不进资产与执行链），但要能渲染图标 ⇒ 必须挂 `_Canvas` 分卷：
  `212 → _Canvas_035.wz + _Canvas_038.wz`、`232 → _Canvas_043.wz + _Canvas_045.wz`。
  漏挂会在导出时报「像素分卷缺失且无已导出产物」（本轮实测过一次）。
- `expectedCatalogCounts` 补 `'212': 24, '232': 27`。
- `scripts/tms273_skill_manifest.cjs`：`SKILL_BOOK_TABS` 补 `'212': 4, '222': 4, '232': 4`
  —— **四转三本共用页签下标 4**（源 `UIWindow2` 只有 7 组页签图，不能顺延）；Hyper 判据由
  「只认 222」改为「四转书 + maxLevel=1 + requiredLevel≥140」；总数断言 `102 → 153`。
- 客户端 `view.ts::BOOK_JOBS` 补 `'212'` / `'232'`（**唯一的书准入权威**）。

### 2.2 服务端

- `mage.rs`：`BOOKS` 补 212/232；`validate()` 的条目数与 Hyper 判据同步；`q` 的判据由 `<= 0` 改为
  `< 0`——源 `2121011` 的 `common.q` 就是 `"0"`，那是**源事实**不是投影错误。新增 212/232 的
  `required(...)` 臂（由留档生成）。
- `world.rs`：与既有槽位同源的两条进具名数组——`2121005 召喚火魔` 进 `MASTERY_SKILLS`（与
  `2221005 召喚冰魔` 同一格 `mastery`）、`2320012 大師魔法` 进 `ELEMENTAL_RESET_SKILLS`（`mdR`）。
- **两格「三分支各一本」的被动改成数组消费**（改前只消费冰雷那一本，另两条分支的玩家凭空少一份属性）：
  - `MAPLE_WARRIOR_SKILLS` = 2221000 / 2121000 / 2321000（`basicStatUp`，四维百分比，**装备折叠前**只乘一次）
  - `MASTER_MAGIC_SKILLS` = 2220013 / 2120012 / 2320012（`madX`，永久魔攻）
  - `attribute.rs` 两处由「单常量」改为 `for skill_id in 数组`，**逐本 `Some(skill_id)` 留痕后求和**
    （分支互斥，角色只可能持有自己分支的那一本，其余查表得 0、`note_nonzero` 不留痕）。
- `INTRINSIC_DURATION_SKILLS` 由 `[2221005]` 扩成 `[2221005, 2121005]`——召喚火魔同样「带 `time`
  却按已学等级读 `mastery`」。这张表记的是**那条字段怎么读**，不是「召唤实体已实现」；召唤实体
  在本包仍无服务端实现（冰魔那套是 `elemental.rs` 里逐条写的）。

### 2.3 为什么改「单常量 → 数组」而不是另开一格

改前 `basicStatUp` / `madX` 只写死 `SKILL_MAPLE_WARRIOR` / `SKILL_MASTER_MAGIC`（都是冰雷那一本）。
只把 212/232 加进**目录**而不改消费，结果是：火毒／主教玩家在目录里看得见楓葉祝福与大師魔法，
学满 30 级／10 级后**属性面板一点不动**。门禁的「源表 == 声明集合」当时就会红（它按字段反推，
不认分支），所以这不是可选项——而改法必须与 `intX` 那几格**同形**，否则留痕就答不出
「这 15% 是谁给的」。

## 5. 「源里有、但本包消费不了」的登记表（本轮新增的门禁机制）

加书之后，源表里新出现 5 个带消费字段的技能。它们的共同根因是：**212／232 的攻击技能在
`handle_cast_skill` 的主分发里落到 `_ => {}`（没有施法分支）**，伤害管线永远不会以这些 skill_id 被
调用 ⇒ 凡是**依附于施法/增益窗**的字段无法消费。

不是漏接线，是它所依附的那条路径还不存在。所以做法是**逐条登记 + 说清理由 + 反向断言**，而不是把
断言放宽：

| 字段 | 技能 | 为什么消费不了 | 登记处 |
| --- | --- | --- | --- |
| `damR` | `2120043` 致命毒霧-強化傷害 / `2120046` 火焰之襲-強化 / `2120049` 地獄爆發-強化加農 | 强化的是 `2111003` / `2121006` / `2121003`，这三招在本包没有施法分支 | `check_tms273_damage_pipeline.cjs::NOT_CONSUMED.damR` |
| `indieDamR` | `2121053` / `2321053` 傳說冒險 | Hyper 主动增益（源带 `time`），另两本没有施法分支 ⇒ 构不成增益窗 | `NOT_CONSUMED.indieDamR` |
| `mdR` | `2321054` 復仇天使 | 同上，`madX` 也一样是窗口值 | `NOT_CONSUMED.mdR` + `check_tms273_attributes.cjs::except` |
| `madX` | `2321054` 復仇天使 | 窗口内的临时魔攻，不是「学得即生效」的被动 | `CONTENT_RULES.madX.except` |
| `asrR` / `terR` | `2320047` 神聖祈禱-抗性提升 | 强化的是 `2311003 神聖祈禱` 的**增益窗内**抗性，本包没有神聖祈禱的施法与增益实现 | `CONTENT_RULES.asrR/terR.except` |

**反向断言**（两个门禁都有）：登记表里每一条都要求「被依附的技能在 `world.rs` 里**没有**常量」。
哪天有人给它起了常量、接了施法分支，门禁立刻红，要求同时把消费补上——而不是静默跳过。
登记表还要求每条都写 `why` / `exceptReasons`，写不出理由就登记不了。
