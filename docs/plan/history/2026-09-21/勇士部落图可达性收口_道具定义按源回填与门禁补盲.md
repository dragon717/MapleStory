## 2. 病根一：启动闸卡在「内容版本号」与「未分发贴图」

`102030100` 本身早在内容里（`shared/maps.json` 已含 211 张图），卡的是**两道启动闸**：

### 2.1 内容版本号四处不同步

沿用既有约定：`CONTENT_VERSION = 'tms273-NN'`，**四处必须同步**——`scripts/assemble_tms273.cjs`
（写清单处）、`shared/protocol.ts`、`server/src/protocol.rs`、`scripts/check_tms273_runtime.cjs`
（默认期望值）。本轮内容确实变了（§4 道具目录），四处统一升到 **`tms273-35`**。

> **协议号 34 未变**：本轮改的只有内容与验收断言，wire 结构一行未动。

### 2.2 传送门闭包把「真实具名地图」误判成缺口

`scripts/check_tms273_portal_closure.cjs --source` 会在源树里强制要求每个 portal 目标**存在**。
但有两张图是**源里真实存在、本包 Map 分卷里没有 `<id>.img` 贴图**：

- `957020004`（病房）← 由 `310010010` 的 portal 指向
- `931060000`（空蕩蕩的房子）

它们不是「漏装」，而是「源包自己没有这张图的分卷」。新增 **`unshippedTargets`** 字段，把这类
目标**显式登记**：门禁报出「未分发贴图」并**停止向下展开/分类**，而不是当成缺口红掉。

```
[portal-closure] 核心判据 PASS：211 图 / 41 个已登记边界
[portal-closure] 源核对 PASS：41/41 条在权威客户端 WZ 里逐条对上门形态与展开分类
[portal-closure] 未分发贴图：957020004（病房）<- 310010010；本包 Map 分卷里没有它的 <id>.img，展开/分类到此为止
[portal-closure] 未分发贴图：931060000（空蕩蕩的房子）＝条目 931060000 自身；本包 Map 分卷里没有它的 <id>.img，展开/分类到此为止
```

**关键点**：这两条是**如实报出并留登记**，不是把它们从判据里删掉——`41 个已登记边界` 就是台账。

## 3. 病根二（真正的大头）：道具定义缺口让商店行被**静默剪掉**

## 4. 三处门禁补盲

这一路踩出的坑，逐个变成**会红的判据**，而不是留在注释里。

### 4.1 防「静默剪枝」复发（`scripts/check_tms273_runtime.cjs`）

在 `expTable` 断言之后新增一段**道具定义覆盖门禁**：

1. 读 `gameplay.sources.items` 台账，取出 `json-missing` 的 id 集合；
2. 断言 `artifacts/tms273_item_definition_backfill.json` 存在，且其 `unresolved` 集合与台账的
   `json-missing` **逐条相等**（`assert.deepEqual`）——**台账里又冒出没人补的缺口就红**；
3. 断言 `written + unresolved.length == targets`（清单自身自洽，防陈旧）；
4. 断言台账里标 `json-present` 的 id **一个都不能缺席** `shared/items.json`。

输出：
```
TMS273 items: 源声明可达 1702 件；无源可补 14 件（逐条留痕于 artifacts/tms273_item_definition_backfill.json）
```

**负向实测**：从清单里删掉一行 → 门禁 exit 1；还原 → exit 0。

> 初版断言写的是 `backfill.json.jsonMissing == missing.length`，实测红了（`actual:171 / expected:14`）——
> 因为 `jsonMissing` 是**当次**的 171，而台账的 `missing` 是**已修掉 157 之后**剩下的 14。改成
> 「`written + unresolved.length == targets`」才是当前该守的自洽式。

### 4.2 `#o<怪物名>#` 标记漏解析（勇士部落警示牌）

13 张勇士部落图装配后，两块警示牌 NPC（`1022116` / `1022117`）的台词里带**怪物名标记**
（`出現怪物 : #o4230400#` / `#o3210100#`），但台词表**双侧**都只认 `#t`/`#i`/`#z` 之类，
`#o#` 原样漏进产物 ⇒ `check_tms273_npc_dialogue.cjs` 红。

修法：`scripts/export_tms273_npc_dialogue.cjs` 与 `scripts/check_tms273_npc_dialogue.cjs`
**两侧同时**补 `#o<id>#` 解析，怪物名读 `shared/mob-names.json`（`String/Mob.json` 的投影）。
修后 PASS：
```
NPC dialogue table: 247/281 templates carry source lines (113 from info/speak, 134 from String/Npc.json),
576 lines, 34 templates have no dialogue in the source; every entry recomputed verbatim.
```
