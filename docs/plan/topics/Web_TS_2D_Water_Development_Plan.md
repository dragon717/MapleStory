# Web / TypeScript 侧视 2D 交互水体开发计划

> 版本：v1.0  
> 整理日期：2026-09-09  
> 前端条件：Web、TypeScript / JavaScript；可采用 Three.js。  
> 交付目标：能起波、能溅水、物品能够自然漂浮或下沉，并具有合理吃水深度和姿态的交互水体。  
> 文档性质：技术选型与实施计划；不是已经完成的程序，也不是实机性能报告。文中的参数和性能数字均为初始建议或验收目标。

---

## 0. 先确定实现路线

**推荐：TypeScript + Three.js + Rapier 2D + 自定义一维动态水面 + 浸没几何浮力 + 粒子水花。**

```text
TypeScript：水面状态、浸没计算、交互事件、参数与测试
Three.js：正交相机、动态水域网格、水下着色、折射、粒子绘制
Rapier 2D：刚体位置、速度、转动、地形和物品之间的碰撞
自定义水体模块：浮力、阻力、水流、物体与水面的相互反馈
```

本计划沿用前文的“横版 / 侧视 2D”理解：物体主要在 XY 平面活动，水面是 `y = H(x, t)`。**不是俯视水面，也不是三维海洋。** Three.js 在这里是渲染工具，不意味着物理必须升成 3D。其正交相机适合不需要透视缩放的场景；Rapier 提供独立的 2D JavaScript / WASM 接口。[R01][R05]

第一版选择“可信的游戏水”，而不是模拟整池流体：

- 水面起伏、物品吃水、倾斜、下沉、入水喷溅必须真实参与交互。
- 大型翻卷浪、倒水、破墙泄洪、液体分裂汇合不属于第一版。
- 水→物体采用准静态浮力与阻力；物体→水采用受限扰动，是**游戏化双向反馈**，不宣称严格的流固耦合、动量守恒或水量守恒。

如果项目已有可用的 2D 刚体系统，优先接入它的施力接口；不要让同一个物体同时由两个物理世界控制。下文以新建独立 Demo、采用 Rapier 2D 为默认路径。

## 1. 产品范围与完成标准

### 1.1 第一版必须实现

| 能力 | 玩家可感知的结果 | 关键实现 |
|---|---|---|
| 自然波浪 | 无人操作时也有轻微起伏，受扰动后能传播和衰减 | 环境波 + 动态高度曲线 |
| 入水反馈 | 轻投与重砸不同，小物件与宽木板不同 | 穿越水面检测 + 分布式冲击 |
| 水花 | 水滴从接触点附近飞出、受重力下落并消失 | 池化粒子 + 批量绘制 |
| 吃水深度 | 轻物体浮得高，较重物体浮得低，过重物体下沉 | 浸没面积与有效密度 |
| 漂浮姿态 | 长木板能倾斜、受力后摆动，不强行贴水平线 | 浮心、质心、力矩、阻力 |
| 水流推动 | 漂浮物逐渐跟随水流，不瞬移 | 相对流速阻力 |
| 水下表现 | 只改变物体水下部分的视觉效果 | 与同一水面对应的遮罩 / 网格 |
| 稳定运行 | 切换刷新率、暂停恢复、连续投物不会数值爆炸 | 固定物理步长、限幅与回归测试 |

### 1.2 第一版主动不做

不做 SPH / FLIP 主求解器、动态水体拓扑、倒水和容器灌满、三维浮力、精确流体压强场、复杂流体升力、真实气泡体积和表面张力。也不默认实现完整游泳角色控制；角色接入单独处理。

固定水位是第一版设定。物体放进水里，不会自动让整池平均水位上升。需要这个玩法时，再增加“有限容器水量”模块，不能把当前波浪数组误称为守恒水量模型。

### 1.3 可交付演示场景

同一页面提供一池水、岸边和水底，至少支持木块、长木板、石块、偏心物体四种样例。用户可投放、拖拽、暂停、单步、重置，调整密度、水流、波浪和阻尼；可打开碰撞轮廓、浸没区域、浮心与力箭头。

验收先看关闭 Shader 后的纯色物理场景，再看最终视觉场景。不能用折射和粒子掩盖吃水位置错误。

Three.js 当前 `WebGLRenderer` 使用 WebGL 2；这里不承诺 WebGL 1 支持。Rapier compat 包把 WASM 嵌入 JS，并仍需要等待初始化完成。[R02][R05] Vite、Vitest、Playwright 的具体接入以对应官方文档为准。[R15][R16][R17]

**版本管理要求：**接入时核对已有 Node / 构建环境，选择互相兼容的版本并固定到 lockfile；提交实际版本清单。不要在文档里凭印象填一个“最新版”，也不要为水体功能擅自升级整个旧工程。

**不把 Three.js `Water` 当作物理水插件。** 官方将其描述为平面反射水效果；本计划的动态轮廓、浮力、水花仍需单独实现。[R03]

第一版不引入 React Three Fiber、WebGPU、Worker 或额外状态管理框架作为前置条件。已有项目使用这些技术时可以复用，但水面模拟不应依赖 UI 组件的刷新周期。

```text
      ├── BuoyancySystem：浮力、阻力、作用点
      ├── PhysicsAdapter：提交受力并推进 Rapier 2D
      └── WaterInteraction：穿水检测、波浪扰动、水花事件

                        ▼

                        │

```

### 3.1 必须坚持的边界

`SurfaceField` 是水面几何的唯一事实来源。浮力、水花、水下判定和渲染都不能维护另一条独立水线。Shader 可增加高光噪声，但不能自行生成会改变可见轮廓、却不被物理读取的大波浪。

模拟层不 import Three.js，不读取 DOM，不访问渲染对象的位置。渲染层不能回写动态刚体位置。水面计算先放主线程，保留以后迁移 Worker 的数据边界，但不为尚未测出的瓶颈增加线程复杂度。

## 4. 坐标、质量与几何契约

### 4.1 统一坐标和时间

| 量 | 约定 |
|---|---|
| 世界 X | 向右为正 |
| 世界 Y | 向上为正 |
| Three.js Z | 仅负责显示层级，不参加 2D 受力 |
| 长度 | 世界米；显示缩放由相机处理 |
| 时间 | 秒；物理使用固定 `dt` |
| 角度 | 弧度，逆时针为正 |
| 重力 | 默认 `(0, -9.81)` |
| 初始显示比例 | 可从约 64 CSS 像素 / 世界米开始调节，不属于物理常量 |

鼠标 / 触摸坐标必须先转换到世界坐标，不能把 CSS 像素直接作为物理米。贴图锚点与刚体本地坐标通过固定偏移映射；不能因为图片透明边缘而移动物理质心。

### 4.2 使用二维有效密度

本计划统一采用面密度 `density2D`，单位是 kg/m²，相当于把统一厚度包含进密度：

```text
物体质量 = 物体有效面密度 × 物体排水轮廓总面积
排开水的质量 = 水的有效面密度 × 浸没面积
```

示例采用水 `1.0`、轻木块 `0.55`、石块 `2.7`，只表示归一化游戏参数，不表示这些材质的真实三维密度。

**质量只能有一个来源。** 选择由碰撞体密度产生质量，或显式设置总质量和惯量；不要再无意叠加同等的 additional mass。通过调试面板核对 Rapier 实际返回的质量。Rapier 的 additional mass 会与碰撞体质量相加。[R06]

浮力应与世界重力对应。给个别物体设置非标准 `gravityScale` 会改变平衡比例，不能仍按简单密度比例验收。

### 4.3 区分图片、碰撞轮廓、排水轮廓

图片边界不是排水轮廓，AABB 也不是浸没面积。第一版只支持矩形和凸多边形；圆形可用足够细的凸多边形近似，面积误差纳入测试。

排水轮廓允许独立于碰撞轮廓：多个碰撞 fixture 可能重叠，不能把它们的浸没面积重复相加。复合物体必须提供不重叠的排水分块，或先完成几何并集。瓶子、船体等空心对象需要明确封闭外轮廓和质量，不能直接拿视觉外壳材质密度计算。

## 5. 动态水面的实现规格

### 5.1 数据模型

把水域横向分成 `cellCount` 个单元，维护 `cellCount + 1` 个节点。每个节点至少保存交互位移 `eta`、交互竖直速度 `u`。数组使用 `Float32Array`，初始化后复用。

```text
H(x, t) = baseLevel + ambient(x, t) + eta(x, t)
ambient(x, t) = Σ A_j × sin(k_j × x - omega_j × t + phase_j)
```

先在 CPU 的水面节点上计算环境波，再与 `eta` 相加。节点之间用分段线性插值：浮力、接触位置和渲染轮廓必须采用同样的插值，不能渲染用平滑样条、物理仍用折线。

弹簧 / 邻接传播是已有社区方案；本文的参数化方程、工程接口与测试要求是建议实现，不是直接照搬某个引擎插件。[R08][R09]

### 5.2 更新方程与稳定性

建议从带回弹的线性波模型开始：

```text
L_i = (eta[i-1] - 2*eta[i] + eta[i+1]) / dx²
a_i = c²*L_i - omega0²*eta[i] + externalAcceleration[i]
u_next[i] = (u[i] + a_i*dt) * exp(-damping*dt)
eta_next[i] = eta[i] + u_next[i]*dt
```

先根据旧数组统一算加速度，再更新速度与高度。不要一边从左向右覆盖高度，一边用已经改过的邻居计算后面的节点，否则会引入顺序偏差。

初始使用 `dt = 1/120 s`。为该线性离散模型设置保守参数检查：

```text
dt * sqrt(omega0² + 4*c²/dx²) <= 1
```

这是本计划建议的数值安全余量，不是对全部非线性耦合的稳定性证明。它提醒开发者：节点更密或传播速度更快时，必须重新检查步长，而不是只增加节点数量。

水波达到安全边界或出现 NaN 时，应记录诊断并恢复最近有效状态；限幅是保护机制，不是掩盖持续失稳的正常工作方式。

### 5.3 边界条件

封闭水池先采用反射边界，边界法向导数近似为零。开放河段增加吸收区，逐渐加强边缘阻尼。水池物理岸壁仍由 Rapier 的固体碰撞体处理。

水位和最大扰动幅度必须保证水面不穿过水底。第一版不处理干湿交界迁移、浪头翻卷或越岸溢出；所有 `x` 查询越界应返回明确的“无水”结果，不能 clamp 后把岸外误判为水里。

### 5.4 水面运动不等于水流

提供独立的 `fluidVelocityAt(x, y)`，不把波峰传播速度当作物品漂移速度。第一版流场是游戏设定的背景流，不求解真实内部流动。

需要表面附近的相对速度时，可采用满足表面运动关系的近似：

```text
surfaceNormal = normalize(-dHdx, 1)
velocityAtSurface.x = currentX
velocityAtSurface.y = dHdt + currentX*dHdx
```

水下的竖直扰动按深度衰减，水平流速按配置采样。这仍是用于交互的近似流场，不保证不可压缩或完整水动力学。

## 6. 浮力与合理吃水位置

### 6.1 主方案：浸没轮廓求交，而不是中心点判定

对每个候选物体：

1. 将排水轮廓变换到世界坐标，用 AABB 只做候选过滤。
2. 找出其横向覆盖的水面单元。
3. 每个单元的水域是一个由两端波高和水底组成的梯形。
4. 将凸轮廓与该梯形裁剪，得到浸没片段。
5. 计算各片段面积 `A_k` 和形心 `C_k`。
6. 汇总总浸没面积与面积加权浮心。

```text
A_sub = Σ A_k
C_buoyancy = Σ(A_k*C_k) / A_sub
F_buoyancy = -densityWater2D * A_sub * gravityVector
```

在没有其他水动力项的情况下，各片段向上浮力的合力，可以施加在总浮心。**浮力方向取重力反方向，不取倾斜水面的法线方向。** 动态波浪上的这一步是准静态近似，不包含全部动态压强效应。

交叠面积与形心求浮力的基本思路可参考 iforce2d。[R10] 这里将水平水域扩展成分段梯形，是适配本计划动态水面的工程设计。

### 6.2 几何函数的实现要求

`polygon.ts` 提供凸多边形半平面裁剪与面积 / 形心函数。处理空多边形、共线边、贴边、很小面积、顺逆时针和退化片段；统一顶点绕序，并使用与场景尺度匹配的 epsilon。

第一版可以使用小数组清晰实现，确认正确后再改为复用缓冲区。优先检查浸没面积是否落在 `[0, totalArea]`，越界超过误差预算要报告，不能随意截断掩盖重复计数。

水域之间第一版要求互不重叠。未来允许重叠时必须定义归属或几何分区；不能在两个水区对同一块面积重复施加浮力。

### 6.3 为什么物体会停在正确位置

在静水、标准重力、均匀实体且没有接触支撑的条件下，平衡要求：

```text
densityWater2D * A_sub * g = mass * g
A_sub / A_total = densityBody2D / densityWater2D
```

这是由本计划质量与浮力定义推导出的验收关系。密度比是 0.55，目标是约 55% 截面积浸没，**不是所有形状都刚好下沉 55% 高度**。有效密度超过水的物体应下沉；有效密度恰好相等的理想物体没有唯一稳定深度，不应强行吸附水面。

### 6.4 姿态与质心

浮力通过浮心施加，重力通过质心作用，两者的偏移自然形成力矩。Rapier 提供世界坐标下的指定点施力与点速度查询接口。[R06]

不要每帧把物品旋转插值回零度。稳定姿态取决于形状和质量分布，并不是所有物体都应横着漂。偏心样例应通过真实质量属性体现质心偏移，而不是只移动图片。

对于只需轻量漂浮的小掉落物，后续可用多个面积加权采样点替换几何裁剪，但要比较吃水误差。不能每加一个采样点就多加一份完整浮力。

## 7. 阻力、水流与受力提交

### 7.1 阻力使用相对点速度

对浸没片段形心 `C_k`，取刚体该点的速度，包含旋转分量：

```text
r = C_k - centerOfMass
v_point = linearVelocity + (-angularVelocity*r.y, angularVelocity*r.x)
v_relative = v_point - fluidVelocityAt(C_k)
F_drag,k = -dragRate * densityWater2D * A_k * v_relative
```

`dragRate` 的量纲为 `1/s`。这是优先保证稳定、易调的线性游戏阻力，不是精确迎流面阻力模型。阻力施加到对应片段形心，能够参与力矩计算。必要时补充适量、与浸没比例相关的角阻尼，但避免与分布式阻力重复叠加过强。

静水中的相对运动应逐渐衰减；有水流时物品应逐渐追随流场。水流通过相对速度进入同一套阻力计算，不再额外叠加一个不受限的“向右推力”。

### 7.2 防止显式阻力过强

高速、轻物体、大阻力组合需要子步或按作用点有效质量限制阻力冲量。同一物体多个片段的限制必须联合考虑，不能每个片段独立获得一整份最大制动力。

把“静水下阻力持续产生正功”“速度一帧反向且放大”“力矩持续增大”列为数值诊断。先降低系数或增加稳定性处理，不能靠把物体位置锁住解决。

### 7.3 明确 Rapier 力的生命周期

Rapier 的用户施加力会跨模拟步持续存在，不会因为调用一次 `world.step()` 自动清零。[R07]

本项目采用统一的 `ForceAccumulator`：每个物理步开始时，由物理适配器清除上一轮用户力与力矩；游戏逻辑、浮力、阻力依次提交本步贡献；最后统一调用 Rapier 施力和 `world.step()`。

**水体模块不能自行调用 `resetForces()` 去清掉其他玩法刚刚提交的力。** 若现有工程采用另一种受力管理方式，要在适配层转换，而不是改变全局契约。

连续力不预乘 `dt` 就交给 `addForceAtPoint`；只有采用冲量接口时才将 `F*dt` 作为冲量。不能乘两次 `dt`，也不能把力值当每步冲量直接提交。

## 8. 入水、水花与物体反向影响水面

### 8.1 检测真实穿水，而不是只看传感器事件

矩形水域传感器或 AABB 只能用于粗筛。真正的入水事件要结合物体前后两步轮廓和前后两步水面，检测从空气进入水的穿越。

第一版针对凸多边形做扫掠检测：先用 swept AABB 找水面单元，再检查运动轮廓与分段水线的接触；复杂旋转可以在本固定步内增加几何检测子采样。只检测物体中心或只比较步末的浸没比例，都可能漏掉高速、浅水和擦水事件。

至少覆盖以下情况：小物体从两个水面节点之间落入；宽木板同时覆盖很多节点；物体一物理步穿过很薄的水层；初始生成就在水下；波峰轻微反复掠过漂浮物。

刚体的 CCD 可以用于防止穿越固体水底，但不能替代自定义动态水面的穿越检测。

### 8.2 接触状态与喷溅门槛

每个 `bodyId + waterId` 维护接触状态、上次浸没比例、离水间距、上次大水花 tick。使用不同的入水 / 离水阈值和短冷却，防止水线抖动不断触发。

```text
首次注册且已在水中 → 初始化 Wet，不生成一次“凭空入水”水花
Dry → 有向下穿水，速度达到门槛 → 生成一次主要入水事件
Wet → 小幅上下摆动 → 小波纹或泡沫，不重复主要水花
Wet → 明确离水并满足重置条件 → Dry
Dry → 再次真实入水 → 可生成新的水花
```

相对入水速度按接触点计算：

```text
v_enter = max(0, -dot(v_bodyAtContact - v_waterAtContact, surfaceNormal))
```

阈值按物体尺寸和场景尺度调节；不能只用一个固定面积阈值过滤掉所有小物件。

### 8.3 水面冲击分布

在实际接触覆盖区内，向多个节点分配扰动。分布权重总和必须为 1，小物件位于节点之间时至少覆盖最近的相关节点。按物体宽度分配入水冲击的思路可参考 prime31。[R09]

建议对外以总波浪冲量表示一次扰动，而不是“每个节点加同样速度”：

```text
J_wave = 经过幅度与能量预算限制的总竖直冲量
alpha_i = 第 i 个受影响节点的归一化权重，Σ alpha_i = 1
M_i = densityWater2D * effectiveDepth * quadratureWidth_i
Delta_u_i = alpha_i * J_wave / M_i
```

`effectiveDepth` 是波面模型的等效参与深度，不是额外排水面积；端点的积分宽度也应合理处理。这样改变采样密度时，不会因为节点变多而直接多出几倍总冲量。

入水扰动初始方向通常向下；传播由波面方程产生。对一次事件，检查新增的波浪动能，并给出相对物体入水动能的可调预算。此预算用于抑制夸张反馈，**不意味着完整系统已经能量守恒**。

### 8.4 持续互动与防止自激

初版先只加入主要入水扰动。稳定后，再把水面附近的部分阻力反作用映射成连续波面作用；其冲量必须按 `force * dt` 积分。深水里的物体不要直接每帧在水面生成大浪。

禁止把静态浮力反作用每步当成新的喷溅冲量，否则漂浮物即使静止也会持续泵入波浪。主要入水事件与持续反馈共用限幅预算，避免同一接触重复放大。

### 8.5 粒子水花

水滴使用 CPU 粒子池做弹道更新、GPU 批量绘制，不给每个水滴创建 Rapier 刚体。

每次喷溅根据入水位置、法线、相对速度、物体宽度和预算设置粒子数量、两侧喷射角、初速度、尺寸和寿命。轻投只有少量水滴，大而快的物体有更宽的喷溅。

水滴回落时读取同一水面快照。可产生弱二次波纹，但二次事件不再生成下一代大水花，防止粒子递归增殖。粒子、泡沫和事件队列都有硬容量；超额时丢弃低优先级视觉事件，不丢失物品的物理状态。

## 9. 固定步长与快照时序

### 9.1 模拟与显示解耦

初始物理频率固定为 120 Hz，渲染跟随 `requestAnimationFrame`。这是一项待基准验证的初始选择，不是要求屏幕也运行 120 FPS。

浏览器的动画回调会随显示刷新率变化，并可能在后台暂停；因此不能一帧固定推进一个假设为 60 Hz 的物理步。[R12] 固定步长加累积器和插值的组织方式可参考 Gaffer。[R11]

### 9.2 每个物理步的权威顺序

```text
已知时刻 n 的刚体状态、水面状态
  1. 保存旧快照，处理本 tick 输入与上一 tick 排队的波浪冲量
  2. 基于时刻 n 的物体轮廓和水面计算浸没、浮力、阻力
  3. 汇总本步所有刚体力；汇总需要加入水面的连续作用
  4. 刚体与水面各推进一次 dt，得到时刻 n+1 的状态
  5. 用 n / n+1 两个状态做穿越检测，生成接触事件
  6. 新的主要入水波浪冲量排队到下一步；生成水花记录
  7. 发布新的模拟快照，更新诊断统计
```

这是显式分步耦合，主要入水扰动最多延后一个物理 tick，不回头修改已经积分完的刚体。先保证顺序可解释、可回放，再考虑更复杂的预测或迭代耦合。

显示层对物体、水面和粒子使用同一显示时间。禁止物体读取插值位置、水面读取最新位置、环境波又按 `Date.now()` 单独计算。

### 9.3 主循环伪代码

```text
每次 requestAnimationFrame：
  读取真实帧间隔；裁剪异常的大间隔
  accumulator += frameDelta
  steps = 0

  while accumulator >= fixedDt 且 steps < maxCatchUpSteps：
    simulation.step(fixedDt)
    accumulator -= fixedDt
    steps += 1

  如仍有超过一个物理步的积压：
    记录 droppedSimulationTime
    按当前应用策略丢弃超额整步积压或进行权威状态重同步

  alpha = accumulator / fixedDt
  render(previousSnapshot, currentSnapshot, alpha)
```

独立 Demo 可以丢弃过量积压以防追帧失控，并明确记录模拟时间落后。联网项目不能静默这样做：必须服从原有服务器时钟和状态恢复规则。固定步长与种子也不自动等于跨浏览器、跨版本的逐位确定性。

页面隐藏时，独立 Demo 暂停；恢复时清理真实时间积压并重建插值前后态，不补算整个后台时长。是否隐藏通过 Page Visibility API 处理。[R13]

## 10. Three.js 渲染实施

### 10.1 最先完成的低成本版本

使用 `OrthographicCamera`，场景主要放在 XY 平面。水域为一条从动态水面延伸到水底的三角形带：每个水面节点对应上、下两个顶点，索引初始化一次。

每帧只更新动态属性并标记需要上传。`BufferGeometry` 用于维护顶点与索引，动态 `BufferAttribute` 的 usage 在首次使用前设置；不要每帧重建 geometry 或 material。[R04]

先绘制背景和物品，再绘制半透明水域、表面亮线和水花。水域自身的轮廓就是遮罩，水上部分不染色。这个版本无需折射 RenderTarget 即可验收物理。

### 10.2 增强版折射流程

```text
Pass A：将允许被水影响的背景和物品渲染到 SceneColorRT，不包含水本身
Pass B：将 SceneColorRT 显示到最终画布
Pass C：绘制动态 WaterMesh，在水域内采样 SceneColorRT 并做着色 / 轻微折射
Pass D：绘制表面亮边、接触泡沫、水花、明确位于前景的对象与 UI
```

Three.js 提供 RenderTarget 与 ShaderMaterial 作为这些步骤的基础。[R14][R18]

必须避免读取正在写入的同一个 RenderTarget。若水 Shader 已把背景、折射与水色混合成最终像素，就采用明确的覆盖输出，不再额外做一次重复透明混合。若选择透明输出路线，也要统一混合公式，不能两套混着用。

物体位于水面前后的关系由渲染层分类决定，而不是仅靠透明物体自动排序猜测。水面高光宽度可用屏幕像素控制，物理轮廓仍按世界坐标。

### 10.3 视觉一致性和资源管理

环境波和交互波都从同一个插值快照生成网格。折射强度、法线噪声等纯视觉参数不参与物理；微小 Shader 细节不能把主水面轮廓再次移动。

水滴用实例化四边形，复用几何和材质；Three.js 的实例化网格适合共享几何 / 材质的多实例绘制。[R19] 第一版可用单种水滴材质，复杂透明排序不是前置要求。

相机缩放、窗口 resize、DPR 改变时，同步更新相机投影和 RenderTarget 尺寸。动态网格设置保守包围盒或更新边界，避免波浪被错误裁剪。销毁场景时释放独占的几何、材质、纹理、RenderTarget、事件监听与动画回调；共享资源不能被提前释放。

## 11. 关键 TypeScript 接口草案

以下是模块间的数据契约，不是完整可运行实现。所有查询必须知道使用的是哪一个 tick 的快照。

```ts
export interface Vec2 {
  x: number;
  y: number;
}

export interface WaveConfig {
  cellCount: number;
  waveSpeed: number;       // m/s
  restoringOmega: number;  // 1/s
  damping: number;         // 1/s
  maxDisplacement: number; // m，异常保护阈值
  effectiveDepth: number;  // m，波面扰动等效质量参数
}

export interface WaterConfig {
  id: string;
  xMin: number;
  xMax: number;
  bottomY: number;
  baseLevel: number;
  density2D: number;       // kg/m²
  currentX: number;        // m/s
  dragRate: number;        // 1/s
  boundary: "reflect" | "absorb";
  wave: WaveConfig;
}

export interface SurfaceSnapshot {
  tick: number;
  waterId: string;
  xMin: number;
  dx: number;
  bottomY: number;
  heights: Float32Array;   // 包含环境波后的最终高度
  heightRates: Float32Array; // 对应的 dH/dt
}

export interface SurfaceSample {
  height: number;
  slope: number;
  heightRate: number;
  normal: Vec2;
}

export interface SubmergedFragment {
  area: number;
  centroid: Vec2;
}

export interface SubmersionResult {
  bodyId: number;
  waterId: string;
  totalArea: number;
  submergedArea: number;
  buoyancyCenter: Vec2 | null;
  fragments: readonly SubmergedFragment[];
}

export interface ForceAtPoint {
  bodyId: number;
  force: Vec2;
  point: Vec2;
  source: "buoyancy" | "water-drag" | "gameplay";
}

export interface SplashEvent {
  id: number;
  tick: number;
  waterId: string;
  bodyId: number;
  position: Vec2;
  normal: Vec2;
  entrySpeed: number;
  contactWidth: number;
  visualBudget: number;
}

export interface WaveImpulse {
  waterId: string;
  targetTick: number;
  xMin: number;
  xMax: number;

}
```

`SurfaceSnapshot` 中的数组按只读借用契约使用：外部不能修改，求解器也不能在消费者仍读取时覆盖它们。主线程先用明确的前后双缓冲；未来使用 Worker 时再定义快照传输和缓冲归还协议。

公开查询建议采用 `sampleSurface(snapshot, x, out): boolean`；范围外返回 `false`。不要返回一个伪造的高度，让调用方误判岸外有水。

## 14. 测试与验收规格

### 14.1 数学与物理回归

以下误差数字为建议验收阈值，应在首个基线实现后记录是否需要调整，不能未经测量宣称已经达到。

| 测试 | 输入条件 | 期望 |
|---|---|---|
| 完全干燥 | 物体在水上或水区横向范围外 | 浸没面积和浮力为零 |
| 完全浸没 | 凸多边形完全在水中 | 面积等于轮廓总面积；形心正确 |
| 水平半浸没 | 规则矩形被水平水线等分 | 浸没面积相对误差不超过 `1e-4` |
| 旋转裁剪 | 多种角度、贴边、共线、非常薄的片段 | 面积非负、不超总面积；无 NaN |
| 浮力比例 | 静水、无接触，密度比 0.2 / 0.55 / 0.8 | 收敛后的浸没比例绝对误差目标不超过 0.02 |
| 中性浮力 | 有效密度比 1，完全浸没 | 不被强行拉回表面；静止时合力近零 |
| 高密度物体 | 有效密度比 2.7 | 下沉，不因水面阈值变成“悬浮” |
| 偏心姿态 | 相同外形、不同质心 | 平衡姿态由受力变化，不共用固定旋转值 |
| 阻力耗散 | 静水，给定初始线 / 角速度 | 运动总体衰减，无持续增能 |
| 波浪衰减 | 无环境驱动、无物体反馈，施加一次扰动 | 振幅包络衰减，不要求离散每一帧能量严格单调 |
| 节点密度变化 | 同物理宽度和总冲量，改变节点数 | 总注入冲量一致，波形随细化收敛 |
| 复合形状 | 多 fixture，但非重叠排水轮廓 | 不重复计算排水量和浮力 |

对较细的圆形近似轮廓，单独记录面积误差；它不能混进“精确几何已通过”的报告。测试平衡深度时关闭环境波、水流与碰撞支撑，并确认已经进入低速度状态，而不是取任意一帧位置。

### 14.2 交互、时序与画面回归

| 测试 | 通过条件 |
|---|---|
| 物体小于水面间距 | 落在节点中间仍有入水反馈 |
| 宽木板入水 | 扰动覆盖实际接触范围，而非单个节点 |
| 高速穿薄水层 | 即使步末已经离开水域，也检测到真实穿越 |
| 初始在水中 | 不产生无来源的主要入水水花 |
| 长期漂浮 | 不因波峰反复掠过而一直触发大水花 |
| 同 tick 事件重放 | 相同事件不会重复消费；删除对象后无悬空引用 |
| 30 / 60 / 120 Hz 显示 | 在相同模拟 tick 比较状态；不因显示帧数改变受力 |
| 后台停留再恢复 | 不补算巨量积压，不生成爆炸波浪 |
| 缩放、DPR 和 resize | 接触位置、水下边界与显示保持一致 |
| 多次创建 / 销毁 | 资源与监听不持续累积；计数回到预期基线 |
| 长时压力场景 | 持续投放 / 回收对象和水花，容量受控，无 NaN |

纯模拟测试使用固定输入 tick 和随机种子。同版本、同环境先比较严格结果；跨浏览器比较带容差的行为性质，不对含复杂碰撞的长轨迹强行要求逐位相等。

UI 与自动化可用 Playwright 的浏览器项目运行 Chromium、Firefox、WebKit；移动视口模拟不能代替真实手机的 GPU、内存与触摸验证。[R17]

### 14.3 最终视觉检查

并排录制低速轻投、高速重砸、长木板、偏心物体和连续投放。分别打开纯色调试模式与最终视觉模式。重点检查“物理浮得对”和“视觉像浸在水里”是否同时成立，而不是只截取最漂亮的一帧。

## 15. 性能预算与降级顺序

### 15.1 待实测的目标档位

| 项目 | 桌面基线目标 | 低性能 / 移动候选目标 |
|---|---|---|
| 渲染帧率 | 60 FPS | 优先 60 FPS，必要时接受 30 FPS |
| 活跃水区 | 3 个，每个约 257 节点 | 1–2 个，每个约 129 节点 |
| 活跃漂浮刚体 | 32 个简单凸轮廓 | 16 个简单凸轮廓 |
| 同屏水滴容量 | 1000 | 256 |
| 基准渲染尺寸 | 1920×1080 实际渲染像素 | 1280×720 或更低实际渲染像素 |
| 水体模拟及其刚体 CPU 开销 | 60 FPS 下，每显示帧合计 p95 目标 ≤ 4 ms | 记录实测后确定 |
| 折射 | 可选；降低 RT 分辨率 | 默认关闭或半分辨率 |

这些是测试场景容量与预算，**不是浏览器兼容性承诺或已获得的性能结论**。基准报告必须注明设备、操作系统、浏览器版本、提交版本、实际像素尺寸、DPR、实体数量、物理子步数和测量时长。

优先记录完整帧间隔、CPU 模拟分项、draw call、粒子与实体峰值。GPU 时间需要对应测量手段，不能直接拿 CPU 提交渲染命令的耗时冒充 GPU 渲染耗时。

### 15.2 优化先后次序

先复用几何 / 材质 / 数组和粒子池，再做空间粗筛，仅裁剪物体覆盖的水面单元。进入宽水区前，不扫描其所有节点。通过 profiling 发现热点后再改复杂数据布局或线程模型。

优先降级视觉：降低 DPR 上限、折射 RT 尺寸、粒子数量、泡沫细节。不要第一反应就减弱浮力、跳过正在互动的物体，或用平水面替代它们看到的动态水面。

降低节点数或物理频率属于改变模拟，应预先验证稳定性和精度，以场景配置切换并重建相关状态；不要无校验地在运行中随 FPS 改来改去。对权威玩法尤其不能让不同客户端因为画质不同而采用不同的受力规则。

### 15.3 何时使用 Worker

只有在主线程模拟明确超预算时，再把水面、几何与 Rapier 整体迁移 Worker。主线程保留绘制，传输紧凑的 tick 快照和事件；不要把刚体与水面分别放在线程两侧，每步再互相等待。

普通消息或可转移缓冲先验证即可。不要为了很小的水面数组把 SharedArrayBuffer、复杂同步与部署限制变成第一版前置需求。

休眠应考虑水流、邻近扰动和碰撞唤醒。一个仍然参与玩法的离屏物体不能仅因摄像机移走就停止受力；纯装饰水体可另行降级。

## 16. 接入现有游戏时的约束

**主循环：**复用项目原有调度，水体作为子系统推进，不新建一个与主循环竞争的 RAF。保留原有启动脚本、构建方式、相机和资源管理策略。

**实体生命周期：**创建 / 删除物品时同步注册 / 注销排水轮廓、接触状态、调试数据和待处理事件。使用稳定的业务 ID，不把会失效的物理句柄当永久业务身份。

**角色：**动态物理角色可接入受力；运动学或自定义控制角色应读取浸没比例与流速，通过其移动控制器实现游泳。不能期待给运动学角色调用普通浮力后就自动获得正确游泳行为。

**网络：**纯装饰水花和非玩法波纹可由客户端生成。能推动关键物品、支撑玩家或改变碰撞结果的水体必须明确权威计算归属；不能让每个客户端自行模拟并直接覆盖服务器位置。同步种子和配置并不足以保证跨版本完全一致。

**发布：**功能开关可关闭水体表现或整个实验水区；加载失败有清晰错误，不静默展示一个看似运行却没有物理的水池。测试本地开发包与生产构建，不只验证 dev server。

## 17. 后续扩展及升级触发条件

| 新需求 | 后续路线 | 不应采用的补丁 |
|---|---|---|
| 物体放入容器导致水位上涨 | 添加有限水量约束；求解扣除排水面积后的水域面积 | 随便给每次入水增加固定水位 |
| 多种液体 | 参数化密度、阻力与外观；明确液体交界 | 在同一区域重复施力 |
| 大量小装饰物 | 面积加权采样近似，建立与精确模式的误差对照 | 每件物体绑定水面高度 |
| 游泳玩法 | 角色状态、输入响应、浸没比例和水流整合 | 把刚体道具浮力原封不动套给角色控制器 |
| 船、封闭容器 | 合理排水外形、总质量、质心；按需考虑进水 | 把船壳材质密度直接当整船有效密度 |
| 倒水、泄洪、液体分裂 / 汇合 | 独立评估 FLIP / SPH 等完整流体路线 | 在单值高度曲线上不断堆特殊分支 |

真正进入完整流体时，可先研究 Ten Minute Physics 的浏览器 FLIP 示例与源码，重新评估求解、刚体双向作用、渲染与性能，而不是把整个示例直接当可替换生产插件。[R20]
