## 0. 开发目标与成功定义

**完整方向：死亡留下墓碑与罕见虚影 → 虚影帮助／危及后来者 → 经验球承接真实怪物经验 → 虚影演化 → 独立NPC → 与玩家共同参与天命资格与位置竞争。**

本计划不把未来功能删除，但必须区分每一阶段的真实交付。只画出墓碑不能叫“死亡世界系统完成”；只给NPC一个称号不能叫“天命接入完成”；只有技术框架没有可玩内容也不算体验闭环。

最先完成可靠的死亡事实，其次完成后来者能亲身遇见的完整因果。融合与觉醒在此之后引入，避免为了远景先把奖励系统、NPC与整个世界重写一遍。

## 4. 工作包详情

每张卡都需要在实际执行时补入负责人、基线差异、实际改动文件与真实验证结果。下列“验收”是要求，不是已经取得的结果。

### D00｜冻结基线、保护范围与实际入口

**输入：**三份专题文档、当前HEAD、工作区状态、AGENTS／长期规范／当前PLAN。

**动作：**只读检查本地未提交改动；核对运行服务与数据库保护说明；定位所有致死、复活、怪物生命结束、奖励与账号解析入口。对照固定提交记录漂移，不回滚用户改动。

**输出：**当前PLAN中的任务入口与负责人；受保护定制清单；致死来源矩阵；奖励写入矩阵；真实账号和角色ID说明；不涉及在线服务的验证方式。矩阵是本任务证据，不另开第四份活动台账。

**验收：**每个会产生正式死亡的路径都有“统一入口／新增适配／明确排除”；所有能向试点怪物造成伤害的路径有唯一结算路由。未知项不得写“已有统一实现”。

**不做：**启动或停止3010、清库、重跑历史全套QA、全仓格式化。

### D01｜绑定真实地图、脚点、怪物与素材

**依赖：**D00。

**动作：**从当前装配结果选择可隔离的公共试点范围。已核到代码含`windbell-bridge`及共享桥范围，可作为查找入口，但不是本文件授权直接开启危险的生产地图；不能伤及已有桥梁恢复体验。[R15]

**输出：**一张可机器校验的内容绑定卡，至少包含 mapTemplateId、真实mapInstance规则、允许区域、合法展示脚点、排除保护区、参考怪物基础经验、允许spawn/template、墓碑／幽魂／虚影／球资源引用及源证据；新增`shared/death-world.json`的对应内容。

**验收：**无虚构坐标、模板和占位安装资源；球落点可到达；墓碑不挡门、不挡主线NPC；参考怪物无治疗／复活／任务关键奖励。原图不足时明确缺失，先在测试夹具验逻辑，不把占位图当正式资源。

**不做：**为方便测试把风铃桥重置成未修、把公共地图变成每人不同物理状态、重写地图装配工具。

### D02｜冻结领域、范围、协议与迁移契约

**依赖：**D00；内容字段与D01协同。

**动作：**落实技术文档INV-01—14；明确death_id复用、真实账号排除、world scope、类型化行动者、唯一奖励键；冻结P1/P2字段和按阶段启用的协议；制定新旧奖励行兼容迁移。

**输出：**Rust／TS同源契约、配置schema、持久表与索引设计、错误码与请求指纹规则、每个共享文件唯一写入者。以当前HEAD选择版本，不硬套旧协议号。

**验收：**虚影没有玩家连接；球没有假itemId；所有范围比较包含真实实例；Store内部helper不嵌套公共事务；全局开关关闭时旧流程不变。

**定向检查：**T10、T35相关schema／验证器的测试设计；本阶段不伪称运行行为已通过。

### D03｜原子死亡事实、墓碑与抽取窗口

**依赖：**D01、D02。

**主要改动：**新增死亡domain／world／Store模块与增量迁移；在经D00确认的致死入口传入类型化原因，构造DeathPlan并一次提交。

**输出：**正式死亡记录、独立墓碑、出生决策、账号区域窗口与可恢复投影。P1明确保存`feature_disabled`，不预生一批升级后补抽的虚影。

**验收：**重复致死只有一次事实；任意持久化失败不会只剩玩家HP0或只剩碑；无法落点有明确降级；保护区与Administrative不产生经济价值；普通历史经验／装备规则不被改变。

**测试：**T01、T02、T03、T07、T08、T09。所有DB用例在临时库执行。

**回滚：**关闭新生成，保留已提交事实；迁移不做破坏性down回滚。

### D04｜复活、重连、到期与崩溃恢复

**依赖：**D03。

**主要改动：**读取并必要时收束完整Store复活事务；补齐最终复活候选、回执与内存应用关系；重启恢复有效死亡痕迹及已到期处理。

**输出：**旧death请求无法复活新death；复活后墓碑独立；断线／换图不删世界状态；时钟与配置版本恢复规则。

**验收：**特别覆盖`complete_revive`末尾持久化失败；旧回执不变成新死亡的成功命令；重启不刷新30分钟墓碑期限；成功死亡判定不再重抽。

**测试：**T04、T05、T06、T15中的期限子集、T36。

**不做：**顺手改变复活HP/MP、增加免费药水、替换全部地图复活落点设计。

### D05｜幽魂、墓碑、碑文与首个痕迹闭环

**依赖：**D01、D02；集成依赖D03/D04。

**主要改动：**新View和碑文模块；Phaser场景／应用层有限接线；资源URL解析、动作去重、快照恢复、销毁；死亡面板与墓碑输入互不遮挡。

**输出：**死亡幽魂最多5秒；复活立即结束幽魂；墓碑继续存在且可读模板碑文；匿名／缺少证据有安全文案；高密度墓碑分页聚合。

**验收：**后来者首次入图看到同一碑；名字纯文本，无源码私聊泄露；刷新／强制更新不会复活过期碑；图像缺失不会卡住复活操作。

**测试：**T05、T30的名称子集、T33、T34、T37；正式素材与手感列用户待验。

**阶段出口P1：**可以称“痕迹闭环已实现”，不得称“虚影帮助后来者已完成”。

### D06｜试点遭遇、类型化伤害与单一奖励路由

**依赖：**P1、D02。

**主要改动：**兼容扩展`monster_rewards`；试点怪物出生冻结策略；持久试点生命、类型化贡献；统一普攻／技能／持续伤害／召唤的试点路由。

**输出：**角色、虚影和后续历史NPC有明确行动者类型；过量伤害截断；旧玩家分支不变；试点遭遇支持重试与重启后同生命去重。

**验收：**只有一个怪物奖励主键认领；不创建虚影假账号；基础经验可对账；世界行NULL不破坏兼容读；某条技能路径未接入时不允许该试点上线。

**测试：**T17、T18、T19、T20、T35。

**风险与回滚：**这是P2最高风险共享写入点，必须先有兼容读取版本；关闭试点并回滚兼容代码，不把含世界行的库交给不兼容旧二进制。

### D07｜稀有虚影、有限AI、被攻击与阴阳干涉

**依赖：**D03出生事实、D06类型化战斗。

**主要改动：**恢复潜伏／活跃状态；守路原型；怪物对虚影的仇恨与受击适配；前摇／范围／安全区／非致命干涉；空地图与驻留条件。

**输出：**一个不受原玩家控制、会针对合法威胁行动的虚影；能被允许的怪物作用；先预警再干涉，复活与入图有保护。

**验收：**原玩家换图／换装不改变虚影；不是无敌刷怪机器人；不抢普通已占据战斗；不隔层伤人；耗尽预算可退为无战斗停留；无人状态不产有效经历。

**测试：**T08、T16的归因子集、T22、T23、T24、T38。

**不做：**第二个模拟task、完整复制来源技能树、所有倾向一起上线、默认致命连锁。

### D08｜经验球物化、预算、领取与升级

**依赖：**D06；与D07共用冻结的虚影身份和来源。

**主要改动：**根预算与区域预算；一次怪物结算物化有限正数球；经验球状态／回执；原子领取与既有升级helper；死亡时冻结真实来源账号、生成球时冻结完整根快照。

**输出：**纯虚影没有原玩家收益；混合预算守恒；两人抢球一次到账；包满不影响球经验；经验球不过邮件／仓库／图鉴物品入口。

**验收：**过期不退预算；重启不补球、不重置根预算；融合前的来源查询已有清晰契约；容量不足不影响已核定的生者经验。

**测试：**T11—T17、T19—T21、T28的基础来源子集、T39的不可变来源子集。

**不做：**宠物自动吸球、离线领取、队伍二次加成、死亡直接给经验。

### D09｜虚影、危险范围与经验球前端

**依赖：**P1 View、冻结的P2协议；集成依赖D07/D08。

**主要改动：**独立虚影View、危险前摇与非颜色唯一提示、球表现与拾取意图、实际回执处理、插值重置和退场。

**输出：**明显区分幽魂／虚影／NPC；原玩家和陌生人看到同一个交互状态；不合资格原因只影响提示，不制造私人球副本。

**验收：**球消失以提交结果／快照为准，不本地先加经验；失败不会出现永久卡住的吸球动画；融合／换图不会让旧ID继续漂移；小屏仍能复活和读取危险。

**测试：**T10、T23、T33、T34；真实资源与触控手感由用户实玩确认。

### D10｜首个完整玩法集成与关闭策略

**依赖：**D06—D09。

**动作：**使用D01选定的真实侧路与少量试点遭遇，将死亡、稀有出现、拦截威胁、干涉、球与后来者领取串成一个内容切片；加入各独立开关与必要指标。

**输出：**可由用户按“甲死亡离开 → 乙经过受助 → 丙竞争拾取 → 甲返回”验证的闭环；包含源码版本、内容版本、真实资源来源与未验证项的交付记录。

**验收：**不靠生产GM命令把虚影塞出来才能触发正常逻辑。自动测试可注入可控随机结果，正式服不能开放客户端指定命中。

**测试：**针对集成实际变化选取T01/T05/T11/T16/T17/T21/T24/T33的端到端或模块组合检查，不重复执行所有已通过且未受影响的测试。

**阶段出口P2：**这是首个完整死亡后果玩法；仍明确不包含吞噬、觉醒NPC与天命。

### D11｜原子吞噬／融合与精确谱系

**依赖：**P2。

**主要改动：**演化判定、输入版本、事务内多实体终态、根集合、凝聚和寿命守恒、演化回执；输出下一Tick才可行动。

**输出：**同一个来源无法被两个并发演化使用；融合结果不复制经验额度；吞噬保留胜者ID也必须更新版本和谱系。

**验收：**失败全回滚；提交后崩溃恢复唯一结果；最多16根；最早死亡六小时未觉醒上限不重置；不能丢来源后领取自己收益。

**测试：**T25、T26、T27、T28、T39。

**不做：**玩家主动投喂养魂、把每次相遇自动改成融合、分裂复制虚影。

### D12｜演化的可观察变化

**依赖：**D11、现有View。

**主要改动：**吞噬／融合前摇、旧实例销毁／新实例出现；至少一个可观察的偏向或行为变化；来源碑文仍保持自己的生命周期。

**输出：**玩家能区分“被吸收”与“产生第三个存在”，而不只是看见一个等级数字变大。

**验收：**新对象不在当前Tick连续吞遍地图；客户端漏演出仍能从快照得到正确终态；重复事件不重复生成精灵；危险前摇不被炫光遮盖。

**测试：**T26/T27的表现恢复子集、T33/T34。

**阶段出口P3：**有真实演化；还不能称为独立NPC人生。

### D13｜唯一觉醒与稳定历史身份

**依赖：**P3；完成当前NPC／天命历史主体实现核查。

**主要改动：**将来源虚影终态与独立ActorId创建放入同一事务；保留谱系与根预算；与当前NPC表现／对白注册绑定；重启只恢复同一个人。

**输出：**一个非账号、非模板ID、非原玩家副本的历史人物；关键经历和可公开来源；明确容量与长期退场策略。

**验收：**相同虚影重复请求只生成一位NPC；原玩家改名换装不复制新资产；觉醒不洗掉预算和来源限制；NPC没有可登录的虚构账号。

**测试：**T29、T30、T35。

**依赖不足时：**先做必要稳定身份与有限记忆，不同时开发完整天命；不得调用不存在的历史计划接口。

### D14｜新选择、有限记忆与世界节点回应

**依赖：**D13；对应实际节点／旅人接口。

**主要改动：**一个有事件证据的觉醒情景；一个不同于原执念的新选择；合法观察者／转述记忆；有限计划及能够实际执行的停留／迁移。

**输出：**例如道路恢复后，NPC不再死守旧点，而开始承担新的护送；相应旅人准确记得其真正做过的事。

**验收：**无人挂机时间不替代经历；不是用三次击杀凑“意识值”；其它NPC不凭空全知；没有可行导航时不伪称完成旅行。

**测试：**T24、T29、T30、T31；针对实际接入的节点事务再补定向用例。

**阶段出口P4：**长期独立NPC成立；未接入正式天命时不得给出正式席位。

### D15｜天命候选与空缺位置承担

**依赖：**P4；真实、可验证的天命候选／承诺／正式任命核心。

**主要改动：**以NPC自己的ActorId和事实参选；沿同一资格、馈赠与边界规则进入候选；原子竞争空缺或未正式承诺的位置。

**输出：**NPC不是来源玩家代理人；和玩家竞争时，事实依据与边界可说明；每个排他位置只存在一个正式持有者。

**验收：**同源玩家无自动优先或禁止权；旧回执不重复任命；同位置并发请求只有一个成功；未接入系统明确返回未开放而不是假Buff。

**测试：**T12的指纹原则、T29、T31、T32；必须复用天命系统自己的定向回归。

**阶段出口：**可称“NPC已参加候选与空位承担”，不声称能够挑战已任命玩家。

### D16｜正式位置竞争与责任冲突

**依赖：**D15；天命已有正式挑战、响应与移交机制，或者此工作包显式实现对应缺口。

**主要改动：**把“争夺正式位置”拆成公开挑战、响应窗口、证据冻结、资格与承担裁决、原子移交、后续关系事实。响应窗口与离线处理必须来自批准的天命规则；缺省时禁止NPC自动挑战已任命者，不自行选一个定时器抢位。

**输出：**至少一个“存续与守护”类具体责任冲突内容；NPC与玩家使用同一正式裁决流程；失败并不抹掉过去贡献，退出／移交有历史。

**验收：**离线不能无预警丢位；不比较来源玩家的战力来决定NPC资格；同一版本的位置只移交一次；重启恢复既有挑战阶段和截止时间，不重开新挑战。

**测试：**T32、T36及天命挑战的失败／恢复／并发用例。

**阶段出口P5：**完成D16后才能称“虚影觉醒NPC可正式与玩家争夺天命与位置”。只有D15时必须如实报告尚缺正式挑战。

## 5. 首个用户实玩验收脚本

下列为交付后的人工步骤，不是本次已经执行的验证。不默认新建机器人或打断用户在线实例。

### 5.1 P1：痕迹

甲在已启用试点中正常死亡，看到短暂幽魂与碑；甲复活，碑留下。乙之后进入能读同一碑。甲刷新、换图或离线不删除碑。到期后碑按世界状态退出；旧复活请求不能处理下一次死亡。

### 5.2 P2：后来者

在隔离测试环境通过可控随机输入覆盖命中与未命中；正式玩法保持服务器稀有判定。命中时甲复活离开，乙经过看到虚影拦截允许的威胁。乙接近时先看到干涉预警，退出后不再积累新干涉。怪物死亡后乙可领取球；甲同账号另一角色不可领取来源球。乙与丙竞争一个球，只有一份经验。

原本独立的纯玩家狩猎、魔心防御、Boss练习、背包和主线仍按原行为工作。应当特别问用户：“这次帮助是否让你理解世界，而不是觉得NPC抢了你的怪？”

### 5.3 P3—P5：从来源到独立人物

两个虚影发生可观察演化，旧实体状态正确结束；重启后不多出第二份。觉醒人物不再使用原玩家最新装备，能保留自己的经历与新选择。天命先验证空缺承担，再验证正式挑战，不把两个验收合并成一张“已完成”截图。
