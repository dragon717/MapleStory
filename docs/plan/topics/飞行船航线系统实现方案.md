## 1. 背景与目标

装配目录 48 张图里，站台四图（`104020100` 大厅、`104020110/120/130` 三个站台）已可进出，但**有站无船**：站台子图在源里只有返程门（`in00/in01/in03`），没有静态登船门；参考端也没有 `inERShip` 等乘船脚本体。本模块补上"候船—检票—开船—航行—到站"完整闭环。

一期范围：**維多利亞樹木站台 ⇄ 天空之城** 一条航线跑通全部机制。
二期（另行排期）：耶雷弗线（`130000210`/`130090000`）、埃德爾斯坦线（`200090600+` 系列）、航行中蝙蝠魔（Balrog）事件。

## 3. 时刻规则（P 级，联网已核对）

多来源一致（百度知道/搜狗/网典 2006–2025 条目）：**15 分钟一班（整点/15/30/45）、开船后 10 分钟到达、开船前约 5 分钟开始检票、开船前 1 分钟停止登船；甲板会刷蝙蝠魔，船舱内安全**。TMS273 无脚本体，具体分钟数无同版证据，采用以下 P 级参数（集中在 `shared` 常量，后续有证据只改一处）：

- 每 15 分钟一个班次槽：槽内 `0..9` 分钟 = 航行中；`10..14` 分钟 = 本端靠港、检票登船（`14` 分起最后 1 分钟只出不进）。
- 两端对开：同一时刻表下维港船与天空船各自独立，互不共用载客名单。
- 航行结束由服务端把船上玩家强制传送到对端站台；掉线重连落在船图则按当前相位恢复或到站释放。

## 4. 服务端设计（`server/src/ship.rs`）

世界内唯一权威状态机，挂进现有顺序模拟 tick（`world.rs` 每 tick 调 `ship::tick(&mut self, now)`），不建独立线程/task。

```rust
// server/src/ship.rs（骨架）
pub const SLOT_SECONDS: i64 = 15 * 60;      // 班次槽
pub const SAIL_SECONDS: i64 = 10 * 60;      // 航行
pub const BOARD_GRACE: i64 = 60;            // 开船前 1 分钟停止登船

pub struct Route {
    pub station: i32,      // 104020110
    pub wait_room: i32,    // 一期可复用站台（候船室为二期）
    pub deck: i32,         // 200090010 甲板（维→天）
    pub cabin: i32,        // 200090011 船舱
    pub dest_station: i32, // 200000100 天空之城码头（需装配，见 §6）
}

#[derive(Clone, Copy, PartialEq)]
pub enum Phase { Sailing { left: i64 }, Boarding { left: i64 } }

pub struct ShipState { pub phase: Phase, pub passengers: Vec<i32> /*playerId*/ }

pub fn phase_of(now_unix: i64) -> Phase {
    let m = now_unix.rem_euclid(SLOT_SECONDS);
    if m < SAIL_SECONDS { Phase::Sailing { left: SAIL_SECONDS - m } }
    else { Phase::Boarding { left: SLOT_SECONDS - m } }
}

impl ShipState {
    /// 检票员放行：仅 Boarding 且 left > BOARD_GRACE；成功后 warp 到甲板出生点并登记 passengers。
    pub fn board(&mut self, player: i32, now_unix: i64) -> Result<(), &'static str> { /* … */ }
    /// tick 到点：Sailing→0 时把 passengers 全体 warp 到对端站台并清空。
    pub fn tick(&mut self, now_unix: i64) -> Vec<(i32, i32)> { /* 到站传送指令列表 */ }
}
```

接入点（沿用既有纪律，不新增并发体）：

1. `world.rs` tick 尾部调用两条航线各一实例的 `tick`；到站传送复用 `warp_player_at`。
2. 检票员/售票员走既有 npc script 装配（`assemble_tms273.cjs`）：售票员对话→查询时刻（`Phase` 注入对话变量）；检票员对话→`board()`。登船权限在 `handle_gm` 之外的普通意图入口，subject 幂等（同一玩家重复点检票返回原结果）。
3. 掉线/切图：`players[].ship` 快照字段（仿 `pet`/`away` 注入），重连按 mapId 恢复；到站名单持久化不需要（到站只是 warp，崩了按地图落点重登即可，符合"内存状态可丢、权威落点在快照"边界）。
