## 0. 当前实施入口

- 正式场景名称：**《巨石之约》**。
- 当前实施仍保留完整人形骨骼、双手十指逐节绑定、自然手型和攀爬上身；旧固定摊掌方案属于历史。身高最终值未定，100000 m 仅是可调工程候选。当前入口是活动列表第三项的第一幕港口及揭晓后的可操作体表／肩部空间；头顶—绕背—后续神庙是当前地图认知方向，尚不等于已开放完整攀登或神庙。既有六区轨道是工程候选，不等于最终叙事箱体，也不代表十二幕或完整地图已经定案。相关实现范围见[六箱庭实施记录](../../plan/history/2026-09-20/巨石之约_六箱庭与手绘贴图.md)，更早的[协议 31 首个候选](../../plan/history/2026-09-20/巨石之约_港口与移动巨像首个可玩候选.md)仅作历史追溯，其中开场神庙外廊已移除。
- 长期方向：逐步承接新场景和玩法，渐进替代当前冒险岛生态，作为重构世界的基础；不删除旧生态，也不默认一次实现全部十二幕。UI 与交互继续复用复刻冒险岛，另立规范须用户明确确认。

## 2. 当前客户端技术栈核实

结论：原版主世界仍为 TypeScript + Vite + Phaser；Three.js 已作为《巨石之约》的独立活动宿主接入同一客户端，React 不在当前客户端栈中。

| 技术 | 当前角色 | 证据 |
| --- | --- | --- |
| TypeScript | 现行客户端源码语言；`typecheck` 与 `build` 均运行 `tsc --noEmit` | [`client/package.json`](../../../client/package.json)、[`client/src/app/main.ts`](../../../client/src/app/main.ts) |
| Vite | 当前开发服务器和 Web 构建工具；`index.html` 指向 `/src/app/main.ts` | [`client/package.json`](../../../client/package.json)、[`client/vite.config.ts`](../../../client/vite.config.ts)、[`client/index.html`](../../../client/index.html) |
| Phaser | 当前主世界运行时和渲染/场景框架；入口创建 `Phaser.Game`，主世界为 `World` Scene | [`client/src/app/main.ts`](../../../client/src/app/main.ts)、[`client/src/scenes/world.ts`](../../../client/src/scenes/world.ts) |
| Three.js | 第三活动动态加载的实际 3D 渲染宿主；进入时暂停 Phaser，退出后恢复 | [`scene.ts`](../../../client/src/features/colossus/scene.ts)、[`view.ts`](../../../client/src/features/colossus/view.ts)、[`main.ts`](../../../client/src/app/main.ts) |
| React | 当前未使用；不在 `client/package.json` 依赖中，源码也没有 React 入口或组件引用 | [`client/package.json`](../../../client/package.json)、[`client/src/app/main.ts`](../../../client/src/app/main.ts) |

补充：[`client/src/main.ts`](../../../client/src/main.ts) 当前为空文件；实际 HTML 入口是 `client/index.html → client/src/app/main.ts`。因此不能把空文件名 `src/main.ts` 当作当前主入口，也不能把安装依赖当作运行时接入证明。

## 3. 统一阅读顺序

1. 先读[设计目的](巨像第一章_设计目的.md)，确认巨像、居民和玩家行动的叙事因果。
2. 再读[分幕情景大纲](巨像第一章_分幕情景大纲.md)，确认港口进入、探索、救援和归途的玩家经历。
3. 需要开场空间时进入[港口巨像开场精要](港口巨像开场_故事精要.md)。
4. 需要复用叙事方法时参考[五步可玩故事设计范式](五步可玩故事设计范式.md)。
5. 进入实现前阅读[技术基建规范](../../technical/2.5D轨道巨像世界技术基建规范.md)，以当前代码证据、服务端权威和首个验证场景为准。

设计文件描述“玩家应经历什么”；技术文件描述“当前系统能证明什么、实现前先验证什么”。两者之间的差异应进入未决问题或验证阶段，不在索引页隐式补齐。
