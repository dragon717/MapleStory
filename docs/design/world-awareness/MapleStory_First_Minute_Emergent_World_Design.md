## 0. 决策摘要与证据边界

### 0.1 本次决定

做一张能被多种办法穿过的小地图，而不是多套互不相通的职业教学副本。

共同目的地是高处的**风铃岛驿站**。起点到终点之间存在同一组树根、岩壁、吊桥、绳索、枯枝和气流。玩家可能沿根道攀登，可能斩断绳索放桥，可能点燃枯枝借热流升空，也可能借风改变叶舟的位置。它们会互相影响，不分别归属于某个职业。

**第一版只完成“根道、放桥、借火”三条有效路径。** 风与轻身路径在同一地图上扩展，不作为第一版发布前置条件。每个玩家第一分钟只需经历一条短因果链；不要求一个人学会所有规则。

这是一段**新的世界化序章**，不是对 TMS273 原版开场的逐步复刻，也不宣称原作已有可燃森林、热流滑翔或这座风铃岛。既有研究计划优先验证操作、战斗、成长和长线闭环；这次只替换最前面的“为什么我愿意进入这个世界”，不取消后续打怪、成长和区域推进。[L01]

## 1. 知识库总纲：世界产生事件，设计帮助玩家理解事件

### 1.1 把“因果关系”写成闭环

```text
世界事实：谁在哪里、材料是什么、现在有多湿、绳索是否完整
                         +
世界规则：满足什么条件，状态就怎样改变
                         ↓
事件发生：绳断、桥落、枯枝燃烧、热流上升、角色离地
                         ↓
新的世界事实：桥已经接通；这里有热流；下面留下了焦痕
                         ↓
玩家能观察到的线索 + 视听表达
                         ↓
理解 / 好奇 / 预期 / 紧张 / 成就
                         ↓
玩家做出下一次行动，重新改变世界事实
```

实体不是在规则之后才“出现”的东西：实体承载位置、材料、能力等事实；规则读取这些事实、产生新事实。工程上不应照着抽象层次再造一套与真实实体脱离的“世界体验管理器”。

能力锁、地标、信息缺口、反馈、风险回报是这个闭环中不同位置的体验解释，**不是必须各实现一个管理器的六套系统**。

### 1.2 需要保留的两条边界

**规则不关心具体人物，不等于规则不看条件。** 燃烧不检查玩家是不是法师，但必须检查目标是否可燃、是否足够干、是否获得足够热量。施放动作仍需校验施法者是否拥有能力、距离是否合理、资源与冷却是否允许。

**不预写玩家的经历，不等于取消设计师的表达。** 地形要能读，绳索的拉力关系要看得懂，气流要能被落叶显示，登高时音乐可以展开。区别在于：视听层解释已经发生的事实，而不是为了凑一个高潮，偷偷把桥放下、把玩家送上去。

### 1.3 这一分钟真正要建立的信念

不是“这里有很多可点的东西”，而是：

> **我刚才学到的规律，换个地方、换个目标、换个施加者，仍然大体成立。**

例如，火既可以点燃枯枝，也能烧弱干绳；斩击既能伤害生物，也能破坏合适的材料；气流既推动落叶，也作用于张开的叶翼。不能第一关如此，第二关遇到完全同材质的东西却无故失效。

## 2. 一分钟的核心场景：风铃岛

### 2.1 一句话场景

清晨，玩家站在巨树根部。一条大龙从树冠上方飞向一块被古树根系牵系的浮空岩岛，岛上有一间亮着暖灯的驿站。龙翼掀起的风让附近风铃与落叶一起动起来。

没有人跳出来说“请到岛上找我”。玩家先看到**一个值得到达、而且确实可到达的地方**。

风铃岛是本项目原创地点；借用森林、树屋、天空、木石平台等美术语言，不把原作几个地区的历史和地理关系硬拼成“官方设定”。

### 2.2 目的地为什么有吸引力

远处可看见暖窗、摇动的铜铃、停靠龙影和一小截朝云层伸出的旧航路标。它们共同给出三个问题：上面有人吗？龙为什么来这里？云后面还有什么？

到达后必须兑现至少一个问题：玩家能够看到驿站有人在修补风铃，龙在更高的停歇枝上休息，航路标的确指向下一片地区。**不能上去以后只给一只普通宝箱，再用空气墙隔开真正展示的地方。**

首个回报是空间和理解的扩展，不是夸张数值奖励。

### 2.3 地图结构：有共同地形，而不是职业颜色门

以下是拓扑示意，不是按比例美术图，也不是现有项目地图坐标。

```text
                                      更远的云中航路
                                            ↑
                               龙的高位停歇枝（远景层）
                                            |
                         [共同目的地：风铃岛驿站]
                              /      ↑      \
                   可放下的树桥    热流出口   高位树根踏点
                        /            ↑            \
              拉紧绳索/配重        枯枝石槽          \
                    |             /                 \
               近侧高台 —— 断口 /                     \
                    |         /                       \
                 [出生地] —— 下方石台/湿地 —— 石脊根道 ——┘
                         
                  风向可以改变叶舟运动（后续扩展）
```

根道是稳定的绕行线；放桥改变中层拓扑；热流改变竖直可达性。高机动角色也可以利用实际可达的平台跨越其中一段。

推荐灰盒尺度：地图约 `36H × 20H`，其中 `H` 为当前角色碰撞体高度；初始视口约 `24H × 13.5H`，起点约 `(3H, 3H)`，目的地约 `(21H, 11H)`。这些值仅用于首次构图。窄屏通过合理取景或远处标志的持续可见性适配，不缩小角色到难以操作。

以现有移动参数实测单跳高度 `J` 和水平距离 `D` 后再摆平台。根道普通台阶首轮不超过约 `0.7J`，主要落脚面留足宽度，不把教学变成像素级跳跃考试。**不为了凑地图形状临时篡改整套角色跳跃手感。**

### 2.4 巨龙的角色与实现边界

原创生物暂名“巡风龙”。它不是来迎接玩家的，而是在自己的巡游和停歇行为中经过这里。

低成本实现采用有位置、速度、航线进度、停歇状态的远景实体；翼拍可以产生有范围的阵风事件，所有处在对应受影响区域的可受风物都按同一规则响应。它不会因为玩家没有抬头而倒飞重播。

首版不做骑龙、龙 Boss 或全图生态。它的高位停歇枝不在本分钟的可操作近景层，不假装拥有尚未实现的全套交互。**所有抵达路径均不依赖“龙恰好经过救我”**，所以错过它不会卡关。若阵风实现成本影响三条核心路径，首版允许先只表现正常航行，但不虚假宣传龙与世界已有深度物理联动。

## 3. 0—60 秒体验：时间是观察窗口，不是剧情触发器

起算点是玩家获得控制的第一个世界帧；登录、建号与资源加载不计入这 60 秒。目标是多数新玩家在约 45—75 秒内形成一次完整经历，而不是第 60 秒强制通关。

| 观察窗口 | 玩家可能经历的事 | 世界里实际发生什么 | 视听表达 | 不能做什么 |
|---|---|---|---|---|
| 0—6 秒 | 确认“我已经能动”；看到高处有亮窗 | 龙正在飞，树叶受风；玩家移动与跳跃直接生效 | 角色周围留空，风铃定位高处；不锁镜头 | 播完片头才给控制、满屏弹窗 |
| 6—15 秒 | 往亮处走，发现眼前断口不能普通一跳通过 | 真实地形阻挡了直达；根道仍存在 | 绳索明显受力；枯枝与湿苔对比；落叶显示空气运动 | 显示“职业不符”“需先完成教学” |
| 15—30 秒 | 试跳、砍绳、点火，或选择绕行 | 输入改变相应状态；没成功也呈现原因 | 绳纤维松裂，湿木冒气，干枝起火，脚下叶翼鼓起 | 按一下就给无前因的机关成功动画 |
| 30—48 秒 | 使用自己创造/发现的通路，途中可能失误 | 树桥落稳，热流托起展开的叶翼，或正常攀爬 | 镜头保持可控，关键落点与气流边界清楚 | 擅自接管移动完成最后一跳 |
| 48—65 秒 | 抵达驿站，回头看见自己的来路 | 到达事实成立；桥、焦痕、物体位置保留 | 森林遮挡减少，远景打开，音乐按高度与可见度展开 | 未到达先播胜利、全场瞬间复原 |
| 超过 65 秒 | 继续探索或寻找办法 | 世界照常运行，通路没有因为超时消失 | 必要时提供可关闭的操作帮助 | 为保留时长指标自动传送或倒计时催促 |

### 3.1 第一帧的构图

角色在左下，主要可交互物在中部，风铃岛在右上。视觉上只强调一个远景目的地和一个近处值得试探的现象。

不要同时把三条路分别画成红、绿、蓝三套高亮解法。让玩家先理解眼前的材料，再慢慢看见它们的关系。

初始音乐与环境声应该留白，让第一次脚步、砍击或火种的反馈被听见。龙翼声不是突然炸响的惊吓点。

### 3.2 最小教学

同屏最多出现一条短操作提示，例如“跳跃键：起跳”“长按跳跃键：展开叶翼”。键名从当前绑定读取，不在素材里写死键盘字母。

第一次普通起跳即可展示叶翼在下落时轻轻张开，建立身体能力的反馈；不要等玩家已经站在火里才解释飞行操作。

帮助层可以在连续尝试无明显进展后出现“落叶正在往上走”之类观察提示，但只能引导观察，不修改湿度、不延长燃料、不自动建立通路。

**没有任务窗口不等于没有引导。引导从“告诉正确答案”改成“让规则可被观察”。**

## 4. 先放事实，再允许故事发生

### 4.1 初始事实表

全部为本项目配置，不是 TMS273 原作地图数据。

| 实体/区域 | 必要事实 | 初始安排 | 为什么存在 |
|---|---|---|---|
| 玩家 | 位置、移动能力、已授权动作、装备、质量/受风参数 | 位于安全地面；可走跳；可具有一种起步能力 | 主动行动，不负责触发整套世界剧本 |
| 旅行叶翼 | 展开状态、受风面积、耐久规则 | 默认随旅行装备携带；不打开菜单也能操作 | 把上升气流变成可用能力，而非让裸角色被小火堆直接吹飞 |
| 风铃岛 | 位置、近景落脚地、发现区域、静态浮空支撑设定 | 从起点可见；有稳定根道连接 | 共同目标与真实奖励空间 |
| 树桥 | 几何、质量、转轴、支撑关系、承载状态 | 被绳索拉起，释放后可在止挡上落稳 | 材料与结构产生可达性改变 |
| 干绳 | 材料、完整度、湿度、承载关联 | 近侧一段可触及，高处一段可远程命中 | 允许斩击、投射物或火走向同一个结构结果 |
| 枯枝石槽 | 燃料量、湿度、热量、邻接对象 | 少量干枝位于石质浅槽，不铺满森林 | 提供可控制的局部热流实验 |
| 湿苔/湿木 | 含水状态、热容量、可燃性 | 包围局部可燃区，表面有湿亮与水滴 | 让“不着火”和火势边界有材质理由 |
| 石脊根道 | 固定碰撞、连接关系 | 位于树桥运动范围之外，由岩石承担主要通行面 | 不依赖特殊能力、消耗品或可破坏机关 |
| 落叶/轻物 | 位置、质量、受风面积 | 有持续少量环境落叶 | 显示看不见的气流 |
| 巡风龙 | 航线、速度、翼拍、停歇状态 | 地图开始时已在一次正常巡游中 | 地标指向与独立世界感 |
| 驿站修铃人 | 工作目标、感知范围、见闻记录 | 在岛上修铃，不站在起点发布任务 | 到达后的生活回应，而非全知任务裁判 |
| 低威胁生物 | 位置、巡游、危险回避 | 可复用已有蜗牛/蘑菇类表现，不堵唯一通路 | 留住生命和可选战斗，不承担“必须杀三只”的门锁 |

浮岛的支撑机制在这一关被定义为稳定世界事实，不要求先模拟整座浮岛的浮力。小地图只实现明确对外承诺的规则，不用一个开场证明“万物皆可模拟”。

### 4.2 最小规则集

| 规则 | 条件 | 产生的新事实 | 可迁移到什么地方 |
|---|---|---|---|
| R1 移动与支撑 | 角色/物体失去支撑或获得位移输入 | 按现有运动规则移动、落地 | 所有平台与移动对象 |
| R2 材料破坏 | 有效切割/冲击超过材料对应阈值 | 完整度减少，达到阈值后断裂 | 绳、弱木构件；不自动切开岩石 |
| R3 加热与含水 | 接受热量，同时发生散热/干燥 | 湿物先干燥；达到点燃条件才燃烧 | 枯枝、木料、绳；不检查职业 |
| R4 有限燃烧 | 有可用燃料且点燃条件成立 | 消耗燃料、发热、向有效邻接物传播热量 | 所有进入支持范围的可燃材料 |
| R5 热流与受风 | 热源形成上升场；物体具有受风参数 | 轻物与展开叶翼被施力，关闭叶翼则响应较弱 | 落叶、叶翼、可扩展的帆面 |
| R6 结构失效 | 支撑绳完整度不足 | 释放连接约束，树桥受重力转动，接触止挡后承载 | 其他同类悬挂结构 |
| R7 风与动量 | 风场覆盖受风物 | 根据受风面积、相对速度与质量改变运动 | 环境风、技能风、龙翼风用同一受风逻辑 |
| R8 有限感知 | 生物/NPC 实际看到或听到事件 | 产生危险回避、注意、见闻等状态 | 不允许 NPC 全图知道谁点了火 |
| R9 到达与发现 | 角色在目标落脚区域形成稳定到达 | 记录发现、更新检查点；与来路无关 | 所有合规路径与未预料到的捷径 |

### 4.3 调试参数的表达

灰盒可先把湿度与完整度归一化为 `0..1`，热量使用游戏内部量，不伪装成准确摄氏温度。首轮让少量干枝在明确加热后约 1—3 秒呈现起火；湿木在同等短时加热下先冒气；可用热流窗口约 12—20 秒。所有数字都须根据可读性和实测修改。

燃料耗尽会失去热流。因此，起火前就要有可见的叶翼与落叶线索，不能让玩家研究操作到火烧完才知道怎么用。

小火堆托举的是具有夸张受风特性的**魔法叶翼**，不是现实人体；上升场是游戏化的有限区域模型，不宣称做了真实热对流计算。

### 4.4 第一版明确不模拟

不模拟全森林温湿度网格、不做连续流体求解、不让每个装饰树叶成为网络实体、不做生物繁衍、不引入完整火灾灭火系统。火只在本地图登记的有限材料节点间传播。

但视觉承诺必须匹配范围：能与玩家近距离交互的同类干枝不能有的会燃烧、有的只是假背景而完全没有区分。远景、不可触及景物和可交互层应在空间与表现上明确区分。

## 5. 不同能力，不同路径，同一个终点

### 5.1 能力不是职业通行证

关卡读取 `Cut`、`Heat`、`Impulse`、`AirControl`、`ExtraJump` 等作用能力，不读取 `if job == 某职业 then 开门`。

原作火系技能、风系技能和龙伙伴可以提供动作/题材参考；官方历史资料可确认 Flame Orb、Wind Walk、Evan 与 Mir 等题材存在。[S04][S05][S06] **让这些能力作用于树桥、绳索和热流，是本项目新增规则，不是对原作技能效果的描述。**

开场能力来源采用两层策略：灰盒测试使用预设角色配置；正式接入时，角色带入已经合理拥有的起步能力。完全没有特殊能力的初心者走根道。新叶翼属于本序章的旅行装备，不冒充原作初始物品。

不为了证明多路线，强迫刚进游戏的人再打开一个“四选一教学职业”菜单；也不为了演示高级位移，默认所有一级角色拥有后期技能。

### 5.2 路径矩阵

| 路径 | 可用能力/条件 | 具体因果链 | 玩家感觉 | 改变了什么 | 阶段 |
|---|---|---|---|---|---|
| A 根道：观察者 | 普通走跳、攀爬 | 找到岩石落脚点 → 绕开断口 → 沿根道上行 | “原来不用打架也有路。” | 基本不破坏环境，可看到低处刻痕 | P0 |
| B 放桥：改变结构 | 可接近绳段的斩击/足够冲击；远程切断是扩展 | 干绳受损 → 支撑失效 → 树桥落稳 → 走到岛上 | “我亲手造出了一条路。” | 后来的同伴也能走桥 | P0 |
| C 借火：理解材料 | 热作用 + 展开的旅行叶翼 | 干枝燃烧 → 上升场 → 落叶先升 → 角色借热流抵达 | “我的技能不只是扣血。” | 留下有限焦痕，绳索也可能受热变弱 | P0 |
| D 借风：改变运动 | 风作用/气流控制 + 叶舟或叶翼 | 改变受风物运动 → 调整跨越方向 → 在岛边落脚 | “这股风原来可以为我所用。” | 叶舟位置、落叶分布不同 | P1 |
| E 轻身：利用几何 | 已有二段跳/短距位移 | 从真实落脚点起跳 → 跨过现有能力覆盖范围 → 到达 | “我看见的缝隙，确实能穿过去。” | 可以没有永久环境改动 | P1，优先接现有能力 |

B 与 C 必须存在交叉：火能够烧断合适的绳索；具有足够效果的远程攻击能替代近身斩击。路线名字只是设计与分析工具，不是运行时必须存储的剧情状态。

### 5.3 路径 A：不是“不会玩的人走的差路”

根道有足够清楚的落脚面，从低处能看见岛底旧航路的刻痕；这条信息是固定存在的环境内容，不因为玩家掉下去才凭空刷新。

路程可以略长，但不能慢到像受罚。首次到达时的检查点、主线资格与核心奖励完全一致。其他路线不独占永久数值奖励；避免玩家认为开局选错了能力。

它也是所有失败的自然恢复网络：从树桥边缘或热流边缘跌落，会落到下方可继续行走的湿地/石台，而不是直接抹掉所有尝试。

### 5.4 路径 B：看懂拉力，而不是找发光机关

绳索要能从近侧固定点一路看向吊起的桥。攻击时先出现纤维受损、拉力回弹，随后约束被解除。桥的落下、碰撞与最终可站立状态必须统一。

不能动画播完就把碰撞体瞬移到最终位置，途中角色却穿桥或被无形碰撞顶飞。可用受限转轴模型，不必引入全地图复杂刚体。

远程命中绳索需要真实命中判定。没有命中、碰到石柱或者能力不具备相应破坏作用，都不会因为“玩家显然想开桥”而自动成功。

### 5.5 路径 C：不是点亮火把就触发升降机

枯枝石槽位于通向高处的自然竖直缺口下方。起火以后，落叶先被向上带动。玩家展开叶翼进入上升场，仍然可以改变方向、离开气流或在中途落下。

热流边界需要看得见：叶片轨迹、柔和气线与叶翼姿态一起说明场的范围。火焰本体不是安全站立区；可从侧面进入上升场，不要求玩家站在火中才能飞。

过度扩大燃烧不能获得无限升力。燃料、气流强度和叶翼速度上限都是规则参数，不因玩家当前离终点还差一点就临时放大。

### 5.6 “相同终点”的真正定义

相同的是空间、可继续冒险的资格和核心奖励；不同的是耗时、理解、遇见的细节、环境状态与可以讲出的经历。

```text
完成条件：角色确实抵达风铃岛驿站的有效落脚区域。
不要求：先砍过绳索 / 先使用火种 / 完成全部教程 / 经过三个检查门。
```

合法的新捷径默认应被接纳。只有越出世界边界、伪造移动、穿越禁止的碰撞体等违反既有规则的情况才拒绝，不能把“不是策划预想的路线”当成作弊。

## 6. 涌现的“剧本”：写条件与后果，不写必然发生的分支树

这里的故事卡是**样例轨迹与测试情景**，不是待实现的 `branch_01 ... branch_06`。它们给策划、美术、测试一个共同想象，但世界代码不按故事编号切换。

### 故事卡 A：《我给后来的人搭了桥》

**可能的玩家复述：**“我把那根绳子砍断，桥就落下来了。后面来的人直接从我开的路过去。”

初始事实是桥被干绳拉住，玩家具有切割作用。行动造成断裂；断裂解除支撑；桥落在止挡上；新的通路对同实例内其他人也成立。

后果不是一段“谢谢英雄”的强制对话，而是另一个人真的能走过。没有目击过程的 NPC 不应准确夸奖“你刚才用剑砍断了绳子”。

**反事实检验：**把切割者替换成具备相同作用的机关，桥仍应落下；把干绳换为参数不同的金属链，结果可不同，但必须由材料规则决定。

### 故事卡 B：《我本来想烧绳子，结果先飞起来了》

**可能的玩家复述：**“我想烧断绳子，旁边枯枝先着了。叶子突然往上飘，我撑开披翼就被带上去了。”

玩家的热作用命中绳索附近可燃节点。相邻干枝达到点燃条件，形成热流；同一热流推动落叶与展开叶翼。绳索可能稍后断裂，树桥还会在玩家身后落下。

这是一条至少涉及**加热、燃烧、气流、身体能力、结构变化**的组合链。没有“玩家进入火路线后，播放飞行”的专用触发器。

首分钟将火控制在几组枯枝范围，不夸大成整片森林烧毁。大规模森林火灾属于后续区域在充分规则支持下才能兑现的经历。

### 故事卡 C：《火点不着，也是一条信息》

**可能的玩家复述：**“我先烧了长苔藓的木头，只冒气。我换成旁边干枝，才有火。”

同样的热作用施加到含水不同的对象，反馈不同。失败不是红字“不可交互”，而是水滴、蒸气与迟迟不出现的火焰，提醒玩家重新判断材料。

如果玩家不愿继续研究，根道仍在；世界不逼他猜对某个策划谜底才允许前进。

**反事实检验：**湿物经过足够合法加热后应能进一步干燥，不能永远因为它被标为“错误答案”就绝对不着火。

### 故事卡 D：《我飞偏了，却发现下面不是死路》

**可能的玩家复述：**“我顺着热流飞起来，飘偏落下去了。下面有旧路，我从树后面绕了上去。”

叶翼离开气流后按运动规则下落，落到预先存在的低处平台。玩家从根道继续，可能注意到岛底刻痕。

没有失败专属传送，也不临时刷出奖励。失败的成本是少量时间与位置变化，不是重播开场；已经烧过的枯枝和落下的桥仍然保留。

### 故事卡 E：《一个人的火，成了另一个人的路》

**P1 小队样例。可能的玩家复述：**“他点火，我借风把叶舟送到热流里，我们最后从不同边落到同一座岛上。”

火、风、叶舟和两个角色共享同一权威实例。叶舟的承载质量、受风面积和碰撞状态共同决定能否载人；不能为了完成合作剧情临时忽略重量。

玩家也可一个走桥、一个飞行。在终点相遇本身就是叙事，不必加一个“合作完成”系统替他们宣告意义。

**此卡依赖 P1 的叶舟承载与风规则，不能在只有火焰特效的 P0 中宣称已支持。**

### 故事卡 F：《我什么都没破坏，但世界不是静止的》

**可能的玩家复述：**“我沿着树根慢慢走。龙已经在上面睡着了，刚才被它吹动的风铃还在晃。”

玩家不施放技能。龙继续航行或进入停歇状态，风与落叶继续变化；玩家靠观察与走跳抵达。没有触发火灾，没有解锁桥，也没有被判为“漏做了教学”。

这是非常重要的对照组：**没有制造混乱也能经历完整冒险，不能把涌现偷换成到处纵火。**

### 6.1 到达后的回应：只说知道的事

| NPC/环境实际掌握的事实 | 可以表现 | 不应表现 |
|---|---|---|
| 修铃人看到桥已经放下，但没看见是谁做的 | 看向桥：“旧桥落下来了？” | “刚才是你砍断了绳子。” |
| 能看见/闻到下方少量烟 | 朝烟处张望：“下面有烟。” | 无条件认定玩家纵火 |
| 玩家身上存在尚未消退的烟灰表现 | NPC 注意到衣服上的灰，递来掸子动作 | 复述玩家全部操作顺序 |
| 玩家安静到达 | 修铃人让开一块观景位置 | 强行夸奖玩家拯救森林 |
| 没有足够信息 | 普通工作状态即可 | 为了每次都有台词而编造事实 |

观察、称赞、问候可以使用短模板，但模板读取见闻与当前状态，不制造不存在的经历。

### 6.2 可以写下来的“个人故事”

可选轻量旅行日志只记录客观事实，如“发现风铃岛”“看到旧航路刻痕”“参与释放树桥”。不自动写“我机智地利用热流拯救同伴”，因为机智、意图与拯救关系未必成立。

首版不接入实时大模型写叙事；先让事件真的有因果，再考虑如何讲述。

## 7. 风险、回报和不软锁的世界

### 7.1 风险要改变过程，而不是取消冒险

放桥要注意落桥的瞬间；热流要辨认边界与剩余燃料；高机动跨越要判断落点。失误落到下层，仍能继续观察、尝试或绕行。

不设首分钟强制死亡，不用巨大数值惩罚新玩家试验。若继承已有伤害系统，危险区必须可见、可绕开，低威胁生物不能把唯一通路持续封住。

### 7.2 安全来自布局与材料，而不是偷偷修改规则

根道主要由岩石承载，避开桥的运动扫掠区与可燃物坠落区；湿地阻断本关有限燃料之间的传播；热流失败落点下方有可行走地面。

不写“玩家快死了就自动把湿度调高”“第 50 秒绳子必断”。要援助玩家，可以给明确的可选帮助或重试入口，不能伪装成自然规律。

首版允许作用范围内的火自然消耗完燃料；不因燃料耗尽而自动生成新枯枝。即使所有可燃物耗尽，根道仍必须可达。

### 7.3 世界记忆的范围

同一实例内，角色掉下去、死亡或重连不应悄悄重置桥与焦痕。实例状态与角色到达事实分别保存。

P0 为单人序章实例，P1 扩展为小队共享实例。暂不把新手开场做成全服可破坏公共区域，避免先来的玩家毁掉后来者的观察条件。

实例结束后可按产品规则回收；这不是承诺整个服务器永远计算这片森林。恢复时应读取该实例快照及明确的时间推进策略，不靠重播开场视频假装历史仍在。

```yaml
new_states_needed: [frayed, severed, scorched]
```

角色拼装与动画还需核对原点、挂点、层次、链接引用和透明边缘。视觉外框不能直接当碰撞体；装饰草叶也不能自动成为可站立地面。[L02]

**素材找到 ≠ 动作齐全 ≠ 实现完成 ≠ 可公开分发。** 发布素材优先采用原创或明确授权版本；本方案本身不提供客户端资源包，也不替代权利核验。

## 9. 美术风格规格：让规则长在画面里

### 9.1 选定的风格方向

“微小旅行者 × 巨大温柔森林 × 清楚可操作的地面 × 高处有生活气息的天空驿站”。

森林不是灾难片，也不是纯儿童玩具场。火和断桥应有后果，但不渲染成黑烟遮天、断肢爆炸。用轻微狼狈与意外惊喜承载风险。

### 9.2 构图与比例

角色保持项目现有动作比例，不为了新图重画成另一个游戏。巨树要足够大，让一个可走平台看起来只是它的一小段根；驿站的门和风铃又要把高处世界拉回日常尺度。

初始取景中，目的地有清楚剪影，但细节不全展示。到达以后开放的远景必须来自新的高度与遮挡关系，不依赖突然变焦到完全不同的透视。

前景可以遮少量画面，但不能遮住绳索支撑关系、热流入口、主要落脚点和危险边界。

### 9.3 图层规范

| 层 | 画面内容 | 规则 |
|---|---|---|
| 远天空 | 天色、远云、云中航路影 | 低对比、低运动密度，不造成平台误认 |
| 远景森林 | 巨树剪影、远处岛影 | 用尺度与对比区分不可到达景物 |
| 中景 | 龙航线、远枝、建筑背面 | 不与近景可交互碰撞混淆 |
| 可交互层 | 角色、树桥、绳、燃料、叶翼、落脚面 | 轮廓和状态变化最清楚 |
| 前景点缀 | 少量近叶、光斑 | 必要时透明/避让，不遮关键操作 |
| UI | 绑定提示、轻帮助、必要状态 | 独立于世界光照，不使用剧情锁屏 |

### 9.4 色彩与材质状态

以下色值只用于新素材方向稿，不是从原作测出的调色板。

| 用途 | 建议方向 | 初始色板例子 | 除颜色外必须有什么 |
|---|---|---|---|
| 清晨天空 | 奶蓝、薄云白 | `#BEDFEB`、`#F2EAD4` | 低细节、不抢互动主体 |
| 可走植被 | 明亮但不荧光的叶绿 | `#6F9A52`、`#A9BE70` | 地面边缘、根部承载关系 |
| 木石主体 | 温暖木色、灰褐石色 | `#947056`、`#7C8078` | 木纹方向、石缝、受力构件 |
| 湿润表面 | 偏冷、略暗 | `#527B75` | 水滴、苔藓、局部反光；不只换色 |
| 可燃干物 | 浅褐、卷曲纤维 | `#BA9566` | 干裂、卷叶、轻薄轮廓 |
| 目的地/火种 | 铜金与暖橙 | `#D9AF60`、`#EFAB63` | 暖窗、铜铃形状、火焰动态区别 |

干/湿、完整/破坏、热流/普通风必须至少有两类提示：颜色与形状、形状与动画、视觉与声音。关闭音频或色彩辨识能力不同的玩家也要能理解。

### 9.5 重点新素材的可读性

**干绳：**有轻微弧度与拉紧方向；受损后出现可见纤维，不用血条代替材料变化。断开时两端分离，桥的支撑关系同时改变。

**湿木与干枝：**不能仅画两个不同颜色的同款木块。湿木有厚苔与滴水，干枝更细、脆、卷曲；同样火种命中后有明显不同过程。

**叶翼：**闭合时是旅行者背后的叶片装备，展开时轮廓足够大，能解释受风；不能整个人毫无变化却开始飘浮。运动方向由姿态与拖尾解释，不靠头顶“飞行 Buff”图标。

**热流：**以真实受场影响的可见落叶为主要信息，柔和气线为补充。特效不能显示“向上”，权威场却在此处向下或已经消失。

**风铃岛：**优先画暖窗、工具、绳结、修补痕迹，而不是到处加神秘发光水晶。这里应该像有人生活，不像为领奖设计的平台。

### 9.6 动画与像素尺度

保持原素材的有效像素尺度与清晰度；角色/交互精灵与背景可采用不同但一致的采样策略。不要全局套像素滤镜，也不要无脑把所有原生小图双线性放大成模糊轮廓。

所有新增动画记录每帧时长、脚底基线、挂点与分层。命中点由权威动作/碰撞决定，特效在相应位置表现，不根据“第几帧看起来最帅”反过来改变伤害与断绳事实。

允许小幅纯表现的回弹和形变，但主要承载物的位置与形状必须与碰撞表示一致。

### 9.7 给新素材创作者的统一简报

> 创作一个二维横向冒险游戏中的清晨巨树驿站。旅行者很小，树与森林很大；人物和可交互物保持清楚的卡通精灵轮廓，远景柔和、有空气层次。草土平台能看清落脚边缘，树桥的绳索能看懂受力关系。用叶绿、温暖木色、薄云奶蓝构成主体，高处只有少量铜金暖光。所有互动素材提供完整、湿润、受损、燃烧/焦化等必要状态，并保持原点和挂点一致。不要使用已有角色或徽标，不照搬原版完整地图；不要写实 3D、过度油画、全屏粒子、霓虹泛光或通用“16 位像素滤镜”。

该简报用于后续原创生产，不表示本次已经生成图片。

## 10. 音乐设计：事件可以涌现，音乐要读懂状态

### 10.1 参考原曲的方式

NECORD 官方发布中可检索到 `When The Morning Comes`、`The Raindrop Flower`、`Start The Adventure` 及交响编配版本。[S07][S08][S09] 它们可用来建立森林、行进、启程等情绪参照，但**不能把演奏版编制直接当成 TMS273 客户端原曲的制作参数**。

本次未对目标客户端音频进行逐段试听或音频分析，故不声称原曲的准确 BPM、调性、乐器轨数、响度或循环点。以下是为这个新序章提出的声音语言；正式制作前，应以有权使用的目标音频补做 A/B 听辨记录。

### 10.2 应当继承的创作语言，而非旋律

为本关选择短小可记忆的旋律动机，温暖而不厚重的和声，木质/拨弦/轻打击的触感，以及能在长时间循环中留出空间的编排。可以带一点未解开的向往，但不在第一次看到龙时就使用终局大战的合唱与铜管齐奏。

这是一项设计取舍：**冒险欲来自“前面还有东西”，不必每次都靠宏大史诗制造。** 不复制既有旋律，不把原曲改几个音当作原创。

### 10.3 原创主题《风从树梢来》的制作规格

| 项目 | 建议 |
|---|---|
| 速度/拍号 | 首轮尝试 96 BPM、4/4；为新作参数，不是原曲参数 |
| 循环长度 | 32 小节，约 80 秒；不是为了第 60 秒必达而写的线性配乐 |
| 核心动机 | 4—6 音的原创短句；起点只出现片段，高处以更开阔的声部回应 |
| 基础音色 | 轻拨弦、少量木质击音、柔和持续音；具体乐器由作曲者听辨后选择 |
| 上层色彩 | 轻木管/气息型旋律、少量钟琴或风铃质感，不堆叠高频尖音 |
| 禁止 | 直接截取原作旋律、预烘焙“第 55 秒成功”高潮、密集战鼓压过交互 |
| 工程交付 | 4 个等长、同起点、可同步循环的 stem，外加短发现音型与混音预览 |

### 10.4 四条音乐分层

| 层 | 名称 | 读取什么状态 | 表现什么 |
|---|---|---|---|
| M1 | 林下 | 始终作为基础循环 | 温暖、可停留、留白 |
| M2 | 行进 | 持续有效移动与运动强度，经平滑处理 | 一点轻盈脉动；不能走一步开、停一步关 |
| M3 | 高处 | 角色真实高度、树冠遮挡、天空可见度 | 音域与空间展开；根道登高也能听到 |
| M4 | 发现 | 首次有效看见驿站近景/云中航路，并已稳定到达 | 一次很短的动机回答，不夺走控制 |

音乐读取 `height/sky_visibility/motion/discovery_fact`，不读取 `route_id == fire`。走桥和借火抵达同样高度，都应有空间打开的感觉。

所有持续层保持同一音乐时钟，通过增益变化出入。普通层切换首轮采用约 1—2 秒平滑与状态回滞，防止在边界来回闪烁。发现音型每个角色每次相关发现最多一次；重连重放历史不重新庆祝。

服务器只给事实与时间基准，客户端负责音乐调度与设备差异。音乐播放完成永远不是通关条件。

### 10.5 风铃：把地标、方向和音乐接起来

风铃既是岛上物件，也能提供方向性声音。真实风改变摇动和短促铃声；到达时音乐里的少量钟音可以与它协调，但不能让每次起风都播放固定长度“成功音效”。

这是本关最重要的声音桥梁：玩家在地面听见它，凭好奇接近它，到达以后发现它真的挂在那里。

### 10.6 给作曲/音效创作者的简报

> 为二维森林冒险的第一分钟创作一首温暖、轻盈、带少量未知感的原创循环音乐。不要复写任何已有游戏旋律。基础层能够独立循环；移动层增加轻微脉动；高度层让听感随树冠遮挡减少而打开；发现层只给一个短回答。整体留足空间给草地脚步、绳索纤维断裂、木桥落地、叶翼张开和远处风铃。重点是“我正在发现一个有生活的世界”，不是“我完成了教程关卡”。

## 11. 音效规格：让耳朵也能理解因果

### 11.1 三层反馈

```text
输入/动作层：挥动、起跳、展开叶翼
接触/材料层：击中干绳、湿木、石头，各不相同
结果/环境层：绳断、桥落、燃烧持续、气流托起、远处风铃回应
```

不能所有技能命中都播放同一个爆炸声，结果只通过 UI 告知。声音层应区分“我出了招”和“世界真的发生了变化”。

### 11.3 混音与无障碍

第一分钟交互声优先于装饰环境声。多个枯枝同时燃烧应聚合成附近火源层，不为每根枝条无限开声道。桥落地等关键变化可短暂让出混音空间，但不能突然掐断整个 BGM。

可调音乐、环境、交互音量；重要因果不能只靠听觉。减少动态选项关闭强晃动和过度镜头缓动，但保留必要落点与气流方向线索。Web 客户端在已有用户手势后启动音频；音频尚未就绪不阻止进入世界。

### 12.2 P1 扩展资产

叶舟需要可承载的平台表示、受风帆面与倾斜反馈；远程断绳需要命中反馈与飞行物；轻身路线主要复用现有角色动作。它们都不需要另画一张“风职业地图”。

更复杂的龙落地/起飞、NPC 见闻表情、小队互相影响与烟雾引起生物回避，放在核心三条路验证之后。

### 12.3 生产顺序

先做地面/角色手感，再做树桥与绳索，然后做干湿材料和热流/叶翼。接着做共同目的地与视听兑现，最后补龙、生活角色与装饰。

**不能先花大部分时间做巨龙电影级出场，再发现玩家砍绳子的反馈根本看不懂。**

## 13. Rust 权威世界与 Web 表达的最小落地

本节描述职责与契约，不假定仓库已存在这些类型或目录。沿用既有研究中的 `CharacterState`、`MapInstance`、`ActionRequest/ActionResult`、事件与物品事务等边界；单进程模块化优先，不为这个开场拆微服务。[L02]

### 13.1 服务端拥有事实，客户端拥有表达

```text
客户端输入意图
  → 服务端校验动作资格/时序/范围
  → 计算命中与热量/切割/冲量等作用
  → 更新材料、结构、气流与移动状态
  → 提交有因果来源的状态变化/事件
  → 客户端表现绳断、桥落、火焰、叶翼、音乐
```

客户端可以预测本地移动和动作起手，但不能自行宣布绳索已经断裂、桥已经承载、热流强度足够或目的地已经发现。预测与权威状态不一致时，要进行受控校正，而不是再维护一套“客户端真实世界”。

### 13.2 最小状态概念

```text
Entity
  id, transform, optional collider
  optional Material { kind, integrity, moisture, heat, fuel }
  optional Support { attachments, hinge, load_state }
  optional Aerodynamics { effective_area, mass, deployed }
  optional Perception { range, occlusion, observed_events }

OpeningInstance
  instance_id, rule_version, scenario_seed, simulation_tick
  entities, active_force_fields, bridge_connections
  discovery_facts, bounded_recent_causal_events
```

组件是能力范围，不要求每个实体都拥有温度、血量和 AI。风既可来自区域场，也可来自带位置的技能事件；两者最终进入同一受风计算接口。

### 13.3 规则计算顺序

复用现有权威 tick。独立灰盒可以从固定 30 Hz 起步，但接入项目时不能为了开场再建立第二个互相冲突的世界时钟。

一个可测试的逻辑顺序如下：

```text
1. 读取本 tick 的合法输入，稳定排序并去重。
2. 生成命中与作用请求：切割、热量、冲量等。
3. 从一致快照汇总作用，更新材料与燃料。
4. 处理材料失效导致的结构约束变化。
5. 更新有限气流场与相关运动，执行支撑/碰撞检测。
6. 根据新状态生成见闻、发现与检查点事实。
7. 发布带序号的权威变化；视听层只消费结果。
```

传播规则采用快照汇总或明确的离散子步，避免实体遍历顺序改变“谁先烧起来”。固定时间步不自动保证跨平台位级确定性；首版回放验证限定同一构建与规则版本，必要时记录权威快照纠偏。

### 13.4 事件记录：支持解释，不盲目全量事件溯源

```yaml
id: event-unique-id
instance_id: opening-instance-id
tick: 824
type: MaterialIgnited
subject_id: dry_branch_cluster_02
source_entity_id: actor_or_heat_source_id
caused_by: [prior_effect_event_id]
rule_id: material.ignite.v1
changed_fields:
  burning: true
```

保留近期关键事件的因果关联，足以解释“热作用 → 燃烧 → 热流 → 上升”。不保存每片装饰落叶每帧的位置，也不为了旅行日志建设全量历史重放平台。

核心到达/奖励事实使用现有持久化与幂等机制；没有既有奖励事务时，P0 先只做发现和检查点，不临时新增会被重连重复领取的货币奖励。

### 13.5 到达判定

服务端校验角色在目标区域形成有效落脚；可用短暂稳定窗口过滤高速掠过，但不能要求停下来点击“完成”。目标条件与职业、路径编号、是否击杀生物无关。

记录发现时，角色检查点和该角色的发现事实应通过同一可靠提交边界更新。断线重试按稳定键去重，事件重放不重复播放发现音型或发奖励。

### 13.6 存档与重连

保存实例中重要材料/结构状态与角色状态；装饰粒子可重建。重连读取权威快照，不将“开场播放进度”当作世界状态。

如果存在离线时间推进，燃料、持续效果和龙航线采用明确、可测试的推进规则；不能客户端自行补算出与服务端不同的烧毁结果。P0 允许实例无人时暂停模拟，但必须明确这是实例生命周期策略，不宣传为全服持续生态。

### 13.7 原有工程约束

后续构建与启动继续统一使用项目中的 `启动3010.command`。本稿不修改该脚本，不另行定义绕过项目入口的启动方法。

## 14. 多人扩展：同一世界，不等于所有人共享一切破坏

P0 单人先证明规则与体验成立。P1 在同一小队实例中验证共同事实：甲砍断绳索，乙看到同一座桥落下；甲点火，乙可以借用同一股热流。

树桥只断一次，结构变化只有一个权威结果；两个客户端同时施加作用不会生成两座桥。每个角色的到达与检查点独立计算，不因队友先到达就把全队强制搬过去。

没有玩家之间的强制身体挤压，没有通过不断放火烧掉唯一通路的设计。风作用于其他玩家叶翼的规则需单独验证可控性；必要时对玩家施力设一致、公开的强度限制，而不是根据“谁快完成了”临时免疫。

将公共大世界的长期环境记忆、修复、资源再生与破坏治理留给后续系统设计，不能用一个新手实例的结果声称已经解决全服涌现生态。

## 15. 验收：证明这是规则的组合，而不是三段隐藏脚本

下列均为计划中的测试，不是已执行结果。

### 15.1 反脚本测试

| 测试 | 操作 | 必须得到的结果 |
|---|---|---|
| 换施加者 | 让另一种合法热源加热同一干枝 | 相同材料条件下可点燃，不检查“火路线玩家” |
| 换目标实例 | 把同材质干绳复制到另一位置 | 使用相同规则，不依赖特定实体 ID |
| 换材料 | 把绳材质改为不可被当前切割破坏的材料 | 不再断；反馈解释来自材料，不是职业权限 |
| 交叉解法 | 用热作用烧断支持范围内的干绳 | 同样释放桥，不要求先选择放桥路线 |
| 提前抵达 | 用已有合法位移越过中间实验 | 到达有效，不补做教程 |
| 不行动 | 玩家静止一段时间 | 环境按其支持范围运行，不主动替玩家通关 |
| 关闭表现 | 禁用发现音乐和镜头帮助 | 世界结果、碰撞与完成条件不变 |
| 遍历顺序 | 调整实体存储/遍历顺序后重放同一固定案例 | 材料与结构结果不应产生无解释差异 |

### 15.2 路径与恢复测试

A 根道在没有任何特殊技能时能完成。B 近身切绳后桥有真实可用碰撞。C 正确干枝与叶翼能完成借热流，湿木的短时反馈不同。全部可燃物耗尽后仍能通过根道完成。桥在各阶段运动时，跌落均不进入无出口口袋。

把角色放在每个重要分支的失误落点，验证可以继续前进或返回尝试点；不能只有理想操作录像能走通。

### 15.3 网络与事实测试

重复输入不重复施放；客户端伪造点燃/到达无效；断绳后重连不复原桥；同时命中同一绳索只有一次结构失效；延迟到达的事件不使火重新点燃；重放发现事件不重复奖励/音乐。

关键因果链可在调试面板查看，但普通玩家界面不暴露内部调试树。

### 15.4 视听与体验测试

关闭音频仍能读出热流。降低色彩区分仍能认出湿木与干枝。减少动态模式不会隐藏落点。不同窗口尺寸均能在合理时机发现风铃岛。所有声音循环正确停止，离开火源不再持续大音量噼啪。

到达时回头能看到与本局行动相符的世界状态，而不是预渲染的一张固定“烧过的森林”图。

### 15.5 新玩家观察指标

建议用约 12—20 名不了解方案的玩家做初轮观察；数字是验证目标，不是已证明效果。观察过程中不口头教解法，结束后再询问。

| 指标 | 首轮期望 | 如何观察 |
|---|---|---|
| 控制权 | 第一个可交互世界帧即可移动；无强制弹窗 | 客户端输入记录 + 录像 |
| 目标理解 | 多数人在约 10—15 秒内注意到高处驿站 | 回放注视/行动方向，事后询问，不把沉默当不理解 |
| 第一次因果反馈 | 约 20—30 秒内发生一次由自己输入带来的可见结果 | 命中、材料变化、移动/落脚均可；不只计算点火 |
| 因果理解 | 大多数尝试者能说出“为什么桥落/为什么飞起” | 事后复述，避免诱导提问 |
| 抵达节奏 | 主体分布约 45—75 秒；慢玩家仍有路走 | 统计实际分布，超时不算自动失败 |
| 迁移能力 | 能预测另一根同类绳索/干枝会怎样反应 | 给第二个未教学目标测试 |
| 可讲述差异 | 出现不只一种自然复述 | 记录原话，而非只统计三个预设路径 ID |

若玩家看不懂，先改材料线索、空间布局与反馈，再考虑加提示。若所有人都只按高亮箭头走一条路，要检查是否把规则重新包装成了固定任务。

## 16. 开发里程碑与停止条件

### M0：基线与资源取证

确认项目现有移动、碰撞、地图、技能作用、存档与音频接口；确认 TMS273 构建和素材清单。先用当前角色测 `H/J/D`，再灰盒地图。每一项原作参考保留来源与核验状态。

退出条件：地图尺度能与现有手感匹配；未核验资源不被当作已存在的正式资产排期。

### M1：只有根道，也值得走到高处

实现同一地图、目的地剪影、根道、稳定落脚和可控视野。先无龙、无火、无复杂特效。

退出条件：完全没有特殊能力的角色能独立找到目标并抵达；到达后的视野兑现有效，而不是空旷白盒里的一个触发区。

### M2：放桥不是机关脚本

加入材料完整度、有效命中、支撑失效与受限树桥运动。实现同材质换实体、换施加者的测试。

退出条件：桥和碰撞一致；交互结果能被解释；失败不软锁；没有硬编码职业开门。

### M3：借火证明规则可组合

加入湿度/热量/燃料、有限燃烧、上升场、叶翼、可视落叶。至少实现“火 → 绳索失效”和“火 → 热流 → 叶翼”两种后果。

退出条件：三条路径能在同一地图上成立，并能交叉；只用换配置就能产生干湿差异，不新增故事分支处理器。

### M4：视听、生活与一分钟节奏

加入原创方向的景物、风铃、音乐分层、必要动作音效与巡风龙低成本表现，最后补修铃人回应。进行真实新玩家观察。

退出条件：玩家能用自己的话说明发生了什么；到达不依赖固定时刻；高处兑现不是 UI 胜利面板。

### M5：扩展风与小队，不扩第二套世界

加入风作用、叶舟承载或已有轻身能力；验证两个玩家共享桥、火和气流。保持根道与共同终点。

退出条件：新能力主要通过新作用参数和现有规则组合加入，而不是复制整个开场地图。

### 第一张可以直接开工的任务卡

**标题：在一张灰盒里，让同一个目标同时可经“根道”和“切绳落桥”到达。**

输入是角色现有走跳与一种合法切割作用；输出是服务端拥有的绳索失效、树桥状态和到达事实。客户端只表现结果。验收包括无技能可达、远端观察一致、重复命中去重、跌落可恢复，以及不依赖任何职业/路线剧情变量。

这张卡通过以后，再接入火与叶翼。不要先做完整巨龙片头，不要先采购所有音乐，不要先设计全森林生态。

## 17. 这一分钟之后，如何接回冒险岛的成长循环

到达驿站不是系统展示结束，而是玩家已经学会一种可以继续迁移的看世界方式。

下一片地区用同样的材料语法提供一个更大的问题：例如热源来自会移动的生物，绳索连接两处结构，风向让同一种能力产生不同结果。随后让战斗、装备与技能成长改变**可施加的作用范围和可承担的风险**，而不只是把伤害数字变大。

不必在第一分钟同时验证任务、装备强化、Boss、多人合作、完整物理与生态。第一分钟只要建立一个足够强的承诺：

> **“你掌握的能力能够改变这个世界；你看到的现象值得理解；同一个地方，不同的人会有不同的来路。”**
