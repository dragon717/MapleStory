## 0. Owner 已经给出的答案与目标修正

原问题：“你最希望在这个世界里亲自经历、并在离开后依然记得的一个瞬间，是什么？”

Owner 原话：

> **我是木鸟，我希望我仍记得这个世界的点点滴滴，我还会继续回来冒险。**

这不是让你精准表演一个感动瞬间。Owner 已进一步明确：

- 需要的不是一个只能完成最小体验的 Demo，而是能够持续向前发展的世界。
- 发展不等于制造无聊内容，而是实现令人振奋的机制与规则，由它们指导技能、对话、世界底层和各类业务逻辑的开发。
- 世界的完整度不主要取决于首批内容量，而在于玩家能在其中发现持续展开的可能，以及支撑后续发展的完整闭环。
- 第一轮允许有实质性的、大量的设计与工程工作；不能以“先做 Demo”为由回避必要基础，也不能提出没有完成边界的无限工程。
- 世界建立后，应能沿着自己的规律继续变得更好玩、更有趣，而不是推倒第一版，另起一个真正的项目。

**本次交付目标：可持续演化的完整世界 v1。**

这里的 v1 是这个世界的第一代正式基础，不代表商业正式上线；后续版本沿用它的身份、世界事实、角色经历、规则契约、内容管线和存档语义继续生长。

“世界可以继续发展”不等于“Agent 可以永远不交付”。第一轮必须有明确范围、完成判据、运行入口和真实成果。

## 1. 这次要纠正的不是内容数量，而是完成标准

上一版已经要求完整入口、行动、成长、回访、后果与人物回应，也反对十个互不相连的演示。但以“约 30—60 分钟首章”为主要交付锚点，仍可能让开发停在一段漂亮流程。

本版明确替换以下口径：

| 旧交付重心 | 本版交付重心 |
| --- | --- |
| 完成一段首章经历 | 建立能够承载首章及后续发展的世界；首章只是进入它的一条路径 |
| 一次到达、一次帮助、一次相认 | 这些行为属于可重复适用、会随事实与关系变化的机制，而非一次性脚本 |
| “之后可以扩展”的架构说明 | 本轮实际完成一次二次生长，展示新内容怎样进入同一个世界 |
| 做完设施恢复后留下静态成果 | 恢复结果继续改变通行、运输、居民目标与后续行动条件 |
| 以体验时长作为范围标尺 | 以因果、资源、关系、历史和扩展闭环是否成立作为标尺 |
| 宏大机制都留在文档，先交演示 | 必要的规则基础和跨模块接入本轮实做；真正后续内容明确列出，不能冒充完成 |

取消“30—60 分钟首章”作为本轮范围或完成依据。不要用地图数、NPC 数、任务数、代码行数和游玩分钟数替代世界完成度。

也不要把“无限可能性”写成无限内容、无限模拟或无限自动生成的承诺。本轮应证明的是：**有限而可信的规则，可以在不同对象、能力、目标和情境中，持续产生新的有效行动与后果；新增内容有真实可行的接入路径。**

## 2. 你承担创作与工程，我承担亲自体验后的判断

你承担设计整合、产品取舍、架构决策、实际实现与交付，不只是给我建议或输出文档。

我已经明确方向，不再要求我先成为总策划、架构师、数值策划、美术总监和代理协调员。正常、可逆、在任务范围内的选择由你决定，记录理由与假设，不将候选方案反复丢回给我批准。

我的回答是长期情绪方向：值得记住，也值得回来。它不授权用每日作业、错过惩罚、无穷刷取和人为制造的事故来逼我回来，也不要求世界处处赞美我。

你的交付要让我能够直接游玩；我的反馈用来判断真实感受，而不是替你发现编译错误、补上断开的接口或脑补尚未实现的机制。

**本轮是实际开发委托。文档必须指导实现，不能代替实现。**

“新的迪士尼”保留为长期文化愿景：拥有自己的名字、地方、人物、声音、故事与共同记忆；不承诺商业成功，不要求本轮制作跨媒体版图。

还要记住，Owner 说的是“我记得这个世界的点点滴滴”，不只是“世界记得我”。这是一种双向关系：人物能认出我的经历，我也能认出这条路、这个人、这段声音，以及它们后来发生的变化。

因此保留可辨认的地方、人物性格、日常细节与回家的路径。不要让一切为了“动态”不停重置或随机换样；变化应在连续身份上积累，过去与现在能够被玩家联系起来。

## 4. 先定义什么叫“完整”，再确定工程范围

本版完整性由下列六个方面共同构成，不能只完成其中一项：

**因果完整。** 技能、材料、环境、怪物、NPC 与设施通过一致事实和规则相互作用。一个系统产生的后果可以成为另一个系统的真实输入。

**行动完整。** 玩家能观察、尝试、掌握能力、探索、战斗或采取其他办法、承担后果、返回与再次出发；不是只能观看自动运行的模拟。

**生活完整。** 世界有可以持续的日常、实体目标、资源来源与去向。所有一次性问题解决后，不会只剩等待玩家退出的空场景。

**历史完整。** 重要后果跨交互、跨访问、跨重连保持语义一致；临时状态、长期事实、局部记忆、历史摘要各有生命周期。

**体验完整。** 名称、画面、动作、声音、对白、界面、碰撞与反馈共同解释真实状态。可玩入口与基本引导不需要 Owner 读策划案才能理解。

**生长完整。** 后续能力、人物、区域或材料能利用已建立的契约接入；本轮已经用真实新增内容验证，而不只是留下接口与 TODO。

“完整”不意味着第一版实现所有职业、全部经济、所有生命演化、全服历史文化和所有未来规则。你必须在短设计决策中明确本轮承担的核心能力与后续边界，不能把尚未解决的基础缺口改名为“扩展方向”。

核心机制入选时，必须写清它给玩家带来的新行动、可感知反馈和有意义选择。只有数据流闭合、没有新办法可用或没有值得关心的结果，不算令人振奋的机制。反过来，一段有冲击力的演出如果不能由世界事实支持，也不算规则成立。

你需要同时证明“现在值得玩”和“以后能继续长”，不能拿架构的通用性替代前者，也不能拿一次精彩体验替代后者。

## 5. 本轮必须完成的十件事

这十件事由上一版委托与本次 Owner 修正整合而来，不是声称仓库中已有同名、同序的排名。它们共享一套世界事实，不是十个孤立项目。

### 5.1 作品名字：让它开始拥有自己的身份

自主选择一个贴合核心的原创工作名，写出一句清楚的作品承诺。不要交几十个候选让我选择，也不要只将“冒险岛”替换成近义词。

名字应能容纳探索、未知、温柔与危险、行动痕迹、关系和持续冒险，不被某一张图或某一种能力绑死。落实到原创入口、相应标题与玩家可见表达。

保留原版资料的来源与技术历史。工作名可以迭代，不宣称已做商标、域名或商业使用核验。

### 5.2 世界名字与存在逻辑：先让这里成立

区分作品、世界、地区和地标的命名职责。建立足以指导第一代世界的基础设定：地理关系、居民生活、物资与交通、能力来源、危险、尚未解决的变化。

每个重要设定都要影响至少一种已实现的状态、行动条件或可观察表达，而不是只存在于百科。并非每段背景都要模拟；先写清哪些是作者设定、哪些是运行状态、哪些是传闻。

必须有稳定日常与休憩处，不把所有地方设计成求助现场。世界不在玩家周围临时生成需求来讨好玩家。

### 5.3 概念名字与语义契约：不是只换皮

为实际进入本轮的能力、节点、天命、残留痕迹、重要物件与人物称呼建立统一词表：开发概念、世界内称呼、含义、真实行为、稳定 ID、显示位置、旧称别名。

名称服务于理解；“设置”“背包”等通用词不必强行改名。持久化键、协议字段、素材来源和历史引用不因显示名调整而失效。

技能名、居民称呼、物品说明和地图文化要来自同一套世界逻辑。不能名称很原创，底层仍是互不相关的任务脚本。

### 5.4 规则与状态基础：足以支撑后续业务

在既有 Rust 权威世界中建立清楚的数据与提交边界，令已选核心机制真正贯通，而不只是制作通用规则接口。

```text
认证后的行动意图 / 到期的实体行动 / 环境变化
→ 能力、目标、距离、资源与权限校验
→ 规则读取事实与关系
→ 产生变化提案
→ 冲突处理、资源约束与受控提交
→ 新事实
→ 行为、快照、表现与必要的事件归因
→ 局部记忆及后续行动条件
```

这表示职责，不要求机械新增上述每一层。优先沿现有状态拥有者接入，避免复制第二套世界。

必须让关键规则跨来源、跨对象、跨情境成立。火源不能直接调用“送玩家到高台”，对白不能直接伪造货物已经抵达，任务状态不能替代桥的真实通行事实。

### 5.5 地理、移动与能力：让同一地方可以被重新理解

构造相互连通的地区与可记忆地标，保留并打磨既有横版操作。基础移动、碰撞、镜头、遮挡与地图几何必须可信。

能力改变行动空间，不只改变伤害。首轮必须有能力跨探索与其他行动情境复用，且能重新激活旧地点；不允许每张图重新规定同材质的任意例外。

可存在不同难度和路线成本，但合法替代解不能因为不是标准路线而被拒绝。获得新能力后回访要真有新可能，不是隐藏着的任务标记终于变绿。

未来区域可以暂未制作，但已作为当前核心承诺展示的可交互地标必须兑现，不能让一个巨大远景空壳代替世界规模。

### 5.6 技能、战斗、物品与成长：世界规则就是玩法

复用并深化现有战斗、技能、成长、背包与恢复能力，不将项目退化成散步、对白与帮助按钮。

技能用世界已有的作用语义表达，其命中、伤害、位移、状态与环境作用有明确边界。新技能可以需要新规则，但不能每增加一个技能就重写所有环境、NPC 和地图交互。

怪物有可理解的行为与应对方式，战斗危险清楚、反馈有力，战斗结果会进入世界状态，而不只让背包数字增加。

物品有可追溯来源、持有关系与实际用途；消耗、拾取、交付与奖励通过现有权威事务处理。成长要带来可以亲自使用的新方法，数值成长可以保留，但不作为唯一变化。

### 5.7 世界流动与持续需求：恢复之后仍然有生活

以已经存在的桥、旅人、运输与设施为整合起点，恢复通行后继续连接运输、到货、停留和居民目标。

必须写清并实现“恢复后”的正常运行，而不只完成“恢复中”。例如路线恢复可改变持续运输条件；货物有来源与去向；居民会基于实际条件采取下一步行动。

不是为延长玩法反复炸桥，也不是靠无限刷新同一种事故。“后来又发生事情”应来自已经实现的环境变化、实体目标、资源状况或人员到达，不来自玩家留存标签。

同一公共范围中的设施、碰撞、物资和事实一致。部分参与、晚到、直接绕行、离开以及未贡献者使用公共成果都必须成立。

### 5.8 人物、对话与身份：世界认识的是经历过的人

NPC 具有稳定身份、有限目标、可执行的行为、局部知识和可保存的记忆。至少一个重要人物要在多次相遇与不同事实下呈现合理差异，不能只有首次帮助与固定感谢两种表情。

对话读取 NPC 当前知道的事实、处境与关系；对话中的实际交易、承诺或合作请求，仍进入权威命令边界处理。说“货到了”必须有货到的事实，答应合作也应产生可履行、可失败或可退出的行为关系。

不必使用大模型对话；固定文案与条件分支只要正确反映世界，也可以成为正式方案。对白生成不等于世界自主性。

天命保留行动历史、回应、承担、边界的顺序。要有超出通用夸奖的真实关系变化或行动机会，不能把一次帮助当人格判定，也不能把它做成刷分养成条。深层权柄可留后续，但不得用无限后续抵消本轮的人物与关系闭环。

### 5.9 行动、失败与历史：过去继续参与现在

复用已有死亡与世界痕迹能力，逐项核对源码与原设计，不能把历史版本的实现状态当当前状态。

重要行动或失败的痕迹，不应只存在于日志；它可以影响知情人物、后来者的判断、现场信息或后续行动条件。临时表现可以消失，关键归因与结果按明确政策保留。

区分死亡记录、角色幽魂、墓碑、独立虚影、经验球与觉醒人物的不同语义。来源不等于所有权；死亡不能变成更高效的资源生产路线。

本轮具体深化哪条死亡分支，由你结合当前工程和整体闭环决定。若将“残留影响后来者”作为本轮核心卖点，就必须接到真实后果；不能只做视觉影子后宣布机制完成。融合、长期觉醒等未做部分明确列为未实现，不预造一整套空框架。

### 5.10 持续运行与实际扩展：交世界，不交一次性流程

将前九项连接成可进入、可离开、可再次返回、可继续行动的同一个世界。第一段经历结束后，世界仍然有日常、可使用的成果、改变过的关系和合乎规则的后续机会。

美术、动作、音效、音乐、文本与 UI 要具备统一且可体验的表达；不能把完整概念插画当地图，把接口文档当技能，把静态人像当已经完成的行为表现。

**本轮必须完成第八节规定的“二次生长验证”，然后才能将世界基础标为完成。** 不能只把可扩展性写进总结。

## 6. 世界必须形成的六个相互连接的闭环

这里的“闭环”不是机械循环任务，更不是要求每条规则自我回授。它指行动的结果能进入后续生活，同时资源、状态与选择不会被无意耗死。

| 闭环 | 必须成立的链路 | 典型失败 |
| --- | --- | --- |
| 理解与探索 | 观察线索 → 建立预期 → 行动验证 → 学会用法 → 新地方或旧地方的新解法 → 新问题 | 第一张图教过的规律换张图就失效 |
| 能力与实践 | 获得或掌握能力 → 探索/战斗/生活中的实际用途 → 产生后果 → 调整方法与准备 → 再实践 | 新能力只有演示房里的一个靶子能用 |
| 资源与供给 | 来源 → 获取或运输 → 持有与使用 → 消耗/损耗 → 有条件的补充与替代 | 首批材料耗完世界停机，或反复进图无限领资源 |
| 地方与居民 | 环境/设施变化 → 可达性和供给改变 → NPC 更新目标与行动 → 地区新状态 → 后续机会 | 桥修好只有贴图变，人物与世界不再变化 |
| 关系与身份 | 有效行动 → 知情者形成记忆 → 下一次相遇与机会改变 → 玩家承担/拒绝/调整 → 新历史 | 每个 NPC 都读同一好感值，一次帮助永久定性 |
| 失败与再出发 | 风险可识别 → 尝试与失败 → 世界留痕 → 角色恢复/改变准备 → 再冒险 | 必须刷死获利，或一次错误永久锁住主要体验 |

每条闭环必须说明：状态拥有者、资源来源与去向、推进条件、何时结束或稳定、如何恢复、表现入口、保存范围和异常边界。

“全员离开”“所有首发设施已经修好”“一次性秘密已经发现”“某类资源短时不足”都需要有正常状态；它们不能让整个世界变成一次性消耗品。

允许玩家熟悉世界，允许安静与休息。不是每一分钟都需要新奇，更不许为了刺激持续打断玩家。回来可以为了探索，也可以为了熟悉的地方、人物、练习与共同生活。

## 7. 一条跨技能、环境、NPC、对话与历史的机制应当怎样长出来

下面是本委托新增的说明性情境，不是已经实现的功能清单，也不是必须逐幕照做的剧情：

```text
地区存在风向、干湿、热源、可燃材料与通路状态
→ 居民原本就在运输物资，运输受道路和天气条件约束
→ 玩家、NPC 或环境在各自能力范围内施加作用
→ 同样的热与材料规则决定能否燃烧、能否产生有效气流
→ 受风能力改变可达性，某些技能或工具也能处理同类问题
→ 玩家可以取道高处，也可以走旧路、修通路或帮助运输
→ 货物是否抵达取决于实际条件和行动，不取决于是否播放成功对白
→ 知情居民记得具体帮助，并据当前状态调整之后的工作与交谈
→ 玩家带着新能力回来时，旧地点可出现新的用法
→ 后续新增材料、技能、人物和区域继续进入这些契约
```

关键不在于上述内容够多，而在于：**技能、生活、对白、环境和历史没有各演各的。**

可手工创作初始地形、人物、事件条件与对白。规则驱动不是取消作者，而是不替玩家预定唯一解，不在表现层偷偷更改真实结果。

规则可以采用可控的游戏近似，不要求真实流体、全生态或逐原子物理。近似必须稳定、可读、有适用边界，不能一遇到别的对象就变成任意特例。

## 8. 第一轮的强制完成项：实际做一次“二次生长”

第一组核心内容贯通后，不要立即收工。再接入一组真实的新增内容，证明第一版不是只能演一场的程序。

由你选择与世界主题相符、规模可完成的扩展组合；至少覆盖以下三种接入，其中可以相互结合在一个新增区域或事件中：

1. **新增一种材料或能力。** 材料复用已有属性与规则；能力复用已有作用语义，并至少在两个不同情境产生有效后果，其中一个不属于首次教学现场。
2. **新增一个有不同目标的人物。** 复用事实、行动、局部记忆与对话边界，能够在介入、不介入及重逢时作出有依据的差异；不是复制旧 NPC 换名字。
3. **新增一个有实际新问题的区域或情境。** 使用已有规则和内容表达工具，允许旧能力产生不同解法；不为第二张图新写另一套碰撞、任务事实库或世界结算。

这些内容要接进正常游玩路径，不只写单元测试或独立演示页。它们不是制作完就丢弃的验收素材，而是世界继续生长的第一批内容。

交付真实的扩展记录：新增了什么，复用了哪些契约，新增了哪些必要规则，修改了哪些文件，为什么改，旧内容是否仍保持语义一致。

使用隔离的测试存档验证已有记录能继续使用；不能以清空世界、删除角色或重建整套数据库换取扩展成功。

不要承诺以后所有变化都只靠配置。**同机制内容应主要通过内容和数据扩展；真正新机制允许增加代码，但要落在清楚的职责边界，而不是到处补同一个特例。**

如果二次生长暴露出核心基础只能服务第一张图，修正这个基础后再交付。不能把它解释为“Demo 已完成，正式版再重构”。

## 9. 工程上如何做到“工作量大，但能够完成”

### 9.1 用明确契约划定有限范围

在短设计决策中，为本轮核心能力给出一张映射表：

```text
世界机制
→ 对应文档及本次决定
→ 当前已有实现与真实缺口
→ 唯一状态拥有者
→ 有效行动、输入和输出
→ 接入模块与内容位置
→ 资源及生命周期边界
→ 玩家可观察入口
→ 完成证据
```

分清“世界基础必须具备”和“可以继续加的内容”。前者包括权威、因果、供给、行为、记忆、表现和扩展路径中本轮实际依赖的部分；后者可以是更多职业、更多地区、更多物种、更多文化内容。

允许按依赖分阶段实现，但不能擅自把整个委托缩成一个最短流程。内部可使用灰盒、占位和隔离原型；对外验收必须回到完整世界 v1 的标准。

### 9.2 保留现有权威与事务边界

- 沿用当前 Rust 逻辑状态拥有者与有序模拟流程。网络接入投递命令，不绕过队列直接修改世界。
- 客户端提交意图；服务端核定主体、能力、距离、资源、状态和结果。怪物与 NPC 的实际能力可以不同，但不能绕过资源与权限约束。
- 规则读取明确事实并产生变化提案；由受控流程解决冲突和提交。禁止规则互相递归调用串出无法控制的级联。
- 不复制玩家、背包、地形和 NPC 的第二份权威状态。能复用现有领域类型就复用，不为“万物皆事实”强行把全部数据改成字符串属性袋。
- 多条规则竞争同一资源或目标时，要规定稳定处理方式与失败结果；不能分别检查成功后重复消费同一份材料，也不能事后夹到零掩盖冲突。
- 持久事实与相关资源副作用遵循既有事务和幂等约束；写入失败不能广播永久成功。瞬时物理不必每帧入库，但持久化边界必须清楚。
- 协议、版本、前后端、机器人和内容消费者按实际依赖同步更新。稳定 ID 与迁移兼容性纳入本轮，不靠清档解决。

### 9.3 让模拟与存储有明确上限

- 活跃区域使用适合当前游戏的模拟精度；低活跃区域可用到期行动或有界补算。精度差异不能改变关键资源、历史与实体身份语义。
- 无人在线、重连和进程恢复时的推进方式要明确；不以“世界先于玩家”为由要求所有地图永远全帧模拟。
- 区分真实经过时间、模拟步进时间和持久期限，防止重复补算、刷新期限与离线收益重复领取。
- 规则传播、每步工作量、实体数量、积压处理、临时痕迹、记忆和历史保留都有预算。关键事实不能因静默丢弃队列而消失。
- 有反馈回路的机制要有耗散、资源限制、阈值或明确状态边界，防止无限产出与单帧死循环。具体方式由机制决定，不统一塞冷却掩盖问题。
- 性能目标根据当前工程、硬件与实际测量设置，记录真实结果，不虚构支持人数或永远稳定的承诺。

### 9.4 世界稳定不等于不会改变

为关键区域、资源与人物定义正常可持续状态、异常状态以及可恢复途径。允许危险和损失，但不能让一次普通失误或恶意行为永远摧毁所有后续玩法。

公共设施可以具有耐久、维护或危机，但本轮不强制引入周期维护作业。采用任何限制都要清楚说明机制与权限，不能一边声称同规则，一边暗中为标准剧情开特例。

首轮不必实现完整通胀模型、所有资源再生与全生态。必须完成的是本轮实际使用资源的来源、消耗、补充与防重复，以及主要体验的再出发途径。

### 9.5 生长靠真实制作路径，不靠空框架

整理一条实际可用的内容制作路径：定义内容、检查引用与条件、装配资源、加载、运行、必要迁移。复用项目现有工具；缺口只补到本轮真实需要，不先开发通用编辑器、脚本语言和插件生态。

表现层必须解释事实：碰撞与地图一致，技能作用范围与反馈一致，NPC 工作能被感知，声音与状态变化相称。必要 UI、字幕、操作提示与无障碍选择保留，不把看不懂界面当作探索。

渲染器、框架、数据库和服务结构以当前有效工程为准。需要重构时说明阻碍、最小职责调整、兼容方式与验证，不以“渐进”为借口永久叠补丁，也不以“完整”为由全部推倒。

## 10. 自主推进方式：有阶段，但没有停在 Demo 的退路

### 阶段 A：核查与范围落实

读取 Owner 已回答的内容与必要文档，检查代码与实际入口，确定本轮核心机制、六个闭环的落点、已有成果、关键冲突和范围。

选择工作名、世界名与命名体系主方案。输出短而能执行的设计决定，任务仍写进 `PLAN.md`。不在命名或宏大世界观上无限消耗，不向我追加问卷。

### 阶段 B：补足规则基础并接入现有系统

先沿一条端到端因果链验证权威状态、技能/交互、表现和保存，再逐步贯通其他核心领域。不能各模块完成一小部分后，让 Owner 负责想象整体。

最短因果链只是内部集成工具，不是本任务的最终交付。随后必须继续完成生活供给、居民行动、关系历史、再出发与扩展验证。

### 阶段 C：世界运行与长期后果

打通不介入、部分介入、成功、失败、离开、回来与晚到情境。检查一次性内容消耗之后世界仍有什么可做、什么会自行推进、什么进入稳定日常。

把关键后果接到实际表现和后续行为，不用更多文字解释替代还没写的代码。

### 阶段 D：二次生长与回归

完成第八节的真实新增内容，检查旧能力、旧地区、人物与存档仍然成立。修正扩展时暴露的职责问题，然后保留新增内容成为世界的一部分。

### 阶段 E：完成必要自检，交付可直接游玩的世界

执行本轮需要的编译、类型检查、定向规则与持久化检查，修复本轮阻断和回归，保留真实结果。与本次无关的既有问题单独说明，不虚构通过，也不让它们掩盖本次新问题。

有真实子代理能力才按正交职责分配；共享协议、持久状态和集成由统筹负责。没有子代理就顺序完成，不虚构模型、任务与并发工作，不让 Owner 充当协调员。

若工具、权限或资源构成真实阻塞，保存已完成工作、精确定位阻塞、明确哪些目标尚未完成。不能因为工作量大就改称 Demo 已达标，也不能因任务长期而声称当前会话结束后会自动继续开发。

## 11. 验收必须证明“世界成立”与“世界能长大”

下表是本轮行为标准，不构成对用户在线环境的额外测试授权。按仓库政策采用必要定向检查与隔离数据，真实观感交 Owner 亲测。

| 验收面 | 需要验证的情境 | 达标依据 |
| --- | --- | --- |
| 可进入 | 新角色从正常入口进入 | 不需 GM、开发后台或阅读策划案；入口与必要资源齐全 |
| 可行动 | 探索、战斗或其他方式解决问题 | 控制、碰撞、危险反馈和结果真实连通 |
| 可迁移的理解 | 同一规则换材料、来源或地点 | 条件相同则语义一致；新增规则的边界明确 |
| 能力扩展 | 一项能力用于不同活动并回访旧地 | 真实改变行动可能，不只是解锁一段对白 |
| 无人介入 | 玩家走开或没有玩家在场 | NPC 与地区按既定规则推进或进入合理稳定状态 |
| 内容消耗后 | 首发秘密已知、设施已恢复 | 仍存在生活、利用、实践与后续行动，不依赖重置剧情 |
| 资源可持续 | 消耗材料、补给不足或库存变化 | 有限来源、去向、补充或替代；无凭空增殖或永久卡死 |
| 公共现实 | 两个玩家、部分参与和晚到 | 同一事实一致、贡献准确；未参与者能使用公共成果 |
| 局部知识 | 知情与不知情 NPC 面对同一玩家 | 回应有来源，无法读心或全知，承诺对应真实行为 |
| 历史与恢复 | 离开、返回、重连、隔离重启检查 | 保存该保存的事实，清理该清理的临时状态；不重复结算 |
| 失败与后果 | 可识别风险导致失败 | 恢复与再出发成立，痕迹有来源，不鼓励刷死获利 |
| 规则冲突 | 并发意图、重复请求、资源不足 | 明确拒绝或有序裁决，不重复消耗/产出，不留下假成功 |
| 二次生长 | 新材料/能力、人物与区域实际加入 | 新内容已接入游戏，旧内容可继续使用，改动范围可解释 |
| 表达质量 | 名称、画面、声音、动作与对白 | 支持理解与记忆，不以占位符或技术日志代替实际体验 |
| 运行预算 | 持续推进、无人补算、事件/历史积累 | 工作量与保留有上限，关键结果不因静默丢弃而失真 |

不能把“通过检查”写成“Owner 已感到惊奇”。工程结果与情绪结果分别标记。

不要为追求表格全绿恢复已取消的独立 QA、反复跑无关全量测试或自动操作 Owner 的在线角色。证据不足就标“未验证”，不是虚构通过或降低验收标准。

## 12. 权限与现有成果保护

授权范围：当前任务内的可逆代码、配置、内容与文档修改，以及符合仓库政策的必要定向自检。

不因此授权：删库、覆盖未提交修改、强推、破坏性迁移、购买资源、公开发布、批量停进程、访问无关真实账号数据、重置陪测机器人或中断 Owner 正在使用的服务。
