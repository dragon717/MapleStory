## 2. 物品权威世界模型细节

完整审查见 `docs/technical/物品系统审查与权威世界模型改造.md`。

- 「①/②/③」＝**已落地**；「增量 2/3/4/5」＝路线图**未落地**，两套互不相干。
- **位置即身份**：`inventory` / `equipped` / `storage` 主键＝账户+槽位；`InventoryItem` 无 id / owner / state；唯一显式 owner 是 `drops.owner_account_id`。
- `server/src/auth/item_world.rs`：`Owner` / `ItemLocation`（事实）/ `ContainerSide`（意图，**无槽位**）/ `ItemState`；私有 `Source` / `Destination`；`move_stack`。**两层错误**：`peek` / `can_accept` 返回 `Result<Result<_, MoveRefusal>, String>`——`Ok(Err)`＝业务拒绝、`Err`＝回滚；`MoveRefusal` **不含措辞**，可见码只在 `StorageOperation::refusal_code` 翻译，**不要伪造别人的码**。顺序 `peek→can_accept→take→put` 不可变。
- **已论证（别重读代码再推）**：
  - 增量 2 装备栏 ⇒ **不纳入**（槽位互换且反向 put，目标槽位由 `equipment_slot` 唯一决定）。
  - 增量 3 地面 ⇒ **只纳入「去处命名」，不纳入容器契约**（`storage_transfer` 把同一业务码当硬错误、`pickup` 当业务拒绝并恢复掉落 ⇒ 语义相反）；依赖增量 4。
  - `is_drop_restricted` 是**销毁**不是 Move。
- **整表写回**的分界＝**有没有事务**。A 组 4 处非事务（`trade.rs` 买/卖/买回 + `cashshop.rs::step_rental_expiries`）原先静默吞错 ⇒ **NB-04 已修**（`auth/shop.rs::shop_*_commit` 单事务提交，`trade.rs` 三 handler 只在 commit 成功后改内存；`push_shop_rebuy` 收敛为 `#[cfg(test)]`）。B 组 11 处事务内问题是 §34 修改权泄漏。增量 4~5 未做：`add_items` 等降 `pub(crate)`、堵 `write_inventory` 整表重写；`add_inventory_tx` 的 `.code()` 抹掉了类型 ⇒ 拾取侧类型化拒绝要先收敛返回类型。
- **失败注入的坑**：`auth::start` spawn 的常驻后台线程持有同一个 `Arc<Mutex<Connection>>`，「握住库锁」会卡死它（实测挂死 16 分钟）⇒ 用 `Store::deny_persistence()` 作用域守卫（进程级 `AtomicBool` + 串行 `Mutex`），**必须串行**。
- **验收文件撞名坑**：`world_tests.rs` 用 `include!` 并入同模块 ⇒ 裸名与 `use crate::protocol::InventoryItem;` 会重复（E0428/E0252）；helper 加动作前缀，类型写全路径。
