# 3D 场景开发通用指南

检索别名：**3d建模**（大小写不敏感）。用户提到这个别名时，先读取并应用本文；入口登记在 [`技术索引`](INDEX.md) 与 [`AGENTS.md`](../../AGENTS.md)。以下方法可用于 3D 场景开发，射手村的数值、玩法和美术约束仅是本项目实例。

当前初弦地东边村落实装见 [`实装记录`](../plan/history/2026-09-30/初弦地东边村落正式实装.md)。早期射手村案例依据 [`射手村三维场景与主世界实装.md`](../plan/history/2026-09-24/射手村三维场景与主世界实装.md)。历史交付、代码修复与用户实际观感分别记录，不互相代替。

## 开工前：先把事实分层

1. 先读 [`AGENTS.md`](../../AGENTS.md)、[`BUSINESS_DEVELOPMENT.md`](BUSINESS_DEVELOPMENT.md) 和 [`PLAN.md`](../plan/PLAN.md)，再读对应历史记录；不要用旧渲染结论替代当前计划。
2. 把输入分成三层：同版源资源/地图数据、项目现有运行时、这次新增的视觉解释。源数据决定坐标、比例、动画和可交互边界；视觉解释不能反过来改写玩法事实。
3. 单独记录“通用规则”和“项目特例”。例如本项目射手村是 TMS273 地图 `100000000`，不是所有地图都应复制它的出生点、镜头或坐标原点。

## 先定地图脉络，再画空间原型（2026-10-02）

新地图或路网重构采用下列顺序。已认可地图的灯光、材质或NPC小改动只走受影响阶段，不为套流程重新画城。

| 阶段 | 交付物与成立条件 |
| --- | --- |
| 同版来源 | 地图ID/名称、故事与区域职能、现有资源；提取有向门户，区分固定门、NPC/脚本交通、组队实例和旧目录。仅名称或缩略图残留标未知；用户要求保留的旧图纳入布局并补原创连接，不把未知当排除理由，也不补成原版已验证连接。 |
| 空间方案 | 保留原版分支/汇合与区域身份，决定入口、可见目标、主路/环路/隐藏路及上下层关系。改编新增连接、地标与高度标原创P，不反写原版事实。 |
| 尺度卡 | 单位/轴向、角色与门/道路/桥净空、可停留庭院、船/建筑比例及常用镜头。数值有来源或明确为草案；不得拿概念图像素、其他地图px/m直接当当前权威尺度。 |
| 鸟瞰原型 | 先画能看清完整布局的等距鸟瞰或高处斜视，适度微缩/移轴但道路清楚。概念参考只表达设计意图；逐区、逐层的实景图应从同一份真实 Blender 场景模型输出，并标明概念、模型视图或浏览器画面。用正常行走视角或尺度锚点核看角色与目标；无法读路线则先改图，不先加细节。 |
| 可走白模 | 根据原型的区块/路线/连接/标高建立真实几何，验证连续地面、坡阶、桥下净空、交叉是否相连与往返/回出。先做静态净空、承托和路面连续性检查，再在浏览器实际观察动态场景；静态模型检查不能替代浮岛、桥路运动时的观感核对。此时解决可达性和遮挡，尚不以高精贴图掩盖问题。 |
| 模型与实装 | 白模空间成立后先检查输入模型的完整性、部件语义拆分和动画归属；修复后再赋材质/权重，用可编辑模型与授权资产完善，并同步共享布局/权威导航/投影与交互。 |

空间原型是结构设计：一张漂亮城堡图若无法解释“从哪里来、怎样分支、在哪汇合、为什么能到目标”，不能作为建模依据。地标轮廓和前进线索在代表性行走视角可见；沿途允许遮挡、绕行与重新看见，不要求全程露出全部路径。

交织路网必须区分两件事：同层共享庭院是可换路节点；不同高度的桥路仅视觉相交，除非另有真实楼梯/坡道连接。隐藏路线借桥腹、背坡、廊道或旧水道形成连续路径，入口线索和回出路径在白模中成立；不能用“隐藏”解释断路。环路不是错误，检查应抓孤立区块和非预期单向困住。

每个区域内部按实际街道、庭院和平台组织网状路线，不能以区域中心之间的直线代替街道。相邻区边界的出口与入口应成对落在可到达的位置，并核对两端的方向、标高和承载几何。以实际道路中心线作为路面与路线图的共同几何基准；若它们由不同数据生成，就逐点核对，避免模型中心线、路面与导航各自偏移。浮岛聚落应提供足够宽阔的高低台地和周边景观；每条离开岛体的路都要有明确载体，例如主岛、碎岛链、有缆索锚点的吊桥或能量桥，不能把无支撑路面悬在空中。

不规则浮岛山体可用固定种子的低频 fBm 叠加受限的 ridged 噪声塑造有棱角的侧壁，避免逐帧重采样造成外形闪动。可走冠层应独立保持平坦，或让侧壁噪声在顶部渐隐；不要把高频噪声直接施加到行走面。岛上建筑、植被和道路放在同一岛体坐标父组下；桥面、浮阶、缆索及其他连接载体按每帧两端的当前变换重算或更新，不对上帧结果反复叠加位移，以免漂移。

上下平台道路另查断面：预留同标高的平坦到达、转向和回主路区域，坡道在平台外起坡，不能从平台底下斜接。陡段根据角色规则拉长、折返或做有足够踏面的阶梯；梯下/坡下净空不足时封结构或明确划为禁行区，不留看似能钻入却无法回出的空隙。跌落恢复路径须接回真实主路，不能靠自动吸附到上下另一层掩盖缺路。检查楼板与内部螺旋是否互相遮断，并在实际角色尺度下核定净空；“约30°”是本次用户举例，具体坡度、步高和净空数值按当前地图与移动机制确定，不推广为通用硬阈值。

一次迭代维护一份源布局或等价清单，关联原版地图ID、视觉区块、连接类别与标高。先复用已有布局格式/生成器，确有跨层需求才补相应字段，不预建万能地图引擎。图像原型允许美术推演，权威规则仍由共享数据与服务端决定；概念、白模、候选预览和正式实装分别报告。

天空之城本轮应用见[地图脉络与交织螺旋方案](../design/天空之城地图脉络与交织螺旋方案.md)：原版三色庭园各两段汇到天空阶梯是来源；三路交织、隐藏第四路和冠顶圣域是当前用户要求下的3D改编。此例不把三条路、螺旋塔或微缩风格变成其他地图的固定模板。

## 尺度、源坐标与美术约束

4. 保留 TMS273 导出树作为身份与资源来源；当前东村由 Blender GLB 内嵌布局与 `resources/scenes/chuxian-east-v1/source-layout.json` 定义，`scripts/build_chuxian_east_layout.cjs` 生成 `shared/chuxian-east.json` 权威路线；装配同步服务端 foothold、NPC/传送门高度与小地图。
5. 当前东村使用 `45 px/m`、16 条路线、225 段道路和19处共享节点路口；沿路弧长位于互不重叠的 x 区间，y 对应真实标高。旧原点/圆弧/梯子参数仅属历史；以当前共享 JSON 为准。
6. 源坐标 x 表示沿路线的弧长，y 表示竖直高度；`point3d` 转成 glTF Y-up 坐标，Blender Z-up 坐标保持等价。客户端只映射显示，服务端拥有实体碰撞。
7. 当前美术目标是童话卡通与可读的空间层次。树草石与房屋组件优先采用已核实许可证的现成素材；地形允许 Blender 生成。旧版几何体造型限制不再作为本次要求。
8. 台地可跳跃性先由服务端定向检查验证，再布置房屋与植被；当前东村物体使用 `CE_` 前缀（旧场景为 `HR_`），并记录平台 ID 或 CC0 来源标记。
9. 2D 纹理增强不能把整张概念图贴成场景表面；应保留可编辑几何，用局部 UV/贴图表达木纹、石面和手绘细节。源图、裁切区域、单位和角色脚点应写入清单。

### 模型输入检查（材质与权重之前）

- 不凭对象数量或名称认定模型完成。用代表视图、线框和独立部件检查表面连续性、缺面/非流形、部件粘连、材质与 UV 边界，以及每个部件应跟随的动画对象。
- 部件拆分或几何结构不合适时，保留源文件和备份，先按真实结构手动修复、分件；需要时补支撑杆和连接面。修好后再赋材质与权重，避免后续设置掩盖结构问题。
- 检查各材质能否独立调整，并确认刚性杆件不会被布料风压变形或拉动。修补按实际范围、外形和动画结果判断，不机械追求原面数。

### 材质、光源与空间表单的实看检查（2026-10-02）

- 主轴UV投影使用与主法线垂直的两个坐标轴，检查非退化模型三角面的UV面积，避免侧面折成一条线。纹理平铺尺度按米设定，保留原始UV用于需要它的法线图。
- Three会按相机层收集光源，不能仅给模型分层就期待两个太阳分别照船和城。共享渲染器优先一盏主光；另增光前看实际近景/远景及阴影。
- 船上表单需要实体载体、受光的框/纸面和世界锚点；原生输入可透明投影到纸面，保留焦点与业务事件。窄屏退镜头可能被桅杆遮住，应同时检查取景、真实遮挡和按钮可见性。

## Blender 与 MCP：连接先于制作

10. MCP 连接必须可重连、可核验、可追溯。不要把一次性 `/tmp` 启动脚本当持久安装；历史修复把 addon 持久安装到 Blender 用户目录，并让客户端与插件都使用 `127.0.0.1:9987`。
11. 连接前后至少核对 `get_addon_status`、`get_scene_info` 和一次 viewport 截图；场景名、对象数和端口应有前后证据。端口不能只改客户端环境变量，插件默认端口也必须同步。
12. 保留 `BLENDER_MCP_SAFE_MODE=1`、`DISABLE_TELEMETRY=1`，telemetry consent 保持关闭，只监听本机回环地址；不要为制作开放远程监听，也不要修改官方缓存源码。依据见 [`Blender_MCP持久连接修复.md`](../plan/history/2026-09-24/Blender_MCP持久连接修复.md) 与 [`BLENDER_MCP.md`](creative/BLENDER_MCP.md)。
13. MCP 调用、JSON、日志和中文路径统一 UTF-8；若数据要进 HTTP header，使用 JSON 转义、percent-encoding 或 base64，不能直接塞入非 ASCII 字节。
    安全模式拒绝 `pathlib`、`open`、`exec` 等时，不关闭保护：目录准备交给宿主文件工具，Blender 内用允许的 `bpy` 保存、导出、渲染操作。`9987` 是本机配置实例；升级 addon 可能覆盖本地端口默认值，升级后应重新核对。
14. Blender 中的脚本应可重复执行并只拥有自己的命名空间（如 `HN_` 数据块）。结构检查放在脚本末尾；它只能证明源文件结构，不等于运行时已接入。

## 源文件、GLB 与资源所有权

15. `.blend` 是可编辑源，GLB 是运行模型，PNG 是预览。当前源生成脚本为 `scripts/creative/blender/build_chuxian_east.py`，通过 Blender MCP 操作并保存；产物位于 `resources/scenes/chuxian-east-v1/models/`。旧 rail-v1 源作为历史保留。
16. 准备脚本读取共享配置与下载的素材路径；Blender 保存 `.blend`、导出 GLB，再执行渲染生成预览。碰撞来自共享配置，GLB 不承担权威规则。
17. `scripts/check_henesys_assets.cjs` 校验源布局/权威路线、路网连通、嵌入贴图、NPC/门脚点、装配字节与 HDRI 来源。当前加载地址为 `/assets/henesys/chuxian-east.glb`。
18. `resources/`、`client/public-tms273/` 等美术树按项目约定可能被忽略，Git 提交并不会替你迁移它们。工作树合并或清理前，先做安全同步检查：确认 Blender 已保存、`.blend` 与 GLB/预览存在且非零、来源路径与清单一致、运行资源已复制到目标目录，再核对 `git status --ignored`；检查失败就停止清理。
19. 清理或删除隔离工作树前，确认最新源文件和导出均已安全同步；已有保存且校验一致时无需重复导出。不要把“忽略”理解成“可重建且不重要”。历史射手村资源曾因工作树移除而消失，恢复依赖仍运行的 Blender 场景，这只是应急恢复，不能替代资产备份。

## 运行时边界：复用权威玩法，不复制状态机

20. 3D 层只提供环境、镜头、遮挡和输入重投影。原版 `World` 继续拥有玩家/NPC/任务标记/怪物/掉落/技能/宠物、动画时钟、音频、窗口和命令发送；Three 层不得新建一套战斗或任务状态机。
21. 当前实现由 [`World`](../../client/src/scenes/world.ts) 懒加载 [`HenesysView`](../../client/src/features/henesys/view.ts)：Phaser与Three共享一个WebGL2上下文，原版对象捕获进GPU RenderTarget后以外部纹理独立合成，每个显示根对象的深度参与遮挡；不再逐帧从CanvasTexture上传CPU画布。显示入口只切换显示状态，不发地图迁移或退出指令。
22. 同一共享轨道数据供装配、Blender、投影和服务端规则使用。Three 不根据视觉网格猜测碰撞；2D 切换沿用相同台地规则，不能回退旧地图图层。
23. 生命周期必须成对：地图切换、断线、重连、Three 加载失败都清掉旧模型、材质、纹理、监听器、计时器和快照；异步 GLB 返回时用 generation/当前地图守卫，过期结果立即销毁。`World.clear()` 与 `HenesysView.destroy()` 是可复用参考。

## 航船入口、纸娃娃与地图标配方法

本节是跨地图的方法口径；当前地图的比例、路线数量、船体尺寸、模型参数和天气数值仍写在各自 source-layout、资源清单或历史记录中，不能把一个地图的具体值升格成通用标准。

### 角色装备链路先取证，再修复

1. 从服务端 `PlayerState`/大厅角色摘要确认角色外观与当前 `equipped` 的来源。装备槽、现金装、空装备和武器动作分支必须以同一份权威快照为输入；缓存的基础外观只作明确的旧快照回退。
2. 从同版 WZ 导出报告核对每个动作帧的 `origin`、命名 `map`/anchor、基础 `zmap`、遮挡 `smap`、动作 `delay`、UOL/PNG 来源和装备槽信息。组合后的 `x/y` 已相对脚点图像左上角定位，运行时不得再次减 `origin`；按 `z` 排序，并把整套纸娃娃作为一个容器翻转。
3. 船上预览与真实 `PlayerView` 应共用纸娃娃组合器。对比 `composeAppearance` 输入、动作名、帧延迟、懒加载层 JSON/PNG、纹理就绪和整容器朝向，明确记录船上本地动作与真实权威动作的差异；不要在船上另造装备叠图规则。
4. 找到缺装、站立抖动、脚点漂移或层次错误后，按“源导出 → 懒加载就绪 → 组合坐标/z → 脚点/容器朝向”的顺序定位。优先做最小运行时修复；只有导出报告证明源字段错误时才改导出器，并保留源证据。异步结果须由当前角色/组合 key 或 generation 守卫，过期结果和失败资源要清理。

### 航船入口与正常行走

- 船上入口保持可行走状态，加载使用非阻塞的小进度窗（底部或当前产品约定的位置），不锁死船上镜头和移动。船上动作、装备预览和世界快照的边界分别记录。
- 只有资源、权威快照和地图运行时状态全部 ready 后，才播放书页/灯光过渡；加载失败、断线、地图切换或过期回调应恢复可操作状态并销毁旧对象。不能用先显示半成品再补齐来制造“ready”。
- 正式镜头以正常行走和角色尺度为基准，鸟瞰只用于读拓扑。权威连续路网由共享布局和服务端规则拥有；道路中心线、路面、碰撞和导航需逐点核对，视觉网格不能反推碰撞，也不能以单向或断头连接代替连续可回出的路线。
- 路口头顶提示只给上、下、左、右四个方向，不生成斜向组合；持续按键沿当前路线穿过弯道，去程与回程使用同一连接。NPC/传送交互键另行配置，不把交互动作塞进方向选择。

### 模型、遮挡与天气标配

- 输入模型检查必须包括栏杆/扶手等安全边界件的缺失扫描；缺失时先在可编辑源中补齐并复查导出节点、材质和碰撞清单，不能只在运行时用贴图或透明片遮住空位。
- 船体及地图模型保留语义部件和可编辑动画：主帆可独立收放并绑定布料动画，枫叶保留一个可独立编辑的实例。源结构通过、预览可见、正式运行时已接入是三个独立结论，未接入时写需求和验收条件。
- 室外栏杆、楼梯边缘等部分遮挡保留真实关系；只有全身确实被遮住才对角色附近脚点和短段选路做局部透视，空门洞与船体大包围盒不能当作实墙。已有室内按源模型明确房间体积、外壳及楼层语义剖视：隐藏对应外壳和挡住下层的上层部件，保留当前地板、道路和陈设，退出恢复原可见状态，门边使用小滞回范围。合并的纯外观建筑仍只局部透视，不能冒称已有室内。
- 脚下反馈读取真实接地、步点、速度、地表、湿度和当前天气。雪地至少验收脚点位置、雪粉/扬雪强度、停步清理和遮挡；持久脚印、积雪形变、多人共享天气或物理影响需另列需求，不能把当前材质换色写成这些功能已完成。

## 2D 混合呈现、清晰度与点击取证

24. 清晰度问题要沿链路取证：原始 2D 资源 → manifest/逻辑 URL → 浏览器响应 → Phaser drawing buffer/GPU RenderTarget → Three外部前景纹理与材质 → 最终截图（旧CanvasTexture链路仅供追溯）。每一段记录 viewport、CSS 尺寸、drawing-buffer 尺寸、devicePixelRatio、Three pixel ratio、相机缩放和截图裁切。
25. 不要先损失像素，再放大补救。射手村初版用 Phaser `zoom=.75` 栅格化，再经 Three `LinearFilter` 放大到原尺寸，DPR=2 时最终 drawing buffer 又只有 CSS 尺寸的 1.5 倍。修复在桥接处保留源 `zoom=1`，对已经栅格化的像素前景采用最近邻采样，最终像素比上限为 2 并响应 DPR 变化；前景禁用雾和色调映射以保留文字对比度。3D 环境材质仍沿用自己的过滤，不能把最近邻机械套到所有纹理。需要更大视野时，应提供足够的源缓冲像素，不应先缩掉细笔画。具体观感须用等尺寸截图和实际浏览器确认。
26. 对比必须在同一窗口尺寸和同一角色/文字状态做 `2D → 3D → 2D` 截图；分别放大检查角色边缘、姓名牌、任务标记、NPC 文字和 DOM 窗口。3D 预览清楚不能证明登录后的在线画面清楚，反之亦然。
27. 点击要验证“投影一次、业务一次”：Three canvas 的 pointer 事件先 `preventDefault`，射线与纸面求 UV，再换算回 Phaser canvas 的像素坐标；pointer capture、mouseup、兼容 mouse 事件和右键镜头拖动都要单独覆盖。[`forward`](../../client/src/features/henesys/view.ts) 的做法避免重复触发 NPC 对话，但服务器仍是最终范围校验者。
28. 取证至少包括：透明前景随镜头移动仍对齐；NPC/任务/反应器点击只触发一次；切回 2D 后点击与文字不受 Three 监听器残留影响；断线和返图后旧快照、表情和材质不回流。

## 一次制作的推荐顺序

33. 先做来源盘点：地图 ID、原图层、碰撞、门、角色脚点、资产许可证和现有运行时入口。
34. 再做尺度卡：单位、轴向、像素/米、原点、相机视野、深度层，以及哪些数据只能由服务端决定。
35. 只复制来源到本地工作目录，生成 `source-layout.json` 或等价清单；清单中保留来源路径、版本和用途，不把推断值写成原始事实。
36. 新地图先画空间原型，核看布局、拓扑、高差、目标视线和尺度；再用少量方体与地标完成可走白模，出全景与代表性近景，验证原型中的道路、建筑顺序和遮挡关系。
37. 白模稳定后再加授权植物、局部贴图、灯光和雾；每一步都保持可编辑对象和可回退的 `.blend`。
38. 先保存源场景，再导出 GLB；导出后离线读 GLB 的节点、材质、图片和坐标，再复制到运行时资源目录。
39. 实时体积光只作用环境，最终保留环境深度再绘制原版纸娃娃。先在 preview 验证透明前景、镜头和投影输入，再在 production 验证真实服务、存档和原版玩法。
40. 每轮只报告本轮真的核对过的事实；“资源存在”“浏览器能显示”“用户觉得清楚”是三个不同结论。

## 常见误判与处理

41. “GLB 能打开”不等于“游戏能加载”：继续查 manifest、资源 URL、内容版本、解码失败和异步过期结果。
42. “截图看起来软”不等于“原图分辨率不足”：先沿 2D→Canvas→CanvasTexture→最终 framebuffer 取证，再决定改资源、比例还是采样设置。
43. “点击事件到了 Three”不等于“玩法成功”：投影坐标应回到 Phaser 的真实 hit test，服务器仍核对距离、状态和权限。
44. “预览快照里 NPC 能点”不等于“在线 NPC 对话已通”：预览只能验证显示桥接，在线验证要有真实 snapshot、窗口和服务端回执。
45. “工作树里没有改动”不等于“忽略资源安全”：先检查 ignored 清单、Blender 保存时间、GLB 字节和目标资源目录，再允许清理。
46. “加一个本地状态更快”通常会制造双重权威：新行为先找 `World`、服务端或既有窗口的拥有者，显示层只订阅快照。
47. “提高渲染比例”不等于“文字一定清楚”：同时记录 DPR、CSS/backing-store 比例、相机缩放和浏览器尺寸，否则无法复现。

## 地表行走反馈（2026-10-01，原始需求；下节为实施口径）

本节保留最初收集的地表表现需求；后续获授权的尘雪、压痕与灯具实施以末节为准。不能据此认定所有场景已拥有沙地或可变碰撞。

| 输入事实 | 期望脚下反馈 | 边界 |
| --- | --- | --- |
| 接地后的实际移动与步点 | 普通走少量细尘；更快移动/骑乘提高颗粒量、扬起范围与拖尾 | 速度连续调节；“两百多”是用户举例，不冻结成阈值；静止、空中不持续喷尘 |
| 地表材质 | 草地少、沙土多、石板中等；颜色来自脚下材质 | 后续补地表标识；不能仅按画面颜色猜碰撞，也不能假设所有路都是沙地 |
| 湿度/干燥与降雨 | 干燥时尘较明显，湿润/下雨时减尘 | 复用环境湿度；水花/泥脚印未作为本轮必做需求，不扩大成流体模拟 |
| 冬季飘雪及积雪覆盖 | 落雪与地面覆盖联动；踩雪踢起偏白雪粉，形成踏雪感 | 白色染色不等于累积模拟；覆盖量、积累/融化时间后续定，不提前改变地形高度/速度 |
| 脚下已有雪层 | 优先用雪粉反馈，底层草/石/沙仍影响强弱 | 是否提供短暂踏痕在后续样张核对，持久脚印及真实可压缩雪体未获要求 |

实施建议：跟随原有脚步节拍与接地判定生成局部颗粒，颜色/强度由地表、湿度和雪覆盖共同决定，不另造一套角色行走时钟。瞬移不能沿跨度补喷一路灰尘；卡帧不追赶生成大批颗粒，换图/断线销毁。保留已下载真人脚步素材，不恢复程序合成脚步；新增雪/沙音色需要单独核实授权与实听，不能声称旧录音已经覆盖。

现有事实与入口：`client/src/features/henesys/audio.ts`已有按实际移动、接地及路线选择石/木/草脚步的链路；`environment-settings.ts`保存本机时刻/天气/季节/湿度，`environment.ts`已有雨雪粒子和材质冬季雪色。当前冬季材质覆盖是参数表现，尚非随时间积累、压雪或扬雪系统。本轮未实现扬尘、扬雪和踏痕。

天气当前仅本机显示。先在同一环境状态中对齐雪覆盖与脚下表现；是否成为服务端共享天气、是否影响真实物理/生态，需另定范围。客户端仅做表现时，不能报告多人共享世界模拟已完成。后续验收用同一段道路对比慢走/快骑、干/湿及草/石/沙/雪，检查粒子脚点、方向、遮挡和停步清理；最终正式实装仍通过`启动3010.command`，必要检查随实际改动执行。


## 初弦地尘雪与灯具实施口径（2026-10-01）

- 权威快照只负责角色状态、灯具归属和交易；World插值后的位置同时供纸娃娃、真实步点、雪压痕和点光使用，不新增移动模拟。瞬移消息显式抑制一帧，小幅顺移同样不拖出尘雪。源贴图先按环境和选中点光受光，再进入原清晰合成；姓名、任务标记、HUD不染暗，原始技能/冻结色在帧后恢复。
- 当前模型道路是石砖，码头木板；不得把林根路名称当草地材质。草/沙/土接口按未来真实表面标识选用。尘雪CPU只写新粒子，GPU计算飞散；1024粒池、最近48角色、96粒/帧、32m附近范围。停步/失焦/死亡/跳跃/坐椅/攀爬/瞬移/过期帧不补喷，实际速度越高且骑乘越强，湿润抑尘，积雪转白色雪粉。
