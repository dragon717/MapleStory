# MapleStory 资源与存档恢复

先确认当前仓库是 MapleStory，读取 `docs/technical/BUSINESS_DEVELOPMENT.md`（尤其“登录后无法入图：资源与存档契约”）和 `docs/plan/PLAN.md`。其它项目不沿用本技能的路径、槽位或修复结论。

- 从具体错误字符串追踪全部读写调用方。认证成功、角色加载、世界连接是不同阶段；`(persistence)` 不是数据库损坏证据。Vite 包体积警告、bot 凭据缺失也不能直接当作入图故障根因。
- 对照 `shared/character-creation.json`、`shared/items.json`、`client/public-tms273/assets/items.json`、`resources/tms273-export/items.json` 和实际发布二进制。先检查物品是否存在，再查 `info.islot` 和存档槽位。服务端物品目录由 `server/src/inventory.rs` 的 `include_str!` 编译进二进制。
- 对照生成器 `scripts/generate_tms273_gameplay.py` 的引用集合、创建装备导出器和 `scripts/assemble_tms273.cjs` 的覆盖写入。修复上游真实来源及必需消费者引用，不只手工补生成结果；同版 WZ 为来源，不能按 ID 猜属性或从 83 补数据。
- `InventoryItem.slot` 为正数，装备表/协议为负数，`MaPn` 连身衣占 -5；未知物品导致 `equipment_slot` 返回空也可能报 slot mismatch。不要因此改号、过滤装备或弱化校验。只有持久数据确实错误时才考虑保留实例属性的事务迁移。
- 用现有 `scripts/tms273_creation_catalog.cjs` 检查创建配置的非零装备；装配和发布入口应在切换旧服务之前拦截缺项。检查范围只覆盖创建装备，其它旧存档引用需按实际改动另核，不声称覆盖任意内容退役。
- 使用临时数据库和真实物品目录做定向保存→关闭→重开→加载回归，同时确认真实错槽仍拒绝。按当前任务授权使用统一 `启动3010.command` 加载修复；不要为验证清库、重建账号、另起服务或恢复已取消的独立 QA。已通过的检查不重复执行。

交付写明根因、上游修复、定向检查结果、修复是否已加载，以及用户待验的入图行为。长期规则写入上述规范；任务证据只归档 `docs/plan/history/YYYY-MM-DD/` 并更新索引，当前待办留在 PLAN，不复制新台账。
