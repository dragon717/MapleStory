# 可行走3D地图开发

目标是让玩家在正常游玩镜头下看懂空间、沿真实路线到达目标并能回出。先读取当前项目的地图数据、状态拥有者和已确认规范；复用成熟生成器、角色呈现与交互链路，不把某张地图的参数或一次修复当成通用模板。

## 先确定空间与数据

- 区分源资源事实、现有实现和本次设计。记录入口、出口、主路、分支、环路、上下层与目标；未知连接不能凭名称或缩略图认定已可达。
- 确认单位、坐标轴、原点、角色脚点、镜头投影和运动时间。像素/米、角色高度、坡度、路宽及动画预算从当前项目或实测取值，不复制其他地图的常量。
- 用户已授权原创地图时，缺少旧地图ID、原图或既有坐标不阻止设计：沿项目登记规则分配身份，用已有单位/移动能力拟定可验证的布局和尺度草案，标明设计值后推进。能从代码或合理默认查明的输入自行解决；只对影响目标、硬约束或新机制的缺失作必要讨论。
- 新地图先做能读拓扑的空间原型，再做可走白模，最后完善材质、植被和光照。已有地图的局部修改只走受影响阶段；概念图、真实模型视图和游戏画面分别标明。

## 几何、导航与连续行走

- 道路中心线、承托路面、导航及碰撞采用同一几何基准；核对共享端点、标高、净空和入口落点。同层交叉明确能否换路，不同层视觉相交不能自动相连。
- 使用项目已有的移动和选路规则。持续输入经过弯道、环缝和连续端点时保持前进，正反向均可走通；明确改变方向才选分支，避免楼层连接产生无意折返或把沿路前进算成换路。
- 路口提示与实际选路使用同一数据和镜头方向，按已确认按键方案显示；交互动作与方向选择的关系沿用产品规则，不自创组合键。
- 动态承载体、路面、连接件和乘员按同一姿态/时间变换。连接两端按当前变换重算，不逐帧累计偏移；视觉层不复制另一套权威移动、任务或碰撞状态。

## 模型与角色呈现

- 保留可编辑源、语义部件、材质/UV与动画归属。先查缺面、粘连、栏杆/扶手缺口和承托，再贴图与绑定；刚性部件不能误归入布料。
- 建模工具沿用项目已确认选择，调用前核实当前可用能力；旧连接端口、插件状态和设备名称不当成现状。源模型可重复编辑，导出流程复用既有管线。
- 贴图按原图比例和完整构图核对；跨分片图案共用连续坐标，旋转整图而非各片独立旋转。动画后再查贴片同步和深度闪烁。
- 复用现有角色/装备组合器及权威快照，保留原始锚点、层次、帧延迟和脚点。整体角色统一朝向，动画纹理尺寸变化需正确重建或使用稳定边界；运动与动画时钟不能各自跳帧。
- 2D/3D混合时从源图、栅格缓冲、纹理采样到最终输出检查比例与清晰度。角色、文字和交互坐标都通过真实投影转换，不能只调整可见位置而留下旧命中区域。

## 镜头、遮挡与环境

- 正常行走镜头是空间验收基准，鸟瞰不能替代角色尺度与目标视线。路线变化沿用已确认跟随方式，避免无意跳镜或抖动。
- 按产品已定策略区分部分遮挡、完全遮挡与进入室内。局部透视需真实表面命中，不能用大包围盒将空门洞当墙；室内剖视由房间范围、外壳和楼层语义决定，保留当前地面与内容，退出恢复原可见状态，边界避免闪烁。
- 原表面的积雪、附着物、阴影及其他派生显示同步隐藏和恢复，不能留下悬空副本。地表反馈读取真实接地、步点、速度、材质和环境状态；瞬移、停步与卡帧不补喷一路粒子。
- 性能先测真实资源与实际更新链路，再缓存静态计算、限制不可见更新或复用缓冲；不能靠删掉明确要求的效果达标。离线CPU时间不冒称设备GPU帧率。

## 加载、接入与交付

- 加载中的可操作范围沿用产品约定；资源、快照和运行时都就绪后再进入目标场景或播放过渡。失败、取消、重试与过期回调要回到有效状态，销毁旧资源和等待。
- 源模型、导出和运行资源分别核对。被Git忽略的源资产也要安全保存和同步，清理工作树前检查；提交代码不等于已迁移素材。
- 只验证受影响路线、显示、状态和失败边界，优先已有可运行检查。需要运行时验收时遵循当前项目入口与授权，区分源结构通过、预览通过、正式接入和用户待验。
- 通用方法在真实使用中修订；具体地图的坐标、节点名、资源路径和实现数值留在项目数据，旧方案与修复证据归档历史。已确认方法直接复用，实质冲突提出讨论，确认后更新现行入口。
