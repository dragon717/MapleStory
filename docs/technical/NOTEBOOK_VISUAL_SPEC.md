# 冒险笔记（图鉴）视觉规范

> 适用：`client/src/features/notebook/`（窗口壳 `view.ts`、怪物页 `monster-section.ts`、
> 物品页 `item-section.ts`、样式 `style.css`）。
> 素材来源：TMS273.7 同版客户端 `UI/UIWindow4.img/monsterCollection|itemCollection`，
> 经 `scripts/export_tms273_collection.cjs` 导出、`scripts/assemble_tms273.cjs` 装配。
> 本文件只写**规范与出处**；每个取值的实测方法见 `style.css` 里的同段注释。
> 端到端校验：`node scripts/check_tms273_notebook_ui.mjs`（同时产出样张）。
> 窗口系统本身的规则（`pointer-events`、z 序、宿主）见 `UI_WINDOW_SYSTEM.md`。

## 0. 三条不变量

1. **位置即事实**：窗口、板、卡片、槽位的坐标全部取自源素材的实测值，不用「看起来差不多」的
   布局参数。改坐标前先量源 PNG。
2. **不编造源里没有的东西**：源没给逐槽位等级就不升等级，源没给地区名就不起名，
   源没给名字的条目不拿 id 冒充名字。缺什么就标出「缺」这件事本身。
3. **可读性由层级给，不由去掉内容给**：字看不清就调底色与对比度，不是把字删掉或压暗。
   改造前的主因正是 `filter: grayscale(1) brightness(0.45)` 把 96% 的格子压成黑块。

### 1.1 怪物页＝一页相册

一张相册页 = **一个源分頁**（源每个分頁就是 5 行 × 每行 5 槽）。板内坐标：

| 元素 | 板内坐标 | 来源 |
| --- | --- | --- |
| 相册板 | 0,0 666×520 | 源 `Collection/backgrnd`（origin −204,−120） |
| 页签卡（分頁名 + 地区名 + 图例） | 518,66 129×162 | 源板右上深色面板 |
| 注记卡（分区状态说明） | 518,232 129×248 | 源板右下深色面板 |
| 槽位格 | 列 x=35+73i，行 y=70+84j，68×68 | **实测源板上烤着的亮瓦片** |

槽位列/行不是拍出来的：`check_tms273_notebook_ui.mjs` 自解源板 PNG，按亮度 >
170 聚成 5 条行带与 5 条列带，得出 `35/108/181/254/327 × 70/154/238/322/406`，
瓦片 68×68、列距 73、行距 84。样式表的 `left: 35px; top: 70px` +
`grid-template-columns: repeat(5, 68px)` + `gap: 5px` 用的是同一组数字，
所以槽位是**贴在**源瓦片上，不是另铺一层网格。

> **1px 已登记差异**：源自己的槽位盒是 70×70（`Collection/monsterGrade/0..4` 都是
> 70×70，`empty` 是 74×74 且 origin 为 (2,2) ⇒ 画在盒位 −2 处）。亮瓦片是盒内的 68px，
> 1px 是盒的描边。本项目按亮区取 68px、起点 35（＝源盒 34 的 1px 内），**列距相同**，
> 视觉无差；贴底板仍按 `-2,-2` 放 74×74，与源一致。

### 1.2 物品页＝一页格架

源丝带页眉（`itemCollection/category/backgrndN` 411×38）+ 6 列 × 10 行 × 94×94。
列数 6 是硬约束：服务端 `ITEM_PAGE_SIZE = 60`（`server/src/notebook.rs:40`），
7 列会在 666px 内容区里横向溢出（改造前的问题之一）。

### 2.3 页签底板为什么是重画的

源只给了 6 张 279×28 位图（`Tab/enabled|disabled/0..2`），**每张都把页签文字烧在图里**。
本项目新增的四类内容导航文案不同，直接贴源图会**叠字**，所以底板按源渐变重画、文案另写
（界面扩展 P，计划 §6.4）。重画是安全的：底板横向均匀、只有竖直渐变（实测 x=40/200/270
同一行同色），28px 高的 CSS 渐变能把色标落在与源相同的行上。`Tab/*` 的字面量因此
**不出现在样式表里**——这条被 `view.check.mjs` 钉死。

> 同一条规则也适用于 `Tab/*` 页签底板与菜单项：**字烧在图里 ⇒ 改名必须重画底板**。

## 3. 关键界面的呈现方案

### 3.1 窗口壳

- **标题压在一条半透明黑带上**，不是白纸上。实测源 `backgrnd`：y0..18 是
  `a≈187`（73% 不透明）的黑色渐变带，y19 起才是不透明白纸。
  所以标题给**自己一层 `rgba(0,0,0,.62)` 暗底** + 浅字 `#f4efe2`：
  只换浅字不够——那层带只有 73% 不透明，窗外是亮地图时带最亮处合成到 `#9b9b9b`，
  浅字会掉到 2.5:1。有了自带暗底，可读性与窗外画什么无关。
  （改造前这里写的是「标题画在白纸左上角 ⇒ 墨色」，那是个**错前提**，已修。）
- 页签下缘的分隔线用源 `layer:tab_line`（865×8），不画 1px 边框：源板在白纸上
  没有横线，少这一段页签会「浮」在纸面上。
- 进度读数用源位图数字；「当前可收集 57」这类说明是本地化 DOM 文本，不在数字里掺字。
- 关闭按钮用源 `button:Close/normal|pressed|disabled|mouseOver`（13×13）。

### 3.2 怪物相册页

- **板**：源 `Collection/backgrnd` 整张铺上，槽位贴在烤好的瓦片上（§1.1）。
- **槽位必须是 `.notebook-monster-row` 的 grid 直接子项**。给每个槽位再套一层容器，那层
  容器会自己占掉第 1 格，5 格于是在 68px 里挤成一列——而窗口尺寸、板、列距**全都仍然是对的**，
  所以只量几何的检查抓不到。这一条已有反向断言钉着（`check_tms273_notebook_ui.mjs`）。
- **页签卡**（板右上深色面板）：分頁名 + 地区名 + 图例。图例只解释下面这批格子怎么读
  （「亮框＝本版可收集 · 暗框＝本版未开放 · 金字＝已登记」），**不补服务器没给的分母**。
- **注记卡**（板右下深色面板）：分区状态说明画在页内、跟着内容滚。
  `blockedReason` 是**分区事实**（这一页的事实），不是一次失败，所以不上报成窗口级
  错误横幅——改造前它被 `status(..., true)` 播报成全局错误，已修正。
- **行名**画在瓦片行上方那 16px 留白里，是源行的真名，不能丢。
- **空态**：板仍然画（这一页本来就是一本相册的一页），只说「没有符合条件的收藏条目」，
  不暗示「还有 N 个等你去拿」。

### 3.3 槽位三态（不用 filter 压图）

| 状态 | 底板 | 名字 | 标记 |
| --- | --- | --- | --- |
| 本版未开放（`collectable=false`） | `monsterGrade/empty` @ `opacity:.45` | 常规浅字 | 右上角标 `--nb-notyet` |
| 本版可收集、未登记 | 同底板，全亮 + 青色 glow | 青色名条 | 无 |
| 已登记 | 同底板，全亮 + 金色 glow | 金色名条 | 无 |

- 1493/1550 格都是「未开放」，压到 0.45 才让那 57 格**本版可收集**真正跳出来。
- **源不含逐槽位等级**（源里有 `monsterGrade/0..4`、`special`、`event`、`temp` 各 70×70，
  但目录不提供逐槽位的 grade）。所以一律用 `empty`，**不挑一个等级冒充**。
- 图**永不加 filter**：`grayscale(1) brightness(0.45)` 是改造前「看不清」的主因。
- 「尚不可收集」的角标不用报警红：1493 个红点读起来是「每一格都出了错」，
  而它其实是这一版的默认状态。改用中性浅灰绿（对压暗后的槽位牌 4.9:1，过非文本
  指示的 3:1）。完整的句子仍在 tooltip、`aria-label` 与详情面板里。

### 3.4 物品页

- 源丝带页眉（411×38）承载「装备图鉴 · 当前可获得」，右侧纸面上写「第 1 / 29 页 · 本页 60 格」。
- 槽位牌用源 `category/itemComplete|itemIncomplete`（94×94）。源孔位是暗的、物品图标本身
  也偏暗，所以在孔位铺一层**纸色凹槽**（界面扩展 P，底色取源瓦片纸色族）——
  图标压在凹槽上才读得出。
- 已获得 / 未获得靠牌子亮度区分（源牌子的聚光灯语义），不靠换色。
- 物品名走服务端 `label`（`catalog.item_label(id).unwrap_or(id)`，即 `shared/items.json`）；
  服务端没给名字时才退回 `itemName()`，再不行才是 id。

### 3.5 紧凑布局（窄屏 / 矮屏）

判定：`width < 900 || height < 690`。放弃源绝对坐标改流式：标题、进度、页签、搜索、
地区索引、相册卡片依次竖排，槽位自己换行；**只隐藏铺满整块源坐标的位图**
（`backgrnd`、`tab_line`、`sheet-board`），槽位底板留着——它就是让图能读的那层。
窗口必须 `box-sizing: border-box; width/height: 100%`，否则那圈 1px 边框会让窗口比视口大
2px（实测 846×392 vs 844×390）。

## 4. 界面扩展（P）登记

| 项 | 理由 |
| --- | --- |
| 页签底板重画 | 源图把文字烧在底板里，新文案会叠字（§2.3） |
| 标题自带暗底 | 源顶栏带 73% 不透明，可读性不能取决于窗外 |
| 地区索引栏（可搜索的竖列） | 源只有 `SubCategory/*` 面板；本地化索引是界面扩展 |
| 槽位名条 / 行名 | 源把名字烧在自家牌子里；这里是 DOM 文本，便于本地化与省略 |
| 物品孔位纸色凹槽 | 源孔位过暗，图标读不出（§3.4） |
| 「尚不可收集」角标 | 计划要求「明确标出当前版本尚不可收集」，源无此标记 |
| 字号 / 配色表 | 上述取值的可读性基线（对比度全部 ≥4.5:1，非文本 ≥3:1） |

## 6. 已知边界（如实登记）

- **行名的可读空间只有 16px**：行距 84 − 瓦片 68 = 16px。行名（12px 行高）与上一行的
  名字条（牌内 `bottom:1px`，13px 行高）之间只剩约 2px。行距由源瓦片决定、不能改，
  所以这里偏紧但不重叠；再挤只能砍掉上一行的名字条，那会把源里的名字丢掉。
- **槽位 68px 起于 x=35**，源自己的盒是 70px 起于 x=34（§1.1 已登记）。
- **`monsterGrade/0..4` 未使用**：源有这些帧，目录没有逐槽位等级，不冒充（§3.3）。
- **源有一个地区没有名字**（`monsterStructure.regions[100]`，里面有 5 行
  「2017冬季怪物收藏活動N」）。索引按钮标为「（源未命名地区）」——标出缺，不起名，
  也不留一个认不出来的空按钮。
- **`--nb-paper-2` / `--nb-paper-3` 是推导值**，不是实测像素，已在 §2.2 标出。
- 样张里的物品名走 `shared/items.json`：夹具若给错 `label`（例如读目录里并不存在的
  `items[id].name`）会把真名字盖成物品 id——夹具必须照抄服务端的 `item_label`。
