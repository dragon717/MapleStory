## 先找状态拥有者

| 位置 | 负责内容 | 添加行为的入口 |
| --- | --- | --- |
| `server/src/main.rs` | 配置与启动组装 | 新模块在此显式加载、校验、注册 |
| `server/src/network.rs`、`protocol.rs` | HTTP/WS、消息边界 | 验证字段并投递命令，不能改世界状态 |
| `server/src/auth.rs` | 账号、密码hash、token、SQLite | 身份归属由认证结果产生 |
| `server/src/world.rs` | 唯一权威世界、输入与移动 | 在已有顺序模拟流程调用新规则 |
| `server/src/combat.rs` | 普攻实例、冷却、幂等 | 伤害在world顺序处理，持久事务由auth Store执行 |
| `client/src/features/player/` | 输入和纸娃娃呈现 | 读取权威快照与原始资源时间轴 |
| `client/src/network/` | 登录、连接、断线 | 不上传权威坐标、伤害或替别人操作的ID |
| `shared/protocol.ts`、`shared/map.json` | 两端消息和地图几何 | 同一变更同步修改Rust/TS/机器人 |

Rust只有一个逻辑拥有者顺序处理输入、模拟、广播。网络与认证IO可以并发，不能绕过队列改世界。不要创建每角色模拟task、多个世界锁或并行结算；分片、分布式与并行模拟属于未来决策，先与用户讨论。

## 新配置还是新机制

已有行为的新参数、外观、同机制技能先加数据，注明WZ版本、来源路径、单位和默认值，并在启动时验证范围与引用。不能因写了配置就允许任意脚本执行。

确实需要新机制时，增加普通数据结构与一个处理函数，在已有启动/规则入口显式登记。多个对象组合所需字段，不做每技能一个类，不移植Java深继承。未实现的任务、奖励、背包不提前建空目录或通用工厂。

## 协议与权威边界

改协议必须一起改 `shared/protocol.ts`、Rust serde消息、浏览器发送/接收、机器人。更改不兼容结构时更新protocolVersion；内容结构或素材替换同步contentVersion。类型检查不能代替运行时输入校验：未知字段、枚举、长度、非有限数、频率与包大小仍需拒绝。

连接绑定认证角色，意图只影响自身。连续输入用递增seq拒绝旧包；离散动作以主体+操作+requestId去重，重发返回原动作，不再次广播或结算。普攻、拾取和复活以SQLite事务/持久化去重约束奖励与副作用；进程缓存可以有界，但不能替代持久化记录或宣称单靠内存可跨崩溃exactly-once。
