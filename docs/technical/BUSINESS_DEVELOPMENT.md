# 长期开发规范

这里只维护当前有效的开发约定。任务范围与待办见[PLAN](../plan/PLAN.md)，历史证据见[索引](../plan/INDEX.md)；重构前的逐字节版本见[历史快照](history/2026-10-03/开发规范重构前/长期开发规范.md)。旧授权不自动开启新任务。

## 协作、复用与变更

- 用户首肯后，在已授权范围内自主推进实现、必要验证和交付，不为已确认选择重复请示；中途纠正及时调整。缺失关键输入或未确认的实质冲突才提出最少问题，独立工作继续。
- 已定方法直接复用，新的行为再设计。通用方法维护技能，项目契约维护本文或对应专题，参数维护代码/配置；一次任务的对象名、坐标、错误与测量归历史。新旧冲突讨论确认后，更新现行入口并归档旧版，不靠不断追加“最新补充”维持多套规则。
- 本轮通用技能的维护源在`docs/technical/skills/`，用户技能目录是安装副本；后续改维护源再同步并核对一致，避免两份独立演化。
- 主代理亲自完成核心设计、权威状态/规则、共享协议、持久化、跨模块实现和集成。辅助使用当前用户指定的`gpt-5.6-luna/max`，只承担边界明确的核查或局部工作；文件所有权明确，不能交叉写共享文件。工具/并发不可用先说明，不虚构指派或强度。
- Git提交用简短中文概括实际变更；报告说明结果、必要证据和未测范围。已有授权持续有效，但不会扩大任务范围或替代对外发送、push等操作所需授权。

## 当前项目与来源

- 当前复刻资源来源为`参考/273`中的TMS273.7。同版WZ核定资源、坐标和时间轴；[研究包](../../references/tms273_research_pack/)辅助缺失交互和模块设计。83、跨区源码及私服数据只作有范围的对照，不冒充当前原版事实。
- 保留来源T（同期台服）、R（跨区结构）、P（项目设计）、U（未知）、X（时代外）边界。具体任务允许的临时规则以当前用户授权/PLAN为准，不从旧授予SP或快捷转职记录推导新授权。
- UI实施先核对研究包对应PDF页、HTML图卡原图和本地273节点；编号附所属文件，标题/链接不等于看过原图。无法核看就注明。保留原版界面和交互，除非用户已确认改版。
- 复用已确认组件、资源与导出器。分卷WZ、UOL/outlink、origin/anchor、zmap/smap和delay保留真实语义；整体角色统一翻转，不二次减组合后origin，不在展示入口另造装备规则。
- 文件、命令输出、日志、JSON和路径始终UTF-8；中文路径进入HTTP header时用JSON转义、percent-encoding或base64。其他项目的工具、设备、目录和经验不作为本项目事实。

## 状态与业务所有权

| 位置 | 责任与边界 |
| --- | --- |
| `server/src/main.rs` | 配置、加载、校验、注册 |
| `server/src/network.rs`、`protocol.rs` | 验证消息并投递命令，不直接改世界 |
| `server/src/auth.rs`及Store | 身份、授权、SQLite事务与持久去重 |
| `server/src/world.rs` | 唯一权威世界，顺序处理输入、移动与结算 |
| `client/src/features/` | 读取权威快照、原版资源和既有规则，负责显示与输入 |
| `shared/` | 两端共同的协议、内容与几何契约 |

- 先找状态拥有者，再复用已有行为。新参数/同机制外观先加数据；确需新机制才加必要处理入口，不预建类层次、工厂、空模块、每角色模拟task或第二套世界状态。
- 网络与认证IO可并发，不能绕过顺序世界结算。分片、并行模拟等架构变化另行讨论；性能优化必须有真实瓶颈证据。
- 消息运行时验证未知字段、枚举、长度、非有限数、频率和包大小。认证绑定主体；客户端不能指定他人身份、权威坐标或伤害。连续输入拒绝旧seq，离散副作用按主体/操作/requestId持久去重。
- 奖励、物品、金币及回执在同一持久事务中处理；重试返回原结果，不重复扣费或广播。先校验目的地/操作有效性再消费，进程缓存不能代替跨崩溃的持久去重。
- GM权限只来自服务端稳定账号ID允许名单，默认空；授权租约由认证拥有，World在命令/tick前阻止失效控制并清输入。重新认证、换角、退出和撤销沿现有租约链路处理，客户端不复用已撤销token；姓名、注册顺序和本地开关不能授予权限。
- 改协议同步Rust/TS/机器人及真实收发方；不兼容结构更新protocolVersion，内容结构或资源变化同步contentVersion。当前值查源码与发布制品，不把文档旧版本号当现状。

## UI、地图和生命周期

- HUD用现有网页布局按空间分组、换行或已授权折叠，保留同版素材比例、顺序与可读操作；世界相机与HUD比例分别核对，不能用整屏缩小/裁切掩盖溢出。小屏生命信息、设置和聊天优先；改布局不授权新增业务。
- 窗口、按键和二级入口复用[UI规范](UI_WINDOW_SYSTEM.md)。地图制作使用[地图开发入口](3D场景开发通用指南.md)及通用技能`walkable-3d-maps`；具体地图连接、承载体和参数从当前源布局核对。
- 断线、换图、重连、失败和取消清理输入、监听器、计时器、声音及渲染资源。异步结果用当前对象/地图/generation守卫，过期结果销毁；恢复沿权威快照，不用旧缓存冒充当前状态。
- WZ共享bitmap由archive拥有，资源纹理按URL复用；动画不创建永久监听器。源码、导出、正式接入和用户实际观感分别验证。

## 生成资源与存档故障

- 先追具体错误与全部消费者，再查来源→生成器→装配→编译制品→运行时→存档。失败阶段标签不等于数据库坏；优先修上游真实来源和必需引用，不手补单个生成结果。
- 本项目物品链路：`generate_tms273_gameplay.py`→`resources/tms273-export/items.json`→`assemble_tms273.cjs`→共享/运行物品目录；服务端`inventory.rs`以`include_str!`编入目录，只换JSON不能更新旧二进制。
- 新建角色、商店、掉落、任务和旧存档都是目录消费者，不能只按新地图引用裁剪。`tms273_creation_catalog.cjs`核对非零创建装备，在切换旧服务前拦截缺项；它不证明所有旧存档都兼容。
- 存档`InventoryItem.slot`为正，装备表/协议为负，`MaPn`连身衣为-5。先查物品存在与`info.islot`，未知引用也可能报槽位错配；不通过改号、删装备、清库或放宽校验绕过错误。
- 只有证据证明持久数据需要迁移才做保留实例字段的事务迁移；用临时数据和真实目录验证保存→重开→加载，非法数据仍拒绝。通用调查使用`codebase-investigation`，具体修复证据归历史。

## 构建、资产与最小验收

- 普通启动/重启只用根目录`启动3010.command`，配对候选前后端、健康通过后切换并保留当前/上一成功版，失败恢复。用户数据库、bot凭据和原始资产不参与构建清理；不为测试清库或另起服务。
- `client/public-tms273`是内容装配产物，不复制进生产dist；服务端先读Vite产物再兜底内容。源内容/编译数据变化沿实际消费链判断是否需构建，不能把刷新内容等同更新编入二进制的数据。
- 保留启动/构建现有阶段耗时和日志契约；发布脚本的ASCII阶段标记供启动器解析。目录轮替复用`moveFlat`文件搬移，清理用Node文件API，不恢复曾造成iCloud长阻塞的整目录改名或shell递归删除；具体测量只作历史证据。
- 素材树、派生导出和构建缓存遵循README/.gitignore及[素材管理](ASSET_MANAGEMENT.md)：只留当前可用版和必需输入，删除独立历史素材快照/自动备份，保留计划日志；小素材分批逐文件入库，音乐本轮不处理。被忽略的可编辑源也必须安全同步，清理工作树前检查。提交守卫拒绝超过90 MiB的普通Git blob及被禁的地图大导出，保留`.githooks`接线。
- 非平凡逻辑留一个能抓真实失败边界的可运行检查，优先已有定向检查；权威/幂等改动含非法或重复输入。只跑受影响编译/检查，通过后停止重复验证，不恢复独立QA。
- 资源/表现实玩由用户验收；未测的加载、路线、遮挡、装备、动画、尺寸适配和远端行为如实说明。文档/技能整理只核对内容、引用和技能发现，不无故重启游戏。
