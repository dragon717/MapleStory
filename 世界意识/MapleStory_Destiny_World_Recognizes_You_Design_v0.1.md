# 天命：让世界认得你
## 冒险岛复刻项目 · 世界识人、身份边界与权柄演化设计

> **版本**：v0.1  
> **日期**：2026-09-10  
> **文档性质**：原创设计基线、最小验证规格与工程落地计划。  
> **项目背景**：冒险岛复刻；Rust 服务端权威世界，Web / TypeScript 客户端。  
> **工程边界**：沿用既有世界、战斗、任务、效果、资产和通知模块，不另造一套天命游戏。本文未审查当前仓库源码；新增类型、目录和事件名均为建议，不代表已经存在或已经实现。所有服务启动及集成验证统一使用项目 `启动3010.command`。  
> **原作边界**：天命、人物、事件、权柄与规则均为本项目原创提案，不是 TMS V273 原作设定；文中的“飞侠加力量”只作身份不对称的比喻，不作为现代冒险岛属性公式的依据。

## 0. 总纲：不是给玩家一个系统，而是给世界一种认人的能力

我们要做的不是一个新系统，而是让世界能够认出人。

第一性的问题不是“给什么奖励”，而是：**你做过的事，有没有真实地进入这个世界；某个存在能否因此注意你、记住你，并在下一次相遇时作出不同的回应。**

天命最初不是能力，不是职业选择，不是抽到的稀有词条。它起于自由行动：玩家偏爱一些事，反复作出一些选择，世界逐渐察觉某种轮廓。先是某个人的一句话、某条路的一点变化、某件旧物的一次异动。玩家才开始意识到：这里似乎有什么认出了我。

> 我喜欢什么，我持续做什么。  
> 世界回应什么，我就更像谁，也更愿意投入。  
> 我的偏爱不再只是内心的事，它开始在世界里留下形状。

但只有顺着偏好不断加成，得到的只是熟练度。天命还必须带来边界：一些事情从此与你更相称，另一些可能却不再能够同时保有。它不是额外附送的惩罚，而是“我是这样的人”开始产生真实含义。

当不同的人沿着不同道路走向同一个大道，例如“存续”，他们可能合作，也可能最终对同一个存在提出互不相容的答案。此时争夺的不再是一项技能，而是：**谁有资格让自己的理解成为这个存在实际遵循的规则。**

宿命感不来自出生时写好的终点，而来自回望时发现：原来那些无人强迫的选择，一直在把我带向这里。

NPC 同样如此。他们会坚持、动摇、受诱惑、背叛、争夺，也会在没有玩家见证的地方完成自己的命运。这个世界不是专为玩家准备的英雄舞台，而是一个本来就可能诞生英雄与神的地方。

**整份设计最终只服务于一句话：**

> **我认得你。**

## 1. 本轮冻结的核心判断

| 问题 | 本文采用的判断 |
|---|---|
| 天命是什么 | 行动历史与世界规则相遇后，逐渐形成的关系、身份、边界与有限权能；不是独立养成条 |
| 先发生什么 | 事实变化 → 被具体存在记住 → 世界回应 → 玩家察觉；不是先发天命技能再安排任务 |
| 世界认识的是什么 | 游戏内这个角色做过什么、承担过什么、如何在不同情境下选择；不推断现实人格 |
| 什么使身份成立 | 可回溯的选择与持续承担；不是标签分数最大、刷取次数最多或付出货币最多 |
| 边界何时生效 | 轻微相性可以被发现；重大约束必须经过可理解的征兆与主动承担，不能秘密锁死 |
| 唯一性落在哪里 | 同一世界连续体、同一存在、同一互斥规则位置；不把整个“存续大道”做成仅一人可玩 |
| NPC 与玩家是否同规则 | 对事实、资源、承诺和权柄资格同规则；行为决策与模拟精度可以不同 |
| 首个实现 | 一次有效帮助、同一 NPC 的再次相遇、一次可验证的具体回应；不先做成神与争位 |

### 1.1 必须同时成立的四句话

**被看见，不等于被判定。** 一次救援值得留下记忆，不足以证明角色“天生善良”。

**被认出，不等于被赞许。** 商人可以记住一个守信的人，敌人也可以记住一个执意复仇的人；世界回应不等于道德奖励。

**有边界，不等于失去自由。** 玩家仍能背离、改变、放弃和重新承担，只是世界不会假装旧选择从未发生。

**结局有因，不等于结局预定。** 相同事实应得到一致处理，不同选择必须能够真正改变结果。

### 1.2 不做什么

不新增“天命经验／天命币／天命日常／天命抽卡／天命排行榜”。不以全知人格测验给玩家配职业。不把全世界的 NPC 变成共享同一个好感数据库的嘴。不用黑箱永久惩罚制造深刻，也不把“你应当接受命运”当作设计缺陷的辩护。

同样，不因为担心玩家失去东西，就取消一切舍弃。**需要保护的是选择成立的条件，不是保证每条道路都能兼得所有结果。**

## 2. 与冒险岛复刻的关系：保留动作与成长，改变世界回应人的方式

既有复刻计划优先完成“打怪—成长—换打法—挑战 Boss—进入新区域”的可玩闭环。本设计不替换这条主线，也不要求先完成全部现代冒险岛内容才能验证识人机制。[P1]

两条工作线独立验收：复刻线负责角色操作、战斗、成长与内容正确性；天命线利用已经成立的行为和世界事实，验证“投入被世界具体记住”。不能用一个有情绪的小事件掩盖战斗未完成，也不能让创新变成另一套数值膨胀。

### 2.1 四种概念必须分开

| 概念 | 回答的问题 | 与天命的关系 |
|---|---|---|
| 职业 | 我擅长用什么方式行动 | 提供行动工具，不替角色决定道路 |
| 熟练度与成长 | 我把某件事做得有多好 | 可以增强能力，但不能替代身份与舍弃 |
| 声誉与关系 | 谁知道我做过什么，如何看待我 | 是世界识人的重要入口，但不是全知裁决 |
| 天命 | 当我可以成为许多人时，我持续成为了谁 | 由历史、回应、承担与边界共同构成 |

同为飞侠，一个人可能不断给后来者留下退路，另一个人可能习惯保存将要被抹去的名字。两者使用相近的移动与战斗能力，但逐渐被不同的存在认出。

反过来，战士、法师、弓箭手也可能以不同手段走向相近的道路。**职业影响“我怎么做”，天命更关心“我在什么情况下仍然这样做”。**

### 2.2 与既有世界节点设计的连接

灯塔、古树、圣泉是不同表现的世界生命节点。节点恢复首先改变路、旅人、商队与故事能够发生的条件，而不只是提供属性。

天命不再给这些节点追加一条刷取进度。它关注：面对同一个节点，有人不断修复通路，有人保护周边生命，有人保存失落技艺，有人选择封存危险。节点的事实变化对相关玩家共享；参与者被谁记住、受到什么邀请，则可以不同。

> **世界节点回答“这里怎样重新流动”。**  
> **天命回答“在让它流动的过程中，世界认出了谁”。**

## 3. 因果结构：世界事实在前，身份解释在后

```text
世界事实与通用规则
       ↓
角色／NPC 在当时条件下采取行动
       ↓
行动产生后果、代价、痕迹与新的可能
       ↓
知情者形成记忆；相关存在留下感应依据
       ↓
多种情境中的倾向逐渐浮现
       ↓
世界给出有来源、有限度的回应
       ↓
玩家察觉、理解、接受或拒绝这种关系
       ↓
更明确的承担使身份获得边界
       ↓
少数身份在具体领域形成权柄资格
       ↓
新的行动、新的冲突、新的世界历史
```

这不是一条必须走完的升级路线。有人只被一个村庄记住，有人一生没有正式命名自己的道路，有人背离旧命，有人到达权柄。这些都可以是完整的游戏经历。

### 3.1 每条回应都必须回答五个问题

| 问题 | 合格答案的形式 |
|---|---|
| 发生过什么 | 能找到具体事件、参与者和状态变化 |
| 谁有理由知道 | 亲眼看见、参与其中、听见有来源的转述，或符合明示的超自然感应规则 |
| 为什么认为与这个人有关 | 有角色身份与贡献的归因，不靠站在附近或抢到最后一下 |
| 这次回应改变什么 | 对话、关系、行动机会、环境事实或受约束的能力，而不只是浮字 |
| 玩家怎样理解它 | 能从现场、旧事、人物行为或可查看的记录中找到解释 |

答不上这些问题的“命运回应”，先不制作特效。

### 3.2 世界可以回应，但不能为讨好玩家捏造需求

玩家经常修桥，可以让真实存在的桥梁问题更容易被他发现，或让知情工匠想到请他帮忙。不能因为系统判定他“喜欢修桥”，就不断在他前方生成断桥。

机会首先来自世界事实。偏好最多改变合理的信息到达与关系邀请，不能改变事故是否真实发生。

**回应应扩大玩家能够认识的世界，而不是把他关进自己偏好的回声室。**

## 4. “世界认得你”其实包含三种不同的认识

### 4.1 事实：发生了什么

服务器掌握权威事实。例如：桥板确实装上了、药品确实消耗了、某人确实活着离开、记录确实被焚毁。

事实记录不是世界里所有人物都可读取的广播。后端知道一件事，不代表旅馆老板也知道。

### 4.2 记忆：谁知道什么

NPC 记忆是带来源的局部认识。一个车夫可能记得你扶起过车，却不知道你后来为什么烧掉了一封信。他可以误解，可以只知道一半，也可以在获得新证据后改变看法。

转述必须有路径：旅人告诉商队，商队抵达驿站，驿站的人才可能听说。不同 NPC 不必持有相同解释，谣言也不能被悄悄升级为系统事实。

### 4.3 感应：什么存在会对什么事实作出反应

世界的超自然回应也需要规则，而不是用“它是神”替代规则。

例如，本项目可以定义：某盏古灯保存经过灯路的生命痕迹，并对“主动为他人保持通路的人”产生感应。那么感应只能使用这盏灯能够接触的事实，不能知道角色在另一片大陆未被记录的秘密。

首版不做全知的“宇宙人格评审器”。先做能说明感应范围的灯、树、遗物与地方存在。后续大道层面的认识，也必须明确其媒介与边界。

### 4.4 三者分离带来的叙事空间

一个人可以在事实层面救了村庄，却在社会层面被误解；也可能得到某件遗物的认可，却不愿接受人们给他的称呼。

这里才有误认、平反、秘密、牺牲与历史。若所有 NPC 自动共享后台真相，这些空间都会消失。

**世界记得 ≠ 所有人知道 ≠ 所有人赞许 ≠ 每次都有奖励。**

## 5. 从自由行动识别倾向，但不进行人格判决

### 5.1 保存已经发生的事，不保存“这个人本质是什么”

行为证据记录的是：谁在什么条件下做了什么，改变了什么，实际承担了什么，以及哪些事实仍然不知道。

不记录“玩家善良度 82”“玩家真实人格是守护者”。不使用私聊、现实资料、充值金额、在线时长、输入速度或社交关系推断角色的命运。

即使有人是为了奖励才救人，服务器也通常无法知道他的真实动机。合适的回应是“你那天回来了”，不是“我知道你内心毫无私欲”。

### 5.2 哪些事件值得成为证据

| 事件 | 可以说明什么 | 不能直接说明什么 |
|---|---|---|
| 扶起翻倒的车 | 帮助确实发生，车重新可用 | 此人必然走向守护 |
| 返程时再次修复已松动的桥板 | 对后续使用者持续关心的可能 | 此人拒绝所有冒险 |
| 战斗失败但实际掩护同伴撤离 | 曾选择承担风险，且存在可核实后果 | 获得了并不存在的胜利 |
| 保留并传授一份旧配方 | 知识被接续到新的持有者 | 所有传承都值得保留 |
| 路过而没有帮助 | 这次没有发生帮助行为 | 冷漠、自私，或未来永远不会帮助 |
| 在强制教学中完成操作 | 学会了操作、完成了既定事项 | 在自由选择中显露了偏爱 |

失败可以成为证据；未选择不能被自动当成反证。人物可能没有看懂、没有能力、没有资源，或者正在处理另一件同样重要的事。

### 5.3 用“证据组合”而不是“隐藏经验条”

首版只维护少量可解释的候选倾向。例如“为后来者留路”，需要能够互相说明的事实：留下可用通路、在不必返回时维护它、在其他条件下仍关心后续通行者。

这些事实共同支持一种可能的解释，但不自动把角色永久定型。多条候选可以并存，也可以暂时无法解释。

规则不是“修桥三次 = 留路者”。同一次事故反复拆修不能扩充独立证据；同一种受迫行为重复很多次也不等于自由偏好。反过来，许多平凡的小选择可以慢慢形成身份，不强制每个人都经历一次宏大牺牲。

### 5.4 四种证据状态

| 状态 | 含义 | 系统允许做什么 |
|---|---|---|
| 单次记忆 | 一件事值得被记住 | 具体感谢、后续认人、留下环境痕迹 |
| 候选倾向 | 多件事实可由同一方向解释 | 提供低风险、可拒绝的接触与回应 |
| 有效承担 | 角色理解并主动承担了一段明确关系 | 启用与关系相符的馈赠与边界 |
| 已形成历史 | 承担经过持续行动、变故或公开后果 | 进入地方身份与后续权柄资格判断 |

这些是内部证据语义，不是对外显示的四个品阶，不配经验条，不用稀有度颜色包装。

### 5.5 防刷必须尊重真实事实

同一因果事件中的扶车、递药、站岗，可以分别记录贡献，但不能伪装成三次独立人生选择。玩家主动造成危险后再修复，损坏与修复都进入事实链；不能只保留对其有利的一半。

知情 NPC 是否看穿，要依据他的知识。规则侧是否把这次修复当成新的道路证据，要依据已知因果来源。不能让防作弊逻辑变成全体 NPC 的读心能力。

结伴玩家可以真实地反复互助，不能因为“总是这几个人”就抹去他们的关系。高阶资格需要不同条件下的承担、可靠的事实来源与实际后果，而不是粗暴否认固定队友之间的意义。

## 6. 世界如何回应：先具体，再神秘，最后才有能力

| 层次 | 回应方式 | 原创示例 | 不该怎样做 |
|---|---|---|---|
| 记得这件事 | 具体的人记住具体行为 | 车夫保留了你垫车轮的木块，再见时提起 | 所有人统一说“伟大的英雄” |
| 关系改变 | 人物对你的行动预期改变 | 工匠先问你的意见，而不是只发任务 | 直接解锁一页声望奖励 |
| 机会改变 | 真正相关的人与事情更容易与你相遇 | 有来源的求助、可拒绝的托付、一条可信的消息 | 凭空制造事故喂给玩家 |
| 存在回应 | 具有规则的节点或遗物注意到你 | 古灯在符合条件的经历之后作出微弱反应 | 一次行为后弹出 SSR 天命 |
| 能力与边界 | 已理解、已承担的关系改变可执行行为 | 一段灯路因你的驻守而保持，但不能随你同时移动 | 永久叠加攻击力而无身份意义 |
| 权柄影响 | 对特定存在的解释成为实际世界规则 | 根火选择封存或繁生，改变所在领域的演化条件 | 只换一个更大的技能特效 |

### 6.1 有形回报可以有，但不能抢走第一次回应

旅人可以送出合理的小礼物，节点后续也可以提供条件性效果。问题不在“能不能给”，而在：玩家是否把世界的回应理解成结算面板。

首个验证切片不增加战斗属性、不设置天命货币、不提高稀有掉率。先验证“他真的记得我”。后续能力必须复用现有技能与效果系统，不再制作第二份属性计算器。

### 6.2 没有立即获得好结果，也不意味着投入被吞没

桥可能后来又被洪水冲坏，但曾经通过它的人确实已经抵达。传下的技艺可能被误用，但它的传播确实由你改变。失败不是自动退还全部投入，也不是删除行为记录。

投入不被吞没，指的是**后果与历史真实存在**，不是保证付出始终盈利。世界的回应可以是感激、依赖、误解、拒绝、警惕或新的责任，但不能只是为了延长在线时长而无限索取。

## 7. 玩家旅程：从无名到权柄，不是六次转职

以下是体验上的可能演化，不是固定关卡顺序。命名可以迟到，角色也可以拒绝命名、长期保留混合倾向，或在形成权柄之前结束自己的故事。

| 体验阶段 | 玩家可能察觉到什么 | 世界实际发生了什么 | 设计禁区 |
|---|---|---|---|
| 无名 | 我只是按自己的喜好行动 | 事实正常积累，没有预选命运 | 出生即暗中分配终局 |
| 被记得 | 这个人似乎真记得上次的事 | 局部记忆与关系成立 | 单次善举盖人格章 |
| 异兆 | 这已经不完全像普通感谢 | 存在依据规则作出回应 | 立刻解释全部世界观 |
| 认识自己 | 原来这些事之间有联系 | 玩家回顾多段事实，并形成自己的解释 | 后台替玩家宣布唯一正确人格 |
| 立命 | 我愿意以这样的方式继续 | 主动承担使馈赠与边界同时成立 | 不知情的永久职业锁 |
| 执道 | 我开始遇到同道者与不同答案 | 身份与具体世界问题发生冲突 | 强制所有同道敌对 |
| 权柄 | 我的理解开始成为某处的现实 | 获得有对象、有边界的规则权限 | 全服绝对优势与任意改写世界 |

### 7.1 命名不是分配

世界可能先给出一个称呼：“留灯的人”“记得那些名字的人”。这可以是别人对角色的理解，而不是系统已经定下的职业。

玩家可以承认，可以拒绝，也可以说“你只看见了我的一面”。拒绝称呼不会删除已发生的事。真正的边界来自之后如何行动与承担，而不是在一个对话框里选了某个浪漫词语。

### 7.2 不立命也是有效状态

普通冒险者不应因此无法完成基础成长、进入主要区域或参与队伍。天命不能变成所有玩家为了数值不得不做的隐形主线。

但“不立命”也不是一个把所有道路优点都拿走的最优职业。它保留灵活性，同时没有那些只有明确承担才会成立的特殊权能。

## 8. 馈赠与边界：不是附赠诅咒，而是同一规则的两面

### 8.1 边界要从力量的成立条件里长出来

如果力量来自“我让后来的人仍有路可走”，那么它可以维持一条正在承载他人的通路；但不能一边维持这条关系，一边借同一种权能把受保护者封死在路上。

这不是“做好事获得力量，做坏事扣十点”的道德积分。它是同一项力量不能同时实现相反的命题。

### 8.2 区分三类边界

| 边界 | 含义 | 原创示例 |
|---|---|---|
| 构成性边界 | 没有这个条件，力量本身不成立 | 以见证保存的记忆不能凭空补出从未被见证的内容 |
| 承担性边界 | 这段关系要求持续承担某件具体事情 | 将自身与灯路相系期间，离开作用范围就不再维持灯路 |
| 排他性边界 | 同一个载体不能同时容纳互斥状态 | 同一根火不能在同一时刻既冻结原态又用于繁生 |

边界不应无理由横向蔓延。承担灯路，不意味着角色突然不能交易、跳跃、学习职业技能或进入正常副本。

### 8.3 重大边界的成立流程

```text
出现可忽略的征兆
    → 玩家在安全情境中理解它如何回应
    → 看见或亲历这份力量的局限
    → 在真正承担前获得明确说明
    → 以有世界意义的行动主动承接
    → 馈赠、约束与历史同时生效
```

确认可以融入仪式、托付或物件互动，但涉及持久损失时必须有朴素说明，不能只剩诗句。

例如：

> “将灯与你相系后，这段临时灯路会由你维持。你仍可以离开；离开会结束维持。当前尚未完成通行的人需要改走已有退路。此承诺不影响你的职业技能。”

这里不预设“按下离开就必须害死人”。应由当时可用的退路、护送者和场景规则结算实际后果。世界可以严肃，规则不能故意埋雷。

### 8.4 可以背离，但不能假装没有背离

改变道路采用“新事实覆盖当前状态，旧事实仍然可追溯”的方式。角色可以解除契约、寻找继承者、修复关系、偿还具体损失，也可以拒绝偿还并承担对应社会后果。

不能做成“花钱洗掉过去”；也不能要求玩家永久被早期探索困住。早期倾向允许变化，正式承担之后的改道才需要相称的过程。

### 8.5 诅咒感属于人物体验，不是策划免责条款

角色可能曾把一份馈赠视为荣耀，后来才体会到它的重量，并称它为诅咒。这是成立的叙事。

但不能把所有不适都解释为“玩家境界不够”。若代价无法预见、与能力无因果联系、只能通过长期打卡解除，那是机制问题，不是深刻的天命。

## 9. “存续”不是一个技能系，而是多条道路共同面对的问题

存续关心的不是简单的“活下来”，而是：**什么值得继续存在，它以什么形式继续存在，谁有权决定这种继续。**

它可以指生命、名字、技艺、文化、关系、道路与火种。走向同一大道，不等于重视同一个对象，也不等于接受同一种方法。

### 9.1 四条原创道路样本

这些名字是内容探索用的候选称呼，不是开局四选一职业卡。

| 道路 | 反复选择的方向 | 世界最初怎样认出他 | 馈赠与边界的同源关系 |
|---|---|---|---|
| 留灯 | 不让眼前的人被遗落在黑暗或断路里 | 被他接回的人记得，承担通行的灯路留有痕迹 | 能维持正在承载人的联系；无法用同一承诺把他们主动隔绝 |
| 传火 | 让技艺、语言与愿望不随唯一载体消失 | 学徒、迁徙者与已被接续的事物记得 | 能促成接续；不能同时保证原载体、原样貌与一切关系永不改变 |
| 铭史 | 让真实发生过的生命与选择不被抹去 | 名册、证物与见证者留下回应 | 能保存可证实的痕迹；不能为安慰或胜利伪造未发生的过去 |
| 开途 | 让被截断的往来重新可能 | 后来者实际走过的路成为证据 | 能建立符合条件的联系；不能把“通路”同时定义为只许自己通过的囚笼 |

它们可以共同修复一个节点：留灯者维持夜间通行，传火者教会当地人维护装置，铭史者保留施工者与亡者的名字，开途者寻找新连接。

这里没有必要发生神战。**相同大道首先提供理解与合作的可能，只有具体答案互斥时才产生根本争夺。**

### 9.2 不是每条道路都必须被命名为神

地方称呼、民间故事、某种遗物的认可，已经足以成立身份。神与权柄是少数道路在特定世界条件下抵达的结果，不是每个版本都要上调的成长档位。

## 10. 唯一性与权柄：谁的理解能够成为现实

### 10.1 冲突不能仅仅因为“你们都选了存续”

同一座森林中可以同时有保存记忆的人与培育新生的人。真正互斥的不是他们的称号，而是某个具体存在必须采用哪一种状态。

一场权柄冲突必须明确四件事：争夺的存在是什么、互斥的命题是什么、为什么不能同时实现、什么世界事实会使这种互斥解除。

最后一项尤其重要。**若玩家真正找到了符合规则的第三条路，设计必须允许冲突被化解，不能为了保住剧本临时宣布“还是只能死一个”。**

### 10.2 原创冲突样本：根火的两种存续

某区域的古树根火保存着最后一份完整的旧世生命印记。根据已建立、可验证的规则，它当前只有一个完整的核心，且同一时刻只能处于一种工作状态。

| 答案 | 支持者想保住什么 | 采取什么方式 | 真实的代价 |
|---|---|---|---|
| 封存 | 当前生命印记的完整性与不可替代性 | 维持原态，禁止根火进入会改变印记的繁生过程 | 不能用这部分根火推动新的生长与传播 |
| 传续 | 让印记中仍有价值的生命与文化进入未来 | 允许它改变、分化，成为新的承载者 | 无法保证原貌、全部细节与唯一载体继续完整存在 |

守藏者不是因为自私才反对传续：他认为，一旦允许缺失与重写，“延续”可能只是对真正消失的粉饰。

传火者也不是因为轻视生命才反对封存：他认为，永不变化的保存可能只是一座不再有未来的墓。

双方都在诚实地追求存续。冲突来自他们保护的对象和可接受的损失不同。

### 10.3 不把冲突写成必须发生的结局

根火案例的冲突成立依赖当时事实。若世界规则允许培育第二个完整核心，且角色真的完成了它，原先的资源互斥就可能消失。若允许分阶段运行，时间分配也可以成为答案；若转换本身会不可逆损坏印记，则必须提前建立这个事实，不能临时补设。

协商、继承、分域、暂缓、创造新载体、主动让位与武力都可能改变局面。战斗只能解决规则允许它解决的问题；打赢对手不自动证明其世界观正确，也不自动满足权柄资格。

### 10.4 权柄不是 GM 权限

权柄是对已定义对象与规则位置的有限授权。它只能调用预先存在的世界能力，例如维持节点模式、建立某种有条件的通路、决定一种明确的传承方式。

它不能任意删除角色、修改他人资产、封锁基础成长、绕过伤害校验或获得管理权限。玩家与 NPC 使用同样的许可边界。

### 10.5 唯一性的正确主键

```text
错误：AuthorityKey = 大道（存续）
      → 全世界只能有一个存续者，其余人的道路失去意义。

正确：AuthorityKey = 世界连续体 + 作用领域 + 具体存在 + 互斥规则位置
      → 对同一根火、同一时刻的同一模式决定，只能有一个有效结果。
```

一个大道可以有许多承载者、解释者与地方权柄。只有作品明确建立了“整个世界只有一个对应存在”的事实，才讨论世界级唯一权柄。

### 10.6 资格、争议与落位必须分开

候选者先用历史与实际承担获得资格；多个资格形成争议；争议通过场景既定规则、行动结果与有效协议形成裁决事实；最后才写入唯一权柄记录。

数据库的“只能写入一条”负责防止双重生效，不负责选择更配的人。不能把谁先发包、谁先上线、谁最后一击，偷偷变成世界的价值裁决。

### 10.7 失去权柄，不等于失去身份

权柄可以移交、分离、沉寂或被夺取。人物曾经怎样走到这里仍然真实存在；NPC 的记忆、已发生的改变与角色的道路不因一个权柄字段清空而被抹除。

这使让位、传承与失败成为可以生活下去的故事，而不是所有投入作废。

## 11. 宿命感：事后看见方向，而不是事前锁定终点

### 11.1 允许预设世界语法，不允许预设角色答案

策划可以写下古灯如何感应、根火有哪些限制、NPC 已经历过什么，也可以准备人物在不同条件下的行为。不能在创角时决定“这个玩家最终必定杀死某人并成为某神”，再把所有路径拉回同一结果。

可以预写表达片段，不能用表达片段伪造实际历史。

### 11.2 “冈格尼尔”作为本项目的设计隐喻

这里沿用用户的隐喻，不作神话考据：投出之前，没有人能够替你宣布落点；回望时，却发现无数次自由选择已经逐渐构成方向。

工程上要保证的是：真实选择累积成事实，事实影响后续机会和边界，结果可以被解释。不是让后台提前知道最终胜者。

> **必要的是“同因同果”，不是“任何因都导向同一个果”。**

### 11.3 三个必须通过的反事实检验

| 检验 | 合格表现 |
|---|---|
| 玩家在关键处改变选择 | 后续关系、身份或结局可以实质改变，而非换台词后回到同一结果 |
| 玩家始终没有参与 | NPC 和世界规则仍能推动事件，结果不必为玩家保留 |
| 第三条路在规则内被实现 | 旧冲突可以失效，不强行补一个新的不可解条件 |

### 11.4 回望如何呈现

后期的重要回应应引用前期真实细节，而不是临时添加“原来你从小就被选中”的设定。

例如，曾被拿来垫车轮的木块后来被做成一盏路灯的灯座；它成为新物件，必须有真实的保留、加工与交接事实。若木块早已被消耗或丢失，就不能凭空让它出现在仪式中。

真正的宿命感来自“我记得那件事，它真的走到了这里”，不是旁白替角色声称一切早有安排。

## 12. NPC 的天命：他们拥有过去、目标与不等你的未来

### 12.1 同一套主体模型，不同的行动来源

玩家通过输入发出行动意图；NPC 根据目标、知识、资源与承诺选择行动。进入世界之后，两者都必须经过权威校验，都产生事实，都受到相同的契约与权柄规则约束。

重要 NPC 可以拥有作者预设的过去，但过去应作为初始历史导入，而不是附带预设未来胜利。普通店员也可以有记忆与偏好，不必每个人都发展到神格竞争。

### 12.2 NPC 的最小决策结构

```text
已知事实 + 当前目标 + 可用资源 + 已承担的承诺
      → 找到当前可行的行动
      → 在有限决策预算内选择
      → 向世界提交普通行动命令
      → 承受真实结果
      → 更新记忆、计划与对承诺的理解
```

首版使用可检查的规则与有限目标选择即可，不需要在线大模型。未来即便使用模型生成对白或建议，也不能让生成文本直接改写资产、身份或权柄。

### 12.3 坚持、动摇、诱惑与背叛如何产生

| 行为 | 因果来源 | 不合格写法 |
|---|---|---|
| 坚持 | 已承担的目标仍被优先保护，资源允许继续 | 到第三幕自动变得坚定 |
| 动摇 | 两个真实目标发生冲突，旧办法持续失效 | 无原因随机切换阵营 |
| 受诱惑 | 世界中出现能解决其真实困境、但代价冲突的机会 | 专为推进剧情生成万能诱惑 |
| 背叛 | NPC 理解并选择违背某段承诺，留下可核实行动 | 播放背叛动画，但状态没有变化 |
| 争位 | NPC 已具资格，并与其他解释发生具体冲突 | 给 NPC 一个隐藏的必败标记 |

背叛不必意味着成为反派。一个守藏者可能为了保护还活着的孩子，主动焚毁自己守了一生的档案。他确实背离旧命，也确实可能正在形成新的理解。

### 12.4 无人见证时，也能完成命运

没有玩家在场时，NPC 仍可以尝试修路、传授技艺、让位或取得地方权柄。事件结果记录到世界历史。玩家后来通过遗物、转述、人物状态与环境变化获知，而不是进入地图才触发“其实等了你三个月”的假时间。

但不可跳过行动所需资源，也不可在离线结算时把一切直接判定成功。粗粒度模拟可以减少表现帧，不能省略决定结果的因果。

### 12.5 模拟分层

近处 NPC 执行完整移动与交互；远处重要 NPC 按事件与到期计划推进；普通群体使用区域状态与抽象任务。必要时将抽象结果转回可见实体状态。

模拟预算决定精细程度，不改变关键规则。随机结果一旦形成权威事实，重放时复用该结果，不重新抽签改写过去。

### 12.6 不把自主世界做成离线惩罚

世界可以在玩家离开期间变化，NPC 也可以先完成某件事。与此同时，玩家未接受的个人承诺不能被离线自动接受；未读的邀请不能被判定为背叛；命运身份不能因连续几天未登录而自动衰退。

已承担的共享职责可以允许明确的委托与继承。权柄持有人离线时，已生效的规则仍按契约运行；如何终止或移交必须依据事先建立的规则与新事实，不依据运营希望玩家回流的频率。

## 13. 冒险岛场景蓝本：从一辆翻倒的车开始

以下在“射手村林缘的一段原创岔路”中制作小切片，复用项目现有横版地图与互动能力。地图名是场景说明，不指定未经核验的原作地图 ID。人物“旅人阿苇”“守藏者槐生”“传火者烬禾”均为原创占位人物。

### 13.1 第一幕：没有任务，一个人遇到了麻烦

初始世界事实是：阿苇的车翻倒，货物有一部分散落；他需要稳定车辆、处理擦伤并恢复通行。玩家可以直接路过。

首版允许把翻车作为明确的场景初始条件，而不声称已经模拟了完整交通事故。后续自然发生的事故应由世界条件产生，不能根据玩家偏好凭空投放。

| 行动 | 最小可执行规则 | 产生的事实 | 谁能据此记住 |
|---|---|---|---|
| 扶车 | 车辆处于失稳状态，角色在合法交互范围，行动满足稳定条件 | 车辆恢复可装载状态；记录有效参与者 | 参与者、在场且具有感知条件的阿苇 |
| 递药 | 背包中有符合类型的药品，角色主动交付，需求仍存在 | 药品真实转移或消耗，伤势按既有规则处理 | 交付双方与合法见证者 |
| 短暂站岗 | 阿苇正在装车，附近有真实的通行风险；守望行为实际改变风险或掩护条件 | 此次装车获得一段有效掩护 | 被掩护者与相关见证者 |
| 不参与 | 无额外前置条件 | 世界继续推进，不产生“冷漠”标签 | 没有人因此自动认识角色 |

“站岗”不是站满若干秒领取善意分。没有需要掩护的行动、没有风险条件或没有实际改变时，可以有普通交流，但不虚构一次救援。也不能为了证明站岗有效临时刷出追杀怪。

### 13.2 第一次回应必须与动作一致

扶车的人可以听到：“先别松手……好了，这次站稳了。”

递药的人可以听到：“这瓶我记下了。等到了驿站，我把空瓶还你。”只有当空瓶真的保留并被带到驿站时，后续才可兑现这句话。

站岗的人可以听到：“刚才我敢转身搬最后那箱，是因为看见你还在那里。”前提是 NPC 确实知道玩家承担了掩护。

不出现“你获得了 10 点天命值”，也不立即命名角色为守护者。

### 13.3 第二幕：同一个 NPC，再次相遇

车辆恢复后，阿苇根据已有目的地和通行条件抵达营地。第二次遇见玩家时，读取的是这名 NPC 对这名角色的具体记忆，而不是全服的通用完成标记。

若玩家确实使用木块稳定车辆，且木块仍留在车上，他可以说：

> “是你。上回垫在车轮下面的那块木头，我还留着。”

若玩家只负责掩护，他应说另一段符合事实的话，不能把扶车功劳安在他身上。多人参与时承认各人的实际贡献，不把完整救援都归给最后完成交互的人。

营地里的位置、车辆状态或货物必须有对应变化。对白不能是唯一发生变化的东西。

### 13.4 玩家缺席时的分支

玩家没有参与，阿苇仍可依靠自己的资源和后来到场的帮手解决问题；也可能因条件不足延误行程。具体结果由当时的可行动作决定。

后来见面，阿苇不能感谢一个没有帮过他的人。玩家曾经帮助但中途离开，则保留那部分贡献，不把“没有见证最终完成”当成未参与。

### 13.5 从这件事走向天命，需要新的真实生活

单次翻车事件只验证“被记得”。后续再提供不同情境：有人维护返程路标，有人把修车方法教给别人，有人坚持把事故中遗失者的名字带回村庄。

同一行为在不同条件下才逐渐形成更稳定的解释。不能把翻车事件连续复制三次，然后宣布玩家完成了三阶段天命任务。

### 13.6 第一次异兆的制作边界

在后续条件确实成立时，一盏曾参与这些通行经历的旧灯可以出现微弱反应。它不发技能、不宣布宿命，只让玩家注意到“它的回应似乎与过去有关”。

第一次异兆要支持回看与无障碍表达：音效、可读描述、细微动画可以互补，不能只有一帧光点，也不能变成满屏演出打断战斗。

## 14. 多人世界：同一事实，不同关系

### 14.1 先定义世界连续体

本文用 `WorldContinuityId` 表示共享同一段世界历史的范围。项目可以将其映射为逻辑区服，但不能直接假设部署进程、频道或地图模板就是这个范围。

首个切片固定一个世界连续体、一个区域和一个权威场景实例。跨频道的共享节点在后续接入，不能先制造多份事实再尝试合并剧情。

### 14.2 三种状态分层

| 状态层 | 内容 | 一致性要求 |
|---|---|---|
| 共享世界事实 | 桥是否修好、节点模式、NPC 所在位置、权柄归属 | 同一连续体与相应领域内只能有一个权威答案 |
| 局部场景事实 | 当前实例的战斗、临时掉落、可见实体动作 | 由具体场景拥有者负责，不擅自提升为全服历史 |
| 个人关系与认识 | NPC 怎样称呼你、你听过哪些转述、你理解了什么 | 可以不同，但不得伪造共享物理世界 |

两名玩家可以站在同一座已修好的桥上，一个被感谢，一个只是路过。不能为了让每个人都体验“我修好了桥”，让他们看到互相矛盾的桥梁状态，却仍允许在上面共同战斗。

### 14.3 地图模板、NPC 定义与历史身份不能混用

`MapDefId` 不等于具体的一座桥；`NpcDefId` 不等于一个具有连续人生的 NPC。重要 NPC 必须有持久身份，临时表现实体只是它在当前场景中的承载。

多个频道展示同一历史人物时，不得让每个副本分别消耗同一份货物、完成相反承诺或各自取得唯一权柄。应明确哪些是只读表现，哪些行为转交同一个权威拥有者。首版单实例就是为了先避开这类不必要复杂度。

### 14.4 他人的天命可以影响我，但不能夺走我的基本游戏资格

别人修复节点，我可以受益；别人改变地方根火的状态，我可以面对不同的支路与地方故事。世界不必为每个人保持私人最优解。

但世界级能力不能被滥用成任意封禁、抢走他人资产、永久关闭新手成长或强迫非参与者进入 PvP。涉及对抗的能力与区域采用明确参与边界；基础职业成长与必要通行需有不依赖某位在线持有人的可行路径。

这是权柄的作品边界，不是否认共同世界会有代价。

### 14.5 换线、重登与转移

角色换线或重登后，记忆与契约不能重复获得。共享节点按权威版本同步，过期客户端不能使用旧权柄继续生效。跨服迁移和合服在规则明确前不开放权柄自动携带，不能简单复制唯一记录。

## 15. UI 与叙事表达：先让玩家感到，再允许玩家看懂

### 15.1 首次接触不新增一个天命面板

初始表达优先落在 NPC 行为、对话、物件变化、环境声音和可使用的通路。不要用一个未解锁的巨大按钮提前告诉玩家“这里还有一套要刷的系统”。

当玩家主动追问、回顾，或已进入明确承担时，再提供“足迹／被记住的事”一类入口。它是对真实经历的整理，不是每日待办清单。

### 15.2 玩家可见内容

| 内容 | 展示方式 |
|---|---|
| 亲历事实 | 简短记录发生了什么、在哪里、涉及谁 |
| 他人看法 | 标注“阿苇这样记得你”，不冒充客观人格 |
| 听闻 | 标注转述与不确定性，不给出后台秘密 |
| 当前承担 | 显示正在维持什么、馈赠何时成立、边界是什么、如何退出或移交 |
| 重要转折 | 引用真实旧事，呈现新后果，不捏造未发生的回忆 |

不展示候选倾向分数、刷取配方、全体 NPC 的秘密目标或未来必经节点。与此同时，**不把隐藏信息当成隐藏重大成本的理由。**

### 15.3 双层语言

诗性表达负责情绪，朴素表达负责理解。两层都需要存在。

> 诗性：“只要你仍在这里，灯就记得回来的路。”  
> 规则：“这份维持只在你位于当前灯路领域、且契约有效时生效。离开会结束维持，不会削除你的基础职业能力。”

### 15.4 不让世界的期待变成催促

NPC 可以邀请，可以失望，也可以依据事实改变信任。但不发送“你三天没来，大家因为你受苦了”的回流刺激；不让玩家必须不断续费式完成义务才能保住早已形成的身份。

对短期、明确接受的承诺，可以有后果；对没有接受的求助，不制造道德债务。

## 16. Rust 权威后端：新增识人与历史投影，不新增第二个世界写入口

既有工程计划采用“客户端意图 → 权威世界处理 → 已提交事件 → 展示与复制”的方向，并要求世界状态单写、持久化有明确失败语义、慢 I/O 不阻塞世界 tick。本设计沿用这些边界。[P2]

### 16.1 接入结构

```text
Web / TS 玩家意图                    NPC 有限目标决策
          └──────────────┬─────────────────┘
                         ↓
            既有世界命令入口与身份校验
                         ↓
          状态拥有者：地图／角色／物品／节点
                         ↓
           校验、预留必要状态、持久提交
                         ↓
                Committed Domain Facts
                         ↓
        ┌────────────────┼─────────────────┐
        ↓                ↓                 ↓
  语义事实提取       NPC 知识与记忆      既有任务／通知
        ↓                ↓
  候选倾向投影 ────→ 合理回应候选
                         ↓
          回到相应状态拥有者重新验证
                         ↓
             新事实／关系／可见回应
                         ↓
                  客户端展示投影
```

识人模块可以提出“阿苇这次应当认出该角色”的候选，不能直接修改桥梁、背包或技能状态。涉及世界变化的回应仍是普通权威命令。

### 16.2 最小模块边界

| 模块 | 负责 | 不负责 |
|---|---|---|
| `story_facts` | 从已提交事件提取值得保留的语义事实，保留来源与因果 | 记录每个移动包、代替经济账本 |
| `recognition` | 根据有限规则形成可解释候选、提供理由链 | 宣判人格、直接发能力、生成事故 |
| `npc_memory` | 管理观察者知道什么、怎样得知、当前如何理解 | 全体 NPC 共享后台真相 |
| `covenant` | 已理解且主动承担的关系、边界与解除历史 | 替代全部任务系统 |
| `authority` | 有资格裁决后的唯一落位、版本与效力校验 | 自动选择剧情胜者、提供 GM 权限 |

可以先把前三者作为现有 Rust crate 内的小模块实现。后两者随相应玩法阶段再加入。没有证据要求引入微服务、Kafka、向量数据库或独立 AI 服务。

### 16.3 领域类型草案

以下用于约束数据含义，不是当前仓库补丁，也不是完整可运行服务。实际工程应复用已有 ID、序列化、错误和持久化类型。

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub struct EventId(pub u128);
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub struct CausalRootId(pub u128);
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub struct WorldContinuityId(pub u64);

#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub enum ActorId {
    Player(u64),
    Npc(u64), // 持久历史身份，不是某一次 spawn 的临时 ID。
}

#[derive(Debug, Clone)]
pub enum StoryFactKind {
    CartStabilized,
    PassageMaintained,
    RetreatCovered,
    KnowledgeTransferred,
    CovenantAccepted,
    CovenantReleased,
    CovenantBroken,
    AuthorityResolved,
}

#[derive(Debug, Clone)]
pub struct StoryFact {
    pub id: EventId,
    pub root: CausalRootId,
    pub world: WorldContinuityId,
    pub region_id: u64,
    pub world_seq: u64,          // 本世界权威提交序；非客户端时间。
    pub subject: ActorId,       // 本条事实归因的主体。
    pub kind: StoryFactKind,
    pub origin_event: EventId,  // 既有领域中已提交的来源事实。
    pub related_facts: Vec<EventId>,
    pub extraction_revision: u32,
}

#[derive(Debug, Clone)]
pub enum MemorySource {
    Witnessed { fact: EventId },
    Experienced { fact: EventId },
    Heard { teller: ActorId, source_memory_id: u128 },
}

#[derive(Debug, Clone)]
pub struct NpcMemory {
    pub id: u128,
    pub observer_npc_id: u64,
    pub about: ActorId,
    pub source: MemorySource,
    pub statement_key: String, // 受控内容键，不是任意生成的事实。
    pub knowledge_revision: u64,
}

#[derive(Debug, Clone)]
pub struct RecognitionCandidate {
    pub subject: ActorId,
    pub pattern_key: String,
    pub supporting_facts: Vec<EventId>,
    pub conflicting_facts: Vec<EventId>,
    pub rule_revision: u32,
    // 没有“人格分”与“距离下一品阶还差多少”。
}

#[derive(Debug, Clone)]
pub enum CovenantStatus {
    Active,
    Released { by_fact: EventId },
    Broken { by_fact: EventId },
}

#[derive(Debug, Clone)]
pub struct Covenant {
    pub id: u128,
    pub bearer: ActorId,
    pub world: WorldContinuityId,
    pub terms_key: String,
    pub terms_revision: u32,
    pub accepted_by_fact: EventId,
    pub status: CovenantStatus,
}

#[derive(Debug, Clone, PartialEq, Eq, Hash)]
pub struct AuthorityKey {
    pub world: WorldContinuityId,
    pub scope_id: u64,
    pub existence_id: u64,
    pub law_slot: String, // 如 root_fire.operating_mode，而非“存续”。
}

#[derive(Debug, Clone)]
pub enum AuthorityOccupancy {
    Vacant,
    Held {
        bearer: ActorId,
        law_variant: String,
        resolved_by_fact: EventId,
    },
}

#[derive(Debug, Clone)]
pub struct AuthorityRecord {
    pub key: AuthorityKey,
    pub occupancy: AuthorityOccupancy,
    pub epoch: u64,         // 旧权能凭证与旧效果需校验此代次。
    pub state_version: u64, // 并发写入的版本条件。
}
```

多人贡献由来源领域事实记录参与者与角色；语义事实提取时按可核验贡献形成相应记录，不能把多人行为压缩成“最后操作者拥有全部功劳”。

事实类型中的字符串键必须来自已校验的规则与内容注册表。客户端不允许自报 `pattern_key`、`law_variant` 或“我已经履约”。

### 16.4 不把整个游戏改成事件溯源

首版只为有长期意义的动作保留语义事实，例如帮助生效、通行完成、承诺成立、知识接续。移动和每次普通伤害仍按现有方案处理。

既有世界状态仍是对应业务的权威状态；语义事实与记忆是有来源的历史和投影，不制造另一套可以与背包、地图互相矛盾的事实源。

保留关键锚点时可以压缩旧细节，但必须保留足以解释身份、承诺与权柄的可信记录。不能删掉证据后，只剩一个无法说明来源的“你就是这种人”。

### 16.5 事实消费的幂等与持久化

建议复用既有事务与 outbox 能力。数据库产品尚未核实，本文不指定 MySQL、SQLite 或其他新数据库。

| 数据 | 建议约束 |
|---|---|
| 语义事实 | 来源事件 + 主体 + 提取规则具有稳定去重键 |
| NPC 记忆 | 观察者 + 来源事实／来源记忆 + 记忆种类具有稳定去重键 |
| 倾向投影 | 投影更新与消费游标一并提交；重复消费不得重复追加证据 |
| 契约 | 接受／解除命令具有业务幂等键，当前状态具有版本条件 |
| 权柄 | 完整 `AuthorityKey` 唯一；落位必须关联已提交的有效裁决 |
| 待发布消息 | 与必须持久化的业务结果一起提交，允许重试发布 |

普通动画或气泡可以在重连后省略；形成身份的事实、资产消耗、契约与权柄不能因为展示队列满而丢失。

### 16.6 持久化与世界 tick 的关系

需要消耗资产或改变持久承诺的操作先进入待提交状态。相关资源或版本被预留，不能被其他依赖操作越过。存储完成通过消息回到权威拥有者，再确认成功并发布结果。

世界 tick 不等待磁盘；与该操作无关的世界继续推进。若持久化队列不可用，拒绝或暂缓新的持久操作，不能先播放成功、授予权能，再寄希望于稍后写盘。

重启时先恢复这些待决操作，再开放相关状态。已经提交但未通知的结果可重发；未提交的结果不能伪装成已经存在的历史。

### 16.7 不让反馈自我刷取

“NPC 感谢了玩家”“灯出现异兆”不能再被当作玩家作出善举的新证据，否则回应会不断制造自己的依据。

只有后续主体真正采取的新行动，才可能成为新的行为证据。所有回应携带因果来源；跨模块候选回到权威入口后重新检查当前条件。单次因果传播有界，不在同一 tick 内无限递归制造事件。

### 16.8 规则升级不能悄悄改写旧承诺

倾向识别是可重建投影，新规则可以重新评估候选。但已经接受的契约绑定当时的条款版本；不能因为一次热更新，突然给角色追加未曾接受的边界。

必须迁移时，要有显式迁移规则、可读说明和必要的解除／补偿路径。世界记忆也不能因识别器升级而凭空多出未曾发生的往事。

## 17. 权柄落位与跨域变化的正确性

这一节只在实现地方权柄时启用，不作为首个翻车切片的前置工程。

### 17.1 最小落位流程

```text
输入：已形成的裁决事实 ID + AuthorityKey + 预期状态版本

1. 权威拥有者核验裁决来源、候选资格、领域与当前事实。
2. 核验裁决确实解决了这一规则位置，而非只有一场战斗结果。
3. 以幂等命令预留相关状态。
4. 在同一提交边界内：
   - 校验旧版本；
   - 写入新的持有者与规则变体；
   - 提升 epoch 与状态版本；
   - 记录历史与待发布事件。
5. 提交成功后更新内存权威态，并撤销／失效旧 epoch 的效果。
6. 广播相应范围的新版本；断线玩家通过快照追上。
```

并发候选不会靠争抢数据库锁自动获胜。若同时存在两个未解决的有效主张，先进入争议状态；在裁决形成前，不授予任何一方“临时但实际有效”的唯一权能。

### 17.2 多个业务对象一起改变

首个地方权柄切片选择由同一权威边界管理的节点与相关状态，避免提前引入跨进程事务。

未来确需改变多个拥有者时，必须定义明确的预留、提交与补偿协议。跨域执行未完成期间，客户端显示待决，不能一半区域按新命题运行、另一半继续对外声称旧命题已经最终成立。

### 17.3 失效与恢复

旧会话、旧地图投影和旧权柄代次都不能继续施加效果。效果系统按来源权柄及其代次判断资格，不能只在第一次获得时加上一个永久属性。

灾难恢复后必须从持久状态恢复唯一记录、相关契约和裁决事实。历史重放不能产生第二个持有者，重复通知也不能再次发放能力。

## 18. 开发计划：先证明“认得你”，再讨论“命”

### 18.1 P0：定位接入点与建立事实契约

| 项目 | 交付与完成条件 |
|---|---|
| 仓库定位 | 找到真实命令入口、世界所有权、交互提交、物品转移、NPC 身份、地图实例和存储实现；记录实际文件路径 |
| 事件映射 | 将扶车／交付／掩护映射到现有动作或最小新增动作；明确成功、失败与重复请求语义 |
| 身份与范围 | 定义一个测试世界连续体、一个场景、一个持久 NPC 身份 |
| 可靠性 | 确认事件提交与去重方式；没有可靠事实入口时先补入口，不先写识人推断 |
| 启动约束 | 联调与验收统一由 `启动3010.command` 启动；不另建绕过它的启动流程 |

### 18.2 P1：同一 NPC，两次相遇

只实现翻车事件的有效行动、具体记忆、第二次识别与一个可见的世界变化。NPC 有最小自主后续目标，并支持玩家不参与的结果。

验收时，不显示“天命”两个字，不发新增属性，不要求玩家完成强制任务。先检查玩家是否注意到世界真的记住了他。

### 18.3 P2：倾向浮现，但不锁定

在复用现有能力的前提下增加不同情境，不扩建完整商队、供给、气候或社会模拟。选择一条候选道路，制作有来源的倾向证据与一次可拒绝的异兆。

玩家与 NPC 都可进入同一候选识别流程。验证重复刷取无效、不同情境可以互相说明、混合行为不会被强制塞入单一标签。

### 18.4 P3：一份馈赠与一条真正的边界

只制作一份地方性、可解释、可退出或移交的承担，例如一段灯路的维持。实现明示条款、主动接受、效果来源、离开或解除的真实后果，以及重启后的正确恢复。

这里才开始验证“命”而非熟练度。边界若与馈赠没有同一条规则来源，应退回设计，不靠扣属性补齐。

### 18.5 P4：NPC 的独立道路

让一名重要 NPC 在多种事实下坚持、让步或背离承诺，且无需玩家在场。为远处进展建立有限模拟、资源检查、历史记录与玩家回归后的信息到达。

验收重点不是台词数量，而是：同一套事实与选择规则，是否真的允许他走向不同结果。

### 18.6 P5：一次地方权柄冲突

限制在一个领域、一个存在、一个互斥规则位置。实现两种有力量也有代价的答案，允许 NPC 获得资格，并验证合作、让位、争夺与合法第三条路。

到这一阶段才实现唯一权柄登记。它不是 P1 的基础设施，不提前铺开全服神系、世界级 PvP 或无限大道生成器。

### 18.7 建议目录

以下仅为新增位置建议，P0 必须映射到真实仓库结构，不据此声称已找到源码。

## 19. 验收：既验世界是否诚实，也验玩家是否感到被认出

### 19.1 工程与规则测试矩阵

| 编号 | 用例 | 必须成立的结果 |
|---|---|---|
| T01 | 同一有效帮助事件重放 100 次 | 只有一份对应事实与记忆；不增加身份强度 |
| T02 | 同一事故内扶车、递药、掩护 | 分别保留真实贡献，但共享事故因果根，不伪装成三次独立经历 |
| T03 | 多人共同完成 | 各人得到符合贡献的记忆；最后一下不吞掉其他人的历史 |
| T04 | 只路过、强制教学、背包不足 | 不据此判定冷漠，不把被迫操作当自由偏好 |
| T05 | 行动失败但掩护确实生效 | 保存实际发生的掩护，不虚构救援成功 |
| T06 | 先造成危险再修复 | 因果链完整；不只记录有利一半，也不让不知情 NPC 自动全知 |
| T07 | NPC 未在场、未收到转述 | 不能知道该事件；转述到达后只获得被传递的信息 |
| T08 | NPC 的看法被新证据推翻 | 更新理解但保留曾经误解的历史，不改写原始事实 |
| T09 | 玩家与 NPC 对相同条件采取相同行动 | 事实、契约与权柄资格规则一致 |
| T10 | 玩家不参与／不在场 | NPC 可以按规则推进；世界不假装玩家做过事 |
| T11 | 早期倾向改变或拒绝称呼 | 不发生永久能力损失；旧行为仍被有关人物记得 |
| T12 | 接受正式边界 | 条款版本、明确接受事实与效果来源可以一一对应 |
| T13 | 未接受邀请后离线 | 不自动立约、不自动背叛、不因缺勤衰退身份 |
| T14 | 契约解除、违背或合法移交 | 当前效果正确变化，旧历史保留，基础职业不被无关削除 |
| T15 | 存储在提交前失败 | 不报告持久成功，不授予尚未成立的能力 |
| T16 | 已提交后崩溃、通知尚未到达 | 恢复事实并可重新通知；不重复扣物品、发能力或形成记忆 |
| T17 | 两个候选同时请求同一权柄 | 未裁决前保持争议；裁决后仅一份有效记录，不能由先发包决定 |
| T18 | 旧 epoch 的技能与客户端快照 | 不能继续获得已失效权柄的效果；可同步到新版本 |
| T19 | 玩家找到规则允许的新载体 | 原冲突允许解除，不为了剧情强行维持二选一 |
| T20 | 热更新识别规则 | 可重建候选，不偷偷更改既有契约条款或捏造回忆 |
| T21 | 回应事件再次进入事件流 | 不被当作玩家新的道路证据，不形成无限反馈循环 |
| T22 | 换线、重登、断线重试 | 共享事实不分叉，记忆不重复，临时实例 ID 不取代人物身份 |
| T23 | 木块已消耗或遗失 | 后续台词和仪式不能宣称木块仍在，除非有真实找回／替代事实 |
| T24 | 重要 NPC 获得地方权柄 | 后台不因其不是玩家而改判；基础世界服务也不因此被无关破坏 |

“100 次”等数字只是测试负载，不是正式玩法阈值。

### 19.2 体验验证不以在线时长作为结论

首个切片观察四件事：玩家是否发现第二次相遇不同，是否能说出这种不同来自自己的哪次行动，是否相信世界状态真的改变，是否在没有额外属性提示时仍愿意作出一次自发行动。

访谈先问“这两次相遇发生了什么”“你觉得他为什么这样说”，不要先问“你有没有感到被世界认可”，以免把设计者的答案塞给玩家。

可采用两种版本比较：世界后果相同，一版只说通用感谢，另一版引用真实往事并保持相同物质收益。观察具体记忆是否带来额外理解与投入。首批观察只用于发现问题，不宣称已经验证了普遍心理规律。

### 19.3 边界体验的通过条件

玩家在接受前能够用自己的话说明会得到什么、不能同时保有什么、怎样停止承担。承担之后，能够把代价理解为这份能力的成立条件，而不是发现一个隐藏削弱。

即便玩家不喜欢代价，也不等于测试失败；若玩家根本没有机会理解代价，才是设计失败。

### 19.4 两个暂停扩张的信号

若玩家只是在寻找触发公式，先检查收益是否压过关系、回应是否过于机械、证据是否等同次数，不继续增加天命品阶。

若玩家只记得对白却找不到实际后果，先修世界事实与记忆的连接，不继续添加更昂贵的演出。

## 20. 内容生产与风险控制

### 20.1 每个天命内容单元都交付同一张规格

| 字段 | 必须写清的内容 |
|---|---|
| 初始事实 | 事件开始时真实存在的对象、状态和资源 |
| 自由空间 | 玩家可以做什么、不做什么，还有哪些合理替代行为 |
| 事实变化 | 每种有效行为实际改变什么，失败会留下什么 |
| 归因与知情者 | 谁参与、谁知道、谁不知道、转述如何到达 |
| 回应依据 | 每句重要台词、每次异兆依据哪类事实 |
| 候选解释 | 哪些倾向可能被支持，哪些结论不得推出 |
| 馈赠与边界 | 二者是否来自同一规则；何时需要明确接受 |
| 自主推进 | 玩家缺席时 NPC 能采取哪些行动，资源是否足够 |
| 反事实 | 改变哪些事实可以改变结果或解除冲突 |
| 持久性 | 哪些内容需跨重登、换线、重启保留 |

文案最后填写具体表达。不能先写“你果然是被命运选中的人”，再让工程寻找一个勉强符合的触发条件。

### 20.2 核心风险与处理方向

| 风险 | 处理方向 |
|---|---|
| 候选识别变成人格标签 | 保存证据与不确定性，描述行为，不宣判本质 |
| 正反馈把玩家锁进偏好 | 保留无关机会与改道空间，避免按偏好制造世界需求 |
| 边界沦为隐藏惩罚 | 区分探索与正式承担；重大成本前置、范围明确 |
| 唯一权柄被早到者长期垄断 | 让位、继承与资格挑战来自世界规则；不要把登录频率当资格 |
| 大公会垄断世界决定 | 缩小初次权域，限制伤害外溢，先验证真实资格与多方参与规则 |
| NPC 自主造成关键服务消失 | 将店铺等服务角色与某个唯一人物的命运分开，允许合理继任 |
| 全部内容变成行善测试 | 支持求知、复仇、秩序、自由、执念等不同方向；不统一奖惩道德 |
| 为了反转临时补设世界规则 | 在冲突前建立事实；新增规则不得专门否定已成立的解决办法 |
| 系统量过大吞掉复刻进度 | 按 P1 到 P5 逐阶段验收，不越级搭建完整神系与模拟社会 |

“存续”是本轮深化的主轴，不是所有角色必须认可的唯一价值。后续其他大道也应遵循相同的事实、识人、边界与权柄结构，而不是简单换一个技能颜色。

## 22. 最终审查：把“天命”两个字删掉，世界还会认得你吗

上线任何一个相关内容前，先把“天命”“大道”“神”“权柄”这些词暂时删掉。

如果剩下的仍然是：一个真实的人做过一些事，世界确实因此改变，有人记得，他在后来的选择中渐渐承担了某种身份；这份身份给他力量，也让他无法再同时保有所有可能——那么它已经具备天命的基础。

如果删去那些词后，只剩刷取、加点、解锁与排行榜，那么它仍然只是一个换了名字的成长系统。

我们不是提前告诉玩家：“你注定成为谁。”

我们让他经过很多地方，帮助过一些人，也错过一些人；保留过一些东西，也亲手放弃过一些东西。他的偏爱渐渐被看见，他的承担渐渐成为世界运行的一部分。

直到某一天，他回头，发现那些选择已经连成了道路。

那时世界才有资格对他说：

> **我不是今天才选中你。**  
> **我只是终于认出了，一直这样走来的你。**
