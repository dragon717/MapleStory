# 冒险岛复刻：平台跳跃与侧壁碰撞优化方案

日期：2026-09-10  
状态：联网调研与待实施方案；本轮未取得当前项目碰撞源码，没有修改或启动项目。  
适用背景：Rust 权威后端 + Web / TypeScript 客户端。文中的类型、字段和接口是建议名称，不代表仓库现有实现。

## 1. 结论与需求边界

建议采用：**保留单向落脚面 + 明确有限高度侧壁 + 地面/空中统一运动碰撞 + 沿运动路径检测碰撞**。

需要保持的业务事实是：同一条已确认的阻挡侧壁，不能因为角色从行走切换为跳跃而失去阻挡作用。碰到竖墙只去掉朝墙内的水平运动，不取消上升、下落或正常跳跃。

本方案把用户描述理解为：同一地形轮廓中，高低平台边缘由一段竖直侧壁连接。它不包含“任意上下重叠的悬空平台都应自动补墙”。视觉重合不是地形连通的可靠依据。

需要保留：

- 现有行走侧壁阻挡、跳跃曲线、重力、正常落地和斜坡手感。
- 普通单向平台从下方穿过、从上方落地的行为。
- 明确存在的地图碰撞分组、通道及特殊技能规则。

本次不增加：自动攀爬、蹬墙跳、吸附上台、全地图实体填充或新刚体引擎。

## 2. 联网调研结论

### 2.1 最直接的参考：Nexon 的 MapleStory Worlds

官方《Understanding MapleStory Movement Concepts》区分了相连竖直立足线、离开立足点后的移动，以及可选的跳跃竖线阻挡；还说明可以按地图层配置这种阻挡。相关 CustomFootholdComponent API 提供 `IsBlockVerticalLine`。[S1][S2]

**证据边界：这些是 MapleStory Worlds 的官方行为说明，不是 TMS V273 原客户端逐帧实测。** 因此，当前“能挡走路、不能挡跳跃”的表现不能仅凭现象认定为程序漏检；也可能来自某种有意保留的移动语义。本次应把“指定侧壁空中同样阻挡”写成项目自己的明确规则。

### 2.2 Celeste / TowerFall

开发者公开介绍了矩形角色与实体地形，水平/垂直移动分开处理，并逐像素检测即将进入的位置。碰撞基础层不需要根据跳跃动画决定某块实体地形是否存在。[S3]

可借鉴的是：统一移动入口、稳定碰撞形状、阻挡与角色控制分离。不要为了借鉴而把现有连续坐标强行改成整像素坐标。

### 2.3 Unity / Godot

Unity Platform Effector 2D 明确区分单向碰撞、生效表面方向及侧面摩擦/反弹；Godot CollisionShape2D 提供单向碰撞配置。Godot 的角色移动示例把跳跃许可与公共的移动碰撞调用分开。[S4][S5][S6]

可借鉴的是：**顶面是否单向通行，与侧面是否阻挡，是不同的规则。** “侧面无摩擦”也不等于“侧面不碰撞”。

### 2.4 Box2D / Rapier

Box2D 提供 shape cast / time of impact 以处理沿移动路径的碰撞，并解释了相邻线段内部顶点引发的 ghost collision。Rapier 的角色控制器提供 move-and-slide，并使用微小 offset 来改善数值稳定性。[S7][S8]

可借鉴的是：检查整段运动、选择最早接触、只删除穿入方向的分量、处理接缝与微小容差。它们不是要求本项目更换引擎。

## 3. 目标行为契约

| 场景 | 目标行为 |
|---|---|
| 在低平台上向相连高平台走 | 保持现有侧壁阻挡 |
| 跳跃上升时斜撞该侧壁 | 横向受阻，纵向继续上升 |
| 下落时斜撞该侧壁 | 横向受阻，纵向继续下落 |
| 头已经超过墙顶，但脚仍低于墙顶 | 采用身体碰撞体时仍不能穿入侧壁 |
| 碰撞体整体已高于墙顶 | 不被向上无限延伸的假墙阻挡；允许越过 |
| 从上方落到高平台 | 由平台顶面正常承接 |
| 从普通单向平台正下方上跳 | 保留向上穿透；不自动变成顶头碰撞 |
| 两个悬空平台仅上下重叠 | 不因投影重合自动生成侧壁 |
| 下跳正在忽略某个单向平台 | 仅忽略目标落脚面，不自动忽略侧壁 |
| 冲刺、击退等连续位移 | 默认走相同的环境碰撞入口；例外由技能明确声明 |
| 合法瞬移 | 使用明确的瞬移规则与终点合法性检查，不伪装成普通移动 |

身体尺寸应优先复用现有环境碰撞模型。如果现有项目只有脚点式 foothold 判定，第一阶段先保持其尺寸语义，修复空中缺少侧壁约束；引入完整身体 AABB/胶囊应另作可比较的手感变更，不能悄悄改变所有平台可达性。

## 4. 首先定位原因，不预设答案

为同一面墙录制两份最小回放：走路撞墙、跳跃撞墙。记录输入、位置、速度、当前立足点和候选碰撞面。

重点核查以下分支：

1. 墙检测是否仅在 `grounded`、`on_ground`、`current_foothold != None` 等条件下执行。
2. 起跳清空当前立足点后，是否也丢失了墙的查询来源或碰撞分组。
3. 是否把“向上忽略单向落脚面”误写成“向上忽略全部地形”。
4. 是否只测目标点/本帧终点，而没有检测位移途中穿过的薄墙。
5. 是否仅一端执行了侧壁碰撞，另一端的预测、位置包或显示插值覆盖了结果。
6. 是否现有逻辑明确实现了“空中可穿竖线”的兼容策略。

这些是待验证假设，不是本轮已确认的源码缺陷。

## 5. 地形模型：落脚面与侧壁分开

建议在地图导入/编译阶段提供可区分的碰撞语义，而不是运行时根据角色状态改墙：

```text
OneWayFloor：从上方下降时承接角色；从下方上升时忽略。
SolidWall：指定碰撞分组中的实体侧壁；行走、上升、下落都适用。
```

现有实体顶板等其他类型保持原样，本次不扩展其规则。

侧壁建议至少有：

```text
id
x
y_min, y_max
collision_group
blocking_side / normal（存在单面语义时必须明确）
source_surface_ids（追踪地形来源，便于调试）
```

### 5.1 侧壁来源优先级

首先复用地图已有的竖直碰撞段或已明确标注的墙。若数据含相邻立足点关系，利用它验证边界连续性；具体字段名以项目源码为准。

原始数据缺失时，只为“已确认属于同一碰撞轮廓的高低平台边缘”生成连接段。不能仅以 X 相同、贴图遮挡、同一渲染层或平台高度接近作为补墙依据。

侧壁必须保留真实的上下端点。不得向地图顶底无限延伸，也不得把同一 X 下所有分离段直接合并。

### 5.2 地图层与碰撞分组

渲染顺序不能直接当作碰撞归属。空中离开 foothold，不意味着失去整个环境碰撞上下文。

本次保持既有合法穿层规则，并明确哪些侧壁属于当前可碰撞空间。不要为了修复一个台阶而开启全地图所有竖线阻挡。

### 5.3 接缝

合并或共享同一碰撞语义下的共线相邻边，保留端点邻接关系，避免重复线段及内部顶点被误判为墙。Box2D 的 ghost vertices 说明了这种接缝问题的机制；自研实现不一定使用同名结构，但必须处理同类情况。[S7]

## 6. 运动求解

### 6.1 统一入口

```text
输入 + 当前速度 + 原有重力/技能规则
                  ↓
          本物理步的期望位移
                  ↓
     根据扫掠范围查询相关地形
                  ↓
       所有状态共用碰撞求解
                  ↓
        得到合法位移与接触面
                  ↓
     更新速度、立足点与 grounded
                  ↓
          发布权威状态 / 渲染
```

`grounded` 可以决定能否起跳、摩擦、贴地等行为，但不应成为指定 SolidWall 是否存在的开关。单向平台的过滤规则仍然允许依赖相对运动方向和先前位置。

如果现有控制器已经按 X/Y 分轴处理，就保留其顺序和控制手感，在公共路径补齐侧壁检测；不要仅为了本问题重写所有移动代码。

### 6.2 检测沿途，而不是只检测终点

新写的检测优先使用 swept AABB 或现有引擎的 shape cast，按最早接触时刻（TOI）裁剪运动。二维碰撞过程中，侧壁与落脚面应比较实际接触顺序；处理一次接触后，根据修正后的剩余运动重新查询/求解。

仅演示一个从左向右的侧壁接触候选，忽略容差：

```text
t = (wall_x - character_right_at_start) / dx
```

只有 `0 <= t <= 1`，并且角色在这个 t 时刻的纵向范围与侧壁范围重叠，才是相应侧面接触候选。不能拿整帧终点的 Y 坐标代替接触时刻的 Y 坐标。

例如：

```text
墙：x=100，顶端 y=100，底端 y=200（屏幕 Y 向下）
角色开始右边缘：x=90；脚底 y=160；身体高 40
本步位移：dx=20，dy=-80

水平到墙时 t=0.5
此刻脚底 y=120，身体仍与墙的高度范围重叠 → 应阻挡
整步终点脚底 y=80 已高于墙顶，但不能倒推途中也没有撞墙
```

上述公式不是完整求解器：贴墙起步、初始重叠、多碰撞、斜坡、移动地形与端点接触还需既有控制器或完整扫掠实现处理。不要把这段候选公式单独复制成最终移动模块。

已有逐像素分轴控制器可以继续使用逐像素检测，不强制更换算法。若采用子步，子步数量应由允许的最大位移等约束决定；“固定多测几次”并非任意速度下不穿墙的保证。

### 6.3 碰撞响应

对单位法线 n、速度 v，删除朝碰撞面内部的速度分量：

```text
v_after = v - min(dot(v, n), 0) * n
```

对竖墙意味着阻止朝墙内的水平速度，保留竖直速度；剩余位移也按同一原则处理。不要在任意碰撞发生后直接把 `vx`、`vy` 同时归零。

撞墙不等于落地。只有有效的支撑接触才能恢复 grounded、当前 foothold 或落地相关跳跃次数。

### 6.4 墙顶、墙脚、容差

墙顶必须能正常越过，墙脚不能生成无法跨越的小凸起。平台顶面与侧壁同时接触时，要有稳定的接触处理规则，避免顺序依赖造成一帧卡顿、弹起或吸附到高台。

对身体碰撞体，判断墙顶放行应看底部是否已脱离侧壁，而不是头顶是否越过。对点式控制器，则使用项目已定义的接触代理，避免混合两套尺度。

使用微小、统一的 skin/contact tolerance，优先复用项目已有值。数值按世界单位与角色尺寸确定，不能把某引擎的默认 offset 直接当作本项目像素常量。[S8]

不能依靠加粗墙体、扩大吸附范围或自动向上纠正角色位置来掩盖漏检。贴地/台阶吸附也不能把空中撞墙变成免费登高。

### 6.5 性能与求解上限

按角色整个扫掠包围盒做空间查询，不只检查当前立足点的邻居，也不必每次扫描全地图。允许使用已有空间网格、区间索引或树，不为了这次修复引入无关复杂度。[S7]

连续碰撞求解应有迭代上限。到上限时停留在最后合法位置，并记录诊断信息，不直接应用剩余未验证位移。

## 7. Rust 权威端与 Web/TS 客户端

以下是建议的接入约束，而非对当前仓库实现的描述。

Rust 权威端负责最终运动合法性、位置、速度、接触状态与立足点。客户端若已有本地预测，必须对新增侧壁应用同一份地形语义和碰撞规则，不能等服务器回拉来实现视觉上的阻挡。

两端至少对齐：碰撞几何版本、碰撞代理形状、单位、容差、时间步、单向面过滤、碰撞分组与接触排序。

本次不强制提取 WASM 公共核心；已有 Rust/TS 双端实现先通过共享输入回放与断言核对行为。相同的公式和固定时间步本身不等于跨语言逐位确定性，仍需实际对照结果。

保持或明确固定物理时间步，显示帧率不应直接决定可穿越的位移长度。固定物理步与渲染帧分离是 Godot 官方说明的通用模式；具体步频复用本项目既有设计，不顺手修改跳跃手感。[S9]

服务器纠正和显示插值也必须区分：物理状态已经停在墙前时，显示层不能继续外推到墙后，造成“看起来仍穿墙”。

## 8. 实施顺序

### 第一阶段：最小安全修复

定位原墙规则和起跳分支，建立最小失败回放。复用既有行走碰撞模型，把目标侧壁纳入上升与下落路径，消除 current_foothold 缺失造成的候选丢失。保持行走、重力、跳跃速度与坐标精度不变。

此阶段不承诺仅改一个 if 就足够；若原逻辑只是限制地面路径连接，需要先将真正的阻挡边界表达为可查询几何。

### 第二阶段：消除穿透与接缝问题

补齐沿途检测、端点/贴墙接触、多个候选的最早碰撞处理、微小容差和正确的法线响应。防止空中贴墙时卡住、头顶过墙即穿透、墙体无限延伸和高速漏检。

### 第三阶段：双端一致性与实图回归

核对权威与预测，记录修正次数和位置误差。选取存在目标台阶的地图，以及有悬空平台、叠层和斜坡的地图回归。可按地图或边界保留兼容开关，确保修改范围可追踪、可回退。

构建与启动集成验证统一使用项目原有脚本：

```bash
./启动3010.command
```

本方案没有执行该命令。

## 9. 验收矩阵

| 编号 | 用例 | 必须满足 |
|---|---|---|
| T01 | 地面向左/向右撞同一目标墙 | 保持修复前正确行为 |
| T02 | 上升斜撞墙 | 不横穿；纵向继续上升 |
| T03 | 下落斜撞墙 | 不横穿；纵向继续下降 |
| T04 | 头高于墙顶但身体仍重叠 | 身体模式下保持侧面阻挡 |
| T05 | 身体完全越过墙顶 | 能越过并正常落地，不存在无限高墙 |
| T06 | 持续按向墙方向跳跃 | 不粘墙，不凭空恢复跳跃次数 |
| T07 | 从墙边反向移动 | 立即允许离墙，无容差吸附 |
| T08 | 单步位移跨过整段墙 X 范围 | 不因终点在墙另一边而漏检 |
| T09 | 本步终点已过墙顶、但途中撞墙 | 以真实接触时刻阻挡 |
| T10 | 普通悬空平台从下方上跳 | 单向穿透保持 |
| T11 | 两平台上下重叠但无拓扑连接 | 不自动补墙 |
| T12 | 允许的下跳靠近侧壁 | 只忽略目标落脚面，不忽略墙 |
| T13 | 共线平台接缝、坡接平地 | 不生成幽灵墙、不异常弹起 |
| T14 | 合法叠层/通道地图 | 保持既有碰撞分组规则 |
| T15 | 切图或纠正位置恰好贴墙/轻微重叠 | 按稳定规则恢复，不任意弹到另一边 |
| T16 | 30/60/144 渲染 FPS，同一物理步率与输入回放 | 碰撞结论一致 |
| T17 | 客户端预测与服务端同输入 | 不持续回拉；关键碰撞/落地事件一致 |
| T18 | 冲刺/击退与特殊瞬移 | 连续位移默认碰墙，显式例外按独立规则验证 |

核心不变量：对参与普通连续运动碰撞的实体侧壁，角色不能在与墙高度范围重叠时穿越其阻挡侧；改变行走/上升/下落状态本身，不应改变该墙的有效性。

## 10. 调试信息

建议显示：角色环境碰撞代理、平台线、侧壁上下端点与法线、碰撞分组、上一物理步位置、期望路径、实际路径、TOI、接触面 ID、grounded、current_foothold。

网络调试同时区分服务端位置、客户端预测位置与显示插值位置。通过这些信息区分“数据没有墙”“过滤掉墙”“沿途漏检”“响应错误”“显示外推”五类问题。

## 11. 可直接交给编码代理的任务摘要

> 修复已确认的高低平台相连侧壁在空中失效的问题。首先核实当前表现是状态分支漏检、候选查询丢失，还是明确的兼容规则；将指定侧壁定义为行走、上升、下落均生效的有限高度阻挡面。保留普通单向平台向上穿透，不按上下投影关系自动补墙。复用现有碰撞形状与跳跃参数，通过公共移动入口执行沿途检测，撞墙仅去除穿入分量，不设置落地。处理墙顶、接缝、初始贴墙和高速位移，保持地图碰撞分组、Rust 权威端与 Web/TS 预测一致。新增回放与验收矩阵测试，集成验证只通过 `./启动3010.command` 启动。提交时说明修改位置、碰撞语义、测试结果和仍未验证的地图；不得把未运行的测试写成通过。
