# 目录迁移与清理证据

日期：2026-09-12。范围以根 README「项目目录与文件职责」为准。

## 根因与处理

- 文档、历史计划、研究包和缺陷补丁没有统一归属，根目录承担了多种职责。按文档用途迁移，当前任务只由 `docs/plan/PLAN.md` 维护，历史记录逐任务归档并建立索引。
- 检查脚本写死 `output/` 等输出路径；旧检查构建缺少清理规则。改用按上海日期生成的证据路径，删除已确认未被打开的旧 Vite 构建。
- Cargo 缓存存在多代对象和大量编号冲突副本。只清理可再生且未被进程打开的文件，保留在线二进制和打开的缓存；后续候选构建独立生成，不把缓存当历史发布版。
- macOS Vite 原先直接清空现用输出，Windows 启动直接删除旧输出；打包也没有统一两版保留。统一先准备候选，再切换配对制品；健康成功后提交轮替，失败保留或恢复旧版本。打包只在完整性验证通过后发布。
- 新增目录归属检查并挂入 `npm run check`，防止根目录文件和独立 `dist-*` 产物回流。

## 原始证据

- `cleanup.json`：删除构建清单、缓存文件数量及逻辑字节数、保留的打开文件、运行状态观察。逻辑字节数不等于实际释放磁盘空间。
- `moves.json` 保存文档、证据和运行快照的 old→new 映射；`verification.json` 汇总最终检查，日志保留实际输出。
- 数据库未读写或重置。运行控制目录原子移动后，原进程日志描述符继续指向新路径；后续观察到原 PID 消失，未执行任何启停命令，退出原因未获证据。

## 验证结果

npm 检查 29/29、真实 Rust/Vite 候选构建和两种实际 ZIP 完整性检查通过；最终目录门禁、全部 3,300 条迁移目标及文档本地链接检查通过。验证候选已清理，未激活或启停服务；Windows 原生启停仍待用户按既有计划验证。两组逐字节相同的文档已保留一个规范位置，去重 SHA256 见 cleanup.json。
