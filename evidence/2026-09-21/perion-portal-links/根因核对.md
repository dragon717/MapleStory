## 3. 根因：闭包判据用错了源树，且只算一层

`artifacts/portal_closure_check.py`（2026-09-18 那次补闭包的工具）把 `WZ_JSON_TW/Map/Map/MapX/` 当源：

```python
WZ = .../TMS273/WZ_JSON_TW/Map/Map          # ← 这是「已装配图的解包副本」，不是源
```

而那个目录**天然只含当时已解包进来的图**（`Map1/` 里 52 个 json，`102*` 只有 12 个，连已装配的
`102020200.json` 都不在里面）。于是：

```bash
# 复现（把产物改到别处，不动 09-18 的留档）
sed 's#artifacts/portal-closure.json#/tmp/out.json#' artifacts/portal_closure_check.py > /tmp/c.py
python3 /tmp/c.py
# → closure total: 198 new needed: 0
# → SOURCE MISSING: [..., '102030100', '102040100', ...]
```

`102030100` / `102040100` 被算成 **「源缺失」**（`portals_of()` 返回 `None` ⇒ `missing_src.append` ⇒ `continue`），
于是它们既没进「该装配」名单，也**没有继续 BFS**——背后那 3 张 + 8 张共 11 张同簇图从未被这个工具发现。

**但这两张图在权威源里都在。** 权威源是客户端打包 WZ（`export_tms273.cjs` 读的
`参考/273/TMS273少爷一键端/客户端/TMS273.7/Data`），不是 JSON 镜像：

```
102030100: EXISTS bgm=Bgm01/HighlandStar  portals: sp,sp,east00→102030000,west00→102030200,bottom00/top00(自环)
102040100: EXISTS bgm=Bgm12/AcientRemain  portals: sp,sp,west00→102040000,east00→102040200
```

⇒ **两层缺陷叠加**：① 判据源树用错（拿派生副本当源）⇒ 悬空链接被系统性误判为「源不存在」；
② 判中即 `continue`，不做第二层 ⇒ 即使第一层侥幸命中，下游链也不会被发现。

## 6. 顺带发现：整类缺陷不止勇士部落

`SOURCE MISSING` 那 38 个 id **全部**都能在客户端 WZ 里打开（`目标在客户端 WZ 里可打开: 38/38`），
即每一扇指向它们的门现在都是死门。背后可展开的规模（仅第一层，来自 `repro/02` 的 §C 之后 BFS）：

```

130010000  → +6     200000200 → +3     200010000 → +21    200080100 → +5
220010500  → +29    310020100 → +2     310070100 → +11    100030320 → +3

                    310040110 / 310040400 / 220000301..307 → 0（室内，同 `102000001` 的孤岛形状）
```

**勇士部落这一簇（13 张）是这次的范围；其余 36 扇死门另立项，不在本次改动内。**

## 7. 修复方案（待确认范围后执行）

1. `scripts/dump_tms273_wz_json.cjs` 落 13 张图的 `Map/Map/Map1/<id>.json` 到解包树。
2. `scripts/import_tms273.py` 新增一个带注释的 `ADDITIONAL_*_MAP_IDS` 分组（说明装/不装理由）+ dump 列表。
3. `node scripts/build_tms273.cjs`（约 6 分钟）。
4. 内容版本四处同步（`assemble_tms273.cjs` / `shared/protocol.ts` / `server/src/protocol.rs` /
   `scripts/check_tms273_runtime.cjs`）`tms273-NN` 递增；**协议号不动**（无 wire 结构变化）。
5. **根因封堵**：把闭包判据从「派生副本」改成权威源——新增
   `scripts/check_tms273_portal_closure.cjs`（读客户端 WZ），断言「已装配图的每个跨图 `tm`
   要么已装配，要么在**显式 allowlist**里且带理由」；登记进 `client/scripts/run-checks.mjs`。
   没有这一条，下一次补图还会以同样方式漏。
6. 门禁与验收：`check_tms273_runtime.cjs` 加「勇士部落 29 图逐门双向配对 + 终点边界」块；
   同步过期计数基线（图数 198→211、怪数）；`server/src/*_acceptance.rs` 加端到端路由/落点贴地用例。
7. 客户端：类型 2 的门走通用 `handle_portal` + `catalogHasMap`，**不需要** `tms273_remaster.cjs`
   的脚本门授权表；装配后 13 张图的门会自动获得 `pv/default` 光束（装配器已有该规则）。
8. 用户侧：**自己跑 `zsh 启动3010.command`**（前后端一起换；服务端只在启动时读 `shared/maps.json`）。
