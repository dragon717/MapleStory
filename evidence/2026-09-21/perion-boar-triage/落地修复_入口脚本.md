`根因核对.md` 是取证（死亡链路 / 数据对源 / 地图四面）；本文件是改动与验证。

## 2. 真因

`102030000 黑肥肥領土` 与 `102040000 初期挖掘地區` 的源 `info` 都写着：

```
onUserEnter = warning_MobLevel      // 源的「怪物等级警告」
```

而**这条声明在装配后被彻底丢弃**：

- 生产者是唯一的：`scripts/export_tms273.cjs:295` 把 `onFirstUserEnter`/`onUserEnter`
  写成 `entryScripts:{first, each}`，进 `shared/maps.json` 与客户端
  `manifest.json → mapCatalog.maps[].entryScripts`；
- **消费者为零**：`Map`（`server/src/world.rs`）根本没有这个字段，serde 静默丢弃；
  客户端清单类型 `MapCatalogEntry` 里也没有它。`grep -rn entryScripts` 只命中导出器。

于是源作者给这两张越级图准备的提示从未出现过：玩家从 `102020100 風塵山丘`（Lv2x 区）
一步跨进 Lv55 猎场，没有任何信号，只能把「打不动」读成怪物坏了。

> 关键旁证：装配目录 198 张图里，**最高怪等级 ≥ 55 的有 59 张，而声明 `warning_MobLevel`
> 的只有这 2 张**。说明它是源作者**逐图手工**挂的提示，不是可推导的通用规则——
> 这直接否掉了「等级差 ≥ N 就警告」的写法（会在另外 57 张图上多出源里没有的提示）。

## 3. 改动

| 文件 | 作用 |
| --- | --- |
| `client/src/features/world/entry-script.ts` | **新增**。纯判定 `mapEntryWarning()`：脚本名 == `warning_MobLevel` **且** 图内已刷新怪物的最高等级 **>** 玩家等级才返回结果，否则 `undefined`。查不到等级的模板跳过（不兜底成 0）。 |
| `client/src/assets/manifest.ts` | 补 `MapEntryScripts` 类型并挂到 `MapCatalogEntry` / `MapDefinition`（此前类型里没有这个字段）。 |
| `client/src/app/main.ts` | 接进已有的入图播报块（`announcedMapId !== message.mapId`），用 `ChatView.appendSystem` 出系统行。等级取自清单的 `monsters[templateId].info.level`，怪物列表取**服务端快照**。 |
| `client/src/features/world/entry-script.check.mjs` | **新增**门禁（见下）。 |
| `client/scripts/run-checks.mjs` | 登记该门禁（逐条列举，非 glob）。 |

设计上刻意守住的边界：

- **触发只认脚本名**，不设等级差阈值（理由见 §2 的 59 vs 2）。
- **不发明脚本体行为**：`手動服務端/tms273-1/script/map/onUserEnter/` 的 167 个脚本里
  没有 `warning_MobLevel.js`（它是官方客户端内建）⇒「高多少级才提、什么颜色、配不配音」
  无据可循，一律不做。只报告可核事实（该图最高怪物等级 / 玩家等级）。
- 未动任何源数值、未动 `shared/*.json`、未动协议版本（纯客户端消费，**不需要**升
  `PROTOCOL_VERSION`/`CONTENT_VERSION`）。
- 其余 `onFirstUserEnter` 与 `go*`/`enter_*`/`explorationPoint`/`VIWarmingUp_*` 等脚本
  **仍未落地**（脚本体同样不在资源包里），在模块头注释里如实登记。

## 4. 验证

```bash
# 新门禁
cd client && node src/features/world/entry-script.check.mjs
#   → 198 maps carry entryScripts, 2 declare warning_MobLevel (102030000, 102040000),
#     59 maps out-level Lv55.

# 类型检查
cd client && npm run typecheck          # 通过（无输出）

# 全量客户端门禁
cd client && npm run check
```

门禁断言（8 组）：

1. 非该脚本名 / 空 `each` / 旧清单无字段 / 只写在 `first` —— 一律不出提示；
2. `Lv38 → Lv55 图` 出提示；`Lv55` 持平、`Lv60` 够级 —— 不出提示；
3. 空快照 / 未知模板 / 无玩家等级 / `NaN` —— 不猜、不兜底；
4. 取**最强**怪物而非首尾；
5. **真实清单**：198 张图 `entryScripts` 一个不缺（生产者回退即红）；
6. **真实清单**：声明集恰为 `{102030000, 102040000}`；
7. **真实清单**：声明集 ⊊ 越级集（59 > 2）——把「不可用阈值替代」钉死；
8. **真实清单端到端**：`2230102` 的等级经 `manifest.monsters` 读出为 55，
   Lv38 玩家进黑肥肥領土必出提示，Lv60 玩家不出。

## 5. 未做 / 需裁决

  `enter_*`、`contiMove_Whistle`、`go*` 等），脚本体均不在资源包内。要落地需要用户提供
  行为依据，否则等于发明规则。
- **若用户要的是「让黑肥肥更好打」**（而不是「让地图说清楚」），那必须动源数值或转职表，
  属于另一类改动：几处都会牵动 `subject` 与门禁，需明确授权后再做。
  当前 `102030000` 是 `job-211`/`job-231`（**三转 Lv60**，各需击杀 30 只）的猎场，
  等级与目标怪相称，**不建议改**。
