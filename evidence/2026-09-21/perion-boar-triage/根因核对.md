## 2. 死亡链路：证明它是对的

同一账号在该图 15:34:13–15:34:25（约 11.7 s）共 149 条 `attack_actions`：

- 命中记录 149 条，**`killed=1` 的记录 2 条**，合计伤害 63 119，波及 **12 只**不同怪物。
- 逐目标累计（`monster_damage`）：`8000 / 8000 / 6723 / 5578 / 5361 / 5211 / 5025 / 4788 / 4788 / 3429 / 3192 / 3024`。

**决定性判据**——全库累计伤害的上限：

```sql
SELECT max(damage) FROM monster_damage;   -- 8000（= 2230102 的 maxHp，恰好不多不少）
```

累计伤害由 `applied_damage = damage.min(target_hp)` 夹住，所以**任何「血量掉到 0 却没死」的怪物都会留下
>`maxHp` 的记录**。全库 979 行里没有一行越界，唯二到 8000 的两行在 `attack_actions` 里都是 `killed=1`。
⇒ 伤害按预期累加，死亡在 0 血那一刻触发，之后 `death_until`/`respawn_at` 按 `dieDurationMs` 与
`monsterRespawnMs` 走完清除与重生。

## 3. 数值与源一致：0 处漂移

- **怪物表**：把 `shared/gameplay.json` 的 70 个模板逐个对回 `WZ_JSON_TW/Mob/<id>.json` 的
  `info.level / maxHP / exp` ⇒ **70 / 70 全等，0 mismatch**。
- `Mob/2230102.json` 原文：`level 55, maxHP 8000, exp 187, PADamage 346, PDRate 5, pushed 400`。
  ⇒ Lv55 / 8000 HP 是**源数据**，不是解析错误。
- 这是**有意为之**：`docs/design/法师分支转职设计_火毒与主教.md` 把 `2230102` 定为
  `job-211`（210→211，Lv60）试炼「黑肥肥 ×30」与 `job-231`（230→231）「膽小的黑肥肥 ×30」的目标怪。
- **技能表**：当事人用的技能是 `2001008 魔靈彈`（`skill_actions`，Lv20）。
  源 `Skill/200.json` 的 `common` 原文：`"damage": "18+3*x"`、`"attackCount": "4"`、`"mobCount": "4"`、
  `"mpCon": "16+2*d(x/5)"` ⇒ Lv20 = 伤害 78%、4 段、最多 4 目标、耗蓝 24。
  导出值与之一致（`shared/mage-skills.json`）；且库中实测每次施法掉蓝 ≈24，**两个独立字段同时印证 x=等级**，
  说明「公式解析器支持小数」那次改动没有改坏这张表。

## 4. 伤害算术逐位对上

```
magic_attack = INT*4 + LUK + level + 装备 MAD = 119*4 + 4 + 38 + 22 ≈ 540
单段伤害     = floor(540 * (1 - pdRate 5%) * 78%)          ≈ 400
```

库中实测每次命中伤害：`348 / 371 / 378 / 399`，暴击 `×1.2` ⇒ `453 / 478`。
**观测值与公式完全吻合**，没有「伤害被吞」或「命中判空」。

每次施法（`request_id` 形如 `skill-cast-<ts>-<n>:s<segment>:t<monster>`）：
`s1..s4` × 3 个目标 = **12 次命中**，即对每个目标 4 段 × 400 = **1600 伤害/次**。

- 8000 ÷ 1600 ⇒ **一只黑肥肥约需 5 次施法（≈20 下）**。
- 本次 15 次有效施法（其余是 `2001009 瞬間移動`，本就不出伤害）⇒ 打掉 12 只的 38%–100%，
  **只死了 2 只**。「打了很多下它还不死」是**字面为真**的观感，不是逻辑失效。

## 6. 真正该记一笔的缺口

`102030000.img/info` 原文带 **`onUserEnter = warning_MobLevel`**
（装配后在 `shared/maps.json → entryScripts.each`）。这正是源作者为这块「低等级区旁边摆 Lv55 怪」
预留的提示脚本。而：

```
grep -rn "entry_scripts\|entryScripts\|onUserEnter" server/src/
→ 仅 ufo.rs 一条无关注释（说的是另一个未建模的 fieldScript），运行时从不读入口脚本。
```

⇒ **这条提示永远不触发**，玩家一声不响走进 +17 级的区域。这是本仓库侧唯一确凿的**实现缺口**
（登记缺失），不是「野猪不死」的成因。

> 补注：`warning_MobLevel` 的**脚本体在参考树里不存在**（`手工服务端/tms273-1/script/map/onUserEnter/`
> 167 个脚本中没有它，源码 JSON 树里也搜不到该字串）——它是客户端内置脚本。
> 因此**无法从源派生它的行为**，照猜实现＝发明规则，故本轮不动。
